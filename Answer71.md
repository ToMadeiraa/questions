# 71. Разница между указателем и ссылкой в C++

Указатель и ссылка — оба механизма дают доступ к объекту косвенно, но имеют принципиально разную природу, синтаксис и правила использования.

## 1. Определение

**Указатель** — это отдельная переменная, которая хранит адрес объекта в памяти. Указатель — самостоятельный объект, занимающий память (обычно 4 или 8 байт).

**Ссылка** — это псевдоним (алиас) уже существующего объекта. Ссылка не является отдельным объектом, у неё нет собственного адреса и, как правило, она не занимает памяти.

```cpp
int x = 10;
int* p = &x;   // p — отдельная переменная, хранит адрес x
int& r = x;    // r — второе имя для x, тот же объект
```

## 2. Инициализация

- **Указатель** можно объявить без инициализации (содержит «мусор») и присвоить позже.
- **Ссылка** обязана быть инициализирована при объявлении и навсегда привязана к объекту.

```cpp
int* p;          // допустимо (но опасно)
// int& r;       // ошибка компиляции

int a = 1, b = 2;
int& r = a;
r = b;           // это НЕ перепривязка! r по-прежнему ссылается на a, значение a стало 2
```

## 3. Изменение привязки

- **Указатель** можно перенаправить на другой объект.
- **Ссылку** нельзя «пересадить» на другой объект — привязка фиксируется навсегда.

```cpp
int a = 1, b = 2;
int* p = &a;
p = &b;          // OK: теперь p указывает на b

int& r = a;
// r = b;        // присваивает значение, а не перепривязывает
```

## 4. Возможность быть «пустым»

- **Указатель** может быть `nullptr` (не указывать ни на что).
- **Ссылка** всегда должна ссылаться на существующий объект. «Нулевой ссылки» в корректной программе быть не может.

```cpp
int* p = nullptr;   // OK
// int& r = *p;     // UB — разыменование nullptr
```

## 5. Арифметика

- **Указатель** поддерживает арифметику (`p + 1`, `p++`, `p[i]`) и сравнение.
- **Ссылка** арифметику не поддерживает — с ней работают как с самим объектом.

```cpp
int arr[3] = {1, 2, 3};
int* p = arr;
p++;             // OK: указывает на arr[1]

int& r = arr[0];
r++;             // увеличивает arr[0], а не «сдвигает» ссылку
```

## 6. Уровни косвенности

- Можно иметь **указатель на указатель** (`int**`), **массив указателей**, указатель на функцию.
- **Ссылки на ссылки** не существует (хотя `int&&` — это rvalue-ссылка, а не «ссылка на ссылку»). Нельзя иметь массив ссылок.

```cpp
int** pp;        // OK
// int&&& r;     // ошибка
```

## 7. Синтаксис использования

- С указателем нужно явно применять `*` для разыменования и `&` для взятия адреса.
- Ссылка используется как обычная переменная, без дополнительных операторов.

```cpp
*p = 5;          // через указатель
r = 5;           // через ссылку — синтаксис как у обычной переменной
```

## 8. Передача в функции

Оба механизма позволяют менять аргумент в вызывающем коде, но по-разному:

```cpp
void byPointer(int* p) { if (p) *p = 10; }
void byReference(int& r) { r = 10; }

int x = 0;
byPointer(&x);   // нужно явно передать адрес, нужна проверка на nullptr
byReference(x);  // синтаксис как у передачи по значению
```

Ссылка предпочтительнее, когда объект гарантированно существует: код чище и безопаснее. Указатель — когда возможен «пустой» вариант (опциональный параметр) или нужна адресная арифметика.

## Сводная таблица

| Критерий | Указатель | Ссылка |
|---|---|---|
| Отдельный объект в памяти | Да | Нет (псевдоним) |
| Обязательная инициализация | Нет | Да |
| Может быть `nullptr` | Да | Нет |
| Можно перепривязать | Да | Нет |
| Арифметика | Да | Нет |
| Многоуровневость (`**`) | Да | Нет |
| Синтаксис доступа | `*p` | как обычная переменная |
| Собственный адрес (`&p`) | Есть | Обычно нет (может совпадать с адресом объекта) |

## Итог

**Ссылка** — это безопасный и синтаксически удобный псевдоним существующего объекта с фиксированной привязкой. **Указатель** — это самостоятельная переменная-адрес с полной свободой (перенаправление, `nullptr`, арифметика), но и с большей ответственностью программиста. В современном C++ по умолчанию предпочитают ссылки для параметров функций, а указатели — там, где нужна опциональность, адресная арифметика или работа с динамической памятью.
