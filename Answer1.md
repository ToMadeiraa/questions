# Вопрос 1. В чём заключаются основные принципы ООП?

> **Кратко:** ООП — это способ организации программы, при котором данные и операции над ними объединяются в объекты, а программа строится как взаимодействие объектов через их интерфейсы. Классических принципов четыре: **абстракция**, **инкапсуляция**, **наследование** и **полиморфизм**.

---

## 1. Абстракция

**Абстракция** — выделение существенных для задачи свойств объекта и отбрасывание несущественных. В коде она проявляется как разделение «**что** объект умеет» (интерфейс) и «**как** он это делает» (реализация).

Пользователь класса работает с публичным интерфейсом и не зависит от деталей реализации.

```cpp
class Shape {
public:
    virtual ~Shape() = default;

    virtual double area() const = 0;  // «что»: у фигуры есть площадь
    virtual void   draw() const = 0;  // «что»: фигуру можно нарисовать
};
```

`Shape` — абстракция геометрической фигуры. Мы не знаем и не должны знать, как считается площадь у конкретной фигуры.

---

## 2. Инкапсуляция

**Инкапсуляция** — объединение данных и методов, работающих с этими данными, в одной сущности (классе) плюс сокрытие внутреннего состояния от внешнего кода.

В C++ реализуется через секции доступа `private` / `protected` / `public` и через `friend`.

Смысл не только в том, чтобы «спрятать поля», а в том, чтобы класс мог **поддерживать свои инварианты**: например, баланс счёта не может стать отрицательным, и никто снаружи не может его испортить.

```cpp
#include <stdexcept>

class BankAccount {
public:
    explicit BankAccount(double initial) : balance_(initial) {
        if (initial < 0)
            throw std::invalid_argument("initial balance < 0");
    }

    void withdraw(double amount) {
        if (amount <= 0 || amount > balance_)
            throw std::invalid_argument("bad amount");
        balance_ -= amount;               // инвариант проверяется здесь
    }

    void deposit(double amount) {
        if (amount <= 0)
            throw std::invalid_argument("bad amount");
        balance_ += amount;
    }

    double balance() const { return balance_; }

private:
    double balance_;                      // снаружи недоступен
};
```

**Что даёт инкапсуляция:**

- возможность менять реализацию, не ломая клиентов;
- контроль инвариантов класса в одном месте;
- локализацию ошибок;
- уменьшение связанности кода.

## 3. Наследование

**Наследование** позволяет строить новый класс на основе существующего, переиспользуя его интерфейс и/или реализацию. Отношение — «**является**» (*is-a*): `Circle` является `Shape`.

```cpp
#include <numbers>

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override {
        return std::numbers::pi * r_ * r_;
    }

    void draw() const override { /* ... */ }

private:
    double r_;
};
```

**Виды наследования в C++:**

| Вид | Отношение | Когда использовать |
|---|---|---|
| `public` | *is-a* | «Наследник является базой» — основной случай |
| `protected` | *is-implemented-in-terms-of*, с доступом для наследников | Редко; промежуточные детали иерархии |
| `private` | *is-implemented-in-terms-of* | Переиспользование реализации без публичного «является» |

> **Важно:** наследование — самый «жёсткий» из принципов: иерархии крепко связывают классы, а «хрупкий базовый класс» ломает наследников при изменении базы. Часто **композиция предпочтительнее наследования**.

---

## 4. Полиморфизм

**Полиморфизм** — способность одного и того же вызова работать по-разному в зависимости от фактического типа объекта.

В C++ есть два вида:

- **Динамический** (времени выполнения) — виртуальные функции и таблица виртуальных функций (`vtable`), указатель `vptr` в объекте.
- **Статический** (времени компиляции) — перегрузка функций, шаблоны, CRTP, перегрузка операторов.

```cpp
#include <memory>
#include <vector>

void render(const std::vector<std::unique_ptr<Shape>>& shapes) {
    for (const auto& s : shapes)
        s->draw();          // вызовется draw() фактического типа
}
```

Именно динамический полиморфизм позволяет писать код, не зависящий от конкретных типов: добавили новый класс-наследник — старый код работает без изменений (принцип открытости/закрытости).

## Как принципы связаны

| Принцип | На какой вопрос отвечает | Механизм в C++ |
|---|---|---|
| Абстракция | «Что моделируем?» | Абстрактные классы, чистые виртуальные функции, интерфейсы |
| Инкапсуляция | «Кто может менять состояние?» | `private` / `protected` / `public`, `friend` |
| Наследование | «Как переиспользовать и расширить?» | `class Derived : public Base`, `virtual` |
| Полиморфизм | «Как работать с разными типами единообразно?» | `virtual` + `override`, шаблоны, перегрузки |

Абстракция отвечает на вопрос «что моделируем», инкапсуляция защищает модель от внешнего вмешательства, наследование позволяет переиспользовать и расширять модель, полиморфизм даёт единообразную работу с разными реализациями.

## Типичные ошибки

1. **Наследование вместо композиции.** Иерархия ради переиспользования кода, а не ради отношения *is-a*, быстро становится хрупкой.
2. **Публичные поля.** Клиенты начинают зависеть от внутреннего представления; инварианты негде проверить.
3. **Отсутствие виртуального деструктора** в полиморфном базовом классе — удаление через указатель на базу является **undefined behavior**.
4. **Срезка объекта (object slicing)** при передаче наследника по значению в функцию, принимающую базовый класс.
5. **Виртуальные вызовы в конструкторе и деструкторе** — во время конструирования/разрушения объекта динамический тип «сворачивается» до текущего класса, и вызов не уходит в наследника.
6. **Оверинжиниринг.** Для маленькой задачи процедурный или функциональный стиль может быть проще и честнее.

---

## Что добавить на собеседовании

- ООП — не самоцель: это инструмент управления сложностью, а не обязательное требование к любому коду.
- Практическое правило: «**программируйте на уровне интерфейсов, а не реализаций**» и «**предпочитайте композицию наследованию**».
- В C++ принципы ООП тесно связаны с **RAII**, **const-correctness** и **value-семантикой** — это то, что отличает идиоматичный C++ от «Java на C++».
- **SOLID** — развитие идей ООП применительно к проектированию; уместно упомянуть, что знаете, как принципы соотносятся с ним.

## Итог

| Принцип | Суть в одном предложении |
|---|---|
| Абстракция | Выделяем главное и прячем детали за интерфейсом |
| Инкапсуляция | Данные и поведение вместе, состояние защищено, инварианты соблюдены |
| Наследование | Новый класс переиспользует и расширяет существующий (*is-a*) |
| Полиморфизм | Один интерфейс — разные реализации, выбор на этапе компиляции или выполнения |
