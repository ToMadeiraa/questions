# 138. Работа с `std::mutex` в C++

`std::mutex` — это базовый примитив синхронизации, появившийся в C++11, который используется для защиты общих данных от одновременного доступа из нескольких потоков. Он обеспечивает эксклюзивную (нерекурсивную) семантику владения: поток, который захватил мьютекс, становится его единственным владельцем до момента освобождения .

## 1. Основные методы

Класс `std::mutex` (заголовочный файл `<mutex>`) предоставляет три ключевых метода :

| Метод | Описание |
| :--- | :--- |
| `lock()` | Блокирует вызывающий поток, пока мьютекс не будет захвачен. Если мьютекс уже захвачен другим потоком, поток будет ждать. |
| `try_lock()` | Пытается захватить мьютекс без блокировки. Возвращает `true`, если захват успешен, и `false`, если мьютекс занят. |
| `unlock()` | Освобождает мьютекс. Вызывающий поток должен быть владельцем мьютекса, иначе поведение не определено. |

**Важно:** `std::mutex` не является рекурсивным. Если поток попытается вызвать `lock()` на мьютексе, которым он уже владеет, это приведет к неопределенному поведению (обычно к взаимоблокировке) .

## 2. Рекомендуемый способ: RAII-обертки

Прямое использование `lock()` и `unlock()` считается плохой практикой, так как при возникновении исключения между этими вызовами мьютекс останется заблокированным, что приведет к взаимоблокировке (deadlock). В современном C++ настоятельно рекомендуется использовать RAII-обертки, которые автоматически освобождают мьютекс в деструкторе .

### `std::lock_guard` (C++11)

Самый простой и легковесный вариант. Захватывает мьютекс при создании и освобождает при выходе из области видимости. Не поддерживает ручное освобождение или отложенный захват .

```cpp
#include <mutex>
#include <thread>
#include <iostream>

std::mutex mtx;
int shared_counter = 0;

void safe_increment() {
    // Мьютекс захватывается здесь
    std::lock_guard<std::mutex> lock(mtx);
    ++shared_counter;
    // Мьютекс автоматически освобождается при выходе из функции,
    // даже если произойдет исключение
}
```

### `std::unique_lock` (C++11)

Более гибкая обертка. Поддерживает отложенный захват (`std::defer_lock`), ручное освобождение (`unlock()`), а также перемещение (move semantics). Необходим для использования с `std::condition_variable` .

```cpp
#include <mutex>

std::mutex mtx;

void flexible_work() {
    // Создаем объект, но не захватываем мьютекс сразу
    std::unique_lock<std::mutex> lock(mtx, std::defer_lock);
    
    // ... какая-то работа без блокировки ...
    
    lock.lock();   // Захватываем вручную
    // ... критическая секция ...
    lock.unlock(); // Можно освободить досрочно
}
```

### `std::scoped_lock` (C++17)

Предназначен для захвата **нескольких** мьютексов одновременно без риска взаимоблокировки. Для одного мьютекса работает аналогично `lock_guard` .

```cpp
#include <mutex>

std::mutex mtx1, mtx2;

void safe_multi_lock() {
    // Захватывает оба мьютекса без deadlock
    std::scoped_lock lock(mtx1, mtx2);
    // ... работа с данными, защищенными обоими мьютексами ...
}
```

## 3. Сравнение оберток

| Характеристика | `lock_guard` | `unique_lock` | `scoped_lock` (C++17) |
| :--- | :--- | :--- | :--- |
| Захват при создании | Да | Настраиваемый | Да |
| Ручное освобождение | Нет | Да | Нет |
| Отложенный захват | Нет | Да | Нет |
| Поддержка `condition_variable` | Нет | **Да** | Нет |
| Захват нескольких мьютексов | Нет | Нет | **Да** |
| Накладные расходы | Нулевые | Флаг + указатель | Нулевые |

*Данные таблицы основаны на сравнительной характеристике оберток .*

## 4. Практический пример: защита счетчика

Классическая демонстрация состояния гонки (data race) и его исправления с помощью `std::mutex` :

```cpp
#include <iostream>
#include <mutex>
#include <thread>
#include <vector>

std::mutex mtx;
int counter = 0;

void increment(int n) {
    for (int i = 0; i < n; ++i) {
        // Без этой блокировки операция ++counter не является атомарной,
        // и итоговый результат будет меньше ожидаемого
        std::lock_guard<std::mutex> lock(mtx);
        ++counter;
    }
}

int main() {
    constexpr int iterations = 100000;
    std::vector<std::thread> threads;
    
    for (int i = 0; i < 4; ++i) {
        threads.emplace_back(increment, iterations);
    }
    
    for (auto& t : threads) {
        t.join();
    }
    
    // Ожидаемый результат: 400000
    std::cout << "Counter: " << counter << std::endl;
    return 0;
}
```

## 5. Ключевые правила и ограничения

1. **Не копируемый и не перемещаемый:** `std::mutex` нельзя копировать или перемещать. Он должен быть глобальным, статическим или передаваться по ссылке .
2. **Не уничтожать захваченным:** Если уничтожить мьютекс, пока им владеет другой поток, поведение программы не определено .
3. **Не рекурсивный:** Для случаев, когда один и тот же поток должен захватывать мьютекс многократно, используйте `std::recursive_mutex` .
4. **Минимизируйте критическую секцию:** Захватывайте мьютекс на как можно более короткое время, чтобы не снижать производительность многопоточной программы .
5. **Избегайте вложенных захватов:** Захват нескольких мьютексов в разном порядке в разных потоках — классическая причина взаимоблокировок. Используйте `std::scoped_lock` или `std::lock` для безопасного захвата нескольких мьютексов .

## 6. Дополнительные возможности

Для специфических задач существуют другие типы мьютексов:
- **`std::recursive_mutex`**: позволяет одному потоку захватывать мьютекс несколько раз (требует соответствующего количества `unlock`).
- **`std::timed_mutex`**: предоставляет методы `try_lock_for` и `try_lock_until` для захвата с таймаутом.
- **`std::shared_mutex`** (C++17): реализует паттерн "читатели-писатели", позволяя нескольким потокам читать данные одновременно, но блокируя всех при записи .
