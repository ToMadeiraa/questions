# 131. Как синхронизировать передачи информации между потоками?

В C++ синхронизация передач информации между потоками достигается за счёт использования примитивов синхронизации, которые гарантируют, что потоки не будут одновременно обращаться к общим данным, вызывая состояние гонки (data race) или неопределённое поведение. Выбор конкретного механизма зависит от типа передаваемых данных и паттерна взаимодействия.

### 1. Мьютексы и блокировки (std::mutex)

Это базовый и наиболее распространённый способ защиты общих данных. Мьютекс обеспечивает эксклюзивный доступ: поток, захвативший мьютекс, получает монопольное право на работу с защищаемыми данными, а остальные потоки блокируются до его освобождения .

На практике напрямую `lock()`/`unlock()` используют редко из-за риска забыть разблокировать мьютекс при исключении. Вместо этого применяют RAII-обёртки:

- **`std::lock_guard`**: Простейшая обёртка, которая захватывает мьютекс в конструкторе и освобождает в деструкторе. Идеальна для простых критических секций.
- **`std::unique_lock`**: Более гибкий вариант. Позволяет откладывать захват, разблокировать вручную и необходим для работы с `std::condition_variable` .
- **`std::scoped_lock` (C++17)**: Позволяет безопасно захватывать сразу несколько мьютексов без риска взаимной блокировки (deadlock).

**Пример:**
```cpp
#include <mutex>
#include <thread>

std::mutex mtx;
int shared_data = 0;

void writer() {
    std::lock_guard<std::mutex> lock(mtx);
    shared_data = 42; // Безопасная запись
}
```

### 2. Условные переменные (std::condition_variable)

Если потоку нужно не просто защитить данные, а **дождаться** определённого события или изменения состояния (например, появления данных в очереди), используется условная переменная. Она позволяет потоку «спать», пока другой поток не просигнализирует о готовности .

**Ключевые правила использования:**
1.  Ожидающий поток должен захватить `std::unique_lock` на мьютексе, связанном с данными.
2.  Использовать перегрузку `wait` с предикатом (лямбдой), чтобы защититься от «ложных пробуждений» (spurious wakeups).
3.  Изменяющий поток должен захватить мьютекс, изменить данные, а затем вызвать `notify_one()` или `notify_all()` .

**Пример:**
```cpp
#include <condition_variable>
#include <mutex>
#include <queue>

std::mutex mtx;
std::condition_variable cv;
std::queue<int> data_queue;

void consumer() {
    std::unique_lock<std::mutex> lock(mtx);
    // Ждём, пока очередь не станет непустой
    cv.wait(lock, []{ return !data_queue.empty(); });
    
    int value = data_queue.front();
    data_queue.pop();
    // ... обработка ...
}

void producer(int val) {
    {
        std::lock_guard<std::mutex> lock(mtx);
        data_queue.push(val);
    } // Мьютекс освобождается здесь
    cv.notify_one(); // Будим один ожидающий поток
}
```

### 3. Атомарные операции (std::atomic)

Для передачи простых типов (счётчики, флаги, указатели) использование мьютекса может быть избыточным. `std::atomic` гарантирует, что операция чтения или записи будет выполнена неделимо, без гонки данных .

Это особенно эффективно для флагов остановки или счётчиков. Для сложных структур данных `std::atomic` не подходит, так как он не защищает составные операции (например, проверку и изменение).

**Пример:**
```cpp
#include <atomic>
#include <thread>

std::atomic<bool> ready{false};
int data = 0;

void worker() {
    data = 100; // Обычная запись
    ready.store(true, std::memory_order_release); // Гарантирует видимость data
}

void main_thread() {
    while (!ready.load(std::memory_order_acquire)) {
        // Ждём
    }
    // Теперь data гарантированно равно 100
}
```

### 4. Передача результатов через std::future и std::promise

Если задача заключается в том, чтобы один поток вычислил значение, а другой его получил (без организации общей памяти и ручной синхронизации), используется механизм `std::future`. Это высокоуровневая абстракция для одноразовой передачи данных.

- **`std::promise`**: «Излучатель» результата. Поток-производитель вызывает `set_value()`.
- **`std::future`**: «Получатель». Поток-потребитель вызывает `get()`, который блокируется до появления значения .

**Пример:**
```cpp
#include <future>
#include <thread>

void producer(std::promise<int> prom) {
    prom.set_value(42); // Передача данных
}

int main() {
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();
    
    std::thread t(producer, std::move(prom));
    
    int result = fut.get(); // Блокируется, пока данные не придут
    t.join();
}
```

### 5. Синхронизация вывода в поток (C++20)

Отдельно стоит упомянуть передачу информации в стандартный поток вывода (`std::cout`) из разных потоков. Обычно символы могут перемешиваться. В C++20 появился `std::osyncstream`, который буферизует вывод потока и выводит его в конечный буфер атомарно (целиком), предотвращая искажение текста .

**Пример:**
```cpp
#include <iostream>
#include <syncstream>
#include <thread>

void print(int id) {
    std::osyncstream(std::cout) << "Thread " << id << ": Hello\n";
}
```

### Резюме

| Механизм | Когда использовать |
| :--- | :--- |
| **`std::mutex`** | Защита сложных данных (структур, контейнеров) при частом доступе. |
| **`std::condition_variable`** | Ожидание события (например, «появились данные»). |
| **`std::atomic`** | Простые флаги, счётчики, передача указателей без блокировок. |
| **`std::future`** | Одноразовая передача результата вычислений от одного потока другому. |
