## 137. Что такое атомарная операция?

**Атомарная операция** (от греч. *atomos* — «неделимый») — это операция, которая выполняется как **единое неделимое действие**: с точки зрения других потоков она либо ещё не началась, либо уже завершилась, но **не может наблюдаться в промежуточном состоянии**.

### Ключевая идея

В многопоточной программе обычная операция часто состоит из нескольких шагов. Например, инкремент `x++` на самом деле включает:

1. чтение значения `x` из памяти;
2. прибавление `1`;
3. запись результата обратно в память.

Если два потока выполняют `x++` одновременно, их шаги могут перемежаться, и одно из приращений «потеряется» (классическая **гонка данных**, data race).

Атомарная операция исключает такую перемежаемость: другие потоки не могут увидеть частично выполненное действие. Это устраняет гонку данных на уровне данной операции.

### Пример проблемы

```cpp
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; ++i)
        ++counter;   // НЕ атомарно!
}

// два потока вызывают increment() параллельно
// ожидаем 200000, но реально получим меньше из-за гонки
```

### Решение средствами C++

**1. `std::atomic`** — основной инструмент:

```cpp
#include <atomic>
#include <thread>

std::atomic<int> counter{0};

void increment() {
    for (int i = 0; i < 100000; ++i)
        ++counter;   // атомарный инкремент
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    // counter гарантированно равен 200000
}
```

**2. Мьютекс** — более общий, но «тяжёлый» способ обеспечить атомарность целого блока кода:

```cpp
#include <mutex>

int counter = 0;
std::mutex m;

void increment() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(m);
        ++counter;
    }
}
```

**3. Аппаратные примитивы**, лежащие в основе: инструкции `LOCK`-префикса на x86, `LDREX/STREX` на ARM, а также `compare_exchange` (CAS — compare-and-swap), реализуемый обычно через `std::atomic::compare_exchange_weak/strong`.

### Свойства атомарных операций в C++

- **Атомарность** — операция неделима.
- **Порядок памяти (memory ordering)** — атомарные операции дополнительно задают правила видимости изменений между потоками: `memory_order_relaxed`, `acquire`, `release`, `acq_rel`, `seq_cst`. По умолчанию используется самый строгий `seq_cst` (последовательно-согласованный порядок).
- **Отсутствие блокировок** — для многих типов (например, `std::atomic<int>`, указатели) операции реализуются без мьютексов, через аппаратные инструкции; проверяется методом `is_lock_free()`.

### Что важно помнить

- Атомарной является **отдельная операция над объектом**, а не произвольная последовательность действий. Составная логика (например, «проверить и потом изменить») требует либо `compare_exchange`, либо мьютекса.
- `std::atomic` защищает только сам объект; согласованность **нескольких** переменных атомарность по отдельности не гарантирует.
- Атомарные операции не бесплатны: они дороже обычных из-за барьеров памяти и блокировок шины/кэша, хотя обычно дешевле мьютекса.

### Итог

Атомарная операция — это неделимое действие над данными, которое в многопоточной среде воспринимается другими потоками как мгновенное и целостное. В C++ она реализуется через `std::atomic` (и аппаратные инструкции CAS), а также через синхронизацию мьютексами; она служит основой для написания корректных lock-free и потокобезопасных структур данных.
