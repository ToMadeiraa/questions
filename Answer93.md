# 93. Константные методы в C++

## Что такое константный метод

Константный метод — это метод класса, который объявляется с ключевым словом `const` **после** списка параметров:

```cpp
class Point {
private:
    int x, y;
public:
    int getX() const { return x; }   // константный метод
    void setX(int v) { x = v; }      // неконстантный метод
};
```

## Ключевое правило

Внутри константного метода указатель `this` имеет тип `const T*` (указатель на константу). Это значит, что **через константный метод нельзя изменять нестатические поля класса** — компилятор запретит такое изменение.

```cpp
class Counter {
    int value = 0;
public:
    int get() const {
        // value++;  // ОШИБКА компиляции: нельзя менять поле
        return value;
    }
    void inc() { value++; }  // OK — метод неконстантный
};
```

## Как это работает "под капотом"

Для объекта класса компилятор неявно передаёт в метод указатель `this`. Наличие `const` меняет квалификацию этого указателя:

```cpp
// Неявно метод int get() const превращается примерно в:
int get(const Counter* this);

// А неконстантный метод void inc() — в:
void inc(Counter* this);
```

Отсюда следуют два важных вывода:

1. **Константный метод можно вызвать у константного объекта**, а неконстантный — нельзя:
```cpp
const Counter c;
c.get();   // OK
// c.inc(); // ОШИБКА: нельзя вызывать неконстантный метод у const-объекта
```

2. **Внутри константного метода можно вызывать только другие константные методы** того же класса (потому что `this` — константный указатель):
```cpp
class A {
public:
    int a() const { return 1; }
    int b()       { return 2; }
    int c() const {
        // return b();  // ОШИБКА: b() неконстантный
        return a();     // OK
    }
};
```

## Перегрузка по константности

Можно иметь **две версии** одного метода — константную и неконстантную. Компилятор выберет нужную в зависимости от константности объекта:

```cpp
class Array {
    int data[10];
public:
    int& operator[](size_t i)             { return data[i]; }  // для неконстантных
    const int& operator[](size_t i) const { return data[i]; }  // для константных
};

Array a;
const Array ca;
a[0]  = 5;    // вызывает неконстантную версию — можно писать
ca[0] = 5;    // ОШИБКА: вызывается константная версия, возвращает const int&
int v = ca[0]; // OK — чтение
```

## Изменяемые поля: `mutable`

Иногда нужно менять поле в константном методе — например, для кэширования. Для этого поле помечают `mutable`:

```cpp
class Data {
    mutable int cache = -1;   // можно менять даже в const-методах
    int compute() const { /* ... */ return 42; }
public:
    int get() const {
        if (cache == -1)
            cache = compute();  // OK благодаря mutable
        return cache;
    }
};
```

`mutable` не снимает `const` с `this`, а лишь разрешает модификацию конкретных полей.

## Зачем нужны константные методы

1. **Безопасность и самодокументируемость** — сигнатура `const` гарантирует, что метод не меняет состояние объекта.
2. **Возможность работы с константными объектами и ссылками** — без константных методов `const T&` был бы почти бесполезен: у него нельзя было бы вызвать ни один метод.
3. **Передача по константной ссылке** — стандартная практика:
```cpp
void print(const Point& p) {
    std::cout << p.getX();  // работает только если getX() const
}
```
4. **Корректность в многопоточном коде** — константные методы можно безопасно вызывать параллельно (при отсутствии `mutable`-полей и внутренней синхронизации).

## Частые ошибки

- **Забыть `const`** в геттерах — тогда их нельзя будет вызвать у константных объектов.
- **`const` в неправильном месте**: `void f() const` — верно, `const void f()` — неверно (это относится к возвращаемому типу).
- **Попытка изменить поле** в константном методе без `mutable` — ошибка компиляции.
- **`mutable` ради обхода `const`** — злоупотребление, ломающее логическую константность.

## Итог

Константный метод — это метод, которому компилятор передаёт `const this`, что запрещает модификацию нестатических полей объекта (кроме `mutable`). Константность метода — часть его сигнатуры, поэтому методы можно перегружать по ней. Константные методы необходимы для работы с константными объектами, ссылками и указателями, а также для выражения логической неизменяемости интерфейса.
