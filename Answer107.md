## 107. Какие методы генерируются для класса по умолчанию?

Для пустого класса `class MyClass { };` компилятор C++ **неявно** (при необходимости, то есть когда функция используется — вызывается или берётся её адрес) генерирует следующие **специальные функции-члены**:

| Функция-член | Сигнатура (упрощённо) | Условие генерации |
| :--- | :--- | :--- |
| **Конструктор по умолчанию** | `MyClass()` | Генерируется, только если в классе **нет** объявленных пользователем конструкторов. |
| **Деструктор** | `~MyClass()` | Генерируется всегда (если не объявлен пользователем); по умолчанию не виртуальный. |
| **Конструктор копирования** | `MyClass(const MyClass&)` | Поэлементное копирование. |
| **Оператор присваивания копированием** | `MyClass& operator=(const MyClass&)` | Поэлементное присваивание. |
| **Конструктор перемещения** (C++11) | `MyClass(MyClass&&)` | Генерируется, только если не объявлены пользователем копирующие/перемещающие операции или деструктор. |
| **Оператор присваивания перемещением** (C++11) | `MyClass& operator=(MyClass&&)` | То же условие. |

> **Важно**: конструктор по умолчанию генерируется строго при условии, что пользователь не объявил **ни одного** конструктора. Если написать только конструктор с параметрами, конструктор по умолчанию **не** будет сгенерирован.

## В каком случае такие методы не будут генерироваться?

Когда пользователь явно объявляет некоторые функции-члены, компилятор подавляет неявную генерацию остальных или определяет их как `delete`. Основные правила:

### 1. Конструктор по умолчанию подавляется
- Достаточно объявить **любой конструктор** (включая конструктор копирования и перемещения) — конструктор по умолчанию неявно не генерируется.

### 2. Перемещающие операции подавляются
- Если пользователь объявил **конструктор копирования, оператор присваивания копированием, конструктор перемещения, оператор присваивания перемещением или деструктор** — компилятор **не** объявляет неявно конструктор перемещения и оператор присваивания перемещением. Класс откатывается к использованию копирующих операций.

### 3. Копирующие операции удаляются (`= delete`)
- Если пользователь объявил **конструктор перемещения или оператор присваивания перемещением**, неявные конструктор копирования и оператор присваивания копированием определяются как `delete` (а не просто не объявляются). Любой вызов приводит к ошибке компиляции.

### 4. Неявное удаление из-за свойств членов/базовых классов
Даже без объявлений пользователя следующие ситуации приводят к тому, что конкретная специальная функция определяется как `delete`:
- Класс содержит **ссылочный** нестатический член данных → операторы присваивания (копированием и перемещением) удаляются (ссылку нельзя перепривязать).
- Класс содержит нестатический член типа **`const` неклассового типа** → операторы присваивания удаляются.
- Соответствующая операция базового класса или члена недоступна или удалена → соответствующая операция производного класса удаляется.

## Как заставить компилятор добавить/удалить эти методы?

В C++11 появились `= default` и `= delete` для явного управления генерацией специальных функций-членов.

### Заставить сгенерировать: `= default`
Добавьте `= default;` после объявления, чтобы попросить компилятор сгенерировать реализацию по умолчанию. **Важно**: `= default` не «обходит» правила подавления — если реализация по умолчанию должна быть удалена из-за конфликтующих объявлений, явный `= default` всё равно может сделать функцию удалённой.

```cpp
class MyClass {
public:
    MyClass() = default;                     // явно генерируем конструктор по умолчанию
    MyClass(const MyClass&) = default;       // явно генерируем конструктор копирования
    MyClass& operator=(const MyClass&) = default;
    ~MyClass() = default;
};
```

Типичный случай: вы объявили конструктор с параметрами, но по-прежнему нужен сгенерированный конструктор по умолчанию — явно напишите `MyClass() = default;`.

### Заставить удалить: `= delete`
Добавьте `= delete;` после объявления, чтобы запретить функцию: любой вызов приведёт к ошибке компиляции.

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;            // запрет копирования
    NonCopyable& operator=(const NonCopyable&) = delete; // запрет присваивания копированием
};
```

Это стандартный способ реализации семантики «некопируемый» начиная с C++11 — понятнее и с ошибкой на этапе компиляции, чем приём C++03 с приватным объявлением без определения.

## Краткая сводная таблица

| Пользователь объявил… | Влияние на неявную генерацию |
| :--- | :--- |
| Любой конструктор | Конструктор по умолчанию **не генерируется** |
| Деструктор / копирующие операции / перемещающие операции | Перемещающие операции **не генерируются** |
| Конструктор перемещения / присваивание перемещением | Копирующие операции определяются как **`delete`** |
| Конструктор копирования / присваивание копированием / деструктор | Перемещающие операции **не генерируются** (откат к копированию) |
