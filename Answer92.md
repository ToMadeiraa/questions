# 92. Как отловить деление на 0 в C++

В C++ **невозможно напрямую отловить деление на ноль с помощью `try-catch`**, потому что деление целого числа на ноль является **неопределённым поведением (Undefined Behavior, UB)**, а не стандартным исключением C++ . Стандарт языка не требует, чтобы реализация генерировала исключение в этом случае.

## Почему `try-catch` не работает

Для целочисленного деления на ноль стандарт C++ явно указывает, что это неопределённое поведение. Это означает, что компилятор может делать что угодно: программа может аварийно завершиться, выдать мусорный результат или даже "сделать вид", что ничего не произошло. Это **не** исключительная ситуация C++ .

```cpp
int a = 5, b = 0;
try {
    int c = a / b;  // Это НЕ выбросит std::exception!
} catch (...) {
    // Сюда управление не попадёт
}
```

Для чисел с плавающей точкой деление на ноль также не является исключением C++, но IEEE 754 определяет результат как бесконечность (`inf`) или `NaN`, и это можно проверить через `std::fetestexcept` .

## Правильный подход: явная проверка делителя

Самый надёжный и переносимый способ — **проверить делитель перед делением**. Это единственный метод, который гарантированно работает на всех платформах и соответствует стандарту C++.

```cpp
#include <iostream>
#include <stdexcept>

int safe_divide(int numerator, int denominator) {
    if (denominator == 0) {
        throw std::invalid_argument("Division by zero");
    }
    return numerator / denominator;
}

int main() {
    try {
        int result = safe_divide(10, 0);
        std::cout << result << std::endl;
    } catch (const std::invalid_argument& e) {
        std::cerr << "Error: " << e.what() << std::endl;
    }
    return 0;
}
```

Вы можете выбрать любой тип исключения: `std::invalid_argument`, `std::domain_error` или `std::overflow_error` — все они подходят, поскольку стандарт не предписывает конкретный тип для этой ситуации .

## Платформозависимые методы (не рекомендуются для переносимого кода)

Если по какой-то причине проверка делителя нежелательна (например, из соображений производительности в критической секции), можно использовать механизмы операционной системы, но это делает код **непереносимым**.

### Windows (MSVC)

В Windows целочисленное деление на ноль генерирует структурированное исключение (SEH) с кодом `EXCEPTION_INT_DIVIDE_BY_ZERO`. Его можно перехватить с помощью `__try` / `__except` (не путать со стандартными `try` / `catch`):

```cpp
#include <windows.h>
#include <iostream>

int main() {
    __try {
        int a = 5, b = 0;
        int c = a / b;
    }
    __except (GetExceptionCode() == EXCEPTION_INT_DIVIDE_BY_ZERO 
              ? EXCEPTION_EXECUTE_HANDLER 
              : EXCEPTION_CONTINUE_SEARCH) {
        std::cerr << "Integer division by zero caught via SEH" << std::endl;
    }
    return 0;
}
```

Важно: `__try` / `__except` нельзя использовать в одной функции с `try` / `catch` .

### POSIX-системы (Linux, macOS)

На этих платформах деление на ноль обычно приводит к сигналу `SIGFPE`. Можно установить обработчик сигнала:

```cpp
#include <csignal>
#include <iostream>
#include <stdexcept>

void sigfpe_handler(int) {
    throw std::runtime_error("SIGFPE: division by zero");
}

int main() {
    std::signal(SIGFPE, sigfpe_handler);
    try {
        int a = 5, b = 0;
        int c = a / b;
    } catch (const std::runtime_error& e) {
        std::cerr << e.what() << std::endl;
    }
    return 0;
}
```

**Однако это крайне не рекомендуется**: выбрасывание исключения из обработчика сигнала — неопределённое поведение, и для этого может потребоваться специальный флаг компилятора (например, `-fnon-call-exceptions` в GCC) . Кроме того, на некоторых архитектурах (например, ARM без аппаратной поддержки деления) сигнал может вообще не генерироваться .

## Итоговая рекомендация

| Метод | Переносимость | Безопасность | Рекомендация |
|---|---|---|---|
| Явная проверка `if (denominator == 0)` | Полная | Полная | **Основной метод** |
| `__try` / `__except` (Windows) | Только Windows | Средняя | Только для диагностики/логирования |
| `SIGFPE` + `signal()` (POSIX) | Только POSIX | Низкая (UB при throw из обработчика) | Крайне не рекомендуется |
| `try-catch` напрямую | Не работает | — | Не применимо |

**Вывод**: в C++ деление на ноль — это не исключение, а ошибка программиста или некорректные входные данные. Правильный подход — **проверять делитель до операции деления** и либо выбрасывать собственное исключение, либо возвращать код ошибки, в зависимости от архитектуры вашей программы.
