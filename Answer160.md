# 160. Named Pipe (именованный канал)

**Named Pipe** (именованный канал) — это механизм межпроцессного взаимодействия (IPC), который позволяет двум или более процессам обмениваться данными через специальный файл или объект ядра, имеющий имя в файловой системе или специальном пространстве имён. В отличие от анонимных каналов (anonymous pipes), именованные каналы могут использоваться для связи между **неродственными процессами** (не имеющими общего предка), а в некоторых реализациях — даже между процессами на разных машинах в сети.

В контексте C++ реализация и поведение Named Pipe существенно различаются в зависимости от операционной системы: **Windows** и **Linux/POSIX**.


## Named Pipe в Windows

В Windows именованный канал — это объект ядра, создаваемый функцией `CreateNamedPipe`. Каналы располагаются в специальном пространстве имён `\\.\pipe\имя_канала` (для локального компьютера) или `\\имя_хоста\pipe\имя_канала` (для удалённого доступа).

### Ключевые характеристики

| Характеристика | Описание |
|---|---|
| **Направление передачи** | Одностороннее (`PIPE_ACCESS_INBOUND` / `PIPE_ACCESS_OUTBOUND`) или дуплексное (`PIPE_ACCESS_DUPLEX`) |
| **Режим данных** | Поток байтов (`PIPE_TYPE_BYTE`) или поток сообщений (`PIPE_TYPE_MESSAGE`) |
| **Экземпляры** | Один сервер может создать несколько экземпляров канала с одним именем для обслуживания нескольких клиентов одновременно |
| **Сеть** | Поддерживает подключения с удалённых машин (можно запретить флагом `PIPE_REJECT_REMOTE_CLIENTS`) |
| **Безопасность** | Поддерживает ACL через `SECURITY_ATTRIBUTES`, а также олицетворение клиента (`ImpersonateNamedPipeClient`) |

### Минимальный пример сервера (C++)

```cpp
#include <windows.h>
#include <iostream>

int main() {
    const wchar_t* pipeName = L"\\\\.\\pipe\\MyTestPipe";
    
    HANDLE hPipe = CreateNamedPipeW(
        pipeName,
        PIPE_ACCESS_DUPLEX,              // дуплексный канал
        PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE | PIPE_WAIT,
        PIPE_UNLIMITED_INSTANCES,        // макс. экземпляров
        1024, 1024,                      // размеры буферов
        0,                               // таймаут по умолчанию
        nullptr                          // атрибуты безопасности
    );
    
    if (hPipe == INVALID_HANDLE_VALUE) {
        std::cerr << "CreateNamedPipe failed: " << GetLastError() << "\n";
        return 1;
    }
    
    std::cout << "Ожидание подключения клиента...\n";
    BOOL connected = ConnectNamedPipe(hPipe, nullptr) 
                     ? TRUE 
                     : (GetLastError() == ERROR_PIPE_CONNECTED);
    
    if (connected) {
        char buffer[256];
        DWORD bytesRead;
        ReadFile(hPipe, buffer, sizeof(buffer) - 1, &bytesRead, nullptr);
        buffer[bytesRead] = '\0';
        std::cout << "Получено: " << buffer << "\n";
        
        const char* response = "Привет от сервера!";
        DWORD bytesWritten;
        WriteFile(hPipe, response, strlen(response), &bytesWritten, nullptr);
        
        DisconnectNamedPipe(hPipe);
    }
    
    CloseHandle(hPipe);
    return 0;
}
```

Клиент подключается к каналу через `CreateFile` с именем `\\.\pipe\MyTestPipe`, после чего может использовать `ReadFile`/`WriteFile` для обмена данными.

### Безопасность (важно для привилегированных служб)

При использовании Named Pipe в Windows следует учитывать:
- Указывать `PIPE_REJECT_REMOTE_CLIENTS`, если удалённые подключения не нужны.
- Задавать явный ACL через `SECURITY_ATTRIBUTES`, чтобы огранизить круг пользователей, которым разрешено подключение.
- Использовать `FILE_FLAG_FIRST_PIPE_INSTANCE` при создании первого экземпляра для защиты от «захвата имени».
- При олицетворении клиента (`ImpersonateNamedPipeClient`) **обязательно проверять возвращаемое значение** и вызывать `RevertToSelf` после завершения работы от имени клиента.


## Named Pipe в Linux (FIFO)

В Linux/POSIX именованный канал называется **FIFO** (First In First Out). Это специальный файл в файловой системе, создаваемый системным вызовом `mkfifo()` или командой `mkfifo`.

### Ключевые характеристики

| Характеристика | Описание |
|---|---|
| **Создание** | `mkfifo(path, mode)` — создаёт файл-канал в указанном пути |
| **Тип файла** | Специальный файл с типом `p` (pipe), виден в `ls -l` как `prw-r--r--` |
| **Открытие** | `open()` с флагами `O_RDONLY` (читатель) или `O_WRONLY` (писатель) |
| **Связь** | Любые процессы (не только родственные) могут открыть один и тот же FIFO-файл и обмениваться данными |
| **Направление** | Однонаправленный по умолчанию; для двунаправленной связи обычно используют два FIFO |
| **Удаление** | `unlink(path)` после завершения работы |

### Пример (C++)

**Сервер (читатель):**

```cpp
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <iostream>

int main() {
    const char* fifoPath = "/tmp/my_fifo";
    
    // Создаём FIFO (если уже существует — ошибка, можно игнорировать)
    mkfifo(fifoPath, 0666);
    
    // Открываем для чтения (блокируется, пока не появится писатель)
    int fd = open(fifoPath, O_RDONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }
    
    char buffer[256];
    ssize_t n = read(fd, buffer, sizeof(buffer) - 1);
    if (n > 0) {
        buffer[n] = '\0';
        std::cout << "Получено: " << buffer << "\n";
    }
    
    close(fd);
    unlink(fifoPath);  // удаляем файл канала
    return 0;
}
```

**Клиент (писатель):**

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <cstring>

int main() {
    const char* fifoPath = "/tmp/my_fifo";
    
    // Открываем для записи (блокируется, пока не появится читатель)
    int fd = open(fifoPath, O_WRONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }
    
    const char* msg = "Привет через FIFO!";
    write(fd, msg, strlen(msg));
    
    close(fd);
    return 0;
}
```

### Важные нюансы Linux FIFO

- Открытие FIFO на чтение (`O_RDONLY`) **блокируется**, пока другой процесс не откроет его на запись, и наоборот. Это поведение можно обойти, используя `O_NONBLOCK` или открывая канал в режиме `O_RDWR` (последнее не рекомендуется стандартом POSIX, но работает в Linux).
- После завершения работы файл FIFO остаётся в файловой системе, пока не будет удалён через `unlink()`.
- Данные в FIFO обрабатываются как поток байтов; границы сообщений не сохраняются (в отличие от `PIPE_TYPE_MESSAGE` в Windows).


## Сравнение с анонимными каналами

| Критерий | Анонимный канал | Named Pipe |
|---|---|---|
| **Связь процессов** | Только родственные (родитель-потомок) | Любые процессы |
| **Имя** | Нет | Есть (файл или объект ядра) |
| **Сеть** | Нет | Да (Windows) |
| **Несколько клиентов** | Обычно нет | Да (Windows, multiple instances) |
| **Сложность** | Проще | Сложнее, но функциональнее |


## Когда использовать Named Pipe в C++

Named Pipe целесообразно выбирать, когда:
- Требуется связь между **независимыми процессами**, не имеющими отношения родитель-потомок.
- Нужна **простая в освоении** альтернатива сокетам для локального IPC (особенно в Windows).
- В Windows требуется **дуплексная связь** или **несколько одновременных клиентов** на одном сервере.
- В Linux нужна **простая однонаправленная передача данных** между процессами без накладных расходов на сокеты.

Для сценариев с высокой нагрузкой, сложной маршрутизацией или кроссплатформенностью обычно предпочтительнее сокеты домена Unix (Unix domain sockets) или TCP/IP.
