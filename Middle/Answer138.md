# 138. Как работать с std::condition_variable?

`std::condition_variable` — это примитив синхронизации, который позволяет одному или нескольким потокам блокироваться до тех пор, пока другой поток не изменит общую переменную (условие) и не уведомит об этом . Он всегда используется в паре с `std::mutex` для защиты этой общей переменной.

## Основные принципы работы

### Со стороны ожидающего потока

Поток, который собирается ждать, должен:

1.  **Захватить `std::unique_lock<std::mutex>`** на том же мьютексе, который используется для защиты общей переменной.
2.  **Вызвать `wait`, `wait_for` или `wait_until`**. Эти операции атомарно освобождают мьютекс и приостанавливают выполнение потока.
3.  Когда поток просыпается (после уведомления, тайм-аута или ложного пробуждения), мьютекс снова атомарно захватывается, и поток должен **проверить условие** и, если оно не выполнено, продолжить ожидание .

На практике почти всегда используется перегрузка `wait` с предикатом, которая инкапсулирует этот цикл проверки.

### Со стороны уведомляющего потока

Поток, который хочет изменить общую переменную, должен:

1.  **Захватить `std::mutex`** (обычно через `std::lock_guard`).
2.  **Изменить общую переменную**, пока блокировка удерживается.
3.  **Вызвать `notify_one` или `notify_all`**. Уведомление может быть выполнено как с удерживаемой блокировкой, так и после её освобождения .

Важно: даже если общая переменная является `std::atomic`, её изменение должно происходить под защитой мьютекса, чтобы корректно опубликовать изменение для ожидающего потока .

## Ключевые методы

| Метод | Описание |
| :--- | :--- |
| `wait(lock, pred)` | Блокирует поток, пока предикат `pred` не вернёт `true`. Автоматически обрабатывает ложные пробуждения. |
| `wait_for(lock, duration, pred)` | То же, но с тайм-аутом. Возвращает `false`, если время истекло. |
| `wait_until(lock, time_point, pred)` | Ожидание до указанного момента времени. |
| `notify_one()` | Пробуждает **один** из ожидающих потоков. |
| `notify_all()` | Пробуждает **все** ожидающие потоки. |

## Пример использования

Типичный паттерн — ожидание готовности данных в рабочем потоке:

```cpp
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <thread>

std::mutex m;
std::condition_variable cv;
std::string data;
bool ready = false;
bool processed = false;

void worker_thread() {
    // Ожидание, пока main() отправит данные
    std::unique_lock<std::mutex> lk(m);
    cv.wait(lk, []{ return ready; }); // Предикат защищает от ложных пробуждений

    // После wait мы владеем блокировкой
    std::cout << "Worker thread is processing data\n";
    data += " after processing";

    // Отправка данных обратно в main()
    processed = true;
    std::cout << "Worker thread signals data processing completed\n";

    // Ручная разблокировка перед уведомлением, чтобы избежать
    // немедленной повторной блокировки ожидающего потока
    lk.unlock();
    cv.notify_one();
}

int main() {
    std::thread worker(worker_thread);

    data = "Example data";
    // Отправка данных рабочему потоку
    {
        std::lock_guard<std::mutex> lk(m);
        ready = true;
        std::cout << "main() signals data ready for processing\n";
    }
    cv.notify_one();

    // Ожидание рабочего потока
    {
        std::unique_lock<std::mutex> lk(m);
        cv.wait(lk, []{ return processed; });
    }
    std::cout << "Back in main(), data = " << data << '\n';

    worker.join();
}
```

## Важные нюансы

- **Всегда используйте предикат.** Перегрузка `wait(lock)` без предиката может проснуться ложно (spurious wakeup) и продолжить выполнение, когда условие ещё не выполнено. Версия с предикатом `wait(lock, pred)` реализована как цикл `while (!pred()) wait(lock);` и безопасна .
- **`std::condition_variable` работает только с `std::unique_lock<std::mutex>`.** Если вам нужна поддержка других типов блокировок (например, `std::shared_lock`), используйте `std::condition_variable_any` .
- **Уведомление можно делать после разблокировки.** Это часто рекомендуется, чтобы избежать ситуации, когда разбуженный поток сразу же блокируется на всё ещё удерживаемом мьютексе .
