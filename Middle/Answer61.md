# 61. Что такое dynamic_cast и run-time type identification?

**Run-Time Type Identification (RTTI)** — это механизм C++, позволяющий определять фактический тип объекта во время выполнения программы, а не на этапе компиляции. Он был добавлен в язык, чтобы стандартизировать функциональность, которую ранее библиотеки реализовывали по-разному, что вызывало несовместимости .

RTTI включает три основных элемента :
1.  **Оператор `dynamic_cast`** — для безопасного преобразования типов в иерархии наследования.
2.  **Оператор `typeid`** — для получения точной информации о типе.
3.  **Класс `std::type_info`** — для хранения информации, возвращаемой `typeid`.

---

### Оператор `dynamic_cast`

`dynamic_cast` — это оператор, который выполняет безопасное преобразование указателей или ссылок между типами в одной иерархии наследования (вверх, вниз и «вбок»). В отличие от `static_cast`, он использует информацию RTTI для проверки корректности преобразования во время выполнения .

#### Синтаксис
```cpp
dynamic_cast<new_type>(expression)
```

*   `new_type`: указатель или ссылка на полный класс, либо указатель на `void` (с опциональными cv-квалификаторами).
*   `expression`: выражение, тип которого является полиморфным классом (содержит хотя бы одну виртуальную функцию), если выполняется преобразование вниз или вбок .

#### Ключевые особенности поведения

1.  **Безопасное приведение вниз (Downcast)**:
    Если у вас есть указатель на базовый класс, и вы хотите получить указатель на производный, `dynamic_cast` проверит, действительно ли объект, на который указывает базовый указатель, является экземпляром производного класса.
    *   При успехе возвращается указатель на производный объект.
    *   При неудаче (если объект не того типа) возвращается `nullptr` (для указателей) или генерируется исключение `std::bad_cast` (для ссылок) .

2.  **Приведение вбок (Sidecast / Crosscast)**:
    Позволяет преобразовать указатель на один производный класс в указатель на другой производный класс, если они оба наследуют общий базовый класс. `dynamic_cast` проверит, что полный объект действительно содержит нужный подобъект .

3.  **Приведение вверх (Upcast)**:
    Преобразование указателя на производный класс в указатель на базовый. Это преобразование безопасно и может быть выполнено неявно или через `static_cast`, но `dynamic_cast` также поддерживает его (и оно всегда успешно, если базовый класс однозначен и доступен) .

4.  **Требование полиморфизма**:
    Для выполнения проверки во время выполнения (при приведении вниз или вбок) исходный тип должен быть **полиморфным**, то есть содержать хотя бы одну виртуальную функцию. Это необходимо, потому что RTTI хранит информацию о типе именно в таблице виртуальных функций (vtable) .

#### Пример использования
```cpp
#include <iostream>
#include <typeinfo>

class Base {
public:
    virtual ~Base() {} // Делает класс полиморфным
};

class Derived : public Base {
public:
    void specificMethod() { std::cout << "Derived method\n"; }
};

void process(Base* b) {
    // Пытаемся привести к Derived
    if (Derived* d = dynamic_cast<Derived*>(b)) {
        d->specificMethod(); // Безопасно, если b действительно указывает на Derived
    } else {
        std::cout << "Object is not of type Derived\n";
    }
}
```

---

### Когда использовать?

`dynamic_cast` следует использовать только тогда, когда статическая проверка типов (виртуальные функции, шаблоны) не подходит или невозможна. Чрезмерное использование RTTI для организации логики (например, длинные цепочки `if/else` с проверкой типов) считается плохой практикой, так как это снижает производительность и ухудшает структуру кода. Идеальный вариант — расширять функциональность через виртуальные функции, а `dynamic_cast` применять для специфических случаев, например, при работе с библиотеками, которые нельзя изменить .
