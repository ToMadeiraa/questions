# 119. Как проверить, есть ли в контейнере элементы? Почему вызов container.size() является плохой практикой?

## Краткий ответ

Для проверки наличия элементов в контейнере следует использовать метод **`empty()`** (или свободную функцию `std::empty()` начиная с C++17). Вызов `container.size() == 0` (или `container.size() > 0`) считается плохой практикой по нескольким причинам: в старых стандартах C++ (до C++11) сложность `size()` для некоторых контейнеров могла быть **линейной** (O(n)), а не константной; `empty()` явно выражает намерение программиста; некоторые контейнеры (например, `std::forward_list`) вообще не имеют метода `size()`.

---

## Подробное объяснение

### 1. Правильный способ проверки на пустоту

**Для контейнеров STL** используйте метод-член `empty()`:

```cpp
std::vector<int> v;
if (v.empty()) {
    // контейнер пуст
}

if (!v.empty()) {
    // в контейнере есть элементы
}
```

**Начиная с C++17** рекомендуется использовать свободную функцию `std::empty()` из заголовка `<iterator>` (или любого контейнерного заголовка). Она работает единообразно для контейнеров, C-массивов и `std::initializer_list`:

```cpp
#include <iterator>

std::vector<int> v;
if (std::empty(v)) {
    // пуст
}

int arr[10];
if (!std::empty(arr)) {
    // массив не пуст (всегда false для ненулевого размера)
}

auto il = {1, 2, 3};
if (!std::empty(il)) {
    // initializer_list содержит элементы
}
```

Для C-массивов `std::empty()` всегда возвращает `false` (кроме массивов нулевого размера, которые не соответствуют стандарту), а для `std::initializer_list` проверяет `size() == 0`.

### 2. Почему `container.size() == 0` — плохая практика

#### 2.1. Проблема производительности (историческая)

В стандартах C++ **до C++11** для некоторых контейнеров (например, `std::list`) метод `size()` **не гарантировал** константную сложность. Реализация могла вычислять размер путём обхода всех элементов, что давало сложность **O(n)**. В то же время `empty()` всегда реализовывался как сравнение `begin() == end()` и имел гарантированную константную сложность **O(1)**.

В C++11 и позже стандарт требует, чтобы `size()` для всех стандартных контейнеров имел константную сложность. Однако:
- Старый код может компилироваться с флагами совместимости со старыми стандартами.
- Некоторые сторонние или нестандартные контейнеры могут не следовать этому требованию.
- Привычка использовать `size() == 0` может привести к проблемам при смене типа контейнера на тот, где `size()` дорог.

#### 2.2. Ясность намерения

`empty()` **явно** сообщает читателю кода: «я проверяю, пуст ли контейнер». Конструкция `size() == 0` — это косвенная проверка, требующая дополнительного мыслительного шага. Clang-Tidy и другие статические анализаторы помечают такие конструкции как нарушение читаемости.

#### 2.3. Универсальность и переносимость

Не все контейнеры имеют метод `size()`. Классический пример — **`std::forward_list`** (односвязный список, добавленный в C++11). Он предоставляет `empty()`, но **не имеет** `size()`, потому что хранение размера сделало бы операцию вставки/удаления в начало списка более дорогой. Если вы пишете шаблонный код, использующий `size() == 0`, он не скомпилируется для `forward_list`. Использование `empty()` делает код более общим и позволяет легче менять тип контейнера в будущем.

#### 2.4. Рекомендации статических анализаторов

Инструменты статического анализа (Clang-Tidy, Cppcheck, Polyspace) выдают предупреждения при использовании `size() == 0` или `size() > 0` для проверки пустоты контейнера. Clang-Tidy имеет специальную проверку `readability-container-size-empty`, которая рекомендует заменить `size()` на `empty()`.

### 3. Сравнение способов

| Способ | Рекомендация | Примечание |
|-------|-------------|-----------|
| `container.empty()` | ✅ Рекомендуется | Явно, эффективно, универсально |
| `std::empty(container)` | ✅ Рекомендуется (C++17) | Работает также для C-массивов и `initializer_list` |
| `container.size() == 0` | ❌ Не рекомендуется | Менее ясно, потенциальные проблемы с производительностью/переносимостью |
| `container.size() > 0` | ❌ Не рекомендуется | То же самое |
| `container.begin() == container.end()` | ⚠️ Допустимо, но не нужно | `empty()` делает то же самое, но читаемее |

### 4. Практический пример

```cpp
#include <iostream>
#include <vector>
#include <forward_list>

template <typename Container>
void process(const Container& c) {
    // Плохо: не скомпилируется для forward_list
    // if (c.size() == 0) { ... }

    // Хорошо: работает для всех стандартных контейнеров
    if (c.empty()) {
        std::cout << "Контейнер пуст\n";
        return;
    }

    std::cout << "В контейнере есть элементы\n";
}

int main() {
    std::vector<int> v{1, 2, 3};
    std::forward_list<int> fl{1, 2, 3};

    process(v);   // OK
    process(fl);  // OK, empty() есть, size() нет
}
```

### Резюме

Используйте **`empty()`** (или `std::empty()`) для проверки пустоты контейнера. Избегайте `size() == 0` — это не только вопрос стиля, но и вопрос производительности (в исторической перспективе), универсальности (не все контейнеры имеют `size()`) и ясности кода. Современные стандарты C++ гарантируют константную сложность `size()`, но привычка использовать `empty()` остаётся лучшей практикой, поддерживаемой статическими анализаторами и сообществом C++.
