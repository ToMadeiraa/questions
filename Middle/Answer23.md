# 23. Как прорабатывается константа переменных?

В C++ работа с константными переменными (объявленными с ключевым словом `const`) прорабатывается на нескольких уровнях: семантическом (запрет изменения), оптимизационном (вычисление на этапе компиляции) и на уровне системы типов (связывание, указатели, функции). Ключевой момент заключается в том, что `const` в C++ — это не просто «обещание не менять», а полноценный квалификатор типа, который влияет на то, как компилятор обрабатывает переменную.

### 1. Базовая семантика: запрет модификации

Когда переменная объявляется как `const`, компилятор запрещает любое прямое изменение её значения после инициализации. Попытка присвоить новое значение или использовать инкремент/декремент приводит к ошибке компиляции .

```cpp
const int i = 5;
i = 10;   // Ошибка компиляции
i++;      // Ошибка компиляции
```

Это основной контракт: программист сообщает компилятору, что значение не должно меняться, и компилятор обеспечивает соблюдение этого контракта в пределах прямой видимости.

### 2. Константа как выражение на этапе компиляции (и ограничения)

В C++ `const`-переменная **не всегда** является константным выражением (constant expression), то есть не всегда может быть вычислена на этапе компиляции. Это важное отличие от `constexpr`.

Переменная, объявленная как `const`, может использоваться в константных выражениях только при выполнении определённых условий:
- **Тип является интегральным** ( `int`, `char`, `bool` и т.п.) .
- **Инициализатор является константным выражением** (например, литерал или выражение из других константных выражений) .

Если хотя бы одно условие не выполняется, `const`-переменная является **переменной только для чтения** (read-only variable), но не константой времени компиляции .

Примеры:

```cpp
const int x = 3 + 4;        // OK: интегральный тип, инициализатор — константное выражение.
                            // x можно использовать в константных выражениях (например, для размера массива).

const double d = 1.2;       // d НЕ является константным выражением, потому что double — не интегральный тип.
                            // Его нельзя использовать там, где требуется константа времени компиляции.

int runtime_val = 10;
const int y = runtime_val;  // y НЕ является константным выражением, потому что инициализатор не константен.
```

Именно из-за этой «непоследовательности» и ограничений `const` в C++ был введён `constexpr`, который **гарантирует** вычисление на этапе компиляции и может применяться к типам, отличным от интегральных .

### 3. Вычисление на этапе компиляции: когда это происходит

Даже если `const`-переменная инициализирована константным выражением, это не означает, что она **всегда** вычисляется на этапе компиляции. Компилятор обязан вычислить её на этапе компиляции только тогда, когда она используется в контексте, требующем константного выражения (например, размер массива, аргумент шаблона, инициализатор `constexpr`-переменной) .

В остальных случаях компилятор может вычислить её на этапе компиляции (для оптимизации), но не обязан.

### 4. Внутреннее связывание (internal linkage)

В C++ (в отличие от C) `const`-переменные на глобальном уровне или в пространстве имён по умолчанию имеют **внутреннее связывание** (internal linkage). Это означает, что они видны только в пределах той единицы трансляции (файла), где определены. Это позволяет определять `const`-переменные в заголовочных файлах без нарушения правила одного определения (ODR) .

Если нужно, чтобы `const`-переменная имела внешнее связывание (была доступна из других файлов), её нужно объявить с `extern` .

### 5. `const` и указатели

Квалификатор `const` может применяться как к самому указателю, так и к данным, на которые он указывает. Это важный аспект «проработки» константности в системе типов:

- **Указатель на константу** (`const int* p` или `int const* p`): данные, на которые указывает указатель, нельзя изменить через этот указатель. Сам указатель можно переназначить на другой адрес .
- **Константный указатель** (`int* const p`): сам указатель нельзя изменить (нельзя переназначить), но данные, на которые он указывает, можно менять .
- **Константный указатель на константу** (`const int* const p`): нельзя менять ни указатель, ни данные .

Компилятор строго проверяет эти квалификации: нельзя присвоить адрес `const`-объекта неконстантному указателю без явного `const_cast` (что является плохой практикой и ведёт к неопределённому поведению, если объект действительно находится в памяти только для чтения) .

### 6. `const` в параметрах функций и методах

- **Параметры функций**: `const` в параметре, передаваемом по значению, означает лишь, что функция не может изменить локальную копию. Для вызывающего кода это не имеет значения. Для параметров, передаваемых по указателю или ссылке, `const` гарантирует, что функция не изменит объект через этот указатель/ссылку .
- **Константные методы-члены**: Метод класса, объявленный с `const` после списка параметров (например, `int getValue() const;`), обязуется не изменять состояние объекта (не модифицировать нестатические поля данных). Компилятор проверяет это. Константные методы можно вызывать у константных объектов .

### 7. Оптимизация и размещение в памяти

Компилятор C++ может использовать `const`-квалификацию для оптимизации. Поскольку программа не может изменить `const`-объект (без нарушения правил через `const_cast`), компилятор может:
- Размещать `const`-объекты с статическим временем жизни в **памяти только для чтения** .
- Выполнять **свёртку констант** (constant folding): подставлять известное значение `const`-переменной непосредственно в код, особенно если она инициализирована константным выражением и используется в контексте, где требуется константа .

Однако для локальных `const`-переменных, адрес которых берётся, компилятор обычно вынужден размещать их в стеке, как обычные переменные, хотя и запрещает их модификацию.

### Итог

Проработка `const`-переменных в C++ — это комбинация:
1.  **Семантического запрета** на изменение после инициализации.
2.  **Условного участия в константных выражениях** (только для интегральных типов с константным инициализатором).
3.  **Строгой типизации** при работе с указателями и ссылками.
4.  **Внутреннего связывания** по умолчанию для глобальных/пространственных констант.
5.  **Возможных оптимизаций** компилятора, включая размещение в read-only памяти и свёртку констант.

Для гарантированного вычисления на этапе компиляции и использования в любых контекстах, требующих константных выражений, следует применять `constexpr`, а не просто `const`.
