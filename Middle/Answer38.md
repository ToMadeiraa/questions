# 38. Что такое copy elision? Сколько раз будет вызван конструктор/деструктор у объекта, которого возвращают по значению?

## Что такое copy elision

**Copy elision** (элизия копирования) — это оптимизация в C++, при которой компилятор исключает вызов конструктора копирования или перемещения для объекта, создаваемого из другого объекта того же типа (с игнорированием cv-квалификаторов) . Это единственная оптимизация, которая может изменять наблюдаемое поведение программы (побочные эффекты конструкторов/деструкторов), не нарушая правило "as-if" .

Copy elision тесно связана с **RVO** (Return Value Optimization) и **NRVO** (Named Return Value Optimization). RVO применяется, когда возвращается безымянный временный объект, NRVO — когда возвращается именованная локальная переменная .

**Ключевое изменение в C++17:** для prvalue (чистых rvalue, таких как `T()`) copy elision стала **обязательной** и перестала считаться просто оптимизацией. В C++17 prvalue не материализуется до момента, когда это действительно необходимо, и объект конструируется сразу в конечном месте назначения . Это означает, что в некоторых случаях конструктор копирования/перемещения может вообще отсутствовать у типа.

## Сколько раз вызываются конструктор и деструктор

Ответ зависит от стандарта C++ и формы возврата.

### Случай 1: Возврат prvalue (безымянного временного объекта)

```cpp
T f() {
    return T();  // prvalue
}

T obj = f();
```

**C++17 и новее (гарантированная элизия):**
- **Конструктор по умолчанию:** 1 раз (создаёт объект сразу в хранилище `obj`)
- **Конструктор копирования/перемещения:** **0 раз** (не вызывается и даже не требуется)
- **Деструктор:** **1 раз** (в конце жизни `obj`)

Объект `T()` конструируется непосредственно в памяти, предназначенной для `obj`. Промежуточный временный объект не создаётся вообще .

**До C++17 (необязательная оптимизация):**
- Компилятор **может** выполнить элизию (тогда 1 конструктор и 1 деструктор), но **не обязан**. Без оптимизации может быть вызван конструктор копирования/перемещения и дополнительный деструктор .

### Случай 2: Возврат именованной локальной переменной (NRVO)

```cpp
T f() {
    T local;
    return local;  // NRVO
}

T obj = f();
```

**C++17 и новее:**
- NRVO остаётся **необязательной** оптимизацией (в отличие от RVO для prvalue) .
- **Если NRVO выполнена:** конструктор по умолчанию — 1 раз, конструктор копирования/перемещения — 0 раз, деструктор — 1 раз.
- **Если NRVO не выполнена:** конструктор по умолчанию — 1 раз, конструктор перемещения (или копирования) — 1 раз, деструктор — 2 раза (для `local` и для `obj`).

Однако даже при выполненной NRVO конструктор перемещения/копирования должен **существовать и быть доступным** (не удалённым), иначе программа некорректна .

### Практический вывод

Если вы возвращаете объект по значению из функции:

- При возврате **prvalue** (`return T();`) в C++17+: **один конструктор (по умолчанию или соответствующий), один деструктор, ноль копирований/перемещений**.
- При возврате **именованной переменной** (NRVO): компилятор **обычно** выполняет элизию в режиме оптимизации, но стандарт этого не гарантирует. Полагаться на конкретное количество вызовов конструкторов/деструкторов в этом случае **нельзя** — программа, зависящая от побочных эффектов в конструкторах копирования/деструкторах, непортируема .

**Важно:** не помещайте критическую логику в конструкторы копирования/перемещения или деструкторы, если объект возвращается по значению, — вы не можете гарантировать, сколько раз они будут вызваны (за исключением гарантированных случаев C++17).
