# 7. Какие знаете паттерны проектирования?

Паттерны проектирования (design patterns) — это типовые, многократно проверенные решения часто встречающихся задач проектирования ПО. Их делят на три основные группы по классификации «Банды четырёх» (GoF — Gang of Four: Gamma, Helm, Johnson, Vlissides).

## 1. Порождающие (Creational)

Отвечают за создание объектов, скрывая логику инстанцирования и делая систему независимой от того, как создаются и компонуются объекты.

- **Singleton (Одиночка)** — гарантирует единственный экземпляр класса и даёт глобальную точку доступа. В C++ часто реализуется через статическую локальную переменную (thread-safe с C++11) или `std::call_once`.
- **Factory Method (Фабричный метод)** — определяет интерфейс для создания объекта, но позволяет подклассам решать, какой класс инстанцировать.
- **Abstract Factory (Абстрактная фабрика)** — интерфейс для создания семейств связанных объектов без указания их конкретных классов.
- **Builder (Строитель)** — пошаговое конструирование сложного объекта; позволяет отделить процесс построения от представления.
- **Prototype (Прототип)** — создание новых объектов копированием существующего экземпляра (в C++ — через виртуальный `clone()`).

**Пример Singleton (Meyers Singleton, потокобезопасен с C++11):**
```cpp
class Singleton {
public:
    static Singleton& instance() {
        static Singleton obj;   // инициализация при первом обращении
        return obj;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() = default;
};
```

## 2. Структурные (Structural)

Описывают способы компоновки классов и объектов в более крупные структуры.

- **Adapter (Адаптер)** — преобразует интерфейс класса в другой интерфейс, ожидаемый клиентом.
- **Bridge (Мост)** — разделяет абстракцию и реализацию, чтобы они могли изменяться независимо.
- **Composite (Компоновщик)** — древовидная структура «часть-целое»; клиент единообразно работает и с отдельными объектами, и с их группами.
- **Decorator (Декоратор)** — динамически добавляет объекту новые обязанности, оборачивая его.
- **Facade (Фасад)** — простой интерфейс к сложной подсистеме.
- **Flyweight (Приспособленец)** — разделение общего состояния множества мелких объектов для экономии памяти.
- **Proxy (Заместитель)** — суррогат объекта, контролирующий доступ (ленивая загрузка, защита, логирование).

**Пример Facade:**
```cpp
class CPU { public: void freeze() {} void jump(long) {} };
class Memory { public: void load(long, const char*) {} };
class HardDrive { public: const char* read(long, int) { return ""; } };

class ComputerFacade {  // клиенту не нужно знать про три подсистемы
    CPU cpu_; Memory mem_; HardDrive hd_;
public:
    void start() {
        cpu_.freeze();
        mem_.load(0, hd_.read(0, 1024));
        cpu_.jump(0);
    }
};
```

## 3. Поведенческие (Behavioral)

Описывают взаимодействие объектов и распределение обязанностей между ними.

- **Chain of Responsibility (Цепочка обязанностей)** — передача запроса по цепочке обработчиков до первого, кто его обработает.
- **Command (Команда)** — инкапсуляция запроса как объекта (позволяет параметризовать, ставить в очередь, отменять).
- **Iterator (Итератор)** — последовательный доступ к элементам коллекции без раскрытия её внутреннего устройства (в C++ это стандартная идиома: `begin()/end()`).
- **Mediator (Посредник)** — централизует взаимодействие множества объектов.
- **Memento (Снимок)** — сохранение и восстановление внутреннего состояния объекта (undo).
- **Observer (Наблюдатель)** — оповещение подписчиков об изменении состояния субъекта (событийная модель).
- **State (Состояние)** — поведение объекта меняется вместе с его состоянием, смена выглядит как смена класса.
- **Strategy (Стратегия)** — взаимозаменяемые семейства алгоритмов, инкапсулированные за общим интерфейсом.
- **Template Method (Шаблонный метод)** — каркас алгоритма в базовом классе, отдельные шаги переопределяются в наследниках.
- **Visitor (Посетитель)** — операции над элементами структуры объектов без изменения их классов.

**Пример Strategy:**
```cpp
#include <memory>
#include <vector>

struct SortStrategy {
    virtual void sort(std::vector<int>&) const = 0;
    virtual ~SortStrategy() = default;
};

struct QuickSort : SortStrategy { /* ... */ void sort(std::vector<int>& v) const override {} };
struct MergeSort : SortStrategy { /* ... */ void sort(std::vector<int>& v) const override {} };

class Sorter {
    std::unique_ptr<SortStrategy> strategy_;
public:
    explicit Sorter(std::unique_ptr<SortStrategy> s) : strategy_(std::move(s)) {}
    void run(std::vector<int>& v) const { strategy_->sort(v); }
};
```

**Пример Observer (упрощённо):**
```cpp
#include <vector>
#include <functional>

class Subject {
    std::vector<std::function<void(int)>> observers_;
public:
    void subscribe(std::function<void(int)> f) { observers_.push_back(std::move(f)); }
    void notify(int value) { for (auto& o : observers_) o(value); }
};
```

## Дополнение: идиомы и «вне GoF»

Помимо классических паттернов, в C++-практике полезно знать:
- **RAII** — идиома управления ресурсами через время жизни объекта (не совсем паттерн, но ключевой принцип C++).
- **PIMPL (Pointer to Implementation)** — сокрытие деталей реализации (частный случай Bridge / «компиляционный барьер»).
- **Non-Virtual Interface (NVI)** — публичные невиртуальные функции вызывают приватные виртуальные.
- **CRTP** — статический полиморфизм через наследование от шаблона с параметром-наследником.
- **Rule of Zero / Three / Five** — правила управления специальными функциями-членами.

## Важные замечания для собеседования

- Паттерны — не самоцель: не стоит «вкручивать» их везде, они решают конкретные проблемы.
- В современном C++ часть паттернов выражается лаконичнее благодаря `std::function`, лямбдам, `std::unique_ptr`, шаблонам и `std::variant` (например, Strategy и Command часто заменяются на `std::function`).
- Стоит уметь привести по 1–2 примера из практики и объяснить, **какую проблему** решает паттерн, а не только его структуру.
