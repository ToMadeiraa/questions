# 128. Как работает spinlock?

**Spinlock (спин-блокировка)** — это низкоуровневый примитив синхронизации, используемый в многопоточном программировании. В отличие от обычного мьютекса, который при неудачной попытке захвата «усыпляет» поток (переводит его в состояние ожидания), spinlock заставляет поток **активно ожидать** в цикле (так называемое «busy-waiting» или «холостое вращение»), непрерывно проверяя, не освободился ли замок .

### 1. Принцип работы

В основе spinlock лежит атомарная переменная (флаг). Процесс захвата и удержания выглядит следующим образом:

1.  **Захват (Lock)**: Поток пытается атомарно изменить состояние флага с «свободно» на «занято». Если это удается, поток входит в критическую секцию.
2.  **Ожидание (Spin)**: Если флаг уже занят другим потоком, текущий поток не засыпает, а входит в цикл, где снова и снова пытается выполнить атомарную операцию захвата. Он «крутится» в этом цикле до тех пор, пока флаг не станет свободным .
3.  **Освобождение (Unlock)**: Поток выходит из критической секции и атомарно сбрасывает флаг в состояние «свободно».

### 2. Реализация в C++

В C++ (начиная с C++11) для реализации простейшего spinlock обычно используется `std::atomic_flag`, так как этот тип **гарантированно** не использует внутренние блокировки (lock-free) .

Классическая реализация выглядит так:

```cpp
#include <atomic>

class SpinLock {
    std::atomic_flag flag = ATOMIC_FLAG_INIT;
public:
    void lock() {
        // test_and_set возвращает предыдущее значение и устанавливает true.
        // Если предыдущее было false (свободно), мы забираем лок и выходим из цикла.
        // Если true (занято), крутимся в цикле (spin).
        while (flag.test_and_set(std::memory_order_acquire)) {
            // Можно добавить _mm_pause() для x86, чтобы снизить нагрузку на шину
        }
    }
    
    void unlock() {
        // Сбрасываем флаг, освобождая лок
        flag.clear(std::memory_order_release);
    }
};
```

**Важные детали реализации:**
*   **Memory Order**: При захвате используется `std::memory_order_acquire`, чтобы гарантировать, что все операции записи в критической секции, выполненные другим потоком до освобождения лока, будут видны текущему потоку. При освобождении используется `std::memory_order_release`, чтобы гарантировать завершение всех операций перед снятием лока .
*   **Оптимизация (C++20)**: В C++20 появились методы `wait` и `notify_one`, которые позволяют избежать бесконечного «вращения», если лок не удается взять сразу. Поток может «уснуть» на атомарной переменной до момента освобождения, что экономит ресурсы процессора .

### 3. Ключевые характеристики и применение

Spinlock имеет смысл использовать только при определенных условиях:

*   **Короткие критические секции**: Если время удержания лока очень мало (например, изменение одной переменной), overhead на переключение контекста потока (сон/пробуждение) может быть больше, чем время, потраченное на «вращение» .
*   **Многопроцессорные системы**: Spinlock эффективен, когда ожидающий поток крутится на другом физическом ядре, в то время как владелец лока завершает работу на своем ядре .
*   **Риски**: Если поток-владелец будет удерживать лок долго, «крутящиеся» потоки будут впустую сжигать циклы процессора. В системах с одним ядром или при вытеснении потока-владельца spinlock может привести к взаимной блокировке (deadlock) или полному истощению кванта времени .

В отличие от мьютексов, spinlock не выполняет системных вызовов для блокировки, что делает его быстрее в сценариях с низкой конкуренцией, но потенциально очень дорогим при высокой конкуренции .
