# 13. Какая разница между статической и динамической библиотеками?

Ключевое различие между статической и динамической библиотеками в C++ заключается в **моменте и способе связывания**: статическая библиотека копирует необходимый код в исполняемый файл на этапе компоновки, тогда как динамическая библиотека лишь записывает зависимость, а фактический код загружается и разделяется во время выполнения программы.

### 📦 Статическая библиотека (Static Library)

В Linux/Unix такие библиотеки обычно имеют расширение `.a` (archive), в Windows — `.lib`.

- **Механизм компоновки**: При компоновке программы компоновщик извлекает из статической библиотеки только те объектные файлы (`.o`/`.obj`), которые содержат используемые программой символы, и **физически включает** их в итоговый исполняемый файл .
- **Результат**: Исполняемый файл становится самодостаточным. После создания программы статическая библиотека больше не нужна для её запуска.
- **Преимущества**: Простота развертывания (не нужно беспокоиться об отсутствии библиотек в целевой системе), немного более быстрый запуск (нет накладных расходов на динамическую загрузку).
- **Недостатки**: Размер исполняемого файла больше; если несколько программ используют одну и ту же статическую библиотеку, в памяти и на диске будет храниться несколько копий её кода, что приводит к напрасной трате ресурсов .

### 🔗 Динамическая библиотека (Dynamic/Shared Library)

В Linux/Unix такие библиотеки обычно имеют расширение `.so` (shared object), в Windows — `.dll` (Dynamic Link Library).

- **Механизм компоновки**: При компоновке программы компоновщик не копирует код библиотеки, а лишь записывает в исполняемый файл информацию о зависимости от библиотеки (и, возможно, таблицу импорта). **Фактическая загрузка** библиотеки в адресное пространство процесса происходит при запуске программы (или явно через `dlopen`/`LoadLibrary` во время выполнения) .
- **Результат**: Исполняемый файл содержит только «ссылку» и не включает код библиотеки.
- **Преимущества**: **Экономия памяти и дискового пространства**: несколько одновременно работающих программ могут совместно использовать одну копию кода динамической библиотеки в памяти, что значительно снижает потребление ресурсов . **Удобство обновления**: если интерфейс библиотеки не изменился, достаточно заменить файл `.so`/`.dll`, и программу не нужно перекомпилировать или перекомпоновать .
- **Недостатки**: Программа зависит от среды выполнения; если в целевой системе отсутствует соответствующая динамическая библиотека (или версия несовместима), программа не запустится; динамическая загрузка при запуске создает небольшие накладные расходы по времени.

### 📊 Сравнение

| Критерий | Статическая библиотека | Динамическая библиотека |
| :--- | :--- | :--- |
| **Типичное расширение** | `.a` (Linux) / `.lib` (Windows) | `.so` (Linux) / `.dll` (Windows) |
| **Момент компоновки** | Этап компоновки (Compile-time) | Этап загрузки/выполнения (Load-time / Run-time) |
| **Содержимое исполняемого файла** | Включает полный код используемых функций | Включает только ссылки/таблицы импорта |
| **Размер исполняемого файла** | Больше | Меньше |
| **Использование памяти** | Каждая программа имеет независимую копию | Несколько программ совместно используют одну копию |
| **Сложность обновления** | Требуется перекомпиляция и повторное развертывание | Достаточно заменить файл библиотеки (при совместимости ABI) |
| **Зависимость при развертывании** | Нет внешних зависимостей | Требуется наличие соответствующей библиотеки в целевой системе |

**Дополнительное замечание для C++**: При использовании динамических библиотек в C++ особое внимание следует уделять **совместимости ABI** (двоичного интерфейса). Разные компиляторы (например, MSVC и GCC) или даже разные версии одного компилятора могут иметь несовместимые механизмы искажения имен (name mangling) и раскладки классов, что делает невозможным прямое связывание динамических библиотек C++, скомпилированных разными инструментами. Для решения этой проблемы обычно предоставляют чистый C-интерфейс (с `extern "C"`), поскольку ABI языка C относительно стабилен и универсален.
