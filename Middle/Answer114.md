# 114. Как реализован list?

`std::list` в STL реализован как **двунаправленный (двусвязный) кольцевой список** с фиктивным (sentinel) узлом. Такая структура обеспечивает вставку и удаление элементов за константное время `O(1)` в любом месте контейнера, но исключает произвольный доступ по индексу.

Ниже разобраны ключевые аспекты реализации на основе типичных реализаций (libstdc++ от GCC, SGI STL, MSVC).

### 1. Структура узла (Node)

Каждый элемент списка хранится в отдельном узле, который содержит три поля :

```cpp
struct _List_node_base {
    _List_node_base* _M_next;  // указатель на следующий узел
    _List_node_base* _M_prev;  // указатель на предыдущий узел
};

template <class T>
struct _List_node : public _List_node_base {
    T _M_data;  // сами данные (значение)
};
```

В libstdc++ используется разделение на базовый узел (только указатели) и производный (с данными), что позволяет выносить общую логику работы с указателями в базовый класс и уменьшать дублирование кода .

### 2. Кольцевая структура и фиктивный узел (Sentinel)

Список не хранит указатели на «голову» и «хвост» отдельно. Вместо этого создаётся **один фиктивный узел** (sentinel node), который не содержит пользовательских данных. Его указатели `_M_next` и `_M_prev` замыкаются сам на себя, если список пуст .

Внутри класса `list` хранится только один указатель на этот sentinel:

```cpp
template <class T, class Alloc>
class list {
protected:
    _List_node<T>* _M_node; // указывает на sentinel (end)
};
```

**Как это работает:**
- `begin()` возвращает итератор на `_M_node->_M_next` (первый реальный элемент).
- `end()` возвращает итератор на сам `_M_node` (фиктивный узел).
- `push_back` вставляет элемент перед `_M_node` (то есть в конец).
- `push_front` вставляет элемент после `_M_node` (то есть в начало).

Благодаря кольцевой структуре, переход от последнего элемента к первому (и наоборот) происходит без проверок на `nullptr`, что упрощает итерацию и вставку/удаление .

### 3. Выделение памяти и создание узлов

Память под узлы выделяется через аллокатор, «перепривязанный» (rebound) к типу узла `_List_node<T>`, а не к типу `T`. Это важно, потому что размер узла больше размера `T` (из-за двух указателей) .

Создание нового узла (`_M_create_node`) происходит в два этапа:
1. Выделение «сырой» памяти под узел через аллокатор.
2. Конструирование объекта `T` в поле `_M_data` с помощью placement new (или `allocator_traits::construct`) .

```cpp
_Node* _M_create_node(const T& __x) {
    _Node* __p = this->_M_get_node(); // выделить память под узел
    try {
        _M_get_Tp_allocator().construct(&__p->_M_data, __x); // создать T
    } catch(...) {
        _M_put_node(__p); // при исключении вернуть память
        throw;
    }
    return __p;
}
```

### 4. Вставка (Insert)

Вставка нового узла перед позицией `position` выполняется за `O(1)` и не инвалидирует итераторы на другие элементы . Алгоритм:

1. Создать новый узел `tmp`.
2. Установить связи:
   - `tmp->_M_next = position._M_node`
   - `tmp->_M_prev = position._M_node->_M_prev`
3. Скорректировать соседние узлы:
   - `position._M_node->_M_prev->_M_next = tmp`
   - `position._M_node->_M_prev = tmp`

Вставка в начало (`push_front`) или конец (`push_back`) сводится к вызову `insert` с соответствующей позицией (`begin()` или `end()`).

### 5. Удаление (Erase)

Удаление узла по итератору также выполняется за `O(1)`. Узел «отцепляется» от соседей, после чего вызывается деструктор для `T` и память возвращается аллокатору .

```cpp
iterator erase(iterator position) {
    _Node* __p = position._M_node;
    // переставить указатели у соседей
    __p->_M_prev->_M_next = __p->_M_next;
    __p->_M_next->_M_prev = __p->_M_prev;
    // уничтожить T и освободить память узла
    _M_erase_node(__p);
    return iterator(__p->_M_next);
}
```

Инвалидируются только итераторы и ссылки на удалённый элемент.

### 6. Итераторы (Bidirectional Iterator)

Итератор `list` — это не «сырой» указатель, а объект класса, инкапсулирующий указатель на узел `_List_node_base*`. Он перегружает операции `*`, `->`, `++`, `--`, `==`, `!=`. При инкременте (`++`) итератор переходит по `_M_next`, при декременте (`--`) — по `_M_prev` .

Поскольку итератор хранит указатель на узел, а не на данные, он остаётся валидным при вставках и удалениях других элементов (кроме удаления того элемента, на который он указывает).

### 7. Специфические операции

Из-за особенностей связного списка `std::list` предоставляет операции, которых нет у `vector` или `deque` :

- **`splice`**: перемещает узлы из одного списка в другой **без копирования данных** — просто переставляются указатели. Сложность `O(1)` (для одного элемента или целого списка) или `O(n)` (для диапазона).
- **`merge`**: слияние двух отсортированных списков без копирования, также путём перестановки указателей.
- **`sort`**: сортировка слиянием (merge sort), оптимизированная для связного списка (не требует произвольного доступа).
- **`reverse`**: перестановка указателей `next` и `prev` у всех узлов.
- **`unique`**: удаление подряд идущих дубликатов.

### 8. Особенности разных реализаций

| Реализация | Особенности |
|------------|-------------|
| **libstdc++ (GCC)** | Кольцевой список с sentinel-узлом. Разделение узла на `_List_node_base` (указатели) и `_List_node<T>` (данные). Аллокатор привязан к типу узла, а не к `T` . |
| **SGI STL** | Историческая реализация, также использует кольцевой список с sentinel. `list_node` содержит `void* prev`, `void* next` и `T data` . |
| **MSVC** | Аналогичная концепция: двусвязный кольцевой список с sentinel. Реализация может отличаться в деталях аллокации и обработки исключений . |

### Итог

`std::list` — это классический двусвязный кольцевой список с фиктивным узлом. Такая реализация даёт:
- **Плюсы**: `O(1)` вставка/удаление в любом месте, стабильность итераторов (кроме удалённых), отсутствие реаллокаций, эффективные `splice` и `merge`.
- **Минусы**: отсутствие произвольного доступа (`O(n)` для поиска элемента по индексу), дополнительные расходы памяти на два указателя в каждом узле, плохая локальность данных (узлы разбросаны по памяти) .
