# 149. Как отредактировать комит?

В Git редактирование коммита означает **перезапись истории**. Конкретный метод зависит от того, является ли целевой коммит **последним** или **историческим**, а также был ли он **отправлен в удалённый репозиторий**. Основной принцип: изменять можно только те коммиты, которые ещё не были отправлены в общий репозиторий; если коммит уже отправлен, после изменения потребуется принудительная отправка (`--force-with-lease`), что может повлиять на другихCollaborators.

## 1. Редактирование последнего коммита (HEAD): `git commit --amend`

Это самый простой и распространённый сценарий, подходящий для исправления сообщения коммита, забытых файлов или изменения содержимого последнего коммита.

**Только изменение сообщения коммита:**
```bash
git commit --amend
```
После выполнения откроется редактор с сообщением последнего коммита. После редактирования и сохранения будет создан **новый коммит** для замены старого, и SHA-1 хеш изменится.

**Добавление забытых файлов в последний коммит:**
```bash
git add forgotten_file
git commit --amend --no-edit   # Сохранить исходное сообщение коммита
```
Параметр `--no-edit` означает сохранение исходного сообщения без открытия редактора.

> **Внимание**: `--amend` не "изменяет" старый коммит, а создаёт совершенно новый коммит для его замены. Если старый коммит уже был отправлен, потребуется принудительная отправка, и это перезапишет историю удалённой ветки.

## 2. Редактирование исторических коммитов (не последних): интерактивный rebase

Если нужно изменить коммит, который не является последним (например, сообщение коммита трёхкоммитной давности или содержимое файлов), необходимо использовать `git rebase -i` (интерактивный rebase).

### Шаги

**Шаг 1: Запуск интерактивного rebase**

Предположим, нужно изменить сообщение коммита трёхкоммитной давности:
```bash
git rebase -i HEAD~3
```
Или укажите конкретный коммит через хеш (обратите внимание на `^`, обозначающий родительский коммит):
```bash
git rebase -i a1b2c3d^
```

**Шаг 2: Изменение инструкций в списке**

Откроется редактор со списком коммитов (в обратном хронологическом порядке). Найдите строку с целевым коммитом и измените `pick` на нужную команду:

| Команда | Сокращение | Назначение |
|---------|------------|------------|
| `reword` | `r` | Только изменение сообщения коммита |
| `edit` | `e` | Приостановка для изменения содержимого коммита (файлов) |

**Шаг 3: Выполнение редактирования**

- Если выбрано `reword`: после сохранения и выхода Git последовательно откроет редактор сообщений для каждого отмеченного коммита, измените и сохраните.
- Если выбрано `edit`: Git приостановится на этом коммите, после изменения файлов выполните:
  ```bash
  git add <изменённые_файлы>
  git commit --amend --no-edit   # Или без --no-edit для изменения сообщения
  git rebase --continue           # Продолжить применение остальных коммитов
  ```

**Шаг 4: Завершение**

После завершения rebase все коммиты после изменённого получат новые хеши (перезапись истории). Если в процессе возникнут конфликты, их необходимо разрешить вручную, затем выполнить `git add` и `git rebase --continue`; для отмены всей операции используйте `git rebase --abort`.

## 3. Особые случаи и меры предосторожности

**Изменение корневого коммита**: если нужно изменить самый первый коммит репозитория, используйте `git rebase -i --root`.

**Уже отправлен в удалённый репозиторий**: после изменения истории необходимо выполнить принудительную отправку, но **никогда не используйте** обычный `--force`, применяйте `--force-with-lease` — он безопаснее, так как при наличии новых коммитов от другихCollaborators откажется перезаписывать:
```bash
git push --force-with-lease origin <branch-name>
```

**Изменение коммитов в общей ветке**: если над этой веткой работают другиеCollaborators, перезапись истории вызовет хаос. В таких случаях следует использовать `git revert` для создания нового коммита, отменяющего изменения, а не изменять историю.

**Резервная копия**: перед выполнением любой операции перезаписи истории рекомендуется создать резервную ветку:
```bash
git branch backup-before-rebase
```
