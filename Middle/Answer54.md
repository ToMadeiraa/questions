# 54. Что такое const correctness?

**Const correctness** (корректность по отношению к `const`) — это практика в C++ последовательного и осмысленного использования ключевого слова `const` для указания того, что объект, переменная или метод не изменяют состояние (или не позволяют изменять его через предоставленный интерфейс). Это не просто синтаксическое украшение, а способ документирования намерений и обеспечения безопасности на этапе компиляции: компилятор проверяет соблюдение обещаний `const`, не добавляя накладных расходов во время выполнения .

Основная идея заключается в том, что `const` на методе или параметре означает обещание: «эта операция не изменит наблюдаемое состояние объекта». Если вы передаете объект по константной ссылке (`const T&`) или указателю на константу (`const T*`), вы можете быть уверены, что вызываемый код не сможет изменить этот объект (по крайней мере, через этот интерфейс) .

### Ключевые аспекты const correctness

#### 1. Константные методы-члены (Const Member Functions)
Метод, помеченный `const` после списка параметров, называется **константным методом** (или «инспектором»). Он обещает не изменять логическое состояние объекта `*this`. Вызов такого метода разрешен для константных объектов, тогда как вызов неконстантного метода для константного объекта приведет к ошибке компиляции .

```cpp
class Fred {
public:
    void inspect() const;   // Обещает не изменять *this
    void mutate();          // Может изменять *this
};

void userCode(Fred& changeable, const Fred& unchangeable) {
    changeable.inspect();   // OK
    changeable.mutate();    // OK
    unchangeable.inspect(); // OK
    // unchangeable.mutate(); // Ошибка компиляции
}
```

#### 2. Логическая vs. Физическая константность
Важно различать **физическую** (побитовую) и **логическую** константность. Компилятор проверяет физическую константность (неизменность битов объекта). Однако смысл `const` метода должен определяться с точки зрения пользователя: если метод не меняет наблюдаемое поведение объекта (его логическое состояние), он должен быть `const`, даже если он меняет какие-то внутренние кэши или счетчики .

Для случаев, когда константному методу нужно изменить физическое состояние (например, обновить кэш), используется ключевое слово **`mutable`**. Оно указывает, что данное поле не является частью логического состояния объекта и может изменяться в `const` методах .

```cpp
class Cache {
    mutable int hitCount = 0; // Изменяется даже в const методах
    int data;
public:
    int getData() const {
        ++hitCount; // OK, так как hitCount mutable
        return data;
    }
};
```

#### 3. Параметры и возвращаемые значения
Передача параметров по `const` ссылке (`const T&`) или указателю на константу (`const T*`) является стандартом для больших объектов, которые не должны копироваться и не должны изменяться функцией. Это позволяет избежать копирования и одновременно гарантирует безопасность .

Возврат указателей или ссылок на неконстантные объекты из константных методов считается **нарушением const correctness** (если только это не явно задумано, например, для реализации неконстантного геттера через константный с использованием `const_cast`, что допускается в некоторых стилях, но требует осторожности) .

#### 4. Стиль «East const» (Константа справа)
Хотя это не является частью семантики языка, существует стиль написания `const` справа от типа (`int const` вместо `const int`, `X const&` вместо `const X&`). Сторонники этого стиля (называемого «East const» или «consistent const») утверждают, что он более последователен: `const` всегда стоит справа от того, что он квалифицирует. Это особенно полезно при работе с указателями и `typedef`/`using`, где традиционный стиль может запутать (например, `const X*` против `X* const`) .

#### 5. Инструменты и руководства
Многие руководства по стилю (например, C++ Core Guidelines, Chromium) рекомендуют объявлять переменные `const`, если их значение не предполагается изменять. Инструменты статического анализа, такие как `clang-tidy` (проверка `misc-const-correctness`), могут автоматически находить локальные переменные, которые можно сделать `const` .

### Резюме
Const correctness — это дисциплина проектирования API и написания кода, которая делает программы более безопасными, самодокументируемыми и понятными. Она позволяет компилятору отлавливать случайные модификации данных, которые должны оставаться неизменными, и является важным аспектом качественного кода на C++.
