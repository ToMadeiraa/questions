# 65. Что произойдет, если exception выйдет за пределы блока noexcept функции?

Если исключение выходит за пределы функции, объявленной как `noexcept` (или `noexcept(true)`), немедленно вызывается `std::terminate()`.

## Механизм

Спецификатор `noexcept` сообщает компилятору, что функция не должна выбрасывать исключения. Однако это не проверяется на этапе компиляции — это обещание программиста. Если во время выполнения исключение всё же возникает и механизм поиска обработчика (stack unwinding) достигает внешнего блока `noexcept`-функции, стандарт предписывает вызвать `std::terminate`.

```cpp
extern void f(); // потенциально выбрасывающая исключения функция

void g() noexcept {
    f();      // допустимо, даже если f() выбросит исключение
    throw 42; // допустимо синтаксически, но фактически приведёт к вызову std::terminate
}
```

В приведённом примере, если `f()` выбросит исключение, оно не будет распространяться за пределы `g()` — вместо этого будет вызван `std::terminate`.

## Важные уточнения

**Это не ошибка компиляции.** Компилятор не обязан диагностировать возможное нарушение `noexcept` (хотя некоторые компиляторы могут выдавать предупреждения в очевидных случаях). Нарушение обнаруживается только во время выполнения.

**`std::terminate` по умолчанию вызывает `std::abort`**, что приводит к аварийному завершению программы. Пользователь может установить собственный обработчик через `std::set_terminate`.

**До C++17** в некоторых контекстах (динамическая спецификация исключений `throw()`) вместо `std::terminate` мог вызываться `std::unexpected`, однако для `noexcept` поведение всегда было связано с `std::terminate`.

## Практический смысл

`noexcept` следует применять только тогда, когда программист уверен, что функция действительно не выбрасывает исключений. Это позволяет компилятору оптимизировать код (например, избегать генерации кода для размотки стека) и делает функцию безопасной для использования в контекстах, где исключения недопустимы (например, деструкторы, перемещающие конструкторы для `std::vector`).
