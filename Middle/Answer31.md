# 31. Что такое явное и неявное приведение типов в С++? Зачем делать explicit-конструктор?

## Краткий ответ

**Неявное приведение** — это автоматическое преобразование типов компилятором без явного указания в коде. **Явное приведение** — это преобразование, которое программист указывает явно с помощью операторов приведения (`static_cast`, `(Type)value` и т.п.) или прямой инициализации.

**`explicit`-конструктор** запрещает компилятору использовать данный конструктор для неявных преобразований. Это предотвращает случайное создание объектов и трудноуловимые ошибки, когда компилятор "любезно" преобразует аргумент одного типа в другой, хотя программист этого не подразумевал.

---

## Неявное приведение типов

Неявное приведение происходит, когда компилятор автоматически преобразует значение одного типа в другой, если это необходимо для выполнения операции или вызова функции. В контексте пользовательских типов это часто связано с **преобразующими конструкторами** (converting constructors) — конструкторами, которые можно вызвать с одним аргументом.

### Пример проблемы

Рассмотрим класс `MyString`, конструктор которого принимает `int` (размер строки):

```cpp
class MyString {
public:
    MyString(int size);  // создаёт строку заданного размера
    // ...
};

void print(const MyString& s);

print(3);  // Компилятор неявно вызовет MyString(3)
```

Если программист хотел вывести строку `"3"`, но случайно передал целое число `3`, компилятор молча создаст пустую строку длиной 3 символа вместо строки `"3"`. Это классический пример ошибки, которую предотвращает `explicit` .

Другой известный пример — **проблема безопасного bool** (Safe Bool Problem): класс с оператором преобразования в `bool` может неявно использоваться в целочисленных контекстах, где это не задумано, из-за дополнительных стандартных преобразований .

### Правила неявного преобразования

Компилятор может применить **одно** пользовательское неявное преобразование для каждого аргумента функции. Если существует конструктор, вызываемый с одним аргументом (или с несколькими, но все кроме первого имеют значения по умолчанию), он может быть использован для неявного преобразования .

---

## Явное приведение типов

Явное приведение выполняется, когда программист прямо указывает необходимость преобразования. В C++ есть несколько форм:

| Форма | Пример | Примечание |
|---|---|---|
| C-style cast | `(Money)9.99` | Может выполнять комбинацию `static_cast`, `const_cast`, `reinterpret_cast` |
| Функциональная нотация | `Money(9.99)` | Вызывает конструктор |
| `static_cast` | `static_cast<Money>(9.99)` | Предпочтительный способ для связанных типов |
| Прямая инициализация | `Money m(9.99);` | Вызывает конструктор напрямую |

Если конструктор объявлен как `explicit`, он **может** использоваться для явного приведения и прямой инициализации, но **не может** — для неявного преобразования или копирующей инициализации .

---

## Зачем делать конструктор `explicit`?

### 1. Предотвращение случайных неявных преобразований

Ключевое слово `explicit` сообщает компилятору, что данный конструктор нельзя использовать для неявных преобразований. Это заставляет программиста явно указывать намерение:

```cpp
class Money {
public:
    explicit Money(double amount);
};

void display_balance(Money m);

// display_balance(49.95);      // ОШИБКА: неявное преобразование запрещено
display_balance(Money(49.95));  // OK: явное создание объекта
display_balance(static_cast<Money>(49.95)); // OK
```

Без `explicit` вызов `display_balance(49.95)` скомпилировался бы, создав временный объект `Money` из `double` .

### 2. Защита от логических ошибок

Как показано в примере с `MyString(int)`, неявное преобразование может скрыть ошибку программиста. `explicit` делает код безопаснее, требуя явного подтверждения намерения .

### 3. Улучшение читаемости и самодокументируемости кода

Когда конструктор помечен `explicit`, читающий код сразу понимает, что создание объекта из другого типа должно быть осознанным действием, а не случайным побочным эффектом.

### 4. Рекомендация по умолчанию

Согласно рекомендациям Microsoft и сообщества C++, **все преобразующие конструкторы следует делать `explicit`, кроме случаев, когда вы абсолютно уверены, что неявное преобразование желательно и безопасно** . Инструменты статического анализа (например, `clang-tidy` с проверкой `google-explicit-constructor`) также рекомендуют помечать `explicit` конструкторы, вызываемые с одним аргументом, и операторы преобразования .

## Что меняется с `explicit` (сводка)

| Контекст | Без `explicit` | С `explicit` |
|---|---|---|
| Копирующая инициализация `Money m = 9.99;` | ✅ Разрешено | ❌ Ошибка |
| Передача аргумента `f(9.99)` | ✅ Разрешено (неявно) | ❌ Ошибка |
| Прямая инициализация `Money m(9.99);` | ✅ Разрешено | ✅ Разрешено |
| Явное приведение `static_cast<Money>(9.99)` | ✅ Разрешено | ✅ Разрешено |
| Возврат из функции `return 9.99;` | ✅ Разрешено | ❌ Ошибка |

> **Примечание:** Начиная с C++11, `explicit` можно применять также к операторам преобразования (`explicit operator bool()`), а с C++20 — использовать условный `explicit` с константным выражением .
