# 120. Что такое exception safety guarantee? Какую exception safety guarantee имеют STL-контейнеры?

## Что такое exception safety guarantee

**Exception safety guarantee** (гарантия безопасности исключений) — это формальный контракт между функцией/операцией и её вызывающим кодом, описывающий, в каком состоянии останется программа, если во время выполнения операции будет выброшено исключение.

В C++ принято выделять четыре уровня гарантий (строгие надмножества друг друга):

1. **Nothrow (noexcept) guarantee** — функция гарантированно не выбрасывает исключений. Ожидается от деструкторов, `swap`, move-конструкторов и других операций, используемых при разворачивании стека.

2. **Strong guarantee** — если функция выбрасывает исключение, состояние программы **откатывается** к состоянию непосредственно перед вызовом. Операция либо завершается успешно, либо не имеет эффекта (commit-or-rollback). Пример: `std::vector::push_back`.

3. **Basic guarantee** — если функция выбрасывает исключение, программа остаётся в **валидном состоянии**: не происходит утечек ресурсов, все инварианты объектов сохранены. Однако конкретное состояние (например, содержимое контейнера) может измениться непредсказуемым для вызывающего кода образом.

4. **No guarantee** — при исключении программа может оказаться в невалидном состоянии: утечки ресурсов, повреждение памяти, нарушение инвариантов.

Дополнительно для шаблонных компонентов выделяют **exception-neutral guarantee**: исключение, выброшенное из шаблонного параметра (например, компаратора в `std::sort`), транслируется наружу без изменений.

## Гарантии STL-контейнеров

STL-контейнеры предоставляют **basic guarantee для всех операций** при условии, что пользовательские операции (конструкторы копирования, присваивание, деструкторы элементов) сами корректны: не оставляют элементы в невалидном состоянии, не допускают утечек, деструкторы не выбрасывают исключений.

Поверх базовой гарантии многие операции дают **strong guarantee** или **nothrow**. Ключевые положения стандарта (сводная таблица из Страуструпа):

| Операция | vector | deque | list | map |
|---|---|---|---|---|
| `push_back()` | **strong** | **strong** | **strong** | — |
| `push_front()` | — | **strong** | **strong** | — |
| `insert()` одного элемента | **strong** | **strong** | **strong** | **strong** |
| `insert()` N элементов | **strong** | **strong** | **strong** | **basic** |
| `erase()` | nothrow | nothrow | nothrow | nothrow |
| `pop_back()` / `pop_front()` | nothrow | nothrow | nothrow | — |
| `clear()` | nothrow | nothrow | nothrow | nothrow |
| `swap()` | nothrow | nothrow | nothrow | nothrow |

Важные уточнения:

- **Strong guarantee для `push_back`/`insert`** действует при условии, что исключение не выброшено конструктором копирования или оператором присваивания **самого элемента** (`T`). Если `T::T(const T&)` или `T::operator=` выбрасывает исключение, контейнер может дать лишь basic guarantee.
- **`erase`, `pop_back`, `pop_front`** не выбрасывают исключений (при корректном деструкторе элемента), поскольку не выполняют копирования/присваивания.
- **`swap`** для всех стандартных контейнеров не выбрасывает исключений (кроме случая, когда исключение выбрасывает операция копирования/присваивания компаратора у ассоциативных контейнеров).
- **`list::sort`, `list::merge`, `list::remove`, `list::unique`** не выбрасывают исключений, если не выбрасывает предикат/компаратор.

## Практический смысл

При написании кода, переживающего исключения и продолжающего работу, следует полагаться на операции, дающие **strong guarantee**: после неудачного `push_back` вектор останется прежним, и его можно использовать дальше. Для операций с **basic guarantee** (например, `map::insert` диапазона) контейнер останется валидным, но его содержимое может быть частично изменено — вызывающий код должен быть к этому готов.
