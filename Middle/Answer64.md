# 64. Что будет, если не поймать exception?

Если исключение (exception) в C++ выброшено (`throw`), но нигде не поймано (`catch`), происходит вызов **`std::terminate`**, который по умолчанию вызывает **`std::abort`** — программа аварийно завершается. Никакого «продолжения выполнения» после этого не будет: стек не разматывается дальше точки `main`, деструкторы локальных объектов автоматически **не вызываются** (точнее, размотка стека до `main` происходит, но после выхода из `main` вызывается `terminate`).

Разберём по пунктам.

## 1. Базовый сценарий

```cpp
#include <iostream>

void foo() {
    throw std::runtime_error("boom");
}

int main() {
    foo();          // исключение никем не ловится
    std::cout << "unreachable\n";
}
```

Результат: программа печатает что-то вроде

```
terminate called after throwing an instance of 'std::runtime_error'
  what():  boom
```

и завершается с ненулевым кодом (обычно `SIGABRT`, код 134 на Linux/macOS).

## 2. Что именно происходит по стандарту

- Если исключение выходит за пределы `main` (или за пределы функции `noexcept`, или за пределы потока, или при разрушении стека во время уже активного исключения выбрасывается второе — `std::terminate` вызывается и в этих случаях), вызывается **`std::terminate`**.
- `std::terminate` — это функция, поведение которой можно **переопределить** через `std::set_terminate`. По умолчанию она вызывает `std::abort`.
- `std::abort` не выполняет обычную очистку: деструкторы объектов с автоматическим сроком хранения на *уже размотанных* участках стека вызываются (размотка идёт до `main`), но после `abort` — никакой дальнейшей деструкции статических/глобальных объектов не гарантируется, `atexit`-хендлеры не вызываются, буферы `stdout` могут не сброситься.

## 3. Важные нюансы

### 3.1. Размотка стека до `terminate`

Пока исключение «летит» вверх по стеку в поисках обработчика, **деструкторы локальных объектов на каждом пройденном кадре вызываются** (stack unwinding). Это справедливо и для пути до `main`. То есть RAII-объекты (например, `std::unique_ptr`, `std::lock_guard`) корректно освободят ресурсы на всём пути размотки. Не вызываются только деструкторы после вызова `abort`.

### 3.2. `noexcept`-функции

Если исключение выходит за пределы функции, помеченной `noexcept` (явно или неявно — например, деструкторы по умолчанию `noexcept(true)`), это сразу приводит к `std::terminate`, **без** поиска обработчика выше:

```cpp
void f() noexcept {
    throw std::runtime_error("x"); // -> std::terminate
}
```

### 3.3. Исключение в деструкторе во время размотки

Если во время раскрутки стека из-за уже активного исключения деструктор выбросит своё — срабатывает `std::terminate` (двойное исключение).

### 3.4. Потоки

Необработанное исключение, покинувшее потоковую функцию (`std::thread`), также приводит к `std::terminate` всего процесса, а не только этого потока.

### 3.5. Переопределение `std::terminate`

```cpp
#include <exception>
#include <cstdio>

int main() {
    std::set_terminate([]{
        std::fprintf(stderr, "Unhandled exception!\n");
        std::abort(); // всё равно нужно завершить процесс
    });
    throw std::runtime_error("boom");
}
```

Полезно для логирования, но **продолжить нормальное выполнение после `terminate` нельзя** — стандарт требует, чтобы обработчик `terminate` завершил программу (возврат из него — UB, на практике снова `abort`).

## 4. Чего НЕ произойдёт

- Не будет «молчаливого игнорирования» — программа не продолжит работу.
- Не будет автоматического вывода `what()` в стандартном виде (это делает реализация `terminate` в libstdc++/libc++ при непойманном исключении, но это не гарантия стандарта).
- Не будет корректного вызова `atexit`-функций и разрушения глобальных объектов — `abort` этого не делает.

## 5. Практические выводы

1. **Ловите исключения** там, где можете осмысленно обработать ошибку (обычно на границах: `main`, обработчики событий, границы потоков, API-функции).
2. **`catch (...)`** в `main` или на границе потока — разумная страховка, чтобы залогировать и корректно завершиться, а не падать с `abort`.
3. Помните про **`noexcept`**: любое исключение из такой функции — немедленный `terminate`.
4. Не выбрасывайте исключения из **деструкторов** (особенно во время размотки).
5. Для диагностики настройте `std::set_terminate` (логирование, backtrace) — но завершать процесс всё равно придётся.

## 6. Краткая сводка

| Ситуация | Результат |
|---|---|
| Исключение не поймано до `main` | `std::terminate` → `std::abort`, аварийное завершение |
| Исключение выходит из `noexcept`-функции | `std::terminate` |
| Второе исключение во время размотки | `std::terminate` |
| Исключение покидает поток | `std::terminate` (всего процесса) |
| Деструкторы на пути до `main` | вызываются (stack unwinding) |
| `atexit`/глобальные деструкторы | не гарантируются |

Итог: **непойманное исключение = аварийное завершение программы через `std::terminate`/`std::abort`**, при этом стек разматывается до `main` и RAII-деструкторы на этом пути отрабатывают, но дальше процесс просто умирает.
