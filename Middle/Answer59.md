# 59. Что такое функтор? Напишите пример.

## Определение

**Функтор** (functor) в C++ — это объект класса или структуры, который можно вызывать как функцию. Это достигается за счёт перегрузки оператора вызова функции `operator()`.

Функтор — это частный случай более общего понятия «callable object» (объект, который можно вызвать). Помимо функторов, вызываемыми объектами являются обычные функции, указатели на функции, лямбда-выражения и `std::function`.

Ключевая идея: класс инкапсулирует состояние (поля-данные), а `operator()` позволяет использовать экземпляр этого класса в синтаксисе, неотличимом от вызова функции.

## Зачем нужны функторы

1. **Сохранение состояния** — функтор может хранить данные между вызовами (в отличие от обычной функции без статических переменных).
2. **Параметризация поведения** — передача функтора в алгоритмы STL (`std::sort`, `std::transform`, `std::accumulate` и т.д.) позволяет настраивать их логику.
3. **Производительность** — вызов `operator()` у функтора обычно инлайнится компилятором, тогда как вызов через указатель на функцию — нет (в общем случае). Поэтому функторы часто быстрее указателей на функции.
4. **Гибкость** — функтор может иметь несколько перегрузок `operator()`, быть шаблонным, хранить произвольное состояние.

## Простой пример

```cpp
#include <iostream>

class Multiplier {
public:
    explicit Multiplier(int factor) : factor_(factor) {}

    // Перегрузка оператора вызова функции
    int operator()(int x) const {
        return x * factor_;
    }

private:
    int factor_;
};

int main() {
    Multiplier timesTwo(2);
    Multiplier timesTen(10);

    std::cout << timesTwo(5)  << '\n'; // 10
    std::cout << timesTen(5)  << '\n'; // 50

    // Один и тот же класс — разное поведение за счёт состояния
    return 0;
}
```

Здесь `timesTwo` и `timesTen` — два функтора одного типа, но с разным состоянием (`factor_`), поэтому они ведут себя по-разному.

## Пример использования в STL

Функторы традиционно применяются в алгоритмах стандартной библиотеки:

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

struct Greater {
    bool operator()(int a, int b) const {
        return a > b;
    }
};

int main() {
    std::vector<int> v{3, 1, 4, 1, 5, 9, 2, 6};

    // Функтор Greater задаёт порядок сортировки по убыванию
    std::sort(v.begin(), v.end(), Greater{});

    for (int x : v) std::cout << x << ' '; // 9 6 5 4 3 2 1 1
    std::cout << '\n';
}
```

## Функтор с состоянием, изменяющимся между вызовами

```cpp
#include <iostream>

class Counter {
public:
    int operator()() {
        return ++count_;
    }
private:
    int count_ = 0;
};

int main() {
    Counter c;
    std::cout << c() << c() << c() << '\n'; // 123
    return 0;
}
```

Такой функтор хранит внутреннее состояние, которое меняется при каждом вызове. Если бы это была обычная функция, пришлось бы использовать статическую переменную, что менее безопасно и не позволяет иметь несколько независимых счётчиков.

## Шаблонный функтор

```cpp
struct Plus {
    template <typename T>
    T operator()(const T& a, const T& b) const {
        return a + b;
    }
};

// ...
Plus plus;
std::cout << plus(2, 3) << '\n';       // 5 (int)
std::cout << plus(1.5, 2.5) << '\n';   // 4 (double)
```

## Функторы vs лямбды

Начиная с C++11 лямбда-выражения практически вытеснили функторы во многих сценариях — синтаксис короче, а компилятор сам генерирует класс с `operator()`. По сути **лямбда — это синтаксический сахар для функтора**: компилятор создаёт безымянный класс с перегруженным `operator()`.

Однако функторы всё ещё уместны, когда:

- нужно переиспользуемое именованное поведение;
- требуется несколько перегрузок `operator()`;
- нужен шаблонный `operator()` (у лямбд в C++11–C++17 это невозможно, только в C++20 с `template`-параметрами);
- функтор должен иметь явные конструкторы или наследование.

## Итог

Функтор — это объект, для которого перегружен `operator()`, что позволяет вызывать его синтаксически как функцию. За счёт инкапсуляции состояния и возможности инлайнинга функторы являются мощным инструментом параметризации поведения, особенно в алгоритмах STL, и концептуальной основой лямбда-выражений.
