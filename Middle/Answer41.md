# 41. Чем отличается конструктор копирования от оператора присваивания?

Оба механизма служат для копирования состояния одного объекта в другой, но различаются **моментом вызова**, **назначением**, **синтаксисом** и **требованиями к уже существующему объекту**.

## 1. Момент и условие вызова

**Конструктор копирования** вызывается при **создании нового объекта** на основе уже существующего:

```cpp
class A { /* ... */ };

A a1;
A a2 = a1;      // конструктор копирования (инициализация)
A a3(a1);       // конструктор копирования (прямая инициализация)
A a4 = A(a1);   // конструктор копирования
void f(A x);    // копия при передаче по значению
A f2() { A tmp; return tmp; } // копия при возврате (если не NRVO)
```

**Оператор присваивания** вызывается, когда **оба объекта уже существуют**, и левому нужно присвоить состояние правого:

```cpp
A a1, a2;
a2 = a1;        // оператор копирующего присваивания
```

Ключевое отличие: конструктор копирования **создаёт объект с нуля** (объект ещё не инициализирован), а оператор присваивания **изменяет уже существующий объект** (у него уже есть ресурсы, которые надо корректно освободить).

## 2. Синтаксис объявления

Конструктор копирования — это конструктор, принимающий ссылку на тот же тип:

```cpp
class A {
public:
    A(const A& other);            // конструктор копирования
    A& operator=(const A& other); // оператор копирующего присваивания
};
```

- Конструктор копирования **не имеет возвращаемого типа** и называется так же, как класс.
- Оператор присваивания **возвращает ссылку** на `*this` (обычно `A&`), что позволяет цепочки `a = b = c`.

## 3. Возвращаемое значение и цепочки

Оператор присваивания возвращает `*this`, поэтому работает `a = b = c`. Конструктор копирования ничего не возвращает — это конструктор.

## 4. Работа с уже существующим состоянием (главное практическое отличие)

В операторе присваивания объект `*this` уже содержит какие-то ресурсы (выделенную память, открытые файлы и т.п.). Их нужно **освободить перед копированием** (или использовать идиому copy-and-swap). В конструкторе копирования освобождать нечего — объект только создаётся.

```cpp
class Buffer {
    int* data;
    size_t size;
public:
    Buffer(const Buffer& other)                 // объект создаётся с нуля
        : size(other.size), data(new int[other.size]) {
        std::copy(other.data, other.data + size, data);
    }

    Buffer& operator=(const Buffer& other) {    // объект уже существует
        if (this != &other) {                   // защита от самоприсваивания
            int* newData = new int[other.size]; // сначала выделяем новое
            std::copy(other.data, other.data + other.size, newData);
            delete[] data;                      // затем освобождаем старое
            data = newData;
            size = other.size;
        }
        return *this;
    }
};
```

Обратите внимание на **проверку на самоприсваивание** (`this != &other`) — она нужна именно в операторе присваивания; в конструкторе копирования такой ситуации быть не может.

## 5. Проброс исключений и безопасность

- Конструктор копирования: если копирование бросает исключение, объект просто не создаётся (деструктор не вызывается) — это нормально.
- Оператор присваивания: если исключение брошено на середине, объект остаётся в **изменённом/некорректном состоянии**, поэтому нужна аккуратность (copy-and-swap даёт строгую гарантию безопасности исключений).

## 6. Неявное объявление компилятором

Оба генерируются компилятором автоматически (поверхностное копирование), но правила немного разные:

| | Конструктор копирования | Оператор присваивания |
|---|---|---|
| Генерируется неявно | да | да |
| Подавляется объявлением | любого конструктора копирования/перемещения, деструктора (частично) | объявлением копирующего/перемещающего присваивания, деструктора (частично) |
| `= default` / `= delete` | применимо | применимо |

В современном C++ (правило пяти) при явном объявлении одного из членов «большой пятёрки» (деструктор, копирующий/перемещающий конструктор, копирующее/перемещающее присваивание) остальные неявные объявления могут подавляться или считаться устаревшими (deprecated).

## 7. Сводная таблица

| Критерий | Конструктор копирования | Оператор присваивания |
|---|---|---|
| Когда вызывается | при создании нового объекта | при присваивании существующему |
| Объект `*this` | ещё не инициализирован | уже существует, имеет ресурсы |
| Возвращает | ничего | `*this` (ссылку) |
| Нужна проверка на самоприсваивание | нет | да (обычно) |
| Нужно освобождать старые ресурсы | нет | да |
| Синтаксис | `A(const A&)` | `A& operator=(const A&)` |
| Влияние исключений | объект не создаётся | объект может остаться частично изменённым |

## 8. Важное следствие

Если класс управляет ресурсом (владеет указателем, файлом, сокетом и т.п.), то **по умолчанию** ни конструктор копирования, ни оператор присваивания не дадут корректного поведения — оба выполнят поверхностное копирование и приведут к двойному освобождению ресурса. Поэтому для таких классов нужно либо реализовать оба (правило трёх/пяти), либо запретить их (`= delete`), либо использовать RAII-обёртки (`std::unique_ptr`, `std::vector` и т.п.), которые уже реализуют нужную семантику.
