# 34. Что такое делегирующий конструктор?

**Делегирующий конструктор** — это конструктор класса в C++, который в своём списке инициализации вызывает другой конструктор того же класса для выполнения инициализации объекта. Такая возможность появилась в стандарте C++11 и предназначена для устранения дублирования кода между перегруженными конструкторами .

### Синтаксис и принцип работы

Делегирующий конструктор использует имя класса в списке инициализации так же, как если бы это был базовый класс:

```cpp
class Foo {
public:
    Foo(char x, int y) { /* основная инициализация */ }
    Foo(int y) : Foo('a', y) { /* дополнительная логика (если нужна) */ }
};
```

В этом примере `Foo(int y)` является делегирующим, а `Foo(char, int)` — целевым конструктором .

Ключевое правило: **список инициализации делегирующего конструктора должен состоять только из вызова целевого конструктора**. После того как целевой конструктор полностью завершит инициализацию объекта, управление возвращается в тело делегирующего конструктора, где можно выполнить дополнительную логику .

### Зачем это нужно

Делегирование решает проблему дублирования кода. Если у класса есть несколько конструкторов, выполняющих схожую работу (например, валидацию параметров), можно вынести общую логику в один «главный» конструктор, а остальные сделать «тонкими» обёртками, которые лишь подготавливают аргументы и вызывают главный .

### Важные ограничения

1. **Только один вызов в списке инициализации.** В делегирующем конструкторе нельзя одновременно вызвать другой конструктор и инициализировать поля напрямую. Код вида `Foo(int a, int b) : Foo(a), m_b(b) {}` вызовет ошибку компиляции .
2. **Инициализация полей выполняется целевым конструктором.** Все нестатические поля инициализируются именно в том конструкторе, который вызывается первым (в целевом). Делегирующий конструктор не может переопределить эту инициализацию .
3. **Рекурсия не запрещена синтаксически, но опасна.** Компилятор не обнаружит циклическую делегацию (конструктор A вызывает B, а B вызывает A) — программа завершится переполнением стека во время выполнения. Ответственность за отсутствие циклов лежит на программисте .
