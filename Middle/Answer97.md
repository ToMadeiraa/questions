# 96. Какие есть правила вывода типа в шаблоне?

В контексте метапрограммирования (в частности, C++) под «выводом типа в шаблоне» обычно понимают два взаимосвязанных, но различных механизма: **вывод аргументов шаблона функции** (шаблонный аргумент дедуцируется из типов фактических аргументов вызова) и **вывод аргументов шаблона класса** (CTAD, начиная с C++17, когда компилятор выводит параметры шаблона класса из инициализатора). Правила первого механизма строго формализованы и рекурсивны; второй механизм во многом опирается на первый, но добавляет «guide» (направляющие вывода). Ниже приведены ключевые правила и ограничения.

## 1. Вывод аргументов шаблона функции: сопоставление P и A

Вывод выполняется путём сопоставления **типа параметра функции** (обозначается `P`) с **типом фактического аргумента** (обозначается `A`). Если `P` содержит параметры шаблона, компилятор пытается найти такие значения параметров, при которых `P` становится эквивалентным `A` (с учётом разрешённых преобразований) .

Поддерживаемые «дедуцируемые» формы `P` включают (неполный список):

- `T` (с опциональными cv-квалификаторами);
- `T*`;
- `T&` (включая константные ссылки);
- `T&&` (включая forwarding reference);
- `T[]` или `T[N]` (массивы);
- `T(Args...)` (функциональные типы);
- `TT<T>` (параметр шаблона-шаблона);
- `T::*` (указатель на член) и другие рекурсивно вложенные формы .

Ключевая идея: вывод применяется **рекурсивно** к компонентам типа. Например, для `P = std::vector<T>` и `A = std::vector<int>` выводится `T = int`.

## 2. Контексты, в которых вывод не выполняется (Non-deduced contexts)

Если параметр шаблона появляется в `P` в форме, которая не участвует в сопоставлении, он не может быть выведен из соответствующего `A`. Типичные примеры:

- **Вложенные зависимые имена**: `typename A<T>::B` — `T` здесь не выводится из `A<T>::B`, хотя `T` в `A<T>` выводится .
- **Выражения в `decltype`**: `decltype(*std::declval<T>())` — `T` не выводится из такого типа .
- **Константные аргументы шаблона или границы массива, зависящие от параметра**: `std::array<int, 2 * N>` — `N` не выводится из `std::array<int, 10>`, потому что выражение `2 * N` не является простым сопоставлением .
- **Пакеты параметров не в конце списка**: если пакет параметров (`Ts...`) стоит не последним, его вывод из соответствующих аргументов может быть невозможен .
- **`nullptr`**: `T` не выводится из `nullptr` при параметре `T*`, так как `nullptr` имеет тип `std::nullptr_t`, а не указатель на неизвестный тип .

## 3. Специальные правила для ссылок и cv-квалификаторов

- **`T&`**: для вывода `T` из `A` тип `A` не должен быть rvalue; иначе привязка невозможна. `T` выводится как тип объекта, на который ссылаются, без ссылочности.
- **`const T&`**: может привязываться к rvalue; `T` выводится без верхнеуровневого `const`.
- **`T&&` (forwarding reference)**: если `A` — lvalue, `T` выводится как `U&` (сворачивание ссылок); если `A` — rvalue, `T` выводится как `U`. Это основа идеальной передачи (perfect forwarding) .
- **Массивы и функции**: при передаче по значению (`T`) массив «затухает» до указателя, функция — до указателя на функцию. При передаче по ссылке (`T&`) сохраняется исходный тип массива/функции .

## 4. Вывод для параметров шаблона-шаблона (template template parameters)

Для `P = TT<T>` и `A = SomeTemplate<int>` выводится `TT = SomeTemplate`, `T = int`. При этом `TT` может быть шаблоном класса или псевдонимом шаблона, а `T` — списком параметров. Вывод также работает для форм `TT<>` и `TT<I>` (с нетиповыми параметрами) .

## 5. Вывод аргументов шаблона класса (CTAD, C++17+)

При объявлении переменной с именем шаблона класса без явного списка аргументов (например, `std::pair p(1, 2.0);`) компилятор формирует **неявные deduction guides** из конструкторов класса, а также может использовать **явно заданные пользователем guides** .

Правила:

- Для каждого конструктора `Ci` шаблона класса `C` создаётся фиктивный шаблон функции `Fi`, параметры которого — параметры шаблона `C` (и, если `Ci` — шаблон конструктора, его параметры), параметры функции — параметры конструктора, возвращаемый тип — `C<...>`.
- Затем выполняется вывод аргументов шаблона функции для `Fi` с аргументами инициализатора и разрешение перегрузки. Если выбирается `Fi`, его возвращаемый тип определяет специализацию `C` .
- **Пользовательские deduction guides** имеют вид `C(Args...) -> C<...>;`. Они не являются функциями, не имеют тела и не находятся обычным поиском имён; они участвуют только в разрешении перегрузки при выводе аргументов класса .
- CTAD не выполняется, если список аргументов шаблона указан явно (даже частично) .

Пример: для `std::vector v(first, last)` (итераторы) неявный guide из конструктора `vector(InputIt, InputIt)` не может вывести `T` напрямую, поэтому стандартная библиотека предоставляет явный guide, извлекающий `value_type` итератора .

## 6. Взаимодействие с `auto` и возвращаемым типом

Правила вывода аргументов шаблона функции также используются при выводе `auto` для переменных (из инициализатора) и для возвращаемого типа функций с `auto` (из выражений `return`). В последнем случае каждое выражение `return` даёт `A`, а `auto` заменяется на фиктивный параметр `U`; все выведенные `U` должны совпасть .

## Резюме

| Аспект | Ключевое правило |
|---|---|
| Основа | Сопоставление `P` (тип параметра) с `A` (тип аргумента), рекурсивно |
| Ссылки | `T&` не принимает rvalue; `T&&` учитывает категорию значения |
| Non-deduced | `typename A<T>::B`, `decltype(...)`, выражения с `N` в границах, пакеты не в конце |
| CTAD | Неявные guides из конструкторов + пользовательские guides; выбирается лучший `Fi` |
| Ограничения | `nullptr` не выводит `T*`; `{...}` без типа не выводит `T` |

Понимание этих правил критично для метапрограммирования, поскольку позволяет предсказуемо проектировать шаблонные интерфейсы и использовать SFINAE/концепты для отсечения некорректных выводов.
