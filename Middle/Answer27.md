# 27. Для чего нужен extern "C"?

`extern "C"` в C++ используется для указания **языковой связи (language linkage)**. Его основная цель — обеспечить возможность связывания (linking) функций и переменных, написанных на C++, с кодом, написанным на C (или на других языках, поддерживающих C ABI), и наоборот.

### Основные причины использования

1.  **Отключение искажения имён (Name Mangling)**
    Компиляторы C++ искажают (mangle) имена функций, чтобы поддерживать перегрузку функций (overloading) и пространства имён. В результате функция `void foo(int)` в C++ может получить внутреннее имя вроде `_Z3fooi`. Компиляторы C такого не делают. Если вы попытаетесь слинковать C++ код, который вызывает функцию из C-библиотеки, компоновщик не найдёт символ, потому что имена не совпадут. `extern "C"` заставляет компилятор C++ использовать правила именования C (без искажения), что позволяет компоновщику правильно сопоставить символы .

2.  **Обеспечение совместимости соглашений о вызовах (Calling Convention)**
    Хотя стандарт C++ не гарантирует, что соглашение о вызовах C++ совпадает с соглашением о вызовах C, на большинстве платформ `extern "C"` также указывает компилятору использовать соглашение о вызовах, совместимое с C (например, порядок передачи аргументов, очистка стека). Это критически важно для корректного вызова функций между модулями, скомпилированными разными компиляторами .

### Типичные сценарии применения

#### 1. Подключение C-заголовков в C++ коде
Когда вы включаете стандартный C-заголовок (например, `<stdio.h>`) в программу на C++, вы обычно оборачиваете его в `extern "C"`, чтобы компилятор C++ не искажал имена функций, таких как `printf`:
```cpp
extern "C" {
#include <stdio.h>
}
```
Без этого компоновщик будет искать искажённое имя для `printf` и не найдёт его в стандартной библиотеке C .

#### 2. Предоставление C-интерфейса для C++ кода
Если вы пишете библиотеку на C++ и хотите, чтобы её могли вызывать программы на C, вы должны объявить экспортируемые функции с `extern "C"`. Это гарантирует, что имена функций в объектном файле останутся простыми (например, `my_function`), и C-программа сможет их найти:
```cpp
// math_lib.cpp
extern "C" int add(int a, int b) {
    return a + b;
}
```
Теперь C-код может объявить `int add(int, int);` и успешно слинковаться с этой библиотекой .

#### 3. Работа с функциями обратного вызова (Callbacks)
Если C-библиотека ожидает указатель на функцию, которая будет вызвана из C-кода, эта функция (даже если она определена в C++ файле) должна иметь связь `"C"`. Иначе C-код не сможет корректно вызвать её по указателю, так как не знает о C++ искажении имён и соглашениях о вызовах.

### Важные нюансы

*   **Влияние на типы**: `extern "C"` влияет не только на имя функции, но и на её тип. Указатели на функции с C-связью имеют другой тип, чем указатели на функции с C++-связью.
*   **Ограничения**: Внутри блока `extern "C"` нельзя перегружать функции (так как C не поддерживает перегрузку). Однако вы можете использовать любые возможности C++ внутри тела функции (шаблоны, классы, исключения), если только сигнатура функции (параметры и возвращаемое значение) совместима с C .
*   **Стандартные заголовки**: Большинство современных стандартных заголовков C (например, `<cstdio>`) уже содержат необходимые проверки `#ifdef __cplusplus` и `extern "C"`, поэтому их можно включать напрямую без обёртки.
