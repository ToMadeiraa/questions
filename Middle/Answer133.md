# 133. Чем отличается мьютекс от семафора?

## Краткое определение

- **Мьютекс (mutex)** — примитив синхронизации, обеспечивающий **взаимное исключение**: в критической секции в любой момент времени может находиться только **один** поток. Мьютекс имеет понятие «владельца» (owner) — поток, который его захватил, обязан его освободить.
- **Семафор (semaphore)** — счётчик, который ограничивает доступ к ресурсу **N потоками одновременно** (counting semaphore) либо работает как сигнальный флаг (binary semaphore). Владельца у семафора нет — любой поток может выполнить `release()`/`post()`.

## Ключевые различия

| Критерий | Мьютекс | Семафор |
|---|---|---|
| Назначение | Взаимное исключение (1 поток) | Ограничение доступа к пулу ресурсов (N потоков) / сигнализация |
| Внутреннее состояние | Захвачен / свободен (+ owner) | Целочисленный счётчик ≥ 0 |
| Понятие владельца | Есть: разблокировать может только захвативший поток (в `std::mutex`) | Нет: `release()` может вызвать любой поток |
| Кто освобождает | Только поток-владелец | Любой поток (в т.ч. не захватывавший) |
| Реентерабельность | `std::mutex` — нет (нужен `std::recursive_mutex`) | Не применимо в том же смысле |
| Максимум одновременных «держателей» | 1 | N (задаётся при инициализации) |
| Работа из обработчика сигнала / ISR | Обычно нельзя | Часто можно (например, `sem_post` в POSIX) |
| Типичное применение | Защита общих данных | Пул соединений/буферов, producer-consumer, ограничение параллелизма |

## Детали

### 1. Владелец и правило освобождения
`std::mutex` в C++ привязан к потоку: `unlock()` должен вызывать тот же поток, что вызывал `lock()`, иначе — UB. Это позволяет реализациям использовать оптимизации (futex, priority inheritance). Семафор такой привязки не имеет: типичный сценарий — поток A ждёт (`acquire`), поток B сигнализирует (`release`), что делает его удобным для событийной синхронизации.

### 2. Счётчик против флага
Семафор с начальным значением `N` пускает `N` потоков; каждый `acquire()` уменьшает счётчик, `release()` — увеличивает. Мьютекс — это, по сути, семафор со значением 1 **плюс** семантика владельца. Поэтому бинарный семафор **не эквивалентен** мьютексу: у него нет owner, и он не защищает от «чужого» release.

### 3. Что есть в стандарте C++

- **Мьютексы**: `std::mutex`, `std::recursive_mutex`, `std::timed_mutex`, `std::recursive_timed_mutex`, `std::shared_mutex` (C++17). Плюс RAII-обёртки: `std::lock_guard`, `std::unique_lock`, `std::scoped_lock` (C++17), `std::shared_lock`.
- **Семафоры**: появились только в **C++20** — `std::counting_semaphore<N>` и `std::binary_semaphore` (алиас `counting_semaphore<1>`). До C++20 семафоры брали из POSIX (`sem_t`), WinAPI (`CreateSemaphore`) или Boost (`boost::interprocess::interprocess_semaphore`).

Пример на C++20:

```cpp
#include <semaphore>
#include <mutex>
#include <thread>
#include <vector>

std::counting_semaphore<3> pool_sem{3};   // не более 3 потоков одновременно
std::mutex cout_mutex;

void worker(int id) {
    pool_sem.acquire();                   // занимаем слот
    {
        std::lock_guard<std::mutex> lk(cout_mutex);
        // ... работа с ограниченным ресурсом ...
    }
    pool_sem.release();                   // освобождаем слот
}
```

### 4. Производительность и поведение
- Мьютекс обычно реализован поверх futex/atomic + очереди ожидания и оптимизирован под короткие критические секции; часто поддерживает priority inheritance (POSIX `PTHREAD_PRIO_INHERIT`).
- Семафор — более «тяжёлый» счётный примитив, зато естественно выражает ограничение параллелизма и сигналы между потоками.

### 5. Практическое правило выбора
- Нужно защитить **общие данные** → **мьютекс** (+ `lock_guard`/`scoped_lock`).
- Нужно ограничить **число одновременных исполнителей** или передать **сигнал** между потоками (producer → consumer) → **семафор** (или `std::condition_variable` + мьютекс, если нужна более гибкая логика ожидания).

## Итог одной фразой
Мьютекс — это «замок с хозяином» для взаимного исключения (ровно один держатель, освобождает владелец), а семафор — это «счётчик разрешений» на N держателей без владельца, годный и для ограничения параллелизма, и для межпотоковой сигнализации.
