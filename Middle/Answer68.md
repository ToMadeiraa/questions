# 68. Что такое vptr и vtable?

**vptr** (virtual pointer, указатель на виртуальную таблицу) и **vtable** (virtual table, виртуальная таблица) — это механизм, который большинство компиляторов C++ используют для реализации **динамического полиморфизма** (виртуальных функций). Важно понимать: стандарт C++ **не предписывает** конкретную реализацию, поэтому детали (порядок полей, расположение указателя в объекте) зависят от компилятора. Однако общая схема практически едина .

## vtable (Виртуальная таблица)

**vtable** — это статическая структура данных, создаваемая компилятором для **каждого класса**, который содержит или наследует виртуальные функции.

- **Что содержит:** Массив указателей на функции. Каждый элемент указывает на адрес реализации соответствующей виртуальной функции для данного конкретного класса .
- **Где хранится:** На уровне класса. Все объекты одного и того же класса используют **одну и ту же** vtable. Она не дублируется для каждого экземпляра .
- **Формирование:** Компилятор заполняет таблицу адресами функций. Если производный класс переопределяет виртуальную функцию, в его vtable записывается адрес новой функции. Если нет — остается адрес функции базового класса .

## vptr (Указатель на виртуальную таблицу)

**vptr** — это скрытое поле, которое компилятор добавляет **в каждый объект** класса, имеющего виртуальные функции.

- **Назначение:** Связывает конкретный объект с vtable его класса. Через vptr программа в runtime понимает, какую именно реализацию виртуальной функции вызвать для данного объекта .
- **Размер:** Обычно равен размеру указателя (например, 8 байт на 64-битной системе). Это увеличивает размер каждого объекта .
- **Инициализация:** vptr устанавливается в конструкторе объекта. Для классов с виртуальным наследованием может также использоваться `vbptr` (virtual base pointer), но это отдельная сущность для работы с виртуальными базовыми классами .

## Как это работает вместе (Механизм вызова)

Когда вы вызываете виртуальную функцию через указатель или ссылку на базовый класс:

1. Компилятор **не** вставляет прямой вызов функции.
2. Он генерирует код, который берет **vptr** из объекта.
3. По vptr находит **vtable**.
4. Берет из vtable указатель на функцию по известному смещению (индексу).
5. Вызывает эту функцию, передавая ей `this` .

Именно поэтому вызов виртуальной функции работает правильно: хотя у вас есть указатель типа `Base*`, объект в памяти может быть `Derived`, и его vptr будет указывать на vtable класса `Derived`, где лежат правильные адреса функций.

## Важные нюансы

- **Накладные расходы:** Каждый объект с виртуальными функциями несет в себе vptr (расход памяти). Каждый виртуальный вызов требует двух дополнительных разыменований (vptr -> vtable -> функция), что немного медленнее прямого вызова .
- **Расположение:** В Visual C++ vptr обычно находится в начале объекта, в то время как в GNU C++ (GCC/Clang) он может находиться в конце, после полей данных .
- **Множественное наследование:** Если класс наследует несколько базовых классов с виртуальными функциями, объект может содержать **несколько vptr** (по одному на каждую подобъектную часть с виртуальными функциями) .
