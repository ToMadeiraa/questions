# 28. Что будет, если в двух файлах сделать функцию с одинаковым именем и параметрами? На каком этапе возникнет ошибка?

Если в двух файлах исходного кода (`.cpp`) определить **не-inline** функцию с одинаковым именем и одинаковым списком параметров (то есть с одинаковой сигнатурой), это нарушает **правило одного определения (ODR, One Definition Rule)** C++. Компилятор обычно не обнаруживает эту проблему, потому что он обрабатывает каждый файл исходного кода отдельно; ошибка возникает на этапе **компоновки (linking)**.

### Почему компилятор не сообщает об ошибке?

C++ использует модель раздельной компиляции. Каждый `.cpp` файл (translation unit) компилируется независимо в объектный файл (`.obj` или `.o`). В каждом файле отдельно функция определена — синтаксически корректно, и компилятор не знает, что в другом файле есть функция с точно такой же сигнатурой. Поэтому **на этапе компиляции ошибки нет**.

### Что происходит на этапе компоновки?

Компоновщик (linker) собирает все объектные файлы в одну исполняемую программу и должен разрешить каждый символ (например, имя функции) в один адрес. Когда компоновщик обнаруживает, что одна и та же функция с внешним связыванием (external linkage) определена в нескольких объектных файлах, он не может решить, какую из них использовать, и сообщает об ошибке **множественного определения (multiple definition)** .

Сообщения об ошибках различаются в зависимости от платформы:

- **GCC / MinGW / Linux**: `multiple definition of 'function_name'`
- **MSVC (Visual Studio)**: `error LNK2005: ... already defined` и `fatal error LNK1169: one or more multiply defined symbols found` 

### Есть ли исключения?

Есть. Если функция помечена как **`inline`** (включая функции, определённые непосредственно внутри тела класса, которые неявно являются inline, а также шаблонные функции), то в разных единицах трансляции допускается несколько определений при условии, что все определения полностью идентичны (правило ODR для inline) . В этом случае компоновщик выбирает одно из них и ошибки не возникает.

### Как исправить?

Самый распространённый и правильный способ — **поместить только объявление функции в заголовочный файл (`.h`)**, а определение — в один `.cpp` файл. Другие `.cpp` файлы подключают заголовочный файл, и при компоновке находят единственное определение . Если действительно нужно определить функцию в заголовочном файле, необходимо добавить ключевое слово `inline`, чтобы избежать ошибки компоновки.
