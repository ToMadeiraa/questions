# 154. Какие библиотеки знаете для написания тестов?

В контексте SCM/CI/CD выбор библиотек для тестирования зависит от языка программирования, типа тестов (юнит, интеграционные, E2E) и требований к интеграции с пайплайном. Ниже приведён обзор основных инструментов по экосистемам.

### Python
- **unittest**: Встроенная библиотека, не требующая установки. Поддерживает организацию тестов через классы `TestCase`, фикстуры (`setUp`/`tearDown`) и обнаружение тестов .
- **pytest**: Де-факто стандарт для нового кода. Отличается лаконичным синтаксисом (обычные `assert`), мощной системой фикстур и встроенной параметризацией. Для моков часто используется плагин `pytest-mock` .

### Java
- **JUnit 5**: Основной фреймворк для юнит-тестов. Поддерживает параметризованные тесты, вложенные классы и аннотации вроде `@DisplayName` .
- **AssertJ**: Библиотека для «беглых» (fluent) утверждений, делающая проверки более читаемыми по сравнению со стандартными `assertEquals` .
- **Mockito**: Стандарт для создания мок-объектов и проверки взаимодействий .
- **Testcontainers**: Для интеграционных тестов, которым требуются реальные зависимости (БД, брокеры сообщений) в Docker-контейнерах .

### JavaScript / TypeScript
- **Jest**: Популярный фреймворк «из коробки» (assertions, моки, снапшоты). Часто используется в связке с **React Testing Library** для компонентного тестирования .
- **Vitest**: Современная альтернатива Jest с нативной поддержкой Vite и высокой скоростью выполнения .
- **Mocha + Chai**: Гибкая комбинация, где Mocha отвечает за запуск и структуру, а Chai — за утверждения (BDD/TDD стили) .
- **Playwright / Cypress**: Для E2E-тестирования в реальных браузерах. Playwright отличается кроссплатформенностью и поддержкой множества языков, Cypress — удобством для фронтенд-разработчиков .

### Go
- **testing**: Встроенный пакет для юнит-тестов. Поддерживает табличные тесты и бенчмарки .
- **Ginkgo + Gomega**: BDD-фреймворк и библиотека матчеров для написания выразительных тестов, часто используемые в крупных проектах .

### C# / .NET
- **xUnit**: Современный фреймворк, популярный в .NET Core/5+. Отличается простотой и изоляцией тестов .
- **NUnit**: Зрелый фреймворк с богатыми возможностями параметризации .
- **MSTest**: Официальный фреймворк от Microsoft, глубоко интегрированный в Visual Studio .
- **Moq / NSubstitute**: Библиотеки для мокирования зависимостей .

### Кроссплатформенные и специализированные
- **Selenium**: Классический инструмент для автоматизации браузеров (Web UI), поддерживающий множество языков .
- **Cucumber / SpecFlow**: Для BDD (Behavior-Driven Development), позволяют описывать тесты на естественном языке (Gherkin) .
- **JMeter / Gatling**: Для нагрузочного и performance-тестирования, легко встраиваются в CI-пайплайны .

Для CI/CD важно, чтобы выбранная библиотека поддерживала генерацию отчётов в машиночитаемом формате (JUnit XML, Allure) и могла запускаться в headless-режиме без графического интерфейса.
