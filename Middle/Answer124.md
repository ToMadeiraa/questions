# 124. Что такое многопоточность? Какую функциональность предоставляет С++ для разработки многопоточных приложений? Какие основные проблемы многопоточных приложений?

## Что такое многопоточность?

**Многопоточность** — это свойство программы выполнять несколько потоков исполнения одновременно в рамках одного процесса. Потоки разделяют общее адресное пространство (код, глобальные данные, кучу), но имеют собственные стек, регистры и счётчик команд. Это позволяет программе эффективно использовать многоядерные процессоры и параллельно выполнять независимые задачи, например, обработку пользовательского интерфейса и фоновые вычисления.

В контексте C++ многопоточность означает возможность создавать и управлять потоками средствами стандартной библиотеки, начиная с C++11.

## Функциональность C++ для разработки многопоточных приложений

Стандарт C++11 и последующие версии предоставляют развитую библиотеку поддержки потоков (Thread support library), которая включает следующие ключевые компоненты.

### 1. Управление потоками (`<thread>`)

Класс `std::thread` представляет отдельный поток исполнения. Он позволяет:
- Создать поток, передав ему вызываемый объект (функцию, лямбду, функтор) и аргументы.
- Ожидать завершения потока с помощью `join()` или отсоединить его с помощью `detach()`.
- Проверять, является ли поток присоединяемым (`joinable()`).
- Получать идентификатор потока (`get_id()`).

Начиная с C++20, доступен `std::jthread` — поток с автоматическим присоединением в деструкторе и поддержкой кооперативной отмены через `stop_token`.

Пространство имён `std::this_thread` предоставляет функции для управления текущим потоком: `get_id()`, `yield()`, `sleep_for()`, `sleep_until()`.

### 2. Взаимное исключение (`<mutex>`)

Мьютексы (mutex) обеспечивают защиту разделяемых данных от одновременного доступа:
- `std::mutex` — базовый мьютекс.
- `std::recursive_mutex` — допускает повторный захват тем же потоком.
- `std::timed_mutex` и `std::recursive_timed_mutex` — с поддержкой таймаутов.

Для безопасного управления блокировками используются RAII-обёртки: `std::lock_guard`, `std::unique_lock`, `std::scoped_lock` (C++17). Также доступны алгоритмы `std::lock`, `std::try_lock` для одновременного захвата нескольких мьютексов без взаимной блокировки.

### 3. Условные переменные (`<condition_variable>`)

`std::condition_variable` и `std::condition_variable_any` позволяют потокам ожидать наступления определённого события. Поток блокируется до тех пор, пока другой поток не уведомит его через `notify_one()` или `notify_all()`. Условные переменные всегда используются совместно с мьютексом для предотвращения потерянных пробуждений и гонок данных.

### 4. Атомарные операции (`<atomic>`)

Шаблон `std::atomic<T>` предоставляет атомарный доступ к переменным без явной блокировки. Поддерживаются операции `load`, `store`, `exchange`, `compare_exchange_weak/strong`, а также атомарная арифметика для целочисленных типов. Параметры памяти (`std::memory_order`) позволяют тонко настраивать семантику синхронизации между потоками.

### 5. Фьючерсы и асинхронность (`<future>`)

Библиотека предоставляет механизмы для получения результатов асинхронных вычислений:
- `std::async` — запускает задачу асинхронно и возвращает `std::future`.
- `std::promise` / `std::future` — канал передачи значения или исключения между потоками.
- `std::packaged_task` — обёртка для вызываемого объекта, результат которого доступен через `future`.
- `std::shared_future` — позволяет нескольким потокам ожидать один и тот же результат.

### 6. Дополнительные примитивы синхронизации (C++20)

- `std::counting_semaphore` и `std::binary_semaphore` — семафоры для ограничения доступа.
- `std::latch` — одноразовый барьер, который блокирует потоки до достижения заданного счётчика.
- `std::barrier` — многоразовый барьер для синхронизации групп потоков.

## Основные проблемы многопоточных приложений

### 1. Состояние гонки (Data Race)

Возникает, когда два или более потоков одновременно обращаются к одной и той же области памяти, и хотя бы один из них выполняет запись, без должной синхронизации. Результат непредсказуем и зависит от планировщика. Решение — использование мьютексов, атомарных операций или проектирование без разделяемого изменяемого состояния.

### 2. Взаимная блокировка (Deadlock)

Ситуация, при которой два или несколько потоков бесконечно ожидают ресурсов, удерживаемых друг другом. Классический пример: поток A захватывает мьютекс M1 и ждёт M2, а поток B захватывает M2 и ждёт M1. Предотвращение достигается упорядочиванием захвата блокировок (например, с помощью `std::scoped_lock` с несколькими мьютексами) или использованием таймаутов.

### 3. Голодание (Starvation)

Поток не может получить доступ к ресурсу в течение длительного времени, потому что другие потоки постоянно его опережают. Может возникать при несправедливых алгоритмах планирования или при высокой конкуренции за блокировку.

### 4. Живая блокировка (Livelock)

Потоки не блокируются, но постоянно меняют своё состояние в ответ на действия друг друга, не выполняя полезной работы (например, два потока repeatedly уступают друг другу дорогу).

### 5. Потерянные пробуждения (Lost Wakeup)

Поток, ожидающий на условной переменной, может пропустить уведомление, если оно было отправлено до того, как поток начал ожидание. Решается проверкой условия в цикле под мьютексом перед вызовом `wait`.

### 6. Ложные пробуждения (Spurious Wakeup)

`std::condition_variable::wait` может вернуться без явного уведомления. Поэтому ожидание всегда должно выполняться в цикле с проверкой предиката: `cv.wait(lock, []{ return predicate; });`.

### 7. Проблемы с временем жизни объектов

Поток может обращаться к объекту, который уже уничтожен (например, после выхода из области видимости). Особенно опасно при `detach()`. `std::jthread` смягчает эту проблему за счёт автоматического присоединения, но требует внимательного проектирования владения.

### 8. Сложность отладки и тестирования

Многопоточные ошибки недетерминированы: они могут проявляться редко и исчезать при запуске под отладчиком. Это делает их обнаружение и воспроизведение крайне трудоёмким. Для смягчения используются инструменты анализа (ThreadSanitizer), стресс-тестирование и минимизация разделяемого состояния.
