# 82. Что такое exception?

**Exception (исключение)** в C++ — это механизм обработки ошибок и исключительных ситуаций, который позволяет отделить код, обнаруживающий ошибку, от кода, её обрабатывающего. Вместо возврата кодов ошибок и проверки их на каждом уровне вызова, программа «выбрасывает» (throw) объект-исключение, и среда выполнения начинает раскрутку стека (stack unwinding) до тех пор, пока не найдётся подходящий обработчик (catch).

## Основные компоненты механизма

Механизм исключений в C++ состоит из трёх ключевых слов:

1. **`throw`** — генерирует исключение (бросает объект).
2. **`try`** — блок кода, в котором потенциально может возникнуть исключение.
3. **`catch`** — обработчик, перехватывающий исключение определённого типа.

```cpp
#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0.0) {
        throw std::invalid_argument("Деление на ноль!");
    }
    return a / b;
}

int main() {
    try {
        std::cout << divide(10.0, 0.0) << '\n';
    } catch (const std::invalid_argument& e) {
        std::cerr << "Ошибка: " << e.what() << '\n';
    }
    return 0;
}
```

## Ключевые особенности

### 1. Тип исключения
Исключением может быть объект **любого типа** (в том числе встроенного: `int`, `const char*`), но на практике рекомендуется бросать объекты, производные от `std::exception` (например, `std::runtime_error`, `std::logic_error`). Это обеспечивает единообразную обработку через `what()`.

### 2. Перехват по ссылке
Ловить исключения следует **по константной ссылке** (`catch (const std::exception& e)`), чтобы:
- избежать лишнего копирования;
- корректно обрабатывать полиморфные исключения (без «срезки» slicing).

### 3. Раскрутка стека (stack unwinding)
При выбросе исключения локальные объекты в блоке `try` и во всех промежуточных функциях **корректно уничтожаются** — вызываются их деструкторы. Это основа идиомы RAII: ресурсы освобождаются автоматически, даже при возникновении ошибки.

### 4. Порядок обработчиков
Обработчики `catch` проверяются **сверху вниз**. Более общий тип (`std::exception`) должен идти **после** более конкретных, иначе специфичные обработчики станут недостижимы.

```cpp
try {
    // ...
} catch (const std::invalid_argument& e) {
    // конкретный тип
} catch (const std::exception& e) {
    // общий тип
} catch (...) {
    // перехват любого исключения
}
```

### 5. `catch (...)` — перехват всего
Позволяет поймать любое исключение, но не даёт доступа к объекту. Используется как «последняя линия обороны», например для логирования и повторного `throw;`.

### 6. Повторный выброс
`throw;` без аргумента внутри `catch` повторно бросает текущее исключение (сохраняя исходный тип и объект).

## Гарантии безопасности исключений

Стандартная библиотека и хороший код придерживаются уровней гарантий:

- **noexcept (nothrow)** — операция не бросает исключений.
- **strong guarantee** — при ошибке состояние остаётся прежним (атомарность).
- **basic guarantee** — при ошибке объект остаётся в корректном, но неопределённом состоянии.

## Деструкторы и исключения

Деструкторы **не должны** выпускать исключения. Если во время раскрутки стека деструктор бросит исключение при уже активном другом исключении — программа вызовет `std::terminate`. Поэтому деструкторы по умолчанию неявно помечаются `noexcept`.

## Когда использовать исключения

**Рекомендуется:**
- для действительно исключительных ситуаций (ошибки, которые нельзя игнорировать);
- когда ошибку нельзя обработать локально;
- в конструкторах (альтернативы — коды возврата — недоступны).

**Не рекомендуется:**
- для управления обычным потоком выполнения (медленно);
- в критичных по производительности участках;
- в деструкторах;
- при пересечении границ C-кода (без обёрток).

## Итог

`exception` в C++ — это объект, сигнализирующий об ошибке, который распространяется вверх по стеку вызовов до первого подходящего `catch`. Механизм обеспечивает автоматическое освобождение ресурсов (RAII), строгую типизацию ошибок и отделение логики обработки от логики обнаружения, но требует аккуратного применения (перехват по ссылке, `noexcept`-деструкторы, порядок `catch`-блоков).
