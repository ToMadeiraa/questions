# 52. Что делает вызов `throw;` в блоке catch?

## Краткий ответ

Вызов `throw;` **без операнда** внутри блока `catch` повторно возбуждает (rethrow) **тот же самый объект исключения**, который был перехвачен текущим обработчиком. Это позволяет частично обработать исключение и передать его дальше по цепочке — внешнему `catch` или вызывающему коду.

```cpp
try {
    throw std::runtime_error("ошибка");
}
catch (const std::exception& e) {
    std::cerr << "Лог: " << e.what() << "\n";
    throw; // пробрасываем то же исключение дальше
}
```

## Ключевые детали

### 1. Пробрасывается исходный объект, а не копия

`throw;` повторно возбуждает **оригинальный объект исключения**, а не его копию. Это важно, потому что в C++ при `throw e;` (с операндом) объект копируется, и копия может потерять динамический тип (срезка — slicing), если тип в `throw` не совпадает с реальным типом объекта.

```cpp
struct Base { virtual ~Base() = default; };
struct Derived : Base {};

try {
    try {
        throw Derived{};
    }
    catch (const Base& b) {
        throw;        // правильно: пробросится Derived
        // throw b;   // ОШИБКА: срезка до Base
    }
}
catch (const Derived& d) {
    // сюда попадём только при использовании throw;
}
```

### 2. Допустим только внутри обработчика

`throw;` без операнда **легален только внутри блока `catch`** (или в функции, вызванной из него, пока исключение ещё «активно» — то есть до выхода из `catch`). Вне обработчика такое выражение приводит к вызову `std::terminate()` (в C++11 и новее — undefined behavior / terminate в зависимости от контекста; формально это ошибка, диагностируемая не всегда).

```cpp
void f() {
    throw; // ошибка: нет активного исключения → std::terminate
}
```

### 3. Работает и в catch(...)

`throw;` корректно работает и в универсальном обработчике `catch (...)`, повторно возбуждая перехваченное исключение с сохранением его типа.

```cpp
try {
    risky();
}
catch (...) {
    log_error();
    throw; // тип исключения сохраняется
}
```

### 4. Стек-размотка продолжается

После `throw;` начинается нормальная раскрутка стека (stack unwinding) от текущего `catch` к внешнему обработчику: уничтожаются локальные объекты, вызываются деструкторы. Это не «выход из функции», а именно продолжение обработки исключения.

### 5. Не путать с `throw e;`

| Выражение | Что делает |
|---|---|
| `throw;` | Пробрасывает **исходный** объект, сохраняя динамический тип |
| `throw e;` | Создаёт **копию** `e` (обычно статического типа) и возбуждает её — риск срезки |
| `throw std::move(e);` | Перемещает объект и возбуждает его |

## Типичные сценарии использования

- **Логирование и проброс**: записать информацию об ошибке, не «съедая» её.
- **Частичная обработка**: освободить ресурс / преобразовать контекст, но дать исключению дойти до верхнего уровня.
- **Трансляция на границах модуля**: перехватить всё через `catch (...)`, залогировать и сделать `throw;`, чтобы не менять тип исключения.

## Итог

`throw;` в `catch` — это механизм **повторного возбуждения текущего исключения без копирования**, позволяющий строить многоуровневую обработку ошибок с сохранением исходного типа и объекта исключения.
