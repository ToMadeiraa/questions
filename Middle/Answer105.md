# 105. Что такое принцип RAII?

**RAII** (Resource Acquisition Is Initialization — «получение ресурса есть инициализация») — это идиома управления ресурсами, пришедшая из C++, но концептуально применимая в любом объектно-ориентированном дизайне. Суть принципа: **владение ресурсом привязывается к времени жизни объекта**. Ресурс захватывается в конструкторе объекта и гарантированно освобождается в его деструкторе.

## Основная идея

Ресурсом может быть что угодно, что требует парного «захвата» и «освобождения»:

- динамическая память (`new`/`delete`, `malloc`/`free`);
- файловые дескрипторы (`open`/`close`);
- сетевые сокеты;
- мьютексы и блокировки (`lock`/`unlock`);
- соединения с БД, транзакции;
- handles ОС, GDI-объекты и т.п.

RAII превращает парные операции «получить — освободить» в **инкапсулированные в объекте** операции конструктора и деструктора.

```cpp
class FileHandle {
    FILE* f_;
public:
    explicit FileHandle(const char* path) : f_(std::fopen(path, "r")) {
        if (!f_) throw std::runtime_error("cannot open file");
    }
    ~FileHandle() { if (f_) std::fclose(f_); }

    // запрет копирования — владение уникально
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    // разрешаем перемещение — передача владения
    FileHandle(FileHandle&& o) noexcept : f_(o.f_) { o.f_ = nullptr; }

    FILE* get() const noexcept { return f_; }
};
```

Теперь при любом выходе из области видимости (включая исключения) деструктор закроет файл — утечки не будет.

## Ключевые свойства

1. **Гарантированное освобождение.** Деструкторы вызываются при выходе из scope, в том числе при раскрутке стека из-за исключения. Это делает RAII основой *exception safety*.
2. **Инкапсуляция (OOP).** Логика владения ресурсом скрыта внутри класса; клиент работает с абстракцией, а не с сырым ресурсом.
3. **Единственность/разделение владения.** Класс-владелец контролирует копирование и перемещение: уникальное владение (move-only, как `std::unique_ptr`) или разделяемое (как `std::shared_ptr` с подсчётом ссылок).
4. **Детерминированность.** В отличие от сборки мусора, освобождение происходит в строго определённый момент — конце времени жизни объекта.

## Связь с OOD

- **Инкапсуляция**: ресурс и правила работы с ним спрятаны за интерфейсом класса.
- **SRP**: класс-обёртка отвечает только за владение ресурсом (Single Responsibility).
- **Композиция**: RAII-объекты естественно встраиваются как члены других классов — их деструкторы вызываются автоматически.
- **Полиморфизм**: за счёт виртуальных деструкторов можно управлять ресурсами через базовый интерфейс.

## Примеры в стандартной библиотеке C++

| Класс | Управляемый ресурс |
|---|---|
| `std::unique_ptr`, `std::shared_ptr` | динамическая память |
| `std::fstream`, `std::ifstream` | файлы |
| `std::lock_guard`, `std::unique_lock`, `std::scoped_lock` | мьютексы |
| `std::vector`, `std::string` | буферы памяти |
| `std::jthread` | поток + автоматический join |

## Идиома «Scope Guard»

Частный случай RAII — объект, чей деструктор выполняет произвольное действие при выходе из scope (откат транзакции, восстановление состояния и т.п.):

```cpp
class TransactionGuard {
    DB& db_;
public:
    explicit TransactionGuard(DB& db) : db_(db) { db_.begin(); }
    ~TransactionGuard() { db_.rollback(); }   // если commit не вызван явно
    void commit() { db_.commit(); /* ... */ }
};
```

## Аналоги в других языках

- **C#** — `using` / `IDisposable` (детерминированное освобождение, но без деструкторов в C++-смысле).
- **Java** — `try-with-resources` / `AutoCloseable`.
- **Python** — контекстные менеджеры (`with`, `__enter__`/`__exit__`), частично `__del__`.
- **Rust** — владение + трейт `Drop`, по сути тот же RAII как основа всей модели памяти.

## Резюме

RAII — это способ связать **владение ресурсом** с **временем жизни объекта**: конструктор захватывает ресурс, деструктор освобождает. Это даёт автоматическое, исключение-безопасное и детерминированное управление ресурсами, а в терминах OOD — инкапсулирует ответственность за ресурс в отдельном классе и делает композицию объектов безопасной по умолчанию.
