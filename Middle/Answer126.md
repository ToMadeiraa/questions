# 126. Как синхронизировать между собой несколько процессов?

Синхронизация нескольких процессов в C++ принципиально отличается от синхронизации потоков внутри одного процесса. Стандартная библиотека C++ (`std::mutex`, `std::condition_variable`, `std::atomic`) спроектирована для работы в рамках одного адресного пространства и **не предназначена** для межпроцессного взаимодействия (за редким исключением атомарных операций, которые могут работать на разделяемой памяти, но это требует осторожности и выходит за рамки переносимого кода).

Для синхронизации процессов необходимо использовать механизмы операционной системы или специализированные библиотеки, такие как **Boost.Interprocess**. Основная идея заключается в том, чтобы разместить объекты синхронизации (мьютексы, семафоры, условные переменные) в **разделяемой памяти** (shared memory) или использовать **именованные** объекты ядра ОС.

### 1. Основные механизмы синхронизации

Вот ключевые примитивы, доступные для межпроцессной синхронизации (реализуемые через Boost.Interprocess или нативные API POSIX/Windows):

- **Межпроцессный мьютекс (Interprocess Mutex)**: Обеспечивает взаимное исключение. Процесс захватывает мьютекс перед доступом к общим данным и освобождает после. Объект мьютекса должен находиться в разделяемой памяти, чтобы оба процесса видели его.
- **Межпроцессный семафор (Interprocess Semaphore)**: Счетчик, который может использоваться как для взаимного исключения (бинарный семафор), так и для сигнализации о наступлении событий (например, «данные готовы»). В отличие от мьютекса, семафор может быть освобожден (post) другим процессом, не тем, который его захватил (wait).
- **Межпроцессная условная переменная (Interprocess Condition Variable)**: Позволяет процессу ожидать изменения состояния, блокируясь до тех пор, пока другой процесс не уведомит его (notify). Обычно используется вместе с мьютексом для защиты проверяемого условия.
- **Именованные объекты (Named Mutex/Semaphore)**: Позволяют процессам, которые даже не связаны через разделяемую память (например, запущены независимо), находить друг друга по строковому имени (например, `sem_open` в POSIX или `CreateSemaphore` в Windows).

### 2. Практическая реализация с Boost.Interprocess

`Boost.Interprocess` — это де-факто стандарт для кроссплатформенной синхронизации процессов в C++. Он предоставляет классы, которые можно размещать в разделяемой памяти.

**Примерная схема работы:**

1.  **Создание разделяемой памяти**: Один процесс создает область разделяемой памяти (`shared_memory_object`) и отображает ее в свое адресное пространство.
2.  **Размещение синхронизатора**: В этой области с помощью специальных аллокаторов создается объект, например `interprocess_mutex`.
3.  **Доступ второго процесса**: Второй процесс открывает ту же разделяемую память по имени и получает доступ к тому же самому мьютексу.
4.  **Использование**: Оба процесса используют `lock()` / `unlock()` для защиты критических секций при работе с общими данными в этой же разделяемой памяти.

**Важный нюанс времени жизни**: Именованные объекты (и разделяемая память) в Boost.Interprocess имеют «ядерную» или «файловую» персистентность. Это значит, что если процесс-создатель завершится, объект может остаться в системе, пока его явно не удалят (через `remove()`). Это нужно для того, чтобы второй процесс мог его открыть, даже если первый уже завершился.

### 3. Подводные камни и особенности

- **Стандарт C++ и процессы**: В стандарте C++ тема процессов практически не раскрыта (упоминается лишь в контексте атомарных операций). Поэтому использование `std::mutex` в разделяемой памяти приведет к неопределенному поведению, так как его внутреннее устройство (например, дескрипторы ОС) не предназначено для копирования между процессами.
- **Атомарные операции**: `std::atomic` *может* работать в разделяемой памяти, но только если вы уверены, что аппаратная архитектура и реализация компилятора поддерживают это для конкретного типа (обычно это lock-free типы). Однако полагаться на это в общем случае рискованно.
- **Производительность**: Захват межпроцессного мьютекса — дорогостоящая операция, так как она часто требует переключения в режим ядра. Как и в случае с потоками, рекомендуется минимизировать время удержания блокировки и защищать только действительно критические участки.
- **Проблема мертвой блокировки (Deadlock)**: Риск взаимной блокировки между процессами точно такой же, как и между потоками. Необходимо соблюдать порядок захвата блокировок.

### Резюме

Для синхронизации процессов в C++ нужно:
1.  Организовать **разделяемую память** (POSIX `shm_open` / `mmap` или Boost.Interprocess).
2.  Разместить в ней **межпроцессный мьютекс/семафор** (из Boost.Interprocess или нативных API).
3.  Использовать **именованные** объекты, если процессы не связаны через общую память.
4.  Избегать стандартных `std::` примитивов, если они не спроектированы для работы с разделяемой памятью.
