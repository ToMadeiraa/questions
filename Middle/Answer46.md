# 46. Как реализовано наследование в большинстве компиляторов?

В большинстве компиляторов C++ (особенно под Linux, macOS и другие Unix-подобные системы, следующие Itanium C++ ABI, например GCC и Clang) наследование реализуется на уровне двоичного представления объектов и таблиц виртуальных функций. Языковая стандартизация C++ не фиксирует конкретную схему размещения в памяти, оставляя это на усмотрение ABI (Application Binary Interface) . Однако доминирующий промышленный стандарт — **Itanium C++ ABI** — предлагает четкий набор правил.

Основные механизмы реализации следующие:

### 1. Размещение данных: вложенность подобъектов базовых классов

Для **невиртуального наследования** (одиночного или множественного) объект производного класса в памяти содержит **базовые подобъекты** (base subobjects), вложенные в порядке объявления.

- **Одиночное наследование**: базовый подобъект обычно размещается по адресу `0` объекта производного класса (в начале), за ним следуют собственные данные производного класса. Это обеспечивает совместимость адресов указателей `Base*` и `Derived*` без дополнительных вычислений .
- **Множественное наследование**: первый базовый класс (primary base) обычно также размещается в начале (смещение 0). Последующие базовые подобъекты размещаются после предыдущих подобъектов, и их смещения (offset) фиксируются на этапе компиляции. При преобразовании указателя производного класса в указатель не-первого базового класса компилятор автоматически добавляет константу смещения .

### 2. Полиморфизм: таблица виртуальных функций (vtable) и указатель vptr

Если класс содержит виртуальные функции, компилятор генерирует для него **таблицу виртуальных функций (vtable)**, а каждый объект, содержащий виртуальные функции, содержит скрытый указатель **vptr**, указывающий на vtable своего класса.

- **Формат vtable**: типичная vtable (в Itanium ABI) содержит в начале служебную информацию (например, смещение до вершины объекта `offset-to-top`, указатель на информацию о типе RTTI `typeinfo`), за которой следуют адреса виртуальных функций в порядке объявления .
- **Виртуальный вызов**: при вызове виртуальной функции компилятор генерирует код, который извлекает `vptr` из объекта, затем по фиксированному смещению (индексу функции в vtable) извлекает адрес функции и выполняет косвенный вызов. Именно поэтому виртуальные вызовы невозможно полностью определить на этапе компиляции .

### 3. Специальная обработка множественного наследования: вторичные vtable и thunk-функции

При множественном наследовании, если несколько базовых классов содержат виртуальные функции, производный класс может содержать несколько указателей `vptr` (по одному на каждый полиморфный подобъект).

- Когда указатель базового класса указывает на подобъект, расположенный не по нулевому смещению, и вызывается виртуальная функция, `this`-указатель внутри функции должен указывать на полный объект производного класса. Для этого в vtable может храниться **thunk-функция** (адаптер): она сначала корректирует `this`-указатель (добавляет фиксированное смещение), затем передает управление реальной реализации .

### 4. Виртуальное наследование (решение проблемы ромба)

При **виртуальном наследовании** общий виртуальный базовый класс в объекте производного класса появляется только один раз, независимо от количества путей наследования.

- **Динамическое определение смещения**: поскольку позиция виртуального базового подобъекта в полном объекте зависит от иерархии наследования (может различаться в разных конечных производных классах), смещение не может быть зафиксировано на этапе компиляции. Itanium ABI обычно использует **таблицу виртуальных базовых классов (virtual base table)** или специальные записи в vtable для хранения смещения к виртуальному базовому классу, которое определяется во время выполнения через `vptr` .

### 5. Различия между компиляторами

Хотя Itanium ABI доминирует на платформах Unix, **MSVC (Microsoft Visual C++)** использует собственную схему ABI. Поведение MSVC при множественном и виртуальном наследовании (например, размещение vfptr/vbtable) отличается от Itanium ABI, и двоичные файлы, скомпилированные разными компиляторами, обычно несовместимы на уровне ABI. Кроме того, MSVC предоставляет специальные ключевые слова, такие как `__single_inheritance`, для управления моделью наследования, используемой указателями на члены .

**Резюме**: с точки зрения непрозрачного для программиста двоичного уровня, наследование в основном реализуется через **вложенность данных (статическое смещение)** + **косвенные вызовы через vtable (динамическая диспетчеризация)** + **корректировку thunk и таблиц виртуальных баз (для множественного/виртуального наследования)**. Конкретные детали определяются выбранным ABI компилятора.
