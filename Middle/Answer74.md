# 74. Что такое блоки try-throw-catch?

**`try`, `throw` и `catch`** — это три ключевых элемента механизма **обработки исключений** (exception handling) в C++. Вместе они позволяют отделить обнаружение ошибки от её обработки: функция, заметившая проблему, «бросает» исключение (`throw`), а код выше по стеку «ловит» и обрабатывает его (`catch`). Блок `try` задаёт защищённую область, в которой исключения перехватываются.

Главная идея: исключение — это объект некоторого типа, который распространяется вверх по стеку вызовов до первого подходящего обработчика. Если обработчик не найден, программа аварийно завершается через `std::terminate()`.

---

## 1. Общая схема

```cpp
try {
    // защищённый код: здесь может быть брошено исключение
    risky_operation();
} catch (const SomeError& e) {
    // обработка исключения типа SomeError (и производных)
} catch (const std::exception& e) {
    // обработка прочих стандартных исключений
} catch (...) {
    // обработка всего остального
}
```

Синтаксически `try`-блок **обязан** сопровождаться хотя бы одним `catch`-обработчиком. Пустой `try {}` без `catch` — ошибка компиляции. Обработчики проверяются **сверху вниз**, срабатывает первый подходящий.

---

## 2. Блок `try`

`try` — это составной оператор, который вводит новую область видимости и помечает код как «защищённый»:

```cpp
try {
    int x = std::stoi(input);   // может бросить std::invalid_argument
    std::cout << x << '\n';
} catch (const std::invalid_argument& e) {
    std::cerr << "Некорректное число: " << e.what() << '\n';
}
```

Важные свойства:

- **Область видимости.** Переменные, объявленные внутри `try`, не видны в `catch`-блоках. Если значение нужно обработчику, его объявляют *до* `try`.
- **Локальность.** `try` можно ставить в любом месте функции и даже вкладывать друг в друга. Вложенный `try` перехватывает только то, что брошено внутри его собственной защищённой области.
- **Не требует `throw`.** Внутри `try` вовсе не обязано быть ключевое слово `throw`: исключение может прийти из любой вызываемой функции, из конструктора, оператора `new` и т.д.
- **Не ловит всё подряд.** Исключение, брошенное в обработчике `catch`, этим же `try` уже не перехватывается — оно уходит наружу.

---

## 3. Оператор `throw`

`throw` создаёт объект-исключение и запускает раскрутку стека:

```cpp
double divide(double a, double b) {
    if (b == 0.0)
        throw std::domain_error("деление на ноль");  // бросаем объект
    return a / b;
}
```

Ключевые моменты:

- **Тип исключения** определяется статическим типом операнда. `throw std::domain_error("...")` бросает объект `std::domain_error`, а не строку.
- **Копирование.** Объект-исключение создаётся в специальной области памяти (не в стеке бросающей функции), поэтому он «переживает» раскрутку стека. Обычно объект копируется (или перемещается); для prvalue-выражений копирование может быть элидировано.
- **Срезка (slicing).** Если бросить объект по значению через базовый тип, производная часть потеряется:
  ```cpp
  Derived d;
  Base b = d;
  throw b;        // брошен именно Base — «срезка»
  ```
- **Строковые литералы.** `throw "error";` бросает `const char*` (указатель), а не `std::string`. Ловить его надо как `const char*`, и это плохая практика — лучше бросать полноценный объект исключения.
- **Повторный `throw;`** без операнда пробрасывает **текущее** обрабатываемое исключение дальше, сохраняя его динамический тип и исходный объект:
  ```cpp
  catch (const std::exception& e) {
      log(e.what());
      throw;   // тот же объект уходит вызывающему коду
  }
  ```
  Если `throw;` выполнить вне обработчика (нет активного исключения), вызывается `std::terminate()`.
- **`throw` в `noexcept`-функции** немедленно приводит к `std::terminate()`, а не к нормальной раскрутке стека.

Бросать можно объекты любого полного типа: встроенные типы, классы, указатели. Но на практике бросают **классы, унаследованные от `std::exception`**, — это даёт единый интерфейс `what()` и возможность ловить всё одной ссылкой на базовый класс.

---

## 4. Блок `catch`

Обработчик `catch` объявляет параметр — переменную, которая инициализируется объектом-исключением:

```cpp
catch (const std::runtime_error& e) { ... }  // по константной ссылке — рекомендуется
catch (std::runtime_error e)        { ... }  // по значению — копия (и возможная срезка)
catch (std::runtime_error& e)       { ... }  // по неконстантной ссылке — можно менять
catch (...)                         { ... }  // перехват любого исключения
```

### Правила сопоставления

Обработчик подходит, если выполнено хотя бы одно условие:

1. Тип обработчика совпадает с типом исключения (с точностью до top-level `const`/`volatile`).
2. Тип обработчика — однозначный **публичный базовый класс** для типа исключения (работает и для ссылок, и для указателей).
3. Исключение и обработчик — указатели, и между ними допустимо стандартное преобразование указателей (например, `Derived*` → `Base*`, `T*` → `void*`).
4. Исключение имеет тип `std::nullptr_t`, а обработчик — указатель.

При этом **не применяются**:

- арифметические преобразования (`int` не поймается как `double`);
- пользовательские преобразования (конструкторы/операторы приведения);
- неоднозначные или закрытые преобразования базового класса.

| Брошено | Обработчик | Подходит? |
|---|---|---|
| `Derived` | `catch (const Base&)` | да |
| `int` | `catch (double)` | нет |
| `int` | `catch (long)` | нет |
| `Derived*` | `catch (const Base*)` | да |
| `std::string` | `catch (const char*)` | нет |
| `std::nullptr_t` | `catch (const void*)` | да |

### Порядок обработчиков

Обработчики перебираются в порядке написания, поэтому **производные типы должны идти раньше базовых**, а `catch (...)` — всегда последним. Иначе специализированный обработчик станет недостижимым:

```cpp
try {
    throw std::out_of_range("...");
} catch (const std::exception& e) {   // поймает всё, включая out_of_range
    // ...
} catch (const std::out_of_range& e) { // НИКОГДА не выполнится
    // ...
}
```

### Почему `catch (const T&)`

- Нет копирования и, главное, **нет срезки**: виртуальный `what()` вернёт сообщение производного класса.
- `const` запрещает случайно менять объект-исключение.
- Если нужна модификация — берут неконстантную ссылку `catch (T& e)`. Изменения затронут исходный объект-исключение, и при `throw;` они сохранятся.
- `catch (T e)` создаёт копию; изменения в ней не влияют на оригинал.

### `catch (...)`

Перехватывает исключение **любого** типа, в том числе не наследующее `std::exception` и даже не класс (например, `throw 42;`). Внутри такого обработчика недоступен объект исключения, но можно узнать о нём через `std::current_exception()` и пробросить дальше:

```cpp
catch (...) {
    std::exception_ptr p = std::current_exception();
    // ... логирование ...
    throw;   // пробросить дальше
}
```

## 5. Что происходит при броске: раскрутка стека

Механизм работы `throw`:

1. Создаётся объект-исключение в специальном хранилище.
2. Начинается **раскрутка стека** (stack unwinding): функции покидаются одна за другой, пока не найдётся подходящий `catch`.
3. В каждой покидаемой функции **вызываются деструкторы всех полностью сконструированных автоматических объектов** — в порядке, обратном их созданию. Именно на этом основана идиома RAII: ресурсы (память, файлы, мьютексы) освобождаются автоматически.
4. Управление передаётся в найденный обработчик.
5. После выхода из последнего обработчика объект-исключение уничтожается. Если обработчик сделал `throw;`, объект живёт дальше и уничтожается позже.

Если обработчик не найден ни в одной функции, вызывается `std::terminate()` (по умолчанию — `abort()`; функцию можно заменить через `std::set_terminate`).

Важное следствие: **деструкторы не должны бросать исключения**. Если исключение вылетает из деструктора во время раскрутки стека (уже есть активное исключение), вызывается `std::terminate()`. С C++11 деструкторы неявно объявлены `noexcept`, поэтому любое исключение из них всё равно приведёт к `terminate()`.

## 6. Function-try-block (try-блок функции)

Особый синтаксис позволяет обернуть в `try` не только тело функции, но и **список инициализации конструктора** (включая инициализацию баз и полей):

```cpp
class Widget {
    std::string data_;
public:
    Widget(const std::string& s) try : data_(s) {
        if (s.empty())
            throw std::invalid_argument("пустое имя");
    } catch (const std::exception& e) {
        // сюда попадают и исключения из data_(s)
        std::cerr << "Widget: " << e.what() << '\n';
        throw;   // для конструктора/деструктора перебрасывание происходит и автоматически
    }
};
```

Особенности:

- В **конструкторе** такой блок ловит исключения из списка инициализации членов и базовых классов.
- Если обработчик конструктора или деструктора завершается нормально, исключение **автоматически пробрасывается дальше**: объект всё равно не был полностью построен (или уже разрушается), и «проглотить» ошибку нельзя.
- Если конструктор бросил исключение, деструктор самого объекта **не вызывается**, но деструкторы уже сконструированных полей и баз — вызываются.

## 7. Стандартная иерархия исключений

В заголовке `<stdexcept>` и `<exception>` есть готовый набор классов, унаследованных от `std::exception` с виртуальным `what() noexcept`:

```
std::exception
├── std::logic_error
│   ├── std::invalid_argument
│   ├── std::domain_error
│   ├── std::length_error
│   ├── std::out_of_range
│   └── std::future_error
├── std::runtime_error
│   ├── std::range_error
│   ├── std::overflow_error
│   └── std::underflow_error
├── std::bad_alloc
├── std::bad_cast
├── std::bad_typeid
├── std::bad_weak_ptr
├── std::bad_function_call
├── std::ios_base::failure
└── std::system_error
```

Собственные исключения обычно наследуют от `std::runtime_error` или `std::logic_error`:

```cpp
class ConnectionError : public std::runtime_error {
public:
    explicit ConnectionError(const std::string& msg)
        : std::runtime_error("ConnectionError: " + msg) {}
};
```

Тогда клиентский код может ловить либо конкретный `ConnectionError`, либо всё семейство через `catch (const std::exception&)`.

## 8. `noexcept` и завершение программы

Спецификатор `noexcept` сообщает, что функция не бросает исключений:

```cpp
void safe_cleanup() noexcept;      // исключение наружу не выйдет
void may_throw() noexcept(false);  // может бросать
```

Если исключение всё же попытается покинуть `noexcept`-функцию, вызывается `std::terminate()`; гарантий раскрутки стека при этом нет. `noexcept` важен для оптимизаций: например, `std::vector` при реаллокации использует перемещение, только если перемещающий конструктор объявлен `noexcept`, иначе копирует элементы ради строгой гарантии безопасности.

Устаревшие динамические спецификации (`throw(std::bad_alloc)`) удалены из C++17; современный код использует только `noexcept`.

## 9. Практические рекомендации

1. **Бросайте по значению, ловите по константной ссылке** — это классическое правило C++: `throw MyError(...)`, `catch (const MyError& e)`.
2. **Бросайте объекты, а не указатели** — иначе придётся думать, кто и когда удалит память.
3. **Наследуйте исключения от `std::exception`** и переопределяйте `what()`.
4. **Не используйте исключения для обычного ветвления логики** — на «счастливом пути» они почти бесплатны (таблицы раскрутки), но сам `throw` дорог (микросекунды).
5. **Обеспечивайте безопасность относительно исключений**: применяйте RAII, умные указатели, copy-and-swap. Различают гарантии *nothrow*, *strong* (атомарность: либо успех, либо откат) и *basic* (инварианты сохраняются).
6. **Не позволяйте исключениям покидать деструкторы** — объявляйте их `noexcept` (по умолчанию так и есть) и не бросайте из них.
7. **Соблюдайте порядок `catch`**: от производных к базовым, `catch (...)` — в конце.
8. **Не глотайте исключения молча** — как минимум логируйте, а при необходимости пробрасывайте через `throw;`.
9. Для ошибок, которые не являются «исключительными», рассматривайте альтернативы: `std::optional` (C++17), `std::variant`, `std::expected` (C++23) или коды ошибок.

---

## 10. Краткий итог

- **`try`** — защищённая область, в которой перехватываются исключения; требует хотя бы одного `catch`.
- **`throw`** — создаёт объект-исключение и запускает раскрутку стека с вызовом деструкторов; `throw;` без операнда пробрасывает текущее исключение дальше.
- **`catch`** — обработчик, выбираемый по типу исключения (с учётом наследования и преобразований указателей); порядок обработчиков важен.
- Вместе они реализуют обработку ошибок, **не размазанную по коду**: проверка условия и реакция на него могут находиться в разных функциях, а ресурсы корректно освобождаются за счёт RAII.
- Если подходящий обработчик не найден (или исключение выходит из `noexcept`/деструктора во время раскрутки), вызывается `std::terminate()`.
