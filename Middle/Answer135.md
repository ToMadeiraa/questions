# 135. Что случится, если exception выйдет за пределы потока? Какие инструменты есть для безопасной асинхронности в С++?

## Краткий ответ

Если исключение покидает начальную функцию `std::thread` (или любой поток, созданный средствами стандартной библиотеки), вызывается `std::terminate()`, что по умолчанию приводит к аварийному завершению всей программы через `std::abort()` . Это фундаментальное ограничение модели исключений C++: механизм раскрутки стека (stack unwinding) не может пересекать границы потоков.

Для безопасной асинхронности стандартная библиотека C++11 и последующих версий предоставляет инструменты, которые **перехватывают исключение внутри потока и передают его вызывающему коду через разделяемое состояние**: `std::promise`/`std::future` (с `set_exception` и `std::exception_ptr`), а также `std::async`, который делает это автоматически.

## 1. Что именно происходит: `std::terminate` и почему это так

Согласно стандарту C++, если выполнение начальной функции потока завершается через исключение, вызывается `std::terminate` . Это правило существует потому, что исключения в C++ спроектированы для синхронной раскрутки стека в одном потоке. Когда исключение выходит за пределы потока, нет «вызывающего», который мог бы его перехватить, — поток является независимой единицей выполнения.

Важно понимать: **`std::terminate` вызывается до того, как исключение могло бы быть перехвачено где-либо ещё**. Даже если у вас есть глобальный обработчик или `try/catch` вокруг `join()`, исключение из потока всё равно приведёт к завершению программы, если оно не было перехвачено внутри самого потока.

```cpp
#include <thread>
#include <stdexcept>

int main() {
    std::thread t([] {
        throw std::runtime_error("boom"); // исключение выходит из потока
    });
    t.join(); // сюда управление не дойдёт — программа уже завершена
}
```

В некоторых реализациях (например, libstdc++) было предложено не перехватывать исключение внутри `std::thread`, а позволить среде выполнения вызвать `terminate` с сохранением backtrace, чтобы облегчить отладку . В любом случае результат один: программа аварийно завершается.

## 2. Инструменты для безопасной асинхронности

### 2.1 `std::promise` + `std::future`: ручная передача исключения

Основной паттерн: рабочий поток перехватывает **все** исключения и сохраняет их в `std::promise` через `set_exception`. Вызывающий поток получает исключение при вызове `future::get()`.

`std::promise<R>::set_exception(std::exception_ptr p)` атомарно сохраняет указатель на исключение в разделяемом состоянии и переводит состояние в готовность . `std::current_exception()` захватывает текущее активное исключение.

```cpp
#include <future>
#include <thread>
#include <iostream>
#include <stdexcept>

int main() {
    std::promise<int> p;
    std::future<int> f = p.get_future();

    std::thread t([&p] {
        try {
            throw std::runtime_error("ошибка в потоке");
            // p.set_value(42); // нормальный путь
        } catch (...) {
            p.set_exception(std::current_exception()); // сохранить исключение
        }
    });

    try {
        int result = f.get(); // здесь исключение будет переброшено
        std::cout << "Результат: " << result << "\n";
    } catch (const std::exception& e) {
        std::cout << "Перехвачено из потока: " << e.what() << "\n";
    }

    t.join();
}
```

Ключевые моменты:
- `set_exception` необходимо вызывать внутри `catch(...)`, чтобы исключение не покинуло поток.
- `std::exception_ptr` — это тип, способный хранить любое исключение и перебрасывать его в другом контексте.
- `set_exception` сам может бросить `std::future_error` (например, если состояние уже установлено), поэтому в реальном коде стоит оборачивать и его .

### 2.2 `std::async`: автоматическая передача исключения

`std::async` с политикой `std::launch::async` запускает задачу в отдельном потоке и **автоматически** перехватывает исключение, сохраняя его в разделяемом состоянии связанного `std::future`. Когда вы вызываете `get()` у этого future, исключение перебрасывается в вызывающем потоке.

```cpp
#include <future>
#include <iostream>
#include <stdexcept>

int main() {
    auto f = std::async(std::launch::async, [] {
        throw std::runtime_error("из async");
        return 42;
    });

    try {
        int val = f.get(); // исключение перебрасывается здесь
    } catch (const std::exception& e) {
        std::cout << "Перехвачено: " << e.what() << "\n";
    }
}
```

Это самый простой способ безопасно запустить асинхронную задачу, которая может выбросить исключение. Однако `std::async` не даёт контроля над потоком (нельзя, например, отменить задачу), и его реализация может различаться (некоторые реализации используют пул потоков, а не новый поток каждый раз).

### 2.3 Дополнительные соображения

| Инструмент | Что делает с исключением |
|---|---|
| `std::thread` | Ничего; исключение → `std::terminate` |
| `std::async` | Сохраняет в future; перебрасывает при `get()` |
| `std::promise::set_exception` | Ручное сохранение исключения для future |
| `std::exception_ptr` | Транспорт для исключения между контекстами |
| `std::packaged_task` | Оборачивает вызываемый объект; сохраняет исключение в future |

`std::packaged_task` — ещё один инструмент: он оборачивает функцию и автоматически сохраняет результат или исключение в future, который можно получить через `get_future()`. Это удобно, когда вы хотите отделить создание задачи от её выполнения (например, передать её в пул потоков).

---

## 3. Практическое правило

**Никогда не позволяйте исключению покидать поток.** В начале каждой потоковой функции ставьте `try/catch(...)` и обрабатывайте исключение внутри. Если потоковая функция не может обработать ошибку осмысленно, передайте её вызывающему коду через `std::promise`/`std::future` или `std::exception_ptr`.

Для большинства задач, где нужна асинхронность с обработкой ошибок, предпочтительны `std::async` или `std::packaged_task` в сочетании с `std::future` — они снимают с вас бремя ручного перехвата и передачи исключений.
