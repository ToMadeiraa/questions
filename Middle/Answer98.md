# 98. Чем отличается using от typedef?

В современном C++ (начиная с C++11) `using` и `typedef` решают одну и ту же базовую задачу — создание псевдонима (синонима) для существующего типа. Для простых, нешаблонных типов они полностью эквивалентны по семантике: ни один из них не создает новый тип, а лишь вводит новое имя для уже существующего.

Однако между ними есть два ключевых различия, которые делают `using` предпочтительным выбором в современном коде.

### 1. Поддержка шаблонов (Alias Templates)

Это главное и принципиальное отличие. `typedef` не позволяет создавать псевдонимы для шаблонов с незафиксированными параметрами. `using` позволяет создавать так называемые **шаблонные псевдонимы** (alias templates), которые принимают параметры шаблона.

**Пример с `typedef` (не работает для шаблонов):**
Вы не можете написать `typedef std::vector<T> MyVector;`, потому что `T` не определен. Приходится либо фиксировать тип, либо использовать обертку через структуру.

**Пример с `using` (работает):**
```cpp
template<typename T>
using MyVector = std::vector<T, MyCustomAllocator<T>>;

// Теперь можно использовать:
MyVector<int> v; // Эквивалентно std::vector<int, MyCustomAllocator<int>>
```
Этот механизм особенно полезен для сокрытия сложных параметров шаблонов (например, кастомных аллокаторов) и повышения читаемости кода.

### 2. Читаемость и синтаксис (особенно для сложных типов)

Синтаксис `using` (стиль `using NewName = Type;`) более интуитивен, так как имя псевдонима всегда находится слева, а тип — справа. В `typedef` имя «зарыто» внутри объявления, что особенно неудобно для указателей на функции и массивов.

**Сравнение для указателя на функцию:**
```cpp
// typedef: имя (func) находится в середине
typedef void (*func)(int, double);

// using: явное присваивание, имя слева
using func = void (*)(int, double);
```
Для сложных типов (например, указателей на функции-члены или массивов) синтаксис `using` значительно легче читается, так как он следует общему правилу «слева — имя, справа — тип».

### 3. Нюансы семантики (краевые случаи)

Хотя в документации указано, что семантика идентична, существуют тонкие различия в правилах языка для специфических случаев, связанных с **линковкой (linkage)** безымянных типов.

Согласно стандарту C++, если `typedef` используется для определения безымянной структуры или перечисления (например, `typedef struct { ... } S;`), то имя `S` приобретает специальный статус «typedef-name для целей линковки» (linkage purposes). Это означает, что тип получает внешнюю линковку (external linkage).

В случае с `using` (alias-declaration), согласно текущей формулировке стандарта, это правило не применяется автоматически, так как оно явно требует определения именно через `typedef declaration`. Это может привести к различиям в поведении при компоновке в редких сценариях использования безымянных структур в заголовочных файлах.

### Итог: что выбрать?

В современном C++ (C++11 и новее) **рекомендуется использовать `using`** везде, где это возможно.

- **Используйте `using`**, если вы пишете новый код. Это обеспечивает единообразие синтаксиса, поддерживает шаблоны и лучше читается.
- **Используйте `typedef`**, только если вам необходимо поддерживать совместимость с очень старыми компиляторами (до C++11) или если вы работаете в кодовой базе, где по стандартам запрещен C++11.
