# 32. Что такое Uniform initialization? Aggregate initialization?

**Uniform initialization** (универсальная инициализация) и **Aggregate initialization** (агрегатная инициализация) — это два тесно связанных понятия в C++, которые используют фигурные скобки `{}` для инициализации объектов, но преследуют разные цели и применяются к разным типам.

## Uniform Initialization (Универсальная инициализация)

**Uniform initialization** — это концепция, введённая в C++11, цель которой — предоставить **единый синтаксис с фигурными скобками `{}`** для инициализации объектов **любого типа** в **любом контексте** . Бьёрн Страуструп сформулировал идеал так: «Мы хотим единый синтаксис, который можно использовать везде, и где бы он ни использовался, для одного и того же значения инициализатора получается один и тот же инициализированный объект» .

### Ключевые особенности

1. **Единый синтаксис**: `{}` можно использовать для:
   - Инициализации переменных: `X x{v};`
   - Инициализации временных объектов: `X{v}`
   - Явного преобразования типа: `x = X{v};`
   - Выделения в свободной памяти: `p = new X{v};`
   - Возврата значения: `return {v};`
   - Передачи аргумента: `f({v});`
   - Инициализации базового класса: `Y::Y(v) : X{v} { ... }`
   - Инициализации членов класса 

2. **Запрет сужающих преобразований (narrowing)**: Одним из главных нововведений uniform initialization является запрет неявных сужающих преобразований. Например, `int x{1.5};` вызовет ошибку компиляции, тогда как `int x = 1.5;` или `int x(1.5);` скомпилируются (с предупреждением или без) .

3. **Приоритет `initializer_list`**: Если у класса есть конструктор, принимающий `std::initializer_list`, он имеет приоритет при использовании синтаксиса `{}` .

4. **Различие с `()`**: В отличие от круглых скобок, фигурные скобки не допускают «most vexing parse» и позволяют инициализировать агрегаты и массивы единообразно .

### Важное замечание

Uniform initialization — это **идеал**, который в C++ реализован не полностью. Например, если у класса есть и конструктор от `std::initializer_list`, и обычный конструктор с теми же типами аргументов, синтаксис `{}` всегда выберет `initializer_list`, что может привести к неожиданному поведению . Кроме того, `auto x = {1, 2, 3};` выведет тип `std::initializer_list<int>`, а не массив или агрегат .

## Aggregate Initialization (Агрегатная инициализация)

**Aggregate initialization** — это конкретная форма инициализации, которая применяется к **агрегатам** — типам, которые не имеют пользовательских конструкторов и соответствуют определённым критериям. В C++11 и позднее агрегатная инициализация является частным случаем list-initialization (инициализации списком) .

### Что такое агрегат

**Агрегат** — это один из следующих типов:
- Массив
- Класс (обычно `struct` или `union`), который:
  - не имеет объявленных пользователем или унаследованных конструкторов (до C++11 — не имеет пользовательских конструкторов; в C++11–C++17 — не имеет user-provided конструкторов, но явно defaulted или deleted разрешены) 
  - не имеет закрытых (private) или защищённых (protected) нестатических членов данных
  - не имеет виртуальных функций
  - не имеет виртуальных, закрытых или защищённых базовых классов (начиная с C++17) 

### Как работает агрегатная инициализация

При агрегатной инициализации элементы инициализатора `{...}` **последовательно применяются к элементам агрегата** в порядке их объявления :

```cpp
struct Point {
    int x;
    int y;
};

Point p{1, 2};  // x = 1, y = 2
int arr[3] = {10, 20, 30};  // arr[0]=10, arr[1]=20, arr[2]=30
```

Если инициализаторов меньше, чем элементов, **оставшиеся элементы инициализируются значениями по умолчанию** (value-initialized) или с помощью default member initializers, если они указаны :

```cpp
struct S { int a; int b = 42; int c; };
S s{1};  // a=1, b=42, c=0 (value-initialized)
```

### Назначенные инициализаторы (Designated Initializers, C++20)

Начиная с C++20, в агрегатной инициализации можно использовать **назначенные инициализаторы** для явного указания, какой член инициализируется :

```cpp
struct A { int x; int y; int z; };

A a{.x = 1, .z = 3};  // y инициализируется нулём
// A b{.y = 2, .x = 1}; // ОШИБКА: порядок designation не совпадает с порядком объявления
```

Порядок назначенных инициализаторов **должен совпадать** с порядком объявления членов в структуре. В отличие от C, в C++ нельзя пропускать designation с нарушением порядка, использовать вложенные designation или смешивать назначенные инициализаторы с обычными .

### Пропуск фигурных скобок (Brace Elision)

При агрегатной инициализации вложенных агрегатов фигурные скобки можно опускать для совместимости с C :

```cpp
struct S1 { int a, b; };
struct S2 { S1 s, t; };

S2 x[2] = {1, 2, 3, 4, 5, 6, 7, 8};
// Эквивалентно:
// S2 x[2] = {{{1, 2}, {3, 4}}, {{5, 6}, {7, 8}}};
```

Однако это работает только при использовании синтаксиса `T object = {...}` или `T object{...}` (начиная с C++14); при использовании круглых скобок (C++20) правила другие .

## Соотношение понятий

- **Uniform initialization** — это **философия и синтаксис** (использование `{}` везде).
- **Aggregate initialization** — это **конкретный механизм** инициализации агрегатных типов, который является одним из путей, выбираемых при list-initialization (инициализации списком).

Когда вы пишете `T obj{...}`:
1. Если `T` — агрегат, выполняется **aggregate initialization**.
2. Иначе, если у `T` есть конструктор от `std::initializer_list`, он используется.
3. Иначе рассматриваются обычные конструкторы.
4. Если ничего не подходит, и `T` — агрегат, всё равно может сработать aggregate initialization (через parenthesized aggregate initialization в C++20, но это отдельная тема) .

Таким образом, uniform initialization — это **надмножество** синтаксических возможностей, а aggregate initialization — один из **частных случаев** его применения.
