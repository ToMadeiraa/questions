# 44. Чем отличается интерфейс от абстрактного класса?

В C++ **на уровне синтаксиса языка отдельного понятия «интерфейс» не существует** . C++ не имеет ключевого слова `interface`, как Java или C#. Всё, что в других языках называется интерфейсом, в C++ реализуется через абстрактные классы.

Однако на **концептуальном уровне** (и в практике программирования) различия провести можно. Интерфейс — это, по сути, «строгая» или «чистая» форма абстрактного класса.

### Ключевое различие: наличие реализации

**Абстрактный класс** — это класс, который содержит **хотя бы одну чисто виртуальную функцию** (объявленную с `= 0`). Такой класс нельзя инстанцировать (создать его объект), но он **может содержать**:
- обычные (не виртуальные) методы с готовой реализацией;
- виртуальные методы с реализацией по умолчанию;
- поля данных (состояние);
- конструкторы и деструкторы.

**Интерфейс** (в понимании C++-программистов) — это абстрактный класс, который содержит **только чисто виртуальные функции** и, как правило, **не имеет полей данных** и готовых реализаций . Он задаёт исключительно «контракт»: какие методы должны быть реализованы в наследующих классах, не навязывая никакого поведения или состояния.

### Сравнительная таблица

| Характеристика | Абстрактный класс | «Интерфейс» (идиома C++) |
| :--- | :--- | :--- |
| **Чисто виртуальные функции** | Минимум одна | Все методы (обычно) |
| **Реализация методов** | Может быть | Обычно отсутствует |
| **Поля данных (состояние)** | Может иметь | Обычно отсутствуют |
| **Множественное наследование** | Поддерживается | Поддерживается (и активно используется) |
| **Назначение** | Повторное использование кода + полиморфизм | Определение контракта (чистый полиморфизм) |

### Важное следствие: множественное наследование

Поскольку интерфейс не несёт состояния и реализации, его безопасно использовать в **множественном наследовании**. Класс в C++ может наследовать от одного «настоящего» базового класса (с реализацией и данными) и от нескольких «интерфейсов» одновременно. Это позволяет классу реализовывать несколько независимых контрактов, не сталкиваясь с проблемой ромбовидного наследования состояния .

### Пример

```cpp
// Абстрактный класс: есть и контракт, и общая реализация
class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;  // чисто виртуальная — контракт
    
    void printInfo() const {          // готовая реализация
        std::cout << "Area: " << area() << "\n";
    }
protected:
    std::string name_;                // состояние
};

// «Интерфейс»: только контракт, без состояния и реализации
class Drawable {
public:
    virtual ~Drawable() = default;
    virtual void draw() const = 0;    // только чисто виртуальные
    virtual void resize(double factor) = 0;
};

// Класс реализует оба контракта
class Circle : public Shape, public Drawable {
public:
    double area() const override { return 3.14 * r_ * r_; }
    void draw() const override { /* ... */ }
    void resize(double factor) override { r_ *= factor; }
private:
    double r_;
};
```

### Резюме

Если вам нужно **переиспользовать код** (общая реализация, вспомогательные методы, состояние) — используйте **абстрактный класс**. Если вам нужно только **задать набор требований** к классу, не диктуя, как именно он должен быть устроен внутри, — используйте **«интерфейс»** (абстрактный класс с одними чисто виртуальными функциями).
