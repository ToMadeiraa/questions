# 130. Расскажите о read-write mutex

**Read-write mutex** (или `shared_mutex` в терминологии стандарта C++17) — это примитив синхронизации, который позволяет решить классическую проблему "читателей и писателей". В отличие от обычного `std::mutex`, который обеспечивает строго эксклюзивный доступ, read-write mutex поддерживает два уровня блокировки: **разделяемый (shared)** для чтения и **эксклюзивный (exclusive)** для записи .

## Основная идея и семантика

Главная цель такого мьютекса — повысить параллелизм в сценариях, где данные читаются значительно чаще, чем модифицируются. Если несколько потоков только читают данные, они не мешают друг другу и могут делать это одновременно. Однако если потоку нужно произвести запись, он должен получить монопольный доступ, чтобы никакой другой поток (ни читатель, ни писатель) не видел данные в промежуточном, несогласованном состоянии .

Правила доступа формулируются следующим образом:
- **Разделяемая блокировка (`lock_shared`)**: Множество потоков могут одновременно удерживать разделяемую блокировку. Это позволяет им параллельно читать данные .
- **Эксклюзивная блокировка (`lock`)**: Только один поток может удерживать эксклюзивную блокировку. Пока она удерживается, никакие другие потоки не могут получить ни разделяемую, ни эксклюзивную блокировку .
- **Совместимость**: Разделяемые блокировки совместимы друг с другом. Эксклюзивная блокировка несовместима ни с чем, кроме самой себя (то есть она несовместима и с разделяемыми, и с другими эксклюзивными) .

## Реализация в стандартной библиотеке C++

Начиная с C++17, в заголовочном файле `<shared_mutex>` доступен класс `std::shared_mutex` .

Для удобного и безопасного (с точки зрения исключений) использования этого мьютекса применяются RAII-обертки:
- **`std::shared_lock`**: Используется для захвата разделяемой блокировки (для чтения). Он вызывает `lock_shared()` в конструкторе и `unlock_shared()` в деструкторе .
- **`std::unique_lock`** (или `std::lock_guard`): Используется для захвата эксклюзивной блокировки (для записи). Он работает с `shared_mutex` через методы `lock()` и `unlock()` .

### Пример использования

Классический пример — потокобезопасный счетчик, который часто читают, но редко изменяют:

```cpp
#include <shared_mutex>
#include <iostream>
#include <thread>
#include <vector>

class ThreadSafeCounter {
    mutable std::shared_mutex mutex_;
    unsigned int value_ = 0;
public:
    // Чтение: захватываем shared_lock, несколько читателей могут работать одновременно
    unsigned int get() const {
        std::shared_lock lock(mutex_);
        return value_;
    }

    // Запись: захватываем unique_lock, доступ только у одного потока
    void increment() {
        std::unique_lock lock(mutex_);
        ++value_;
    }
};
```

## Важные нюансы и подводные камни

При использовании read-write mutex необходимо учитывать несколько аспектов:

1.  **Политика планирования (Reader/Writer Preference)**: Стандарт C++ не гарантирует, какая стратегия используется в конкретной реализации. Это может быть "предпочтение читателям" (новые читатели могут войти, даже если писатель ждет), "предпочтение писателям" (новые читатели блокируются, если есть ожидающий писатель) или что-то среднее . Это важно, так как при большом потоке читателей писатель может "голодать" (starvation), если новые читатели постоянно захватывают разделяемую блокировку. Многие реализации (например, в MSVC или некоторых версиях libstdc++) склоняются к защите от голодания писателей, блокируя новых читателей при наличии ожидающего писателя .

2.  **Отсутствие рекурсивности**: `std::shared_mutex` не является рекурсивным. Если поток, уже удерживающий разделяемую блокировку, попытается захватить эксклюзивную (или наоборот), это приведет к взаимной блокировке (deadlock) или неопределенному поведению .

3.  **Производительность**: Хотя `shared_mutex` и задумывался для повышения производительности при частом чтении, его использование не всегда быстрее обычного `std::mutex`. Внутренняя логика подсчета читателей и управления очередями может создавать дополнительные накладные расходы. Если критическая секция очень короткая, или соотношение чтения/записи невелико, обычный мьютекс может оказаться эффективнее .

4.  **Обновление блокировки**: В стандартной библиотеке C++ **нет** прямой поддержки "обновления" (upgrade) блокировки — то есть перехода от разделяемой блокировки к эксклюзивной без промежуточного разблокирования. Если потоку нужно сначала прочитать данные, а затем, при определенном условии, изменить их, ему придется отпустить `shared_lock` и заново захватить `unique_lock`. Это создает окно, в котором данные могут быть изменены другим потоком, поэтому логику часто приходится перепроверять.

## Резюме

Read-write mutex (`std::shared_mutex`) — это мощный инструмент для оптимизации сценариев с интенсивным чтением. Он позволяет достичь высокого параллелизма за счет одновременного доступа множества читателей, но требует осторожного обращения с политиками планирования и потенциальными проблемами голодания, а также не всегда гарантирует выигрыш в производительности по сравнению с обычным мьютексом.
