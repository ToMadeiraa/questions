# 93. Что такое паттерн Observer?

**Observer (Наблюдатель)** — это поведенческий паттерн проектирования, который определяет зависимость типа «один ко многим» между объектами: при изменении состояния одного объекта (издателя) все зависящие от него объекты (подписчики) автоматически получают уведомление и обновляются .

Этот паттерн также известен под названиями **Publish-Subscribe (Издатель-Подписчик)** или **Listener (Слушатель)** .

## Основная идея и участники

Паттерн решает проблему сильной связанности (tight coupling). Без него, если объекту A нужно реагировать на изменения в объекте B, объект A должен постоянно опрашивать B или быть жестко привязан к его конкретному классу. Observer позволяет издателю ничего не знать о конкретных классах своих подписчиков, работая с ними через общий интерфейс .

В паттерне выделяют две основные роли:

1.  **Subject (Издатель / Субъект)**: Объект, который содержит интересное для других состояние. Он ведет список подписчиков (наблюдателей) и предоставляет методы для регистрации (`subscribe`/`attach`) и удаления (`unsubscribe`/`detach`) подписчиков. При изменении своего состояния Издатель вызывает метод оповещения у каждого подписчика из списка .
2.  **Observer (Подписчик / Наблюдатель)**: Определяет интерфейс обновления (например, метод `update`), который вызывается Издателем при наступлении события. Конкретные классы Наблюдателей реализуют этот интерфейс, чтобы выполнить необходимые действия в ответ на уведомление .

## Как это работает (Механизм)

1.  **Подписка**: Клиентский код создает объекты Издателя и Наблюдателей. Наблюдатели регистрируются в Издателе, передавая ему ссылку на себя (обычно через метод `addObserver`).
2.  **Событие**: Внутри Издателя происходит изменение состояния (например, пользователь нажал кнопку, пришли новые данные).
3.  **Уведомление**: Издатель перебирает внутренний список зарегистрированных Наблюдателей и вызывает у каждого из них метод оповещения (например, `notify` или `update`).
4.  **Реакция**: Каждый Наблюдатель, получив вызов, выполняет свою логику (например, перерисовывает график, обновляет текст на экране, отправляет письмо).

## Ключевые преимущества

*   **Слабая связанность (Loose Coupling)**: Издатель не зависит от конкретных классов подписчиков. Он знает только, что у них есть метод, соответствующий интерфейсу Observer .
*   **Динамичность**: Список подписчиков формируется во время выполнения программы. Вы можете добавлять или удалять Наблюдателей на лету, не останавливая работу системы .
*   **Принцип открытости/закрытости**: Вы можете добавлять новых Наблюдателей, не изменяя код Издателя .

## Недостатки и ограничения

*   **Порядок уведомления**: Подписчики оповещаются в случайном порядке, который не гарантируется .
*   **Утечки памяти**: Если Наблюдатель не отписался от Издателя перед своим удалением, Издатель может продолжать хранить на него ссылку, не позволяя сборщику мусора очистить память .
*   **Сложность отладки**: Из-за неявных связей (Издатель вызывает код, о котором он ничего не знает), поток выполнения программы может быть сложнее отследить, чем при прямых вызовах.

## Типичные примеры использования

*   **Пользовательские интерфейсы**: Обработка событий нажатия кнопок, изменения текста в поле ввода (паттерн лежит в основе большинства GUI-фреймворков, таких как Java Swing, .NET Windows Forms) .
*   **MVC (Model-View-Controller)**: Модель (данные) выступает Издателем, а Представления (Views) — Наблюдателями. Когда данные меняются, представления обновляются автоматически .
*   **Событийно-ориентированные системы**: Реакция на приход сетевых пакетов, сообщений из очереди или изменение состояния файловой системы.

### Пример реализации (Псевдокод)

```java
// Интерфейс Наблюдателя
interface Observer {
    void update(String message);
}

// Интерфейс Издателя
interface Subject {
    void attach(Observer o);
    void detach(Observer o);
    void notifyObservers();
}

// Конкретный Издатель
class NewsAgency implements Subject {
    private List<Observer> observers = new ArrayList<>();
    private String news;

    public void attach(Observer o) { observers.add(o); }
    public void detach(Observer o) { observers.remove(o); }

    public void setNews(String news) {
        this.news = news;
        notifyObservers();
    }

    public void notifyObservers() {
        for (Observer o : observers) {
            o.update(news);
        }
    }
}

// Конкретный Наблюдатель
class NewsChannel implements Observer {
    public void update(String news) {
        System.out.println("Новость: " + news);
    }
}
```
