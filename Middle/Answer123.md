# 123. В чем разница между многопоточностью и асинхронностью?

## Краткое определение

- **Многопоточность (multithreading)** — это *механизм реализации* параллельного выполнения: несколько потоков операционной системы выполняют код одновременно (или квази-одновременно на одном ядре).
- **Асинхронность (asynchrony)** — это *модель программирования*, при которой операция инициируется, но результат получается позже, без блокировки вызывающего потока. Это про *порядок выполнения и ожидание*, а не про количество потоков.

Ключевая мысль: **это ортогональные понятия**. Асинхронность можно реализовать без многопоточности (например, через event loop), а многопоточность может быть синхронной (потоки ждут друг друга через `join`/мьютексы).

---

## Сравнительная таблица

| Критерий | Многопоточность | Асинхронность |
|---|---|---|
| Уровень абстракции | Механизм ОС (ресурсы) | Модель/паттерн программирования |
| Суть | Параллельное выполнение кода | Неблокирующее ожидание результата |
| Ресурсы | Поток = стек + контекст ОС (дорого) | Может быть корутина/колбэк (дёшево) |
| Кто переключает | Планировщик ОС (вытесняющая) | Программист/рантайм (кооперативная) |
| Обязателен ли параллелизм | Да (потенциально) | Нет |
| Основная проблема | Гонки данных, блокировки, deadlock | Сложность управления состоянием, callback hell |

## Многопоточность в C++

Стандарт C++11 даёт `std::thread`, `std::mutex`, `std::atomic`, `std::condition_variable` и т.д.

```cpp
#include <thread>
#include <iostream>

void work(int id) {
    std::cout << "Поток " << id << " работает\n";
}

int main() {
    std::thread t1(work, 1);
    std::thread t2(work, 2);
    t1.join();   // синхронное ожидание завершения
    t2.join();
    // Здесь оба потока реально могли выполняться параллельно на разных ядрах.
}
```

Особенности:
- Потоки **вытесняются** планировщиком ОС — код может быть прерван в любой момент (нужна синхронизация).
- Создание потока — «дорогая» операция (сотни микросекунд).
- Если поток заблокирован на I/O (`read`, `recv`), он **простаивает**, но занимает ресурсы.

## Асинхронность в C++

В C++20 появились **корутины** (`co_await`, `co_yield`, `co_return`), а также есть `std::future`/`std::async` и `std::promise`. Асинхронность отвечает на вопрос «*как не блокироваться, пока ждём результат*».

```cpp
#include <future>
#include <iostream>

int compute() { return 42; }

int main() {
    // std::async может (но не обязан!) запустить отдельный поток
    std::future<int> f = std::async(std::launch::async, compute);

    // ... делаем что-то полезное, не блокируясь ...
    std::cout << "Работаем параллельно\n";

    int result = f.get(); // блокируемся только когда результат реально нужен
    std::cout << result << "\n";
}
```

Пример корутины (упрощённо, C++20):

```cpp
task<int> async_fetch() {
    auto data = co_await read_socket();  // не блокирует поток
    co_return parse(data);
}
```

Особенности:
- Асинхронная операция **не обязательно** занимает отдельный поток: event loop / реактор может обслуживать тысячи задач в одном потоке (как в `boost::asio` или `Node.js`).
- Переключение между задачами **кооперативное** — происходит в точках `co_await`/`await`.
- Дёшево по ресурсам: корутина — это объект в куче, а не стек ОС.

---

## Главные различия по пунктам

1. **Что решает.**
   Многопоточность решает задачу *параллельного использования ядер CPU*. Асинхронность решает задачу *эффективного ожидания* (особенно I/O), чтобы не блокировать поток.

2. **Кто управляет переключением.**
   При многопоточности — ОС (вытесняющая многозадачность, preemptive). При асинхронности — рантайм/программист (кооперативная, cooperative).

3. **Блокировки.**
   Многопоточный код требует мьютексов и атомиков из-за гонок. Асинхронный код в одном потоке часто вообще не требует блокировок (но требует аккуратной работы с состоянием между `await`).

4. **Стоимость.**
   Поток — дорого (стек ~МБ, syscall). Корутина/задача — дёшево (можно иметь миллионы).

5. **Масштабирование.**
   Тысячи потоков — плохо (переключения контекста). Тысячи асинхронных задач — нормально.

6. **Комбинируемость.**
   Асинхронность и многопоточность **сочетаются**: пул потоков (`thread pool`) выполняет асинхронные задачи; `boost::asio` может запускать event loop на нескольких потоках.

## Аналогия

- **Многопоточность** — это несколько поваров на кухне, каждый готовит своё блюдо одновременно.
- **Асинхронность** — это один повар, который поставил вариться суп и, пока он готовится, нарезает салат. Работы выполняются «параллельно» по времени, но рук (потоков) — одна.

## Что выбрать в C++

| Сценарий | Рекомендация |
|---|---|
| Тяжёлые вычисления на многоядерном CPU | Многопоточность (`std::thread`, пул потоков, `std::execution`/parallel algorithms) |
| Много сетевых соединений / файловый I/O | Асинхронность (`boost::asio`, корутины C++20) |
| Смешанный сценарий | Асинхронный фреймворк + пул потоков (thread pool) |
| Простые задачи «запусти и дождись» | `std::async` / `std::future` |

**Итог:** многопоточность — это *инструмент* (потоки ОС), асинхронность — это *стиль организации кода* (неблокирующее ожидание). Они не заменяют, а дополняют друг друга; выбор зависит от того, нужен ли вам реальный параллелизм вычислений или эффективное ожидание I/O.
