# 57. Что такое ключевое слово friend и когда его нужно использовать?

`friend` — это ключевое слово в C++, которое позволяет классу предоставить доступ к своим **закрытым (`private`)** и **защищённым (`protected`)** членам функции или другому классу, не являющимся членами данного класса .

По умолчанию сокрытие данных (инкапсуляция) запрещает внешний доступ к `private` и `protected` членам. `friend` создаёт точечное исключение из этого правила: класс сам «дружит» с кем-то, открывая ему доступ к своей внутренней реализации. Важно понимать: дружба не наследуется, не является взаимной (если A объявил B другом, B не получает автоматического доступа к A) и не может быть объявлена кем-то извне — только сам класс решает, кто его друзья .

### Синтаксис

Внутри определения класса можно объявить:

```cpp
class MyClass {
    // Дружественная функция (не член класса)
    friend void friendFunction(MyClass& obj);
    
    // Дружественный класс
    friend class FriendClass;
    
    // Дружественная функция-член другого класса
    friend void OtherClass::someMethod(MyClass& obj);
    
private:
    int secretData;
};
```

### Когда нужно использовать `friend`

Использование `friend` оправдано в нескольких типичных сценариях, где альтернативы (геттеры/сеттеры) привели бы к избыточному коду или нарушению симметрии.

#### 1. Перегрузка операторов ввода-вывода (`<<` и `>>`)

Это самый распространённый и каноничный случай. Операторы `operator<<` и `operator>>` должны быть не-членами класса, потому что левым операндом выступает поток (`std::ostream`/`std::istream`), а не ваш объект. Чтобы иметь доступ к приватным полям для вывода или чтения, их объявляют друзьями .

```cpp
class Point {
    friend std::ostream& operator<<(std::ostream& os, const Point& p);
private:
    int x, y;
};

std::ostream& operator<<(std::ostream& os, const Point& p) {
    return os << "(" << p.x << ", " << p.y << ")"; // доступ к private
}
```

#### 2. Перегрузка бинарных операторов для симметрии

Если вы определяете оператор как функцию-член, левым операндом **обязательно** должен быть объект вашего класса. Это ломает симметрию для случаев вроде `2 * complexNumber`. Чтобы оператор работал с левым операндом другого типа (например, `int * MyClass`), его нужно сделать свободной функцией, а для доступа к приватным данным — объявить другом.

```cpp
class Complex {
    friend Complex operator*(int scalar, const Complex& c);
private:
    double re, im;
};

Complex operator*(int scalar, const Complex& c) {
    return Complex{scalar * c.re, scalar * c.im}; // доступ к private
}
```

#### 3. Функция `swap`

Реализация эффективного `swap` (особенно для классов с дорогим копированием) часто требует обмена внутренними указателями или ресурсами напрямую. Если `swap` определена как свободная функция, она нуждается в дружбе для доступа к приватным членам .

```cpp
class Buffer {
    friend void swap(Buffer& a, Buffer& b) noexcept;
private:
    char* data;
    size_t size;
};

void swap(Buffer& a, Buffer& b) noexcept {
    std::swap(a.data, b.data);
    std::swap(a.size, b.size);
}
```

#### 4. Тесная кооперация между классами

Иногда два класса образуют тесную пару (например, контейнер и его итератор, или класс и его фабрика/строитель). Итератору часто нужен доступ к внутренностям контейнера, чтобы эффективно перемещаться по данным. Вместо того чтобы делать итератор вложенным классом (что не всегда удобно), контейнер может объявить его другом.

### Чего стоит избегать

`friend` — это инструмент, который **ослабляет инкапсуляцию**. Его не стоит использовать как «быстрый способ» обойти `private` без веской причины. Если вам просто нужен доступ к данным извне, часто лучше пересмотреть дизайн класса и предоставить необходимые публичные методы. Чрезмерное использование `friend` делает классы сильно связанными (`tightly coupled`), что усложняет поддержку и рефакторинг .

В современном C++ `friend` чаще всего встречается именно в идиомах перегрузки операторов, где без него не обойтись.
