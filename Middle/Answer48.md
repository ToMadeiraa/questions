# 48. Виртуальное наследование и порядок конструирования?

Виртуальное наследование в C++ решает проблему «ромба» (diamond problem) при множественном наследовании, гарантируя, что в самом производном объекте будет присутствовать только один экземпляр общего виртуального базового класса . Однако это существенно влияет на порядок вызова конструкторов.

## Суть виртуального наследования

При обычном (невиртуальном) множественном наследовании, если два промежуточных класса наследуют от одного и того же базового класса, то в конечном производном классе этот базовый класс будет присутствовать дважды. Это приводит к неоднозначности доступа и избыточности данных .

При виртуальном наследовании (синтаксис `virtual public Base`) компилятор гарантирует, что для каждого уникального виртуального базового класса в иерархии будет создан только один подобъект, независимо от того, сколько раз он встречается на путях наследования .

## Порядок конструирования

Порядок инициализации при наличии виртуальных базовых классов строго регламентирован и отличается от обычного:

1.  **Виртуальные базовые классы**: Сначала конструируются все виртуальные базовые классы. Порядок их инициализации определяется обходом иерархии в глубину слева направо (относительно порядка объявления в списке базовых классов) .
2.  **Невиртуальные базовые классы**: Затем конструируются непосредственные невиртуальные базовые классы в порядке их объявления слева направо .
3.  **Члены класса**: После базовых классов конструируются нестатические члены данных в порядке их объявления в классе.
4.  **Тело конструктора**: В последнюю очередь выполняется тело конструктора самого класса.

**Ключевое правило:** Конструкторы виртуальных базовых классов вызывает **только самый производный класс** (most derived class). Промежуточные классы в своих списках инициализации игнорируют вызовы конструкторов виртуальных баз, если только они не являются самым производным объектом .

### Пример

Рассмотрим иерархию:

```cpp
struct VBase {
    VBase(int x) { /* ... */ }
};

struct A : virtual VBase {
    A() : VBase(1) { /* ... */ } // Этот вызов будет проигнорирован при конструировании D
};

struct B : virtual VBase {
    B() : VBase(2) { /* ... */ } // Этот вызов будет проигнорирован при конструировании D
};

struct D : A, B {
    D() : VBase(3), A(), B() { /* ... */ } // Только этот вызов VBase(3) сработает
};
```

При создании объекта `D`:
1.  Сначала вызывается `VBase(3)`, так как `D` является самым производным классом и явно инициализирует виртуальную базу.
2.  Затем вызывается `A()` (который внутри пытается вызвать `VBase(1)`, но этот вызов игнорируется).
3.  Затем вызывается `B()` (вызов `VBase(2)` игнорируется).
4.  Выполняется тело `D()`.

Если же создать объект `A` напрямую, то `A` будет самым производным классом, и сработает вызов `VBase(1)` .

### Деструкторы

Порядок вызова деструкторов всегда строго обратен порядку конструирования: сначала тело деструктора самого класса, затем члены, затем невиртуальные базы, и в конце — виртуальные базы .
