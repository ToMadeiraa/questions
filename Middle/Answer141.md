# 141. Как работать с std::async?

`std::async` — это высокоуровневый инструмент для асинхронного выполнения задач, появившийся в C++11. Он запускает переданную функцию (или любой вызываемый объект) и возвращает `std::future`, который в будущем будет содержать результат вычислений или исключение, если оно произошло.

Основное его преимущество перед ручным созданием `std::thread` заключается в том, что `std::async` автоматически управляет жизненным циклом потока и берет на себя обработку исключений, передавая их в `future`.

### 1. Базовое использование

Для работы с `std::async` необходимо подключить заголовочный файл `<future>`.

```cpp
#include <iostream>
#include <future>
#include <chrono>

int compute(int a, int b) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    return a + b;
}

int main() {
    // Запускаем задачу асинхронно
    std::future<int> fut = std::async(std::launch::async, compute, 10, 20);

    // Пока задача выполняется в другом потоке, можно делать другую работу
    std::cout << "Main thread is working..." << std::endl;

    // Получаем результат (блокирует поток до готовности)
    int result = fut.get();
    std::cout << "Result: " << result << std::endl; // 30
    return 0;
}
```

### 2. Политики запуска (Launch Policies)

Второй аргумент `std::async` (необязательный) определяет, как именно будет выполнена задача. Это битовая маска, которая может принимать два основных значения:

| Политика | Описание |
| :--- | :--- |
| **`std::launch::async`** | **Принудительный асинхронный запуск.** Задача будет выполнена в отдельном новом потоке (или взята из пула потоков). Вызов `std::async` немедленно запускает выполнение. |
| **`std::launch::deferred`** | **Отложенный запуск (ленивые вычисления).** Задача **не** выполняется сразу. Она выполнится синхронно в том потоке, который вызовет `get()` или `wait()` на этом `future`. |
| **`std::launch::async \| std::launch::deferred`** | **Выбор за реализацией (по умолчанию).** Если политика не указана, используется эта комбинация. Стандарт разрешает реализации выбрать либо асинхронный запуск, либо отложенный, в зависимости от загрузки системы. |

**Важно:** Если вы хотите гарантировать параллельное выполнение, **всегда** явно указывайте `std::launch::async`.

### 3. Критически важные особенности и подводные камни

#### 3.1. «Невидимая» синхронизация (Деструктор `future`)

Это самая распространенная ошибка при работе с `std::async`.

Если вы используете политику `std::launch::async` и **не сохраняете** возвращенный `future` в переменную, деструктор временного объекта `future` немедленно вызовется в конце выражения. Поскольку `std::async` связан с потоком, его деструктор **блокирует** вызывающий поток до завершения задачи (выполняет неявный `join`).

```cpp
// ❌ ОПАСНО: Это выполнится СИНХРОННО!
std::async(std::launch::async, []{ 
    std::this_thread::sleep_for(std::chrono::seconds(2)); 
    std::cout << "Done"; 
});
// Деструктор временного future заблокировал поток здесь на 2 секунды.
std::cout << "This prints after Done";
```

**Правило:** Всегда сохраняйте `future` в именованную переменную, если хотите, чтобы задача выполнялась параллельно.

#### 3.2. Обработка исключений

Если функция внутри `std::async` выбрасывает исключение, оно не приводит к немедленному завершению программы (как в `std::thread`). Вместо этого исключение перехватывается и сохраняется в общем состоянии `future`. Оно будет выброшено заново только тогда, когда вы вызовете `get()`.

```cpp
auto fut = std::async(std::launch::async, []() -> int {
    throw std::runtime_error("Something went wrong");
});

try {
    fut.get(); // Исключение будет выброшено здесь
} catch (const std::exception& e) {
    std::cout << "Caught: " << e.what() << std::endl;
}
```

#### 3.3. Отличие от `std::thread`

| Характеристика | `std::async` | `std::thread` |
| :--- | :--- | :--- |
| **Управление потоком** | Автоматическое (RAII). Поток завершается или присоединяется при уничтожении `future` (для async) или при вызове `get/wait`. | Требует явного `join()` или `detach()`. Иначе при деструкторе произойдет `std::terminate`. |
| **Возврат результата** | Возвращает `std::future` (удобно для получения значений). | Нет встроенного механизма (нужно использовать `std::promise` или глобальные переменные). |
| **Исключения** | Автоматически передаются в `future`. | Приводят к вызову `std::terminate`, если не поймать внутри потока. |

### 4. Практические рекомендации

1.  **Всегда сохраняйте `future`**: Если вы не присвоите результат `std::async` переменной, код станет синхронным (см. пункт 3.1).
2.  **Явно указывайте `std::launch::async`**: Не полагайтесь на политику по умолчанию, если вам нужно именно параллельное выполнение, так как реализация может выбрать `deferred`.
3.  **Вызывайте `get()`**: Если задача завершилась исключением, а вы не вызвали `get()`, исключение будет молча проигнорировано при уничтожении `future` (хотя стандарт гарантирует, что деструктор дождется завершения потока для async-задач, он не перевыбросит исключение).
4.  **Осторожно с `deferred`**: Если вы используете `std::launch::deferred`, задача не начнется, пока вы не вызовете `get()` или `wait()`. Это может быть полезно для ленивых вычислений, но может привести к неожиданной блокировке в неподходящий момент.
