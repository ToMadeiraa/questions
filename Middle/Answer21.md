# 21. Как происходит вызов функции?

Вызов функции в C++ — это процесс передачи управления из точки вызова в тело функции, выполнения её кода и возврата управления обратно. Механизм включает несколько этапов, которые условно можно разделить на **подготовку вызова**, **передачу управления** и **возврат**.

## 1. Общая последовательность вызова

Упрощённо вызов функции `f(a, b)` происходит так:

1. **Вычисление аргументов** — значения фактических параметров вычисляются в порядке, определяемом компилятором (в C++ порядок вычисления аргументов **не определён** стандартом, кроме особых случаев, например списков инициализации).
2. **Передача аргументов** — значения (или адреса для ссылок/указателей) помещаются туда, откуда функция их ожидает (регистры, стек).
3. **Передача управления** — выполняется инструкция `call`, которая сохраняет адрес возврата и передаёт управление на точку входа функции.
4. **Пролог функции** — сохранение регистров, настройка кадра стека (`push rbp; mov rbp, rsp` и т.п.), выделение места под локальные переменные.
5. **Тело функции** — выполняются инструкции.
6. **Эпилог** — восстановление кадра стека, сохранённых регистров.
7. **Возврат управления** — инструкция `ret` извлекает адрес возврата и передаёт управление обратно в точку после `call`.
8. **Использование результата** — возвращённое значение (если есть) читается из регистра/памяти в месте вызова.

## 2. Соглашение о вызовах (calling convention)

Ключевой элемент — **соглашение о вызовах**, которое определяет:
- как передаются аргументы (регистры, стек, их порядок);
- кто очищает стек (вызывающий или вызываемый);
- как возвращается результат;
- какие регистры сохраняются вызываемым.

Основные соглашения на x86-64:

| Соглашение | Аргументы | Возврат | Очистка стека |
|---|---|---|---|
| `cdecl` (x86) | через стек справа налево | `EAX` | вызывающий |
| `stdcall` (x86) | через стек справа налево | `EAX` | вызываемый |
| `fastcall` | первые в `ECX`/`EDX`, остальные в стеке | `EAX` | вызываемый |
| System V AMD64 (Linux) | `RDI, RSI, RDX, RCX, R8, R9`, остальные в стеке | `RAX` (+ `RDX` для 128-бит) | вызывающий |
| Microsoft x64 (Windows) | `RCX, RDX, R8, R9`, остальные в стеке | `RAX` | вызывающий |

Например, для System V AMD64 вызов `int f(int a, int b, int c)` передаст `a` в `EDI`, `b` в `ESI`, `c` в `EDX`, а результат вернётся в `EAX`.

## 3. Кадр стека (stack frame)

При вызове функции создаётся **кадр стека** (activation record), обычно содержащий:

- **возвращаемый адрес** (кладётся инструкцией `call`);
- **сохранённый указатель кадра** (`RBP`/`EBP`);
- **локальные переменные**;
- **сохранённые регистры** (callee-saved);
- **временные значения** (spill slots).

Типичный пролог:

```asm
push rbp          ; сохранить старый указатель кадра
mov  rbp, rsp     ; установить новый указатель кадра
sub  rsp, 32      ; выделить место под локальные переменные
```

Эпилог:

```asm
mov  rsp, rbp     ; восстановить указатель стека
pop  rbp          ; восстановить старый указатель кадра
ret               ; вернуть управление
```

## 4. Передача аргументов

- **По значению** — копия значения передаётся в регистр/стек.
- **По ссылке** (`T&`, `const T&`) — передаётся адрес объекта.
- **По указателю** (`T*`) — передаётся значение указателя (адрес).
- **Объекты классов** — передаются по значению через копирующий конструктор (копия кладётся в стек или в регистры), либо по ссылке; крупные объекты часто передаются «скрытым указателем».
- **Возврат крупных объектов** — используется **RVO/NRVO** (return value optimization) или скрытый параметр (sret — указатель на место для результата, передаётся первым аргументом).

## 5. Возврат значения

- Скалярные типы возвращаются в регистре (`RAX`/`EAX`), `float`/`double` — в `XMM0`.
- Малые структуры (≤ 16 байт на System V) — в `RAX`/`RDX` (или `XMM`).
- Крупные структуры — через скрытый указатель на память, выделенную вызывающим.

## 6. Ключевые моменты C++

- **Порядок вычисления аргументов не определён** — нельзя полагаться на него (исключение: braced-init-list).
- **Вызов виртуальной функции** (`virtual`) — через **vtable**: объект содержит указатель на таблицу виртуальных функций, вызов идёт косвенно (`call [vptr + offset]`), это **динамическое связывание**.
- **Встраивание (inlining)** — компилятор может заменить вызов телом функции, тогда никакой передачи управления не происходит; это оптимизация, не меняющая семантику.
- **Перегрузка** разрешается на этапе компиляции (статическое связывание).
- **Вызов через указатель на функцию / `std::function` / лямбду** — косвенный вызов, соглашение о вызовах у них обычно `cdecl`/System V.
- **Исключения** — при выбросе исключения происходит разворачивание стека (stack unwinding) с вызовом деструкторов локальных объектов.

## 7. Пример

```cpp
int add(int a, int b) { return a + b; }

int main() {
    int x = add(2, 3); // вызов
    return x;
}
```

Упрощённый ассемблер (System V AMD64):

```asm
main:
    mov  edi, 2        ; 1-й аргумент
    mov  esi, 3        ; 2-й аргумент
    call add           ; сохранить адрес возврата и перейти
    mov  DWORD PTR [rbp-4], eax   ; сохранить результат
    ...
add:
    push rbp
    mov  rbp, rsp
    mov  DWORD PTR [rbp-4], edi   ; a
    mov  DWORD PTR [rbp-8], esi   ; b
    mov  eax, DWORD PTR [rbp-4]
    add  eax, DWORD PTR [rbp-8]
    pop  rbp
    ret                ; вернуть управление
```

Таким образом, вызов функции — это согласованный набор действий компилятора и процессора: подготовка аргументов согласно ABI, инструкция `call`, создание кадра стека, выполнение тела, восстановление состояния и инструкция `ret`, возвращающая управление в точку вызова.
