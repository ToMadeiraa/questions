# 115. Как расширить STL-контейнеры?

Расширение STL-контейнеров — задача, которую нужно решать с осторожностью, поскольку стандарт C++ накладывает строгие ограничения на вмешательство в пространство имён `std`. В зависимости от цели, существуют разные合法 подходы: от адаптации существующих контейнеров через композицию или наследование до ограниченной специализации шаблонов.

### 1. Главное правило: не добавляйте объявления в `namespace std`

Стандарт C++ явно указывает, что добавление любых объявлений или определений в пространство имён `std` (или вложенные в него) является **неопределённым поведением (undefined behavior)** . Это означает, что попытка добавить свой метод напрямую в `std::vector` или `std::map` через открытие `namespace std` — это прямой путь к непредсказуемым ошибкам, которые могут проявиться при смене компилятора или даже версии стандартной библиотеки.

### 2. Легальное расширение через специализацию шаблонов

Единственное исключение, разрешённое стандартом, — это **явная специализация шаблонов** для **пользовательских типов** (program-defined types). Вы можете специализировать шаблон стандартной библиотеки в `namespace std` только если:
1. Специализация зависит как минимум от одного пользовательского типа.
2. Специализация удовлетворяет всем требованиям оригинального шаблона.

**Классический пример — `std::hash`:**

Если вы хотите использовать свой тип `MyType` в качестве ключа в `std::unordered_map`, вы можете специализировать `std::hash` для него:

```cpp
#include <typeindex> // Гарантирует объявление std::hash

struct MyType {
    std::size_t hash() const { /* ... */ }
};

template<>
struct std::hash<MyType> {
    std::size_t operator()(const MyType& t) const { 
        return t.hash(); 
    }
};
```

Обратите внимание: даже в этом случае не нужно открывать `namespace std` вручную — используется синтаксис `template<> struct std::hash<MyType>` .

### 3. Создание собственных контейнеров на основе существующих

Если вам нужен контейнер с расширенной функциональностью (например, `set`, который не сортирует элементы, или контейнер с дополнительными методами), правильный путь — **создать свой класс**, который использует стандартный контейнер внутри.

#### Вариант А: Композиция (предпочтительный)

Композиция — самый безопасный способ. Вы создаёте класс, который содержит стандартный контейнер как член и предоставляет нужный интерфейс. Это позволяет ограничить или расширить функциональность по своему усмотрению, не нарушая инвариантов STL .

```cpp
template <class T>
class MyVector {
    std::vector<T> data;
public:
    void push_back(const T& value) { 
        // Ваша дополнительная логика
        data.push_back(value); 
    }
    // Делегируйте нужные методы
    auto begin() { return data.begin(); }
    auto end() { return data.end(); }
    // ...
};
```

#### Вариант Б: Наследование (с осторожностью)

Можно унаследоваться от стандартного контейнера, но это рискованно, так как деструкторы стандартных контейнеров не являются виртуальными. Если вы передадите указатель на базовый класс и удалите объект через него, поведение будет неопределённым. Наследование допустимо только если вы не планируете полиморфное удаление и не добавляете данные-члены, которые могут нарушить инварианты .

```cpp
template <class T>
class MyVector : public std::vector<T> {
public:
    // Переопределение или добавление методов
    void my_extension() { /* ... */ }
};
```

### 4. Что делать, если нужен «новый алгоритм» для существующего контейнера?

Если вам нужна функция, которая работает с `std::vector` или `std::list`, но её нет в `<algorithm>`, просто напишите **свободную функцию** в своём пространстве имён. Она будет принимать контейнер (или пару итераторов) и работать с ним через публичный интерфейс. Это не является расширением STL в буквальном смысле, но решает задачу без нарушения правил.

```cpp
namespace my_algorithms {
    template <typename Container>
    void print_all(const Container& c) {
        for (const auto& elem : c) {
            std::cout << elem << ' ';
        }
    }
}
```

### Резюме

| Подход | Безопасность | Когда использовать |
|---|---|---|
| Добавление в `namespace std` | **Запрещено** (UB) | Никогда |
| Специализация шаблона для своего типа | Разрешено | `std::hash`, `std::numeric_limits` и т.п. для ваших типов |
| Композиция | Безопасно | Нужен кастомный контейнер с расширенным/ограниченным интерфейсом |
| Наследование от STL | Опасно | Только если нет полиморфного удаления и не нарушаются инварианты |
| Свободные функции | Безопасно | Нужны дополнительные алгоритмы, работающие с существующими контейнерами |
