# 50. Какие есть правила вывода типа при использовании auto? В каких случаях auto может привести к нежелательному копированию объекта?

## Правила вывода типа `auto`

`auto` использует те же правила вывода типа, что и параметры шаблонов функций (template argument deduction), за некоторыми исключениями. Ключевой момент: `auto` сам по себе **не является ссылкой** и **отбрасывает ссылки и cv-квалификаторы верхнего уровня** из инициализатора.

**Базовое правило:**
```cpp
int x = 42;
int& ref = x;
const int cx = 42;

auto a = x;      // a: int
auto b = ref;    // b: int (ссылка отброшена, копия)
auto c = cx;     // c: int (const отброшен)
```

Чтобы сохранить ссылку или квалификатор, их нужно указать явно:
```cpp
auto& d = ref;        // d: int&
const auto& e = cx;   // e: const int&
auto&& f = ref;       // f: int& (универсальная ссылка)
```

Особый случай — **фигурная инициализация** (`auto x = {1, 2, 3}`): в C++11/14 выводится `std::initializer_list<int>`, в C++17 правила уточнены. Рекомендуется использовать `auto x = expr;` с обычным `=`, чтобы избежать неожиданностей.

## Когда `auto` приводит к нежелательному копированию

Главная ловушка: **`auto` без `&` всегда создаёт копию**, даже если инициализатор является ссылкой или возвращает ссылку.

### Случай 1: range-based for без ссылки

```cpp
std::vector<std::string> strings = getStrings();
for (auto s : strings) {  // КОПИЯ каждой строки!
    // ...
}
```
Исправление: `for (const auto& s : strings)` — если не нужно изменять; `for (auto& s : strings)` — если нужно изменять.

### Случай 2: инициализация от функции, возвращающей ссылку

```cpp
std::string& return_by_ref();
auto s = return_by_ref();  // Копия, а не ссылка
```
Если копия не нужна, используйте `auto& s = return_by_ref();`.

### Случай 3: извлечение элемента из контейнера

```cpp
std::vector<BigObject> vec;
auto obj = vec[0];  // Копия BigObject
```
`vec[0]` возвращает `BigObject&`, но `auto` отбрасывает ссылку. Для работы с оригиналом: `auto& obj = vec[0];`.

### Практическое правило

| Намерение | Запись |
|---|---|
| Только читать, не копировать | `const auto&` |
| Изменять оригинал | `auto&` |
| Нужна независимая копия | `auto` (осознанно) |
| Мелкий тип (`int`, `double`) | `auto` допустимо |

Microsoft и Google C++ Style Guide явно предупреждают: `auto` без ссылки — распространённый источник случайных дорогостоящих копий. Google также отмечает, что читатель кода должен понимать, когда `auto` даст ссылку, а когда копию, иначе ошибки неизбежны.
