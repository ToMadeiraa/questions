# 162. Напишите максимально корректную реализацию класса string с конструктором копирования и оператором присваивания.

## Введение

Под «максимально корректной» реализацией в контексте учебного задания обычно понимается класс, который:
- корректно управляет динамической памятью (правило пяти: деструктор, копирующий конструктор, копирующее присваивание, перемещающие версии — опционально);
- обеспечивает **strong exception safety** (гарантию сильной безопасности исключений);
- поддерживает самоприсваивание (`s = s`);
- реализует copy-and-swap (идиома, устраняющая дублирование и дающая строгую гарантию).

Ниже — полная реализация с пояснениями.

## Полная реализация

```cpp
#include <cstring>
#include <utility>
#include <iostream>

class String {
public:
    // Конструктор по умолчанию
    String() noexcept
        : data_(nullptr), size_(0) {}

    // Конструктор из C-строки
    String(const char* str) {
        if (str) {
            size_ = std::strlen(str);
            data_ = new char[size_ + 1];
            std::memcpy(data_, str, size_ + 1);
        }
    }

    // Конструктор копирования
    String(const String& other) {
        size_ = other.size_;
        if (other.data_) {
            data_ = new char[size_ + 1];
            std::memcpy(data_, other.data_, size_ + 1);
        } else {
            data_ = nullptr;
        }
    }

    // Перемещающий конструктор (правило пяти)
    String(String&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    // Оператор копирующего присваивания через copy-and-swap
    String& operator=(const String& other) {
        if (this != &other) {
            String tmp(other);       // копия — может бросить исключение
            swap(tmp);               // обмен без исключений
        }                            // tmp уничтожает старые данные
        return *this;
    }

    // Оператор перемещающего присваивания
    String& operator=(String&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    // Деструктор
    ~String() {
        delete[] data_;
    }

    // Обмен
    void swap(String& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }

    // Вспомогательные методы
    std::size_t size() const noexcept { return size_; }
    const char* c_str() const noexcept { return data_ ? data_ : ""; }

private:
    char*       data_;
    std::size_t size_;
};

// Не-членный swap (ADL-friendly)
void swap(String& a, String& b) noexcept {
    a.swap(b);
}
```

## Пояснения по ключевым решениям

### 1. Копирующий конструктор

```cpp
String(const String& other) {
    size_ = other.size_;
    if (other.data_) {
        data_ = new char[size_ + 1];
        std::memcpy(data_, other.data_, size_ + 1);
    } else {
        data_ = nullptr;
    }
}
```

Здесь важно:
- Выделять память **только** если `other.data_` не `nullptr`, иначе получаем UB при `memcpy(nullptr, nullptr, ...)`.
- Копировать `size_ + 1` байт, включая завершающий `'\0'`, — это упрощает и `c_str()`, и последующую работу со строкой.

### 2. Копирующее присваивание: copy-and-swap

```cpp
String& operator=(const String& other) {
    if (this != &other) {
        String tmp(other);
        swap(tmp);
    }
    return *this;
}
```

**Почему это правильно:**

| Аспект | Как обеспечивается |
|---|---|
| Самоприсваивание | Проверка `this != &other` (или без неё — тогда `String tmp(other)` сделает копию, и всё равно безопасно; но проверка дешевле) |
| Сильная гарантия исключений | Если `new` бросит — объект не изменён; `swap` — `noexcept` |
| Утечка памяти | При выходе из `operator=` `tmp` уничтожает старый буфер `this` через свой деструктор |
| Дублирование кода | Копирование делегируется конструктору копирования |

Именно поэтому copy-and-swap считается «максимально корректным» идиоматическим решением: исключение может возникнуть только в одной точке (внутри конструктора копирования), и до этой точки состояние объекта не тронуто.

### 3. Правило пяти

Хотя в вопросе упомянуты только копирующие операции, корректный класс управления ресурсом должен реализовать всю пятёрку:
- деструктор,
- копирующий конструктор,
- копирующее присваивание,
- перемещающий конструктор,
- перемещающее присваивание.

Если не объявить перемещающие версии, копирующие версии всё равно будут работать — но компилятор не сгенерирует перемещающие (так называемые «правило пяти» / implicit move suppression). Поэтому в учебных реализациях перемещающие версии добавляют явно.

### 4. `swap` без исключений

`std::swap` для указателей и `std::size_t` не бросает исключений, поэтому `swap` помечен `noexcept` — это критично для корректной работы copy-and-swap и для того, чтобы `std::vector<String>` мог использовать перемещение.

### 5. Детали

- `c_str()` возвращает `""` вместо `nullptr` для пустого объекта — иначе UB при передаче в `printf`/`strlen`.
- Поле `size_` хранится отдельно — это позволяет избежать `strlen` на каждом шаге и делает класс ближе к `std::string`.
- Деструктор `delete[] data_` безопасен для `nullptr` — можно не проверять.

## Альтернативная реализация без copy-and-swap (классическая)

Иногда в заданиях ожидают «классический» вариант — с явным копированием и защитой от самоприсваивания:

```cpp
String& operator=(const String& other) {
    if (this != &other) {
        char* new_data = nullptr;
        if (other.data_) {
            new_data = new char[other.size_ + 1];
            std::memcpy(new_data, other.data_, other.size_ + 1);
        }
        delete[] data_;          // освобождаем только после успешного new
        data_ = new_data;
        size_ = other.size_;
    }
    return *this;
}
```

Ключевое здесь — **сначала выделить, потом освободить**, иначе при исключении в `new` объект останется в повреждённом состоянии (утечка или висячий указатель). Copy-and-swap делает то же самое компактнее и надёжнее.

## Резюме

Корректная реализация должна:
1. Реализовывать правило пяти (или, как минимум, «трёх»: деструктор + копирующий конструктор + копирующее присваивание).
2. Использовать copy-and-swap для присваивания — это даёт сильную гарантию исключений и решает проблему самоприсваивания.
3. Помечать `swap` и перемещающие операции как `noexcept`.
4. Обрабатывать `nullptr` во всех путях, где это возможно.
5. Не копировать «по-байтово» указатели — только содержимое буфера.
