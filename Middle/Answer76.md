# 76. Что такое move constructor?

**Move constructor (конструктор перемещения)** — это специальный конструктор класса в C++, который позволяет создать новый объект путём «перемещения» (переноса) ресурсов из другого объекта того же типа, вместо их копирования. Он был введён в стандарте C++11 и является ключевым элементом семантики перемещения (move semantics).

## Определение и сигнатура

Согласно стандарту, конструктор перемещения класса `T` — это **нешаблонный конструктор**, первый параметр которого имеет тип `T&&`, `const T&&`, `volatile T&&` или `const volatile T&&`, и при этом либо других параметров нет, либо все остальные параметры имеют значения по умолчанию .

Типичное объявление выглядит так:

```cpp
class MyClass {
public:
    // Конструктор перемещения
    MyClass(MyClass&& other) noexcept;
    
    // Или с явным указанием сгенерировать компилятором
    MyClass(MyClass&& other) = default;
    
    // Или запретить его генерацию
    MyClass(MyClass&& other) = delete;
};
```

## Когда вызывается

Конструктор перемещения вызывается, когда объект инициализируется из **rvalue** (xvalue или prvalue, в зависимости от версии стандарта) того же типа. Типичные ситуации :

- **Инициализация**: `T a = std::move(b);` или `T a(std::move(b));`, где `b` имеет тип `T`.
- **Передача аргумента в функцию**: `f(std::move(a));`, где `a` имеет тип `T`, а функция принимает `void f(T t)`.
- **Возврат из функции**: `return a;` внутри функции вида `T f()`, где `a` имеет тип `T`, для которого доступен конструктор перемещения.

## Ключевая идея: «кража» ресурсов

В отличие от конструктора копирования, который создаёт полную независимую копию объекта, конструктор перемещения обычно **«захватывает» ресурсы**, принадлежащие аргументу (например, указатели на динамически выделенную память, файловые дескрипторы, TCP-сокеты, потоки ввода-вывода, запущенные потоки и т.д.), вместо того чтобы их копировать .

После перемещения исходный объект (аргумент) остаётся в **некотором валидном, но неопределённом состоянии**. Например, после перемещения из `std::string` или `std::vector` исходный объект может оказаться пустым. Однако полагаться на это поведение не следует, так как оно не гарантировано стандартом. Для некоторых типов, таких как `std::unique_ptr`, состояние после перемещения строго определено .

## Неявно объявляемый конструктор перемещения

Если для класса (struct, class или union) не предоставлен пользовательский конструктор перемещения, и при этом выполнены все следующие условия :

- нет объявленного пользователем конструктора копирования;
- нет объявленного пользователем оператора присваивания копированием;
- нет объявленного пользователем оператора присваивания перемещением;
- нет объявленного пользователем деструктора,

то компилятор неявно объявит конструктор перемещения с сигнатурой `T::T(T&&)` как `inline public` член класса.

## Удалённый неявный конструктор перемещения

Неявно объявленный или явно дефолтированный конструктор перемещения определяется как **удалённый** (`= delete`), если выполняется любое из условий :

- класс имеет нестатические члены данных, которые не могут быть перемещены (их конструкторы перемещения удалены, недоступны или неоднозначны);
- класс имеет прямой или виртуальный базовый класс, который не может быть перемещён;
- класс имеет прямой или виртуальный базовый класс с удалённым или недоступным деструктором;
- класс является union и имеет вариант-член с нетривиальным конструктором копирования;
- класс имеет нестатический член данных или прямой/виртуальный базовый класс без конструктора перемещения, который не является тривиально копируемым.

## Тривиальный конструктор перемещения

Конструктор перемещения класса `T` является **тривиальным**, если выполнены все условия :

- он не предоставлен пользователем (т.е. неявно определён или дефолтирован);
- `T` не имеет виртуальных функций-членов;
- `T` не имеет виртуальных базовых классов;
- конструктор перемещения, выбранный для каждого прямого базового класса `T`, является тривиальным;
- конструктор перемещения, выбранный для каждого нестатического члена типа класса (или массива таких типов), является тривиальным;
- `T` не имеет нестатических членов данных с квалификатором `volatile`.

Тривиальный конструктор перемещения выполняет ту же работу, что и тривиальный конструктор копирования — по сути, побитовое копирование (`std::memmove`). Все типы, совместимые с языком C (POD-типы), являются тривиально перемещаемыми .

## Практический пример

Рассмотрим класс, управляющий динамическим массивом:

```cpp
class Buffer {
    int* data;
    size_t size;
public:
    // Конструктор перемещения
    Buffer(Buffer&& other) noexcept 
        : data(other.data), size(other.size) {
        // «Обнуляем» источник, чтобы его деструктор не освободил память повторно
        other.data = nullptr;
        other.size = 0;
    }
    
    ~Buffer() { delete[] data; }
    
    // Запрещаем копирование
    Buffer(const Buffer&) = delete;
    Buffer& operator=(const Buffer&) = delete;
};
```

При перемещении `Buffer b2 = std::move(b1);` указатель `data` просто передаётся от `b1` к `b2`, а `b1.data` устанавливается в `nullptr`. Никакого выделения памяти и копирования элементов не происходит — это значительно эффективнее копирования.

## Важность `noexcept`

Конструктор перемещения настоятельно рекомендуется помечать как `noexcept`, если он не выбрасывает исключений. Это критически важно, потому что стандартные контейнеры (например, `std::vector`) при перераспределении памяти используют конструктор перемещения только в том случае, если он объявлен как `noexcept` (или если копирование недоступно). В противном случае они предпочтут конструктор копирования, чтобы сохранить строгую гарантию безопасности исключений .
