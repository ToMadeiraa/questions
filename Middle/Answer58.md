# 58. Расскажите о лямбда-выражениях в С++ и доступ к переменным во внешней области видимости, захват this в лямбду и время жизни лямбды и захваченных переменных?

Лямбда-выражения в C++ (начиная с C++11) позволяют определять анонимные функции «на месте». Ключевой механизм, который делает их мощными и одновременно источником тонких ошибок, — это **захват переменных** из внешней области видимости. Ниже разобраны три запрошенных аспекта: доступ к внешним переменным, захват `this` и времена жизни.

## Доступ к переменным внешней области видимости

Лямбда может обращаться к переменным, видимым в точке её определения. Однако **захватывать можно только переменные с автоматической длительностью хранения** (локальные переменные, параметры). Переменные со статической длительностью (`static`, глобальные) захватывать в список захвата нельзя — их можно просто использовать внутри тела лямбды, поскольку они существуют всё время работы программы .

Способы захвата задаются в списке захвата `[]`:

| Синтаксис | Значение |
|-----------|----------|
| `[=]` | Неявный захват по значению всех автоматических переменных, которые используются в теле (включая неявный захват `this`) |
| `[&]` | Неявный захват по ссылке всех автоматических переменных, которые используются в теле |
| `[x, &y]` | Явный захват: `x` — по значению, `y` — по ссылке |
| `[x = expr]` | Инициализирующий захват (C++14): создаёт новую переменную `x` в замыкании, инициализированную `expr` |
| `[this]` | Захват указателя `this` по значению |
| `[*this]` | (C++17) Захват копии всего объекта, на который указывает `this` |

**Важно:** захват по значению (`[=]`) для членов класса **не копирует сами члены**. Если лямбда использует нестатический член класса, компилятор неявно захватывает указатель `this` (по значению), а доступ к члену происходит через разыменование этого указателя: `(*this).m` . Это частая причина ошибок, если лямбда переживает объект.

## Захват `this` в лямбду

При захвате `this` в замыкание копируется **указатель**, а не объект. Следовательно, лямбда получает доступ к исходному объекту, а не к его копии. Любые изменения членов через лямбду отразятся на исходном объекте .

```cpp
class Foo {
    int value = 0;
public:
    auto getLambda() {
        return [this]() { return ++value; }; // захвачен указатель this
    }
};
```

### Главная опасность: висячий `this`

Если лямбда, захватившая `this`, вызывается **после уничтожения объекта**, обращение к членам через этот указатель приводит к **неопределённому поведению** . Классический пример:

```cpp
auto lambda = Foo().getLambda(); // временный Foo уничтожен
lambda(); // UB: this висячий
```

Именно поэтому MISRA C++:2023 Rule 8.1.1 рекомендует **явно захватывать `this`**, а не полагаться на неявный захват через `[=]` или `[&]` в долгоживущих лямбдах, чтобы сделать намерение очевидным и избежать случайного захвата `this` .

Начиная с **C++17** доступен захват `[*this]`, который создаёт **копию всего объекта** внутри замыкания. Это безопаснее, если лямбда может пережить исходный объект, но следует помнить, что копирование может быть дорогим, а изменения в лямбде не отразятся на оригинале .

## Время жизни лямбды и захваченных переменных

Время жизни **самого замыкания** (объекта-лямбды) определяется обычными правилами C++: если лямбда сохранена в переменной, она живёт, пока жива эта переменная; если возвращена из функции — перемещается/копируется в вызывающий контекст.

Критический момент — **время жизни захваченных сущностей**:

- **Захват по значению:** замыкание хранит **собственную копию** переменной. Время жизни этой копии равно времени жизни замыкания. Оригинальная переменная может быть уничтожена — копия останется действительной .

- **Захват по ссылке:** замыкание хранит **ссылку** (фактически указатель) на оригинальную переменную. Замыкание **не продлевает** время жизни захваченной переменной. Если оригинальная переменная выходит из области видимости раньше, чем вызывается лямбда, возникает **висячая ссылка** и неопределённое поведение . Это касается и неявного захвата `this` через `[&]` или `[=]` — как описано выше.

- **Инициализирующий захват по ссылке** (`[&x = expr]`): стандарт уточняет, что время жизни ссылки заканчивается вместе с временем жизни объекта замыкания . Однако вопрос о продлении времени жизни временных объектов, привязываемых к таким ссылкам, остаётся предметом обсуждения в комитете (CWG issue 2737), и поведение разных компиляторов может различаться .

### Практическое правило

Если лямбда **не будет вызываться после выхода из области видимости** захваченных переменных (например, передаётся в алгоритм сразу или вызывается на месте), захват по ссылке безопасен и эффективен. Если лямбда **сохраняется** (в `std::function`, возвращается из функции, передаётся в асинхронный код) и может пережить захваченные сущности, используйте **захват по значению** или `[*this]` (C++17), чтобы избежать висячих ссылок.
