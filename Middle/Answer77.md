# 77. В чем разница между константным методом и неконстантным?

## Краткий ответ

Константный метод (`const` после списка параметров) **не может изменять состояние объекта** (его нестатические поля-члены) и **может вызываться у константных объектов**. Неконстантный метод таких ограничений не имеет.

```cpp
class Foo {
public:
    int  getValue() const { return value_; }  // константный
    void setValue(int v)  { value_ = v; }     // неконстантный
private:
    int value_ = 0;
};
```

## Подробно

### 1. Модификатор `const` и сигнатура

`const` в конце объявления метода относится к неявному параметру `this`: внутри константного метода `this` имеет тип `const Foo*`, а внутри неконстантного — `Foo*`. Именно поэтому константный метод не может писать в поля.

```cpp
void Foo::setValue(int v) { value_ = v; }       // ок: this == Foo*
int  Foo::getValue() const { return value_; }   // ок: только чтение
int  Foo::bad() const { value_ = 1; }           // ошибка компиляции
```

Важно: `const` — часть сигнатуры, поэтому методы различаются по константности и могут существовать в паре (перегрузка по константности):

```cpp
class Container {
public:
    T&       operator[](size_t i)       { return data_[i]; }
    const T& operator[](size_t i) const { return data_[i]; }
};
```

При выборе перегрузки компилятор учитывает константность объекта, у которого вызван метод: у `const Container` вызовется константная версия, у обычного `Container` — неконстантная (как более подходящая).

### 2. Что разрешено, а что нет в константном методе

**Запрещено:**
- изменять нестатические поля-члены;
- вызывать неконстантные методы того же класса (через `this`);
- возвращать неконстантные ссылки/указатели на члены (без `const_cast`).

**Разрешено:**
- читать поля;
- изменять поля, помеченные `mutable` (типичный пример — кэш, счётчик вызовов, мьютекс);
- изменять статические члены класса (они не относятся к состоянию конкретного объекта);
- вызывать другие константные методы;
- создавать и изменять локальные переменные.

```cpp
class Cache {
public:
    int compute() const {
        if (!valid_) {              // mutable-поле можно менять
            cached_ = heavy();      // mutable-поле
            valid_  = true;         // mutable-поле
        }
        return cached_;
    }
private:
    mutable int  cached_ = 0;
    mutable bool valid_  = false;
    int heavy() const { /* ... */ return 42; }
};
```

### 3. Константность объекта и вызов методов

- У **константного** объекта (`const Foo f;` или `const Foo&`) можно вызывать **только константные** методы.
- У **неконстантного** объекта можно вызывать и константные, и неконстантные методы.

```cpp
const Foo cf;
cf.getValue();   // ок
cf.setValue(5);  // ошибка компиляции: setValue не константный
```

### 4. Зачем это нужно

- **Корректность и безопасность**: компилятор гарантирует, что «логически читающие» операции не портят объект.
- **Передача по константной ссылке**: функции, принимающие `const T&`, могут работать только с константными методами — без них класс был бы непригоден для такого использования.
- **Перегрузка по константности** даёт разные интерфейсы для чтения и записи (пример с `operator[]` выше).
- **Оптимизации и потокобезопасность**: константные методы можно безопасно вызывать параллельно (при отсутствии `mutable`).

### 5. Тонкости и подводные камни

- **`const` не гарантирует полную неизменяемость**: `mutable`-поля, `const_cast` (злоупотребление) и изменение данных через сохранённые указатели/ссылки позволяют обойти ограничение. Константность в C++ — это «логическая» константность, а не глубокая.
- **`mutable`** стоит применять осознанно — только для вещей, не влияющих на наблюдаемое логическое состояние (кэши, счётчики, синхронизация).
- **Константный метод можно вызывать на неконстантном объекте**, но не наоборот.
- **Правило хорошего тона**: если метод не меняет состояние, делайте его `const`. Это расширяет применимость класса и ловит ошибки на этапе компиляции.
