# 39. Что такое move-семантика?

**Move-семантика (семантика перемещения)** — это механизм, появившийся в C++11, который позволяет передавать владение ресурсами (например, динамически выделенной памятью, файловыми дескрипторами и т.д.) от одного объекта к другому без выполнения дорогостоящего глубокого копирования. Вместо копирования данных происходит «перемещение» — целевой объект забирает ресурсы источника, а источник остаётся в допустимом, но неопределённом состоянии .

Ключевая идея: если объект является временным (rvalue) и больше не будет использоваться, нет смысла копировать его ресурсы — их можно просто «украсть».

## Зачем нужна move-семантика

До C++11 копирование объектов с ресурсами (например, `std::string` или `std::vector`) всегда выполняло глубокое копирование. При возврате объекта из функции или вставке в контейнер это приводило к лишним выделениям памяти и копированию данных.

Move-семантика решает эту проблему: временные объекты (rvalue) можно перемещать, а не копировать, что существенно повышает производительность .

Пример: при реаллокации `std::vector`, если тип элементов поддерживает перемещение, вектор перемещает элементы в новую память, а не копирует их. Это особенно важно для типов, владеющих большими объёмами данных .

## Ключевые компоненты

### 1. Rvalue-ссылки (`T&&`)

Rvalue-ссылки — это ссылки, которые могут связываться с временными объектами (rvalue). Именно они позволяют перегружать функции так, чтобы для rvalue выбиралась «перемещающая» версия, а для lvalue — копирующая .

### 2. Конструктор перемещения и оператор перемещающего присваивания

Класс может определить:

- **Конструктор перемещения**: `T(T&& other)` — создаёт новый объект, забирая ресурсы у `other`.
- **Оператор перемещающего присваивания**: `T& operator=(T&& other)` — освобождает текущие ресурсы и забирает ресурсы у `other`.

После перемещения `other` должен оставаться в допустимом (valid), но неопределённом состоянии — например, указатель внутри него может быть установлен в `nullptr` .

### 3. `std::move`

`std::move` — это **не перемещение**, а приведение типа. Он преобразует lvalue в rvalue-ссылку, тем самым «разрешая» компилятору выбрать перемещающую перегрузку. Сам по себе `std::move` ничего не делает во время выполнения .

```cpp
std::string a = "hello";
std::string b = std::move(a); // a теперь пуст (или в неопределённом состоянии)
```

Важно: `std::move` не гарантирует, что объект будет перемещён — если у типа нет конструктора перемещения, вызовется конструктор копирования .

## Пример: перемещение vs копирование

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::string str = "very long string...";

    // Копирование: str остаётся неизменным
    std::vector<std::string> v1;
    v1.push_back(str); // вызывается push_back(const T&)

    // Перемещение: str становится пустым
    std::vector<std::string> v2;
    v2.push_back(std::move(str)); // вызывается push_back(T&&)
}
```

## Важные замечания

- **Перемещённый объект не следует использовать** без повторной инициализации, если только тип явно не документирует его состояние .
- **`const` объекты нельзя перемещать** — `std::move` от `const` объекта даст `const T&&`, что не свяжется с конструктором перемещения `T(T&&)`, и произойдёт копирование .
- **Перемещение не всегда выгодно**: для маленьких типов (например, `int` или простых структур) перемещение не даёт преимуществ перед копированием, и определять для них конструктор перемещения не имеет смысла .
- **`noexcept` имеет значение**: если конструктор перемещения помечен как `noexcept`, контейнеры (например, `std::vector`) могут безопасно использовать перемещение при реаллокации вместо копирования .

## Итог

Move-семантика — это способ избежать дорогостоящего копирования ресурсов за счёт «передачи владения» от временных объектов. Она реализуется через rvalue-ссылки, конструкторы/операторы перемещения и `std::move`, и является одной из ключевых возможностей C++11, повышающих производительность без потери безопасности типов.
