# 29. Как экспортировать/импортировать функции из динамической библиотеки?

Экспорт и импорт функций из динамических библиотек в C++ сильно зависит от операционной системы и используемого инструментария. Ниже приведено подробное описание для двух основных платформ: **Windows (MSVC)** и **Linux (GCC/Clang)**.

---

## Windows (MSVC)

В Windows динамические библиотеки называются **DLL** (Dynamic-Link Library). Для экспорта функций из DLL и их импорта в исполняемом файле используется механизм таблицы экспорта.

### Экспорт из DLL

Существует два основных способа указать компилятору, какие функции должны быть видны снаружи:

1.  **Использование `__declspec(dllexport)`** (наиболее распространённый способ в современном C++).
    Ключевое слово добавляется к объявлению функции в заголовочном файле, который используется при сборке самой DLL.

    ```cpp
    // MathLibrary.h
    #ifdef MATHLIBRARY_EXPORTS
    #define MATHLIBRARY_API __declspec(dllexport)
    #else
    #define MATHLIBRARY_API __declspec(dllimport)
    #endif

    extern "C" MATHLIBRARY_API int Add(int a, int b);
    ```

    При компиляции DLL вы определяете макрос `MATHLIBRARY_EXPORTS` (обычно через настройки проекта), и функция помечается как экспортируемая .

2.  **Использование файла определения модуля (`.def`)**.
    Это более старый метод, который позволяет экспортировать функции по порядковым номерам (ordinals) или управлять именами экспортируемых функций без изменения исходного кода .

### Импорт в клиентское приложение

Клиентское приложение (EXE или другая DLL) должно знать, откуда брать функцию. Это делается двумя способами:

1.  **Неявное связывание (Implicit Linking)** — наиболее частый случай.
    Вы подключаете заголовочный файл библиотеки (где функция объявлена с `__declspec(dllimport)`) и линкуетесь с **библиотекой импорта** (`.lib`). Библиотека импорта содержит информацию, необходимую линковщику для создания таблицы адресов. При запуске программы ОС автоматически загрузит нужную DLL .

2.  **Явное связывание (Explicit Linking)**.
    Если DLL неизвестна на этапе компиляции, используются функции Win32 API: `LoadLibrary` (или `LoadLibraryEx`) для загрузки DLL и `GetProcAddress` для получения адреса функции.

### Важный нюанс: Искажение имён (Name Mangling)

C++ компиляторы искажают имена функций (добавляют информацию о типах аргументов). Если вы хотите, чтобы функцию можно было легко найти через `GetProcAddress` или использовать из других языков (C, C#, Python), оберните объявление в блок `extern "C"`, как показано в примере выше. Это отключает искажение имён для конкретной функции.

## Linux (GCC / Clang)

В Linux динамические библиотеки называются **разделяемыми объектами** (Shared Objects, `.so`). По умолчанию в Linux **все** нестатические символы (функции и глобальные переменные) являются видимыми и экспортируются автоматически.

### Экспорт из разделяемой библиотеки

Хотя по умолчанию экспортируется всё, хорошей практикой является явное управление видимостью для уменьшения размера таблицы символов и предотвращения конфликтов.

1.  **По умолчанию**: Если ничего не указывать, функция будет экспортирована.
2.  **Явное управление видимостью**:
    Используйте атрибут `__attribute__((visibility("default")))` для функций, которые должны быть экспортированы, и флаг компилятора `-fvisibility=hidden`, чтобы скрыть всё остальное по умолчанию.

    ```cpp
    // mylib.cpp
    #define EXPORT __attribute__((visibility("default")))

    extern "C" EXPORT int Add(int a, int b) {
        return a + b;
    }
    ```

    Компиляция:
    ```bash
    g++ -shared -fPIC -fvisibility=hidden -o libmylib.so mylib.cpp
    ```
    Флаг `-fPIC` (Position Independent Code) обязателен для создания разделяемых библиотек .

### Импорт в клиентское приложение

1.  **Компоновка во время сборки**:
    Укажите линковщику путь к библиотеке и её имя (без префикса `lib` и расширения `.so`).
    ```bash
    g++ main.cpp -L/path/to/lib -lmylib -o myprogram
    ```

2.  **Динамическая загрузка (dlopen)**:
    Аналог `LoadLibrary`. Позволяет загружать библиотеку во время выполнения.
    *   `dlopen()` — открывает библиотеку.
    *   `dlsym()` — ищет адрес функции по имени (строке).
    *   `dlclose()` — закрывает библиотеку .

    ```cpp
    #include <dlfcn.h>
    // ...
    void* handle = dlopen("./libmylib.so", RTLD_LAZY);
    if (!handle) { /* обработка ошибки */ }

    typedef int (*AddFunc)(int, int);
    AddFunc add = (AddFunc)dlsym(handle, "Add");
    if (!add) { /* обработка ошибки */ }

    int result = add(2, 3);
    dlclose(handle);
    ```

    При использовании `dlsym` критически важно использовать `extern "C"` в библиотеке, иначе вам придётся искать искажённое имя (например, `_Z3addii`), что крайне неудобно и непереносимо .

## Сводная таблица

| Действие | Windows (MSVC) | Linux (GCC) |
| :--- | :--- | :--- |
| **Расширение файла** | `.dll` | `.so` |
| **Экспорт (явный)** | `__declspec(dllexport)` | `__attribute__((visibility("default")))` (при `-fvisibility=hidden`) |
| **Импорт (неявный)** | Заголовок с `__declspec(dllimport)` + `.lib` | Заголовок + линковка `-l<name>` |
| **Импорт (явный)** | `LoadLibrary` + `GetProcAddress` | `dlopen` + `dlsym` |
| **Отключение искажения имён** | `extern "C"` | `extern "C"` |

**Ключевой вывод**: Для кроссплатформенного экспорта функций из C++ библиотек всегда используйте `extern "C"`, чтобы имена функций оставались предсказуемыми для динамической загрузки и взаимодействия с другими языками.
