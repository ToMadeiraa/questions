# 56. Что такое ключевое слово mutable и когда его нужно использовать

**`mutable`** — это спецификатор в C++, который применяется к **нестатическим** членам данных класса (или к параметрам лямбда-выражений, захваченным по значению) и позволяет изменять эти члены даже внутри **`const`-методов** или у **`const`-объектов**.

По умолчанию, если метод помечен как `const`, компилятор запрещает изменять любые поля класса внутри него. Ключевое слово `mutable` снимает этот запрет для конкретного поля, указывая, что его изменение не влияет на «внешнее» (наблюдаемое) состояние объекта.

### Когда его нужно использовать

Использование `mutable` оправдано в случаях, когда изменение поля является внутренней деталью реализации и не должно нарушать логическую константность объекта. Основные сценарии:

1. **Кэширование (Memoization / Lazy Evaluation)**: Если у вас есть `const`-метод, который выполняет дорогостоящие вычисления, результат можно сохранить в `mutable`-поле, чтобы при повторном вызове вернуть его мгновенно. Для внешнего наблюдателя объект не меняется, но внутри происходит оптимизация.
2. **Счётчики доступа / Инструментация**: Если вам нужно считать, сколько раз был вызван `const`-метод (например, для отладки или статистики), счётчик можно объявить как `mutable`.
3. **Синхронизация (Мьютексы)**: В многопоточном коде `const`-метод может блокировать `mutable std::mutex`, чтобы обеспечить потокобезопасное чтение, при этом логическое состояние объекта (данные) не меняется.

### Пример кода

```cpp
class DataProcessor {
public:
    // Этот метод логически константный: он не меняет "данные", но меняет кэш
    int getResult() const {
        if (!cached) {
            // Дорогостоящее вычисление
            result = performHeavyComputation(); 
            cached = true; // Ошибка без mutable!
        }
        return result;
    }

private:
    int performHeavyComputation() const { return 42; }

    mutable int result = 0;   // Можно менять в const-методе
    mutable bool cached = false; // Можно менять в const-методе
};
```

### Важные ограничения и предостережения

* **Только для нестатических полей**: `mutable` нельзя применять к `static`-переменным или к глобальным переменным. Также нельзя применять к полям, которые уже объявлены как `const` (это противоречило бы смыслу).
* **Не злоупотребляйте**: Если вы используете `mutable` часто и для изменения основных данных, это, скорее всего, признак **плохого дизайна**. `const`-метод должен быть константным по своей сути. `mutable` — это инструмент для исключений (кэш, счётчики, мьютексы), а не для обхода ограничений `const`.
* **Потокобезопасность**: Будьте осторожны с `mutable` в многопоточной среде. Даже если метод помечен как `const`, изменение `mutable`-поля означает, что объект **физически** меняется, поэтому для доступа к нему может потребоваться синхронизация (например, мьютекс), иначе это приведёт к состоянию гонки (data race).
