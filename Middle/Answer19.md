# 19. Что такое internal linkage?

**Internal linkage** (внутреннее связывание) — это свойство имени в C++, которое означает, что сущность, обозначаемая этим именем, **доступна для использования только в пределах одной единицы трансляции** (translation unit), то есть в пределах одного исходного файла (`.cpp`) вместе со всеми включёнными в него заголовочными файлами .

Имена с внутренним связыванием являются «локальными» для своей единицы трансляции. Компоновщик (linker) не видит такие имена, поэтому они не могут конфликтовать с одноимёнными сущностями в других единицах трансляции, и на них нельзя сослаться из другого `.cpp`-файла .

### Какие сущности имеют internal linkage

Согласно стандарту C++, имена, объявленные в области видимости пространства имён (namespace scope), получают внутреннее связывание в следующих случаях :

1. **Переменные, шаблоны переменных, функции и шаблоны функций, объявленные со спецификатором `static`.**
   ```cpp
   static int counter = 0;          // переменная с internal linkage
   static void helper() { /*...*/ } // функция с internal linkage
   ```

2. **Нешаблонные переменные с квалификатором `const` (включая `constexpr`), если они не объявлены как `inline`, не объявлены `extern` и ранее не были объявлены с внешним связыванием.**
   ```cpp
   const int maxSize = 100;         // internal linkage в C++
   constexpr double pi = 3.14159;   // internal linkage в C++
   ```
   > Важное отличие от C: в C файловая `const`-переменная по умолчанию имеет внешнее связывание, в C++ — внутреннее .

3. **Все имена, объявленные в безымянном пространстве имён (`namespace { ... }`), даже если они явно объявлены `extern`.** Это современный и предпочтительный способ дать сущности внутреннее связывание в C++ .
   ```cpp
   namespace {
       int hiddenVar = 42;          // internal linkage
       void hiddenFunc() { /*...*/ } // internal linkage
   }
   ```

4. **Данные-члены анонимных объединений (`union`)** .

### Практическое значение

- **Изоляция:** internal linkage позволяет использовать одинаковые имена в разных `.cpp`-файлах без риска ошибки множественного определения (ODR violation).
- **Оптимизация:** поскольку компилятор видит все использования такой сущности в пределах единицы трансляции, он может агрессивнее её оптимизировать (например, встраивать или удалять неиспользуемые функции).
- **Отсутствие экспорта:** такие сущности не попадают в таблицу символов объектного файла как экспортируемые, что уменьшает риск коллизий при линковке.

**Кратко:** internal linkage = «видно только в этом `.cpp`».
