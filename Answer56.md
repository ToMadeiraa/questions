# 56. Что такое инкапсуляция? Как она реализуется в C++?

## Определение

**Инкапсуляция** — это один из трёх базовых принципов ООП (наряду с наследованием и полиморфизмом), который означает **объединение данных и методов, работающих с этими данными, в единую сущность (класс)** и **сокрытие внутреннего состояния объекта** от прямого доступа извне.

Инкапсуляция решает две задачи:

1. **Объединение (aggregation)** — данные и функции, логически связанные, находятся в одном месте (в классе).
2. **Сокрытие (information hiding)** — внутреннее устройство объекта скрыто, а взаимодействие с ним идёт через строго определённый интерфейс (публичные методы). Это защищает объект от некорректного использования и позволяет менять реализацию, не ломая код клиентов.

## Как реализуется в C++

### 1. Спецификаторы доступа

В C++ инкапсуляция реализуется через **спецификаторы доступа к членам класса**:

| Спецификатор | Доступ |
|---|---|
| `private` | Только внутри самого класса (и `friend`-классов/функций) |
| `protected` | Внутри класса и в производных классах |
| `public` | Откуда угодно |

По умолчанию в `class` все члены `private`, в `struct` — `public`.

### 2. Пример

```cpp
#include <iostream>
#include <stdexcept>

class BankAccount {
private:                       // скрытые данные
    double balance_;
    int    pin_;

    // приватный вспомогательный метод
    bool checkPin(int pin) const { return pin == pin_; }

public:                        // открытый интерфейс
    BankAccount(double initial, int pin)
        : balance_(initial), pin_(pin) {
        if (initial < 0)
            throw std::invalid_argument("Negative balance");
    }

    // геттер — только чтение
    double getBalance(int pin) const {
        if (!checkPin(pin))
            throw std::runtime_error("Wrong PIN");
        return balance_;
    }

    // сеттер с валидацией — контролируемое изменение
    void deposit(double amount) {
        if (amount <= 0)
            throw std::invalid_argument("Amount must be positive");
        balance_ += amount;
    }

    void withdraw(double amount, int pin) {
        if (!checkPin(pin))
            throw std::runtime_error("Wrong PIN");
        if (amount > balance_)
            throw std::runtime_error("Insufficient funds");
        balance_ -= amount;
    }
};

int main() {
    BankAccount acc(100.0, 1234);

    acc.deposit(50.0);
    std::cout << acc.getBalance(1234) << '\n';  // 150

    // acc.balance_ = 1e9;   // ОШИБКА компиляции: private
    // acc.pin_ = 0;         // ОШИБКА компиляции: private
}
```

Здесь `balance_` и `pin_` напрямую изменить нельзя — только через методы, которые проверяют корректность (валидация суммы, проверка PIN). Это и есть инкапсуляция.

### 3. Ключевое слово `friend`

Механизм `friend` позволяет точечно открыть доступ к `private`-членам для конкретной функции или класса (например, для оператора вывода):

```cpp
class Point {
    double x_, y_;
public:
    Point(double x, double y) : x_(x), y_(y) {}
    friend std::ostream& operator<<(std::ostream& os, const Point& p);
};

std::ostream& operator<<(std::ostream& os, const Point& p) {
    return os << '(' << p.x_ << ", " << p.y_ << ')';  // доступ к private
}
```

`friend` стоит использовать умеренно — он ослабляет инкапсуляцию.

### 4. Правило «только необходимая открытость»

Хорошая практика — делать `private` всё, что не является частью интерфейса, а наружу выставлять минимально необходимое. Часто это выражается в:

- **геттерах** (`getX()`) — для чтения;
- **сеттерах** (`setX()`) — если изменение вообще нужно, с проверкой инвариантов;
- **константных методах** (`const`) — не меняющих состояние.

```cpp
class Temperature {
    double celsius_ = 0.0;
public:
    double celsius() const { return celsius_; }
    void setCelsius(double c) {
        if (c < -273.15) throw std::invalid_argument("Below absolute zero");
        celsius_ = c;
    }
};
```

## Преимущества инкапсуляции

1. **Защита инвариантов класса** — объект не может оказаться в некорректном состоянии (все изменения проходят проверку).
2. **Скрытие реализации** — можно поменять внутреннее представление (например, хранить температуру в кельвинах), не меняя публичный интерфейс и не ломая клиентский код.
3. **Упрощение интерфейса** — пользователь видит только то, что ему нужно.
4. **Снижение связанности (coupling)** — модули зависят от интерфейсов, а не от деталей реализации.
5. **Облегчение сопровождения и тестирования** — изменения локализованы внутри класса.

## Итоговая формулировка для ответа

> Инкапсуляция — это принцип ООП, состоящий в объединении данных и методов их обработки в классе и в сокрытии внутреннего состояния объекта от прямого доступа извне. В C++ она реализуется с помощью спецификаторов доступа `private`, `protected` и `public`: данные-члены обычно делают `private`, а доступ к ним предоставляют через публичные методы (геттеры/сеттеры), которые могут проверять корректность значений и поддерживать инварианты класса. Дополнительно используются `friend`-объявления (для точечного доступа) и `const`-методы. Инкапсуляция защищает объект от некорректного использования и позволяет изменять реализацию, не затрагивая внешний код.
