# Вопрос 7. Что такое таблица ASCII?

> **Кратко:** ASCII (American Standard Code for Information Interchange) — стандартная таблица соответствия символов и чисел: 128 символов получают коды от 0 до 127 и укладываются в 7 бит. Она покрывает латиницу, цифры, знаки препинания и управляющие символы, но не содержит кириллицы — для национальных алфавитов нужны другие кодировки.

---

## 1. Что это такое

ASCII — 7-битная кодировка, опубликованная в 1963 году как стандарт ASA X3.4 (позже ANSI X3.4, сегодня ANSI/INCITS 4). Она задаёт **однозначное соответствие** «символ → число» и тем самым позволяет хранить текст в памяти как последовательность чисел.

Свойства:

- **7 бит** — ровно 128 кодов: `0..127`;
- коды `0..31` и `127` — **управляющие**, они не печатаются, а управляют устройством (перевод строки, табуляция, звонок);
- коды `32..126` — **печатные** символы;
- кодировка **однобайтовая**: один символ — один байт, старший бит равен нулю.

---

## 2. Структура таблицы

| Диапазон | Содержимое | Примеры |
|---|---|---|
| `0..31` | управляющие символы | `NUL` (0), `BEL` (7), `TAB` (9), `LF` (10), `CR` (13), `ESC` (27) |
| `32` | пробел | `' '` |
| `33..47` | пунктуация | `! " # $ % & ' ( ) * + , - . /` |
| `48..57` | десятичные цифры | `'0'..'9'` |
| `58..64` | пунктуация | `: ; < = > ? @` |
| `65..90` | заглавная латиница | `'A'..'Z'` |
| `91..96` | пунктуация | `[`, `\`, `]`, `^`, `_`, обратная кавычка |
| `97..122` | строчная латиница | `'a'..'z'` |
| `123..126` | пунктуация | `{`, `|`, `}`, `~` |
| `127` | `DEL` | удаление символа |

**Опорные точки, которые стоит помнить:**

| Символ | Dec | Hex | Замечание |
|---|---|---|---|
| `'\0'` | 0 | `0x00` | терминатор C-строки |
| `'\n'` | 10 | `0x0A` | перевод строки |
| `' '` | 32 | `0x20` | пробел |
| `'0'` | 48 | `0x30` | начало цифр |
| `'9'` | 57 | `0x39` | конец цифр |
| `'A'` | 65 | `0x41` | начало заглавных |
| `'Z'` | 90 | `0x5A` | конец заглавных |
| `'a'` | 97 | `0x61` | начало строчных |
| `'z'` | 122 | `0x7A` | конец строчных |

Полезные закономерности: `'a' - 'A' == 32 == 0x20` — регистр латинской буквы кодируется пятым битом; цифры идут подряд, буквы тоже идут подряд.

---

## 3. Как это выглядит в коде

**Печать печатной части таблицы:**

```cpp
#include <iomanip>
#include <iostream>

int main() {
    for (int code = 32; code < 127; ++code) {   // управляющие не печатаем
        std::cout << std::setw(3) << code
                  << " 0x" << std::hex << std::uppercase << code << std::dec
                  << "  '" << static_cast<char>(code) << "'\n";
    }
}
```

**Арифметика над символами:**

```cpp
#include <stdexcept>

// Регистр латинской буквы — это бит 0x20. Работает только для латиницы.
char toLowerAscii(char c) {
    return (c >= 'A' && c <= 'Z') ? static_cast<char>(c | 0x20) : c;
}

// Цифры в кодировке идут подряд, поэтому вычитаем '0', а не «магическое» 48.
int digitValue(char c) {
    if (c < '0' || c > '9')
        throw std::invalid_argument("not a decimal digit");
    return c - '0';
}
```

**Побайтовый дамп строки:**

```cpp
#include <string>

void dumpHex(const std::string& s) {
    for (unsigned char c : s) {          // unsigned char — байт без знака
        std::cout << std::hex << (c < 16 ? "0" : "")
                  << static_cast<int>(c) << ' ';
    }
    std::cout << '\n';
}
```

## 4. Что гарантирует стандарт C++, а что — нет

| Гарантия | Статус |
|---|---|
| `sizeof(char) == 1` | гарантировано (байт — единица измерения) |
| Цифры `'0'..'9'` идут подряд | гарантировано |
| `'a'..'z'` и `'A'..'Z'` идут подряд | гарантировано |
| Коды символов совпадают с ASCII | **не** гарантировано, но выполняется на всех массовых платформах |
| `'a' - 'A' == 32` | следствие ASCII; на EBCDIC неверно |

Отсюда практическое правило: **сравнивать и вычитать надо символы, а не числа**. `c - '0'` переносимо, `c - 48` — нет. Основной контрпример — EBCDIC на мейнфреймах IBM, где латинские буквы идут не непрерывным блоком.

## 5. «Расширенная ASCII» и кириллица

Свободные 128 кодов (`128..255`) разные производители заполнили по-своему. Единого стандарта «extended ASCII» не существует: это общее название для набора несовместимых 8-битных кодовых страниц.

| Кодировка | `'А'` | `'я'` | Где встречалась |
|---|---|---|---|
| CP1251 | `0xC0` | `0xFF` | Windows, русская локаль |
| CP866 | `0x80` | `0xDF` | DOS, консоль Windows |
| KOI8-R | `0xE1` | `0xD1` | Unix, почта, ФИДО |
| ISO 8859-5 | `0xB0` | `0xEF` | международный стандарт |

Один и тот же байт означает разные символы, поэтому текст, прочитанный не в той кодировке, превращается в «кракозябры». Именно эта проблема и привела к появлению Unicode.

## 6. Байт — не символ

`char` в C++ — это **байт**, а не буква. Знаковость `char` зависит от платформы (на x86 по умолчанию `signed char`), поэтому байт `0xC0` как `char` отрицателен:

```cpp
#include <cctype>
#include <string>

void toUpperBytes(std::string& s) {
    for (char& c : s) {
        // std::toupper принимает int; отрицательный char — UB,
        // поэтому сначала приводим к unsigned char.
        c = static_cast<char>(std::toupper(static_cast<unsigned char>(c)));
    }
}
```

Для работы с байтами используйте `unsigned char` или `std::uint8_t`, а для текста — тип, соответствующий кодировке (см. вопрос про Unicode).

## Типичные ошибки

1. **Считать ASCII универсальной.** В EBCDIC коды другие; переносимая программа не должна полагаться на конкретные числа.
2. **Путать ASCII с кодировкой кириллицы.** В ASCII нет русских букв вообще; CP1251/CP866/KOI8-R — это отдельные кодировки.
3. **Считать `char` символом Unicode.** `std::string` — последовательность байт, `size()` возвращает число байт, а не символов.
4. **Передавать отрицательный `char` в `std::isalpha`/`std::toupper`** — это UB; нужен `static_cast<unsigned char>`.
5. **Использовать `c - 48` и `c - 97`** вместо `c - '0'` и `c - 'a'`.
6. **Ожидать, что `'a' | 0x20` даст строчную букву для любого алфавита.** Для кириллицы это неверно.

## Что добавить на собеседовании

- ASCII — подмножество Unicode: кодовые точки `U+0000..U+007F` совпадают с ASCII, поэтому UTF-8 обратно совместим с ASCII и старый код «просто работает» на латинице.
- Сортировка байтовых строк в ASCII совпадает с лексикографическим порядком, но не с алфавитным порядком для национальных языков — там нужны правила collation.
- Кодировка **исходников** тоже важна: формально до C++23 в файле допускались только символы basic source character set, остальное — через `\uXXXX`; компиляторы при этом давно принимали UTF-8 как расширение.
- Полезно упомянуть связь с вопросом про Unicode: ASCII отвечает «какой код у символа», Unicode — «какой код у любого символа мира и как его закодировать байтами».

## Итог

| Понятие | Суть |
|---|---|
| ASCII | 7-битная таблица: 128 символов, коды `0..127` |
| Управляющие | `0..31`, `127` — не печатаются |
| Печатные | `32..126`, включая пробел |
| Ключевые коды | `'0'`=48, `'A'`=65, `'a'`=97, разница регистров 32 |
| Extended ASCII | не стандарт, а набор несовместимых 8-битных страниц |
| Кириллица | CP1251 / CP866 / KOI8-R / ISO 8859-5 — вне ASCII |
| В C++ | `char` — байт; порядок цифр и букв гарантирован, конкретные коды — нет |
