# 112. Ключевое слово `virtual` в C++

Ключевое слово `virtual` в C++ используется для реализации **динамического (позднего) связывания** — механизма, при котором вызов метода определяется во время выполнения программы, а не во время компиляции. Оно является основой **полиморфизма** в C++.

## 1. Виртуальные функции

При объявлении функции в базовом классе с ключевым словом `virtual` компилятор включает её в **таблицу виртуальных функций** (vtable). При вызове такой функции через указатель или ссылку на базовый класс будет вызвана реализация из **фактического типа объекта**, а не из типа указателя.

```cpp
#include <iostream>

class Animal {
public:
    virtual void speak() const {
        std::cout << "Some animal sound\n";
    }
    virtual ~Animal() = default; // виртуальный деструктор!
};

class Dog : public Animal {
public:
    void speak() const override {
        std::cout << "Woof!\n";
    }
};

class Cat : public Animal {
public:
    void speak() const override {
        std::cout << "Meow!\n";
    }
};

int main() {
    Animal* a1 = new Dog();
    Animal* a2 = new Cat();

    a1->speak(); // Woof!  — вызов определён динамически
    a2->speak(); // Meow!

    delete a1;
    delete a2;
}
```

Без `virtual` оба вызова вывели бы `"Some animal sound"`, так как компилятор связал бы вызов со статическим типом `Animal`.

## 2. Механизм работы (vtable и vptr)

- Для каждого класса, содержащего хотя бы одну виртуальную функцию, компилятор создаёт **таблицу виртуальных функций** (vtable) — массив указателей на реализации.
- Каждый объект такого класса содержит скрытый указатель **vptr** на vtable своего класса.
- При вызове виртуальной функции через указатель/ссылку происходит обращение к vtable и вызов нужной реализации — это и есть **динамическое связывание**.

## 3. Виртуальный деструктор

Если класс предназначен для наследования и удаления через указатель на базовый класс, деструктор **обязан** быть виртуальным. Иначе при `delete basePtr` вызовется только деструктор базового класса, что приведёт к **утечке ресурсов** и неопределённому поведению.

```cpp
class Base {
public:
    virtual ~Base() = default; // правильно
};

class Derived : public Base {
    int* data = new int[100];
public:
    ~Derived() override { delete[] data; }
};
```

## 4. Чисто виртуальные функции и абстрактные классы

Если функция объявлена как `virtual ... = 0;`, она называется **чисто виртуальной**. Класс, содержащий хотя бы одну такую функцию, становится **абстрактным** — от него нельзя создавать объекты, и он задаёт интерфейс для наследников.

```cpp
class Shape {
public:
    virtual double area() const = 0; // чисто виртуальная
    virtual ~Shape() = default;
};

class Circle : public Shape {
    double r;
public:
    explicit Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
};
```

## 5. Ключевые слова `override` и `final`

- **`override`** (C++11) — явно указывает, что функция переопределяет виртуальную функцию базового класса. Помогает компилятору обнаружить ошибки (например, несовпадение сигнатуры).
- **`final`** (C++11) — запрещает дальнейшее переопределение функции в наследниках или запрещает наследование от класса.

```cpp
class Base {
public:
    virtual void f() {}
};

class Derived : public Base {
public:
    void f() override final {} // переопределена и закрыта для наследников
};
```

## 6. Виртуальное наследование (`virtual` при наследовании)

Ключевое слово `virtual` может применяться и к базовому классу при наследовании — это **виртуальное наследование**, решающее проблему «ромба» (diamond problem) при множественном наследовании: общий базовый класс существует в объекте в **единственном экземпляре**.

```cpp
class A { public: int x; };
class B : virtual public A {};
class C : virtual public A {};
class D : public B, public C {}; // в D только одна копия A
```

## 7. Особенности и нюансы

- Виртуальные функции **нельзя** делать `static`, а также нельзя объявлять виртуальными конструкторы (но можно — «виртуальный конструктор» через паттерн `clone()`).
- Вызов виртуальной функции в **конструкторе/деструкторе** базового класса не даёт полиморфного поведения — вызывается версия текущего класса (объект наследника ещё не сконструирован / уже разрушен).
- Виртуальные вызовы имеют **небольшие накладные расходы** (обращение к vtable) и мешают некоторым оптимизациям (например, инлайнингу), поэтому `virtual` стоит применять осознанно.
- Начиная с C++11, для подавления динамического связывания можно явно указывать класс: `obj.Base::f()`.

## Краткий итог

| Применение `virtual` | Что делает |
|---|---|
| `virtual` у функции-члена | Включает динамическое связывание (полиморфизм) |
| `virtual ~Class()` | Корректное удаление наследников через указатель на базу |
| `= 0` + `virtual` | Чисто виртуальная функция → абстрактный класс |
| `virtual` при наследовании | Виртуальное наследование (решение «ромба») |
| `override` / `final` | Контроль корректности переопределения и запрет наследования |

Таким образом, `virtual` — ключевой инструмент ООП в C++, обеспечивающий **полиморфизм**, **корректное разрушение объектов** и **гибкую архитектуру** иерархий классов.
