# Вопрос 22. Что такое препроцессор?

> **Кратко:** препроцессор — первый этап трансляции, который до компиляции обрабатывает директивы `#...`: вставляет содержимое заголовков, раскрывает макросы, включает и выключает фрагменты кода по условию. Он работает с текстом на уровне лексем и ничего не знает о типах, областях видимости и семантике C++, а его результат — новый поток лексем, который получает уже настоящий компилятор.

---

## Место препроцессора в трансляции

Стандарт описывает трансляцию как последовательность фаз; препроцессор — это фазы 1–4: отображение символов, склейка строк через `\`, разбиение на лексемы (комментарии становятся пробелом) и выполнение директив с раскрытием макросов. Дальше начинается фаза 7 — синтаксический и семантический разбор, где появляются типы.

Отсюда два следствия: препроцессор **не типизирован** и видит только поток лексем, а все его ошибки «текстовые» — не найден файл, неизвестная директива, незакрытый `#if`.

Посмотреть результат можно так:

```bash
g++ -E main.cpp | less      # весь поток после препроцессинга
g++ -E -dM main.cpp         # только список определённых макросов
```

## Основные директивы

| Директива | Назначение |
|---|---|
| `#include` | текстовая вставка другого файла (свой — `"..."`, системный — `<...>`) |
| `#define` / `#undef` | определить / отменить макрос |
| `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else`, `#endif` | условная компиляция |
| `defined(X)` | оператор: определён ли макрос (только внутри `#if`) |
| `#error` | прервать трансляцию с сообщением |
| `#pragma` | указание конкретному компилятору (`#pragma once`, `#pragma pack`, `#pragma GCC diagnostic`) |
| `#line` | изменить номер строки и имя файла в диагностике |
| `#` (внутри макроса) | строкизация аргумента |
| `##` (внутри макроса) | склейка лексем |

К операторам препроцессора относятся и проверки возможностей: `__has_include(<filesystem>)`, `__has_cpp_attribute(nodiscard)` (C++17).

---

## Условная компиляция

Главный практический сценарий — платформенные и конфигурационные ветки. Неактивные ветки **вырезаются до компиляции**, в бинарник они не попадают вовсе.

```cpp
#if defined(_WIN32)
    #define PLATFORM "windows"
#elif defined(__linux__)
    #define PLATFORM "linux"
#elif defined(__APPLE__)
    #define PLATFORM "macos"
#else
    #error "unsupported platform"
#endif

#if defined(NDEBUG)                  // релизная сборка: -DNDEBUG
    #define LOG_LEVEL 1
#else
    #define LOG_LEVEL 3
#endif
```

Важно: `#if FLAG` для **неопределённого** `FLAG` даёт `0`, а не ошибку, поэтому проверку существования пишут явно — `#if defined(FLAG)`.

Проверка стандарта и возможностей: `#if __cplusplus >= 202002L` — это C++20, `#if defined(__cpp_concepts) && __cpp_concepts >= 201907L` — конкретная возможность.

## Макросы

**Объектоподобный** макрос — просто подстановка текста; **функциональный** принимает аргументы и подставляет их в тело.

```cpp
#define PI 3.14159265358979          // плохо: константа без типа
#define SQR(x) ((x) * (x))           // опасно: аргумент вычисляется дважды
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int x = SQR(++i);                    // i увеличится ДВА раза — классическая ловушка
```

Правильный C++ не нуждается в макросах для этого:

```cpp
#include <algorithm>

inline constexpr double kPi = 3.14159265358979;          // типизированная константа
inline constexpr int sqr(int x) noexcept { return x * x; }
// вместо MAX — std::max, который умеет выводить тип и не вычисляет аргумент дважды
```

Оператор `#` внутри макроса строкизирует аргумент, `##` склеивает лексемы; чтобы строкизация увидела **значение** вложенного макроса, нужен двухуровневый вызов (`XSTR`).

**Вариативные макросы** — единственный случай, где макросы всё ещё уместны (логирование, обёртки над API):

```cpp
#define LOG(fmt, ...)  std::printf("[log] " fmt "\n", __VA_ARGS__)
#define LOG2(fmt, ...) std::printf("[log] " fmt "\n" __VA_OPT__(,) __VA_ARGS__)  // C++20: пустой список
```

Макрос **не рекурсивен**: своё имя внутри тела не раскрывается повторно (защита от бесконечной подстановки), а аргументы раскрываются до подстановки, кроме случаев, когда используются с `#` или `##`.

## Защита заголовков

Заголовок, включённый дважды, приводит к повторному определению классов и к ошибкам компиляции. Классическое решение — страж включения:

```cpp
// point.h
#ifndef PROJECT_POINT_H
#define PROJECT_POINT_H

struct Point { int x = 0; int y = 0; };

#endif // PROJECT_POINT_H
```

Современная альтернатива — `#pragma once`: короче и быстрее, поддерживается всеми распространёнными компиляторами, но формально не входит в стандарт.

---

## Предопределённые макросы

| Макрос | Значение |
|---|---|
| `__cplusplus` | версия стандарта: `201703L` для C++17, `202002L` для C++20 |
| `__FILE__`, `__LINE__` | имя файла и номер строки — для диагностики |
| `__DATE__`, `__TIME__` | дата и время компиляции (ломают воспроизводимость сборки) |
| `__func__` | не макрос, а предопределённый идентификатор с именем функции |
| `NDEBUG` | при определении `assert` превращается в «ничего не делать» |
| `__cpp_*` | feature-test макросы: позволяют проверить наличие конкретной возможности |

---

## Плюсы и минусы

| Плюсы | Минусы |
|---|---|
| Нулевая стоимость в рантайме: подстановка, а не вызов | Нет типов, областей видимости и проверок — ошибки ловятся поздно |
| Позволяет писать код под разные платформы и компиляторы | Текстовые подстановки плохо отлаживаются, ломают подсветку и пошаговое выполнение |
| Незаменим для feature detection и условной сборки | «Загрязнение» имён: макрос виден во всех включающих файлах |
| Умеет то, чего нет в языке (условное исключение кода) | `#include` — самая дорогая часть сборки C++ |

Практическое правило: **препроцессор — для условной компиляции и `#include`, а не для констант, «инлайна» и обобщённого кода**.

## Чем заменять в современном C++

| Было (макрос) | Стало |
|---|---|
| `#define PI 3.14` | `inline constexpr double kPi = 3.14;` |
| `#define SQR(x) ((x)*(x))` | `constexpr`/`inline`-функция или шаблон |
| `#define MAX(a,b)` | `std::max`, `std::clamp` |
| `#define TYPE int` | `using Type = int;` |
| `#define ERR_OK 0` | `enum class Err { ok, ... };` |
| `#ifdef DEBUG` вокруг проверки | `if constexpr` / `assert` / `static_assert` |
| `__LINE__` в логе | `std::source_location` (C++20) |
| `#include` заголовков | модули C++20 (`import`) |

## Типичные ошибки

1. **Макрос без скобок.** `#define SQR(x) x * x` в выражении `SQR(a + b)` даёт `a + b * a + b`.
2. **Двойное вычисление аргумента.** `SQR(i++)` увеличивает `i` дважды; `MAX(f(), g())` вызывает функцию дважды.
3. **Макрос с именем из стандартной библиотеки** (`min`, `max`, `assert`) — ломает `std::max` и заголовки, включённые после.
4. **Многооператорный макрос без `do { ... } while (0)`** — ломается в `if` без фигурных скобок.
5. **Отсутствие стража включения** — повторное определение классов и структур.
6. **Проверка `#if FLAG` вместо `#if defined(FLAG)`** — опечатка в имени молча даёт ложную ветку.
7. **Имена с `__` или `_` + заглавная буква** — зарезервированы реализацией, их определять нельзя.
8. **`#define private public`** ради тестов приватных членов — UB и разрушенная инкапсуляция.
9. **`__DATE__`/`__TIME__` в коде** — сборка перестаёт быть воспроизводимой.

## Что добавить на собеседовании

- Препроцессор — часть **фаз трансляции**, а не «отдельная программа»: он встроен в компилятор и говорит на языке токенов.
- Директивы `#include` и `#define` — темы смежных вопросов; здесь важно понимать, что обе работают **до** появления типов, поэтому макрос не может быть членом класса, пространства имён или шаблоном.
- Feature-test макросы (`__cpp_*`, `__has_include`) — стандартный способ писать переносимый код без «магии» сборочных систем.
- Отдельно стоит упомянуть, что **модули C++20** заменяют `#include` и обещают убрать главную проблему препроцессора — повторный разбор заголовков.

## Итог

| Аспект | Суть |
|---|---|
| Что это | Этап обработки текста до компиляции: директивы, макросы, `#include` |
| Что понимает | Только лексемы; типы, области видимости и перегрузки — вне его компетенции |
| Главные применения | Условная компиляция, включение заголовков, feature detection, логирование |
| Ключевые директивы | `#include`, `#define`, `#if*`, `#pragma`, `#error`, `#`, `##` |
| Риски | Нет типизации, двойное вычисление, «загрязнение» имён, сложная отладка |
| Современная замена | `constexpr`, `inline`, шаблоны, `enum class`, модули |
