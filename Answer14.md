# Вопрос 14. Что такое шаблонный класс и шаблонная функция?

> **Кратко:** Шаблон — это «чертёж» кода, параметризованный типами или значениями. По этому чертежу компилятор генерирует конкретную функцию или класс под каждый набор аргументов (инстанциация). Шаблонная функция выводит параметры из аргументов вызова, шаблонный класс — нет: его параметры указываются явно.

---

## Терминология

Строго по стандарту — **шаблон функции** (function template) и **шаблон класса** (class template); «шаблонный класс» — разговорный синоним. Шаблон сам по себе не является типом и не порождает код, пока не будет инстанцирован, а подстановка аргументов идёт на этапе компиляции — это **статический полиморфизм** без накладных расходов в рантайме.

---

## Шаблонная функция

```cpp
#include <string>

// T выводится из аргументов вызова
template <typename T>
constexpr T maxOf(const T& a, const T& b) {
    return (a < b) ? b : a;
}

int main() {
    maxOf(3, 7);                     // T = int
    maxOf(2.5, 1.5);                 // T = double
    maxOf<std::string>("a", "b");    // T задан явно
    // maxOf(3, 7.5);                // ошибка: T выводится и как int, и как double
    // maxOf<double>(3, 7.5);        // так можно: оба аргумента приводятся к double
}
```

Параметров может быть несколько, а тип результата — вычисляться из выражения:

```cpp
template <typename T, typename U>
auto add(T a, U b) {        // C++14: возвращаемый тип выводится из return
    return a + b;
}
```

Если нужен именно тип выражения `a + b` (для SFINAE и корректных ссылочных категорий), пишут trailing return type: `auto add(T a, U b) -> decltype(a + b)`.

## Шаблонный класс

```cpp
#include <cstddef>

template <typename T, std::size_t N>   // T — тип, N — значение (non-type параметр)
class FixedArray {
public:
    static constexpr std::size_t size() noexcept { return N; }

    T& operator[](std::size_t i) noexcept { return data_[i]; }
    const T& operator[](std::size_t i) const noexcept { return data_[i]; }

private:
    T data_[N]{};                      // размер известен на этапе компиляции
};

FixedArray<int, 4> buf;                // параметры указываются явно
static_assert(FixedArray<int, 4>::size() == 4);
```

Это учебный аналог `std::array<T, N>`: размер — часть типа, поэтому `FixedArray<int, 4>` и `FixedArray<int, 8>` несовместимы, а динамической памяти в объекте нет.

---

## Виды параметров шаблона

| Вид | Синтаксис | Пример |
|---|---|---|
| Параметр-тип | `typename T` (== `class T`) | `template <typename T> T maxOf(T, T);` |
| Параметр-значение | `std::size_t N`, `int`, enum, указатель, ссылка | `template <typename T, std::size_t N> class FixedArray;` |
| Шаблон как параметр | `template <typename...> class C` | `template <template <typename...> class C, typename T>` |
| Пакет параметров | `typename... Ts`, `Ts... args` | `template <typename... Ts> void printAll(Ts...);` |
| Значение по умолчанию | `typename T = int` | `template <typename T = int> class Box;` |

С C++20 non-type параметрами могут быть также числа с плавающей точкой и литеральные классы (например, `FixedString<"abc">`).

---

## Шаблонная функция и шаблонный класс: различия

| Свойство | Шаблонная функция | Шаблонный класс |
|---|---|---|
| Вывод аргументов | Автоматически из аргументов вызова | Нет; C++17 добавил CTAD и deduction guides |
| Использование | `maxOf(a, b)` | `FixedArray<int, 4> a;` |
| Момент инстанциации | При вызове | При использовании типа |
| Специализация | Только полная | Полная и частичная |
| Где определять | В заголовке | В заголовке (если нет явной инстанциации) |
| Типичные примеры | `std::sort`, `std::max`, `std::make_unique` | `std::vector`, `std::array`, `std::map` |

## Как работает инстанциация

Компилятор подставляет аргументы в шаблон и генерирует обычный код — по одной версии на каждый набор аргументов. Отсюда два следствия:

1. **Определение должно быть видно в точке инстанциации** — шаблоны обычно живут целиком в заголовке; определение в `.cpp` даёт ошибку линковки `undefined reference`.
2. **Разрастание кода** (code bloat): десять инстанциаций — десять копий машинного кода.

Управлять этим позволяет явная инстанциация:

```cpp
// box.hpp
template <typename T>
class Box {
public:
    void put(const T& v) { value_ = v; }
    T get() const { return value_; }
private:
    T value_{};
};
extern template class Box<int>;   // не инстанцировать в каждом TU

// box.cpp
#include "box.hpp"
template class Box<int>;          // единственное определение инстанциации
```

Поиск имён в шаблонах двухфазный: **независимые** от параметров имена проверяются при разборе определения, **зависимые** — при инстанциации. Поэтому ошибки в шаблонном коде часто всплывают только в момент подстановки конкретного типа.

## Ограничение через концепты (C++20)

До C++20 ограничения писали через SFINAE (`std::enable_if`, `decltype`), и сообщения об ошибках были нечитаемыми. Концепты делают требование к типу явным — либо именем концепта, либо `requires`-выражением:

```cpp
#include <concepts>

template <std::unsigned_integral T>
constexpr T gcd(T a, T b) {
    while (b != 0) {
        const T t = a % b;
        a = b;
        b = t;
    }
    return a;
}
```

`gcd(12u, 18u)` компилируется, `gcd(1.5, 2.5)` отвергается с внятной диагностикой: `double` не удовлетворяет `std::unsigned_integral`.

## Шаблоны против виртуальных функций

| Критерий | Шаблоны (статический полиморфизм) | Виртуальные функции (динамический) |
|---|---|---|
| Момент выбора реализации | Компиляция | Выполнение |
| Стоимость вызова | Нулевая, часто инлайнится | Косвенный вызов через `vtable` |
| Требование к типу | Неявное: достаточно нужных операций | Явное наследование от базы |
| Добавление нового типа | Нужна перекомпиляция | Без изменения базового класса |
| Размер бинарника | Растёт с числом инстанциаций | Один общий код |
| Диагностика ошибок | Длинная, на этапе инстанциации | Короче, но ошибки бывают в рантайме |
| Время компиляции | Больше | Меньше |

Практический вывод: шаблоны — когда типы известны при компиляции и важна производительность (контейнеры, алгоритмы); виртуальные функции — когда набор реализаций расширяется в рантайме.

## Типичные ошибки

1. **Определение шаблона в `.cpp`** без явной инстанциации — ошибка линковки `undefined reference`.
2. **Забытый `typename`** перед зависимым именем типа: `typename T::value_type`, иначе компилятор считает это значением.
3. **Несовпадающий вывод**: `maxOf(3, 7.5)` выводит `T` противоречиво; нужен явный аргумент или два параметра.
4. **Специализация после первой инстанциации** — программа некорректна (ill-formed, диагностика не обязательна).
5. **Частичная специализация шаблона функции** — не поддерживается стандартом, только перегрузка.
6. **Шаблон ради шаблона**: если тип один и известен, обычная функция читается лучше.
7. **Ошибки, спрятанные до инстанциации**: шаблон компилируется, но не работает ни с одним реальным типом.
8. **Отсутствие `extern template`** при частом включении тяжёлого шаблона — раздувание времени сборки.

## Что добавить на собеседовании

- Шаблоны — это **compile-time duck typing**: тип подходит, если у него есть нужные операции; проверка отложена до инстанциации.
- Полезно знать инструменты: `std::enable_if`, `if constexpr` (C++17), `std::type_traits`, концепты и `requires` (C++20).
- Стоит упомянуть компромисс «шаблоны против стирания типов»: `std::function` даёт единый тип ценой косвенного вызова, шаблон — скорость ценой размножения кода.
- Пакет параметров (`typename... Ts`) и fold-выражения (C++17) — основа вариадических шаблонов вроде `std::make_unique` и `std::tuple`.
- Хороший ответ показывает понимание **цены** шаблонов: время компиляции, размер бинарника и качество диагностики.

## Итог

| Понятие | Суть |
|---|---|
| Шаблон функции | Функция с параметрами-типами; аргументы выводятся из вызова |
| Шаблон класса | Класс с параметрами-типами и/или значениями; параметры задаются явно |
| Инстанциация | Генерация конкретного кода под набор аргументов |
| Где определять | В заголовке, иначе ошибка линковки |
| Ограничения | Концепты и `requires` (C++20) вместо голого SFINAE |
| Главный компромисс | Скорость и типобезопасность против размера кода и времени компиляции |
