# 95. Для чего использовать `namespace`, anonymous namespace?

## Обычный `namespace`

`namespace` — это механизм группировки имён (типов, функций, переменных, констант) в логические области, чтобы **избежать конфликтов имён** между разными частями программы и библиотеками.

### Основные причины использования

1. **Предотвращение коллизий имён.** Две библиотеки могут содержать функцию `log()` — без пространств имён они не скомпонуются/не скомпилируются вместе.

```cpp
namespace math {
    double log(double x);
}

namespace logging {
    void log(const std::string& msg);
}

int main() {
    math::log(2.718);        // однозначно
    logging::log("hello");
}
```

2. **Логическая организация кода.** Группировка связанного функционала: `std::`, `boost::filesystem`, `myproject::network` и т.д.

3. **Управление видимостью через вложенность.** Вложенные пространства имён (в C++17 — сокращённая запись):

```cpp
namespace company::project::detail {
    void helper();
}
```

4. **Расширяемость.** В отличие от классов, пространство имён можно «открывать» повторно в разных файлах — это позволяет разносить одну логическую группу по нескольким заголовкам.

5. **Псевдонимы для удобства** (особенно для длинных имён):

```cpp
namespace fs = std::filesystem;
fs::path p = "data.txt";

// C++20: namespace-псевдоним для вложенного
namespace io = company::project::io;
```

6. **`inline namespace` для версионирования** — позволяет менять реализацию, сохраняя совместимость ABI:

```cpp
namespace lib {
    inline namespace v2 {
        void foo();   // вызывается как lib::foo(), но реально lib::v2::foo()
    }
}
```

### Важные замечания

- `using namespace std;` в заголовочных файлах — **плохая практика** (загрязняет область видимости у всех, кто подключает заголовок).
- Специализации шаблонов, ADL (поиск, зависящий от аргументов) — тоже завязаны на пространства имён.

## Anonymous namespace (безымянное пространство имён)

Безымянное пространство имён — это пространство имён без имени:

```cpp
namespace {
    int counter = 0;
    void helper() { /* ... */ }
}
```

### Для чего нужно

Главное назначение — **дать сущностям внутреннюю линковку (internal linkage)**, то есть сделать их видимыми **только в пределах текущей единицы трансляции** (`.cpp`-файла). Это современная замена `static` для функций и переменных на глобальном уровне.

### Причины использования

1. **Скрытие деталей реализации.** Вспомогательные функции и переменные не «протекают» в глобальное пространство имён и не конфликтуют с одноимёнными сущностями в других `.cpp`.

```cpp
// file a.cpp
namespace {
    void helper() { }   // видна только в a.cpp
}
void api_a() { helper(); }

// file b.cpp
namespace {
    void helper() { }   // своя, независимая — конфликта нет
}
void api_b() { helper(); }
```

2. **Замена `static`.** Для переменных и функций `static` на файловом уровне делал то же самое, но:

   - `static` **нельзя** применить к определениям типов (классам, `enum`, `typedef`/`using`);
   - безымянное пространство имён работает единообразно для **всех** сущностей.

```cpp
namespace {
    struct Impl { int x; };      // static struct нельзя
    enum class Mode { A, B };    // static enum нельзя
    template<class T> void f(T); // static template нельзя
}
```

3. **Избежание ODR-нарушений.** Сущности из анонимного пространства имён в разных `.cpp` — это разные сущности, поэтому одинаковые имена не приводят к нарушению правила одного определения.

4. **Улучшение инкапсуляции и оптимизаций.** Компилятор знает, что сущность не используется вне файла, и может агрессивнее её оптимизировать (инлайнинг, удаление неиспользуемого).

### Практические нюансы

- Анонимное пространство имён **открывается заново** при каждом `namespace { }`, но все такие блоки в одном файле относятся к **одному и тому же** безымянному пространству.
- Внутри анонимного пространства можно обращаться к именам без квалификации — это удобно.
- Не следует помещать в заголовочные файлы (`*.h`): каждый `.cpp`, включивший заголовок, получит **свою** копию сущности — это почти всегда ошибка (раздувание кода, разные «версии» одной переменной).

```cpp
// ПЛОХО в .h
namespace {
    int global_state = 0;  // у каждого .cpp своя копия!
}
```

### Сравнение `static` vs anonymous namespace

| Критерий | `static` (файловый уровень) | anonymous namespace |
|---|---|---|
| Функции, переменные | ✅ | ✅ |
| Классы, `enum`, шаблоны | ❌ | ✅ |
| Современный стиль | устаревает | рекомендуется |
| Работа с `using`-объявлениями | ограниченно | удобно |

## Краткий итог

- **`namespace`** — группировка имён для предотвращения конфликтов, логической структуры кода и управления видимостью; расширяем, поддерживает псевдонимы и версионирование через `inline`.
- **Anonymous namespace** — даёт **внутреннюю линковку** сущностям в пределах одной единицы трансляции; современная и более универсальная замена `static` для скрытия деталей реализации (функций, переменных, **а также типов и шаблонов**). Не использовать в заголовках.
