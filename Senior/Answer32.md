# 32. Что такое placement new? Для чего используют? Как сделать placement delete?

## Кратко

**Placement new** — это форма `new`, которая **не выделяет память**, а конструирует объект в уже существующем буфере по указанному адресу. За корректность буфера (размер, выравнивание, время жизни) отвечает программист.

**«Placement delete»** как отдельного выражения в языке нет: чтобы завершить время жизни объекта, нужно **явно вызвать деструктор** (`p->~T()` или `std::destroy_at(p)`). Термин «placement delete» в стандарте относится к парной `operator delete(void*, void*)`, которая автоматически вызывается только при исключении в конструкторе и ничего не освобождает.

Сразу оговорка: всё это — **только C++**. В C конструкторов и `new` нет; там аналог — `malloc` + функция инициализации либо запись в буфер через `memcpy`/присваивание.

---

## 1. Синтаксис и семантика

Обычное выражение `new T(args)` делает три вещи:

1. вызывает `operator new(sizeof(T))` — **выделяет** память;
2. вызывает конструктор `T` в этой памяти;
3. возвращает указатель на объект.

Placement new `new (ptr) T(args)`:

1. вызывает `operator new(sizeof(T), ptr)` — стандартная версия просто **возвращает `ptr`**;
2. вызывает конструктор `T` по адресу `ptr`;
3. возвращает `ptr`, приведённый к `T*`.

Никакого выделения, никакой проверки размера и выравнивания нет.

```cpp
#include <new>
#include <cstddef>

alignas(T) std::byte buf[sizeof(T)];   // хранилище
T* p = new (buf) T(args...);           // только конструирование
```

Стандартная форма объявлена в `<new>`:

```cpp
void* operator new  (std::size_t, void* ptr) noexcept;
void* operator new[](std::size_t, void* ptr) noexcept;
```

Эти сигнатуры **зарезервированы**: заменять (replacement) их нельзя, но можно добавлять свои перегрузки с другими параметрами.

## 2. Стандартные placement-формы и «placement delete»

В `<new>` есть четыре функции, образующие пару:

```cpp
void* operator new  (std::size_t, void* ptr) noexcept;   // placement new
void* operator new[](std::size_t, void* ptr) noexcept;   // placement new[]
void  operator delete  (void* ptr, void* place) noexcept; // placement delete
void  operator delete[](void* ptr, void* place) noexcept; // placement delete[]
```

- Первые две **не выделяют память** — просто возвращают `ptr`.
- Вторые две **ничего не делают**. Они не вызываются `delete`-выражением (такого синтаксиса нет). Единственный случай, когда они вызываются, — **исключение в конструкторе** во время выполнения `new (p) T(...)`: тогда реализация ищет подходящую `operator delete` с теми же дополнительными аргументами и вызывает её, чтобы дать возможность освободить ресурсы, захваченные в placement new. Для стандартной формы освобождать нечего, поэтому это no-op.

Важно не путать с похожим синтаксисом:

- `new (std::nothrow) T` — это **не** placement new в классическом смысле: память выделяется, просто при неудаче возвращается `nullptr` вместо `std::bad_alloc`;
- `new (std::align_val_t{64}) T` — выравнивающее выделение, тоже не «конструирование на месте».

## 3. Чем отличается от обычного `new`

| Свойство | обычный `new T` | placement new `new (p) T` |
|---|---|---|
| Выделяет память | да | **нет** |
| Вызывает конструктор | да | да |
| Можно ли `delete p` | да | **нет, UB** |
| Может бросить `bad_alloc` | да | нет (`noexcept`), но конструктор может бросить своё |
| Выравнивание | гарантирует `operator new` | **отвечает программист** |
| Освобождение | `operator delete` | **явный вызов деструктора** + освобождение буфера вручную |

## 4. Зачем используют placement new

1. **Разделение выделения памяти и конструирования.** Классический приём для пулов, арен, кастомных аллокаторов: память берётся большими блоками, а объекты создаются на месте по мере необходимости.

2. **Контейнеры и обёртки.** `std::vector`, `std::optional`, `std::variant`, `std::any`, `std::function` (small buffer optimization) хранят объекты в «сыром» хранилище и создают их именно placement new.

3. **Память из C-API или чужого аллокатора.** `malloc`, `mmap`, разделяемая память, память от драйвера, буфер сетевой библиотеки — конструктор C++ объекта нужно вызвать вручную:

   ```cpp
   void* mem = std::malloc(sizeof(T));
   T* p = new (mem) T(args...);
   // ...
   p->~T();
   std::free(mem);
   ```

4. **Embedded / bare-metal.** Когда динамическое выделение запрещено, объект размещают в статическом буфере или в стеке.

5. **Фиксированные адреса.** Memory-mapped I/O, DMA-буферы, регистры периферии, структуры в shared memory — объект обязан находиться по конкретному адресу.

6. **Переиспользование памяти без освобождения.** В высоконагруженном коде объект уничтожают и создают заново в том же буфере, не трогая аллокатор (меньше фрагментации и накладных расходов).

7. **Точный контроль времени жизни.** Нужно создать объект позже, чем появилась память, или уничтожить раньше, чем освободится буфер.

8. **Реализация собственных контейнеров и аллокаторов.** `std::allocator_traits<A>::construct` по умолчанию как раз делает placement new.

9. **Гарантия отсутствия `bad_alloc`.** Стандартный placement new объявлен `noexcept` — он не может не выделить память, потому что ничего не выделяет.

10. **`constexpr`-конструирование (C++20).** В постоянных выражениях вместо placement new удобнее `std::construct_at`, но концептуально это то же самое.

## 5. Как «удалить» объект, созданный placement new

Главное правило: **`delete p` для результата placement new — неопределённое поведение.** `operator delete` попытается освободить память, которую никто не выделял через `operator new`, — типичный heap corruption.

Правильный способ — **явный вызов деструктора**:

```cpp
p->~T();
```

Начиная с C++17 то же самое делает `std::destroy_at`:

```cpp
#include <memory>
std::destroy_at(p);   // вызывает p->~T(), в C++20 есть и для массивов
```

После этого время жизни объекта завершено, а память буфера остаётся в вашем распоряжении: её можно переиспользовать или освободить тем способом, которым она была получена.

```cpp
#include <new>
#include <cstddef>
#include <iostream>

struct Point {
    int x, y;
    Point(int x, int y) : x(x), y(y) { std::cout << "Point\n"; }
    ~Point() { std::cout << "~Point\n"; }
};

int main() {
    alignas(Point) std::byte buf[sizeof(Point)];

    Point* p = new (buf) Point{1, 2};
    std::cout << p->x << ", " << p->y << '\n';

    p->~Point();                        // конец времени жизни

    p = new (buf) Point{3, 4};          // переиспользуем ту же память
    std::cout << p->x << ", " << p->y << '\n';
    p->~Point();
}
```

Если объект создавался в памяти из `malloc`, после деструктора нужно ещё вызвать `std::free`; если в буфере — просто пометить буфер свободным; если в арене — вернуть арене.

## 6. Placement delete в смысле стандарта: парная `operator delete`

Если вы определяете **свой** placement new, который захватывает ресурс (память арены, дескриптор, слот пула), нужно определить и **парную** `operator delete` с теми же дополнительными параметрами. Тогда при исключении из конструктора она будет вызвана автоматически.

```cpp
struct Arena {
    void* allocate(std::size_t);
    void  deallocate(void*);
};

void* operator new(std::size_t n, Arena& a) {
    void* p = a.allocate(n);
    if (!p) throw std::bad_alloc{};
    return p;
}

void operator delete(void* p, Arena& a) noexcept {
    a.deallocate(p);          // вызывается, если конструктор бросил
}
```

Теперь:

```cpp
struct Widget {
    Widget() { throw std::runtime_error("boom"); }
};

Arena arena;
try {
    Widget* w = new (arena) Widget;   // конструктор бросил
} catch (const std::exception&) {
    // operator delete(ptr, arena) уже вызван автоматически
}
```

То же самое можно оформить как члены класса:

```cpp
struct Widget {
    static void* operator new(std::size_t n, Arena& a) {
        return a.allocate(n);
    }
    static void operator delete(void* p, Arena& a) noexcept {
        a.deallocate(p);
    }
    Widget() { throw std::runtime_error("boom"); }
};

Widget* w = new (arena) Widget;  // при исключении вызовется Widget::operator delete(p, arena)
```

Правила поиска: при исключении из конструктора ищется `operator delete` **в области видимости класса конструктора**, затем в глобальной. Если подходящей не найдено — **ничего не вызывается** (для class-specific placement new это может привести к утечке ресурса; MSVC в таком случае выдаёт предупреждение C4291).

Для **стандартного** `new (ptr) T` парная `operator delete(void*, void*)` уже есть и ничего не делает — утечки нет, потому что память не выделялась. Но и «освободить» ею ничего нельзя.

> Отсюда частая формулировка: «placement delete не существует как средство уничтожения объекта; есть только парный `operator delete` для обработки исключений, а уничтожение — это явный вызов деструктора».

## 7. Полный пример: статический пул

```cpp
#include <cstddef>
#include <new>
#include <utility>

template <typename T, std::size_t N>
class StaticPool {
    alignas(T) std::byte storage_[N][sizeof(T)];
    bool alive_[N]{};

public:
    template <typename... Args>
    T* create(Args&&... args) {
        for (std::size_t i = 0; i < N; ++i) {
            if (!alive_[i]) {
                // ::new — чтобы гарантированно взять глобальный placement new,
                // даже если у T есть собственный operator new
                T* p = ::new (static_cast<void*>(storage_[i]))
                           T(std::forward<Args>(args)...);
                alive_[i] = true;   // только после успешного конструирования
                return p;
            }
        }
        throw std::bad_alloc{};
    }

    void destroy(T* p) noexcept {
        p->~T();
        auto* raw = reinterpret_cast<std::byte*>(p);
        for (std::size_t i = 0; i < N; ++i) {
            if (raw == storage_[i]) {
                alive_[i] = false;
                return;
            }
        }
    }
};
```

Здесь `create` — placement new, `destroy` — то, что обычно называют «placement delete»: деструктор плюс возврат слота в пул. Флаг `alive_` выставляется **после** конструктора, поэтому исключение не оставит «занятый» слот.

## 8. Подводные камни

1. **`delete p` — UB.** Никогда не смешивайте placement new с `delete`/`delete[]`.

2. **Двойной вызов деструктора — UB.** Ведите учёт, жив объект или нет.

3. **Выравнивание.** Буфер обязан быть выровнен под `T`:
   ```cpp
   alignas(T) std::byte buf[sizeof(T)];
   ```
   `std::aligned_storage` объявлен deprecated в C++23 — используйте `alignas`. Стандартный placement new выравнивание **не проверяет**; ошибка проявится позже и в другом месте.

4. **Размер буфера не проверяется.** `new (buf) T` не знает, сколько за `buf` байт.

5. **`std::launder` при переиспользовании памяти.** Если объект с `const`-членом или ссылочным членом создан заново в той же памяти, старый указатель формально может не указывать на новый объект:
   ```cpp
   struct S { const int n; S(int n) : n(n) {} };

   alignas(S) std::byte buf[sizeof(S)];
   S* p = new (buf) S{1};
   p->~S();
   new (buf) S{2};

   int v = p->n;                                        // неопределённое поведение
   S* q = std::launder(reinterpret_cast<S*>(buf));      // корректно
   ```

6. **Исключения.** Стандартный placement delete ничего не освобождает; для своего placement new определяйте парный delete, иначе ресурс утечёт.

7. **`new (nullptr) T`.** По стандарту указатель для стандартного placement new должен быть ненулевым; передача `nullptr` — UB.

8. **Массивы.** `new (buf) T[n]` возможен (`operator new[]`), но `delete[]` к нему применять нельзя; уничтожать элементы нужно циклом.

9. **Повторная инициализация `this`.** `new (this) T(...)` после явного `~T()` — легальный, но экзотический приём; легко получить UB при наследовании и виртуальных функциях.

10. **Полиморфизм.** Если уничтожаете через указатель на базовый класс, деструктор базы должен быть виртуальным — это общее правило, но с ручным вызовом деструктора о нём особенно легко забыть.

11. **Class-specific `operator new`.** Если у `T` есть свой `operator new`, выражение `new (p) T` может найти именно его (или не найти подходящей перегрузки и выдать ошибку). `::new (p) T` принудительно использует глобальную форму.

## 9. Современные альтернативы

| Средство | Стандарт | Комментарий |
|---|---|---|
| `std::construct_at(p, args...)` | C++20 | constexpr-дружелюбная обёртка над placement new; предпочтительна в обобщённом коде |
| `std::destroy_at(p)` | C++17 | Явный вызов деструктора, в т.ч. для массивов в C++20 |
| `std::allocator_traits<A>::construct/destroy` | C++11 | Обобщённый интерфейс аллокатора; по умолчанию — placement new и `p->~T()` |
| `std::uninitialized_copy`, `std::uninitialized_fill`, … | C++11/17 | Алгоритмы, которые сами вызывают конструкторы в сырой памяти |
| `std::optional`, `std::variant`, `std::any` | C++17 | Готовые обёртки вместо ручного управления временем жизни |
| `std::start_lifetime_as` | C++23 | Начало времени жизни для implicit-lifetime типов без вызова конструктора |
| `alignas(T) std::byte buf[sizeof(T)]` | C++17 | Замена `std::aligned_storage` (deprecated в C++23) |

## 10. Шпаргалка

| Действие | Код |
|---|---|
| Создать объект в готовой памяти | `new (buf) T(args...)` |
| Создать в памяти от `malloc` | `T* p = new (mem) T(args...);` |
| Уничтожить | `p->~T();` или `std::destroy_at(p);` |
| Освободить память | вручную: `free`, вернуть в арену, пометить слот |
| `delete p` | **нельзя — UB** |
| Свой placement new с ресурсом | определить парный `operator delete(void*, ...)` для обработки исключений |
| Форсировать глобальный placement new | `::new (buf) T(...)` |

**Итог:** placement new — это способ отделить «взять память» от «создать объект». Он незаменим в пулах, контейнерах, embedded и при работе с чужой памятью. «Удаления» в виде отдельного оператора для него нет: время жизни завершается явным вызовом деструктора, а стандартная `operator delete(void*, void*)` — это лишь no-op-партнёр для раскрутки стека при исключении в конструкторе.
