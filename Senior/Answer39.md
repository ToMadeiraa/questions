# 39. Какое назначение и отличия использования std::variant и std::any?

## Краткий ответ

Оба класса появились в C++17 и решают одну общую задачу — **хранить значение, тип которого не фиксирован одним конкретным типом**. Но решают её принципиально по-разному:

- **`std::variant<Ts...>`** — это типобезопасное объединение (sum type, «или-или») с **закрытым, известным на этапе компиляции** набором альтернатив. Тип значения выбирается из фиксированного списка, и компилятор может проверить, что вы обработали все варианты.
- **`std::any`** — это контейнер для **одного значения произвольного копируемого типа**, набор типов **открыт** и полностью определяется во время выполнения. Тип «стирается» и восстанавливается через `any_cast`.

Грубо говоря: `variant` — это «динамический тип с закрытым меню», `any` — «динамический тип с открытым меню». Первый даёт скорость и статическую проверку, второй — максимальную гибкость ценой производительности и безопасности.

## 1. `std::variant` — назначение

`std::variant` — это замена «голому» `union`, которая:

- хранит **ровно одну** из альтернатив;
- помнит, какая именно альтернатива активна (хранит индекс);
- корректно вызывает конструкторы и деструкторы активного объекта;
- не позволяет читать «не тот» тип без явной проверки.

Заголовок: `<variant>`.

### Типичные применения

- **Алгебраические типы данных**: `variant<Error, Value>`, результат парсинга, состояние конечного автомата.
- **AST/JSON/конфиг**: узел — это число, строка, массив или объект.
- **Замкнутые наборы команд/событий**: `variant<Click, KeyPress, Resize>`.
- **Замена виртуальных функций**, когда набор типов фиксирован и не должен расширяться: value-семантика, отсутствие кучи и виртуальных вызовов.
- **«Результат или ошибка»** до появления `std::expected` (C++23).

### Пример

```cpp
#include <variant>
#include <string>
#include <iostream>
#include <type_traits>

using Value = std::variant<std::monostate, int, double, std::string>;

void print(const Value& v) {
    std::visit([](const auto& x) {
        using T = std::decay_t<decltype(x)>;
        if constexpr (std::is_same_v<T, std::monostate>)
            std::cout << "<empty>";
        else
            std::cout << x;
        std::cout << '\n';
    }, v);
}

int main() {
    Value v;                     // monostate — «пусто»
    v = 42;                      // int
    print(v);

    v = std::string("hello");    // string
    print(v);

    if (auto* p = std::get_if<int>(&v)) {
        std::cout << "int = " << *p << '\n';
    } else {
        std::cout << "index = " << v.index() << '\n';
    }

    try {
        auto d = std::get<double>(v); // не тот тип
    } catch (const std::bad_variant_access& e) {
        std::cout << "bad_variant_access: " << e.what() << '\n';
    }
}
```

Классический приём — «overloaded»-визитор, который требует обработать все альтернативы:

```cpp
template<class... Ts>
struct overloaded : Ts... { using Ts::operator()...; };

template<class... Ts>
overloaded(Ts...) -> overloaded<Ts...>;

std::visit(overloaded{
    [](int i)                { std::cout << "int "    << i << '\n'; },
    [](double d)             { std::cout << "double " << d << '\n'; },
    [](const std::string& s) { std::cout << "string " << s << '\n'; },
    [](std::monostate)       { std::cout << "empty\n"; }
}, v);
```

### Ключевые свойства

- Набор альтернатив **фиксирован в типе**; добавить новый вариант без изменения типа нельзя.
- `std::visit` **статически** требует, чтобы визитор мог обработать каждую альтернативу (иначе ошибка компиляции); возвращаемый тип у всех ветвей должен быть совместим (обычно одинаков).
- Доступ по типу — `std::get<T>` (тип должен встречаться ровно один раз), по индексу — `std::get<I>`; безопасная форма — `std::get_if` (возвращает `nullptr`).
- `std::holds_alternative<T>` и `v.index()` позволяют узнать активную альтернативу.
- `std::monostate` — пустая альтернатива, чтобы `variant` был default-конструируемым или чтобы выразить «значения нет».
- Может хранить **move-only** типы (`std::unique_ptr` и т.п.); тогда сам `variant` move-only.
- Поддерживает сравнение (`==`, `!=`, `<`, … , в C++20 — `<=>`), если его поддерживают альтернативы; порядок — сначала по индексу, затем по значению.
- Может использоваться в `constexpr`-контексте при «литеральных» альтернативах (`std::visit` стал `constexpr` в C++20).
- Не требует RTTI.
- Альтернативы должны быть полными объектными типами: **нельзя** ссылки, массивы, `void`; нельзя хранить сам `variant` напрямую (рекурсия — через `std::vector<Value>` или `std::unique_ptr`).

## 2. `std::any` — назначение

`std::any` — это type-erased контейнер: он хранит **одно значение любого типа, удовлетворяющего `CopyConstructible`**, и позволяет позже извлечь его, **точно** указав тип. Внутри сохраняется информация о типе (обычно через `typeid`) и указатели на операции копирования/уничтожения.

Заголовок: `<any>`.

### Типичные применения

- **Property bag / динамический словарь**: набор именованных значений заранее неизвестных типов (настройки, метаданные).
- **Границы плагинов, скриптов, FFI, C API**: через границу передаётся «что-то», а конкретный тип известен только принимающей стороне.
- **Обобщённые хранилища и реестры**: например, кэш «любых» объектов.
- **Прототипирование**, где важнее гибкость, чем производительность.
- Ситуации, когда набор типов **принципиально открыт** и не может быть перечислен в типе.

### Пример

```cpp
#include <any>
#include <string>
#include <iostream>

int main() {
    std::any a = 42;
    std::cout << a.type().name() << '\n';  // обычно "int"

    a = std::string("hello");
    std::cout << std::any_cast<std::string>(a) << '\n';

    // any_cast не делает преобразований: нужен ТОЧНЫЙ тип
    try {
        int x = std::any_cast<int>(a);     // бросит std::bad_any_cast
    } catch (const std::bad_any_cast& e) {
        std::cout << "bad_any_cast: " << e.what() << '\n';
    }

    // Без исключений: указательная форма возвращает nullptr при несовпадении
    if (auto* p = std::any_cast<std::string>(&a)) {
        p->append("!");
        std::cout << *p << '\n';
    }

    // Изменение значения на месте
    std::any b = 10;
    std::any_cast<int&>(b) = 20;
    std::cout << std::any_cast<int>(b) << '\n';

    b.reset();
    std::cout << std::boolalpha << b.has_value() << '\n'; // false
}
```

### Ключевые свойства

- Хранит значение **любого** `CopyConstructible`-типа; move-only типы (`std::unique_ptr`) напрямую хранить **нельзя**.
- Тип известен только в рантайме; `a.type()` возвращает `std::type_info` (для пустого `any` — `typeid(void)`).
- `std::any_cast<T>` требует **точного** совпадения типа: никаких пользовательских преобразований, никакого срезания/приведения к базовому классу, `int` → `double` не сработает.
- Ошибка извлечения: исключение `std::bad_any_cast` (наследник `std::bad_cast`) или `nullptr` у указательной перегрузки `any_cast<T>(&a)`.
- Пустое состояние — **нормальное** и штатное: `std::any{}`, `has_value() == false`, `reset()`.
- Есть `emplace<T>(args...)`, `swap`, конструкторы `in_place_type<T>`.
- **Нет** операторов сравнения (`==`, `<`) и `std::hash` — сравнивать можно только после извлечения.
- Не является `constexpr` (по крайней мере в C++17–C++23).
- Типичные реализации используют small-buffer optimization, но при нехватке места — **динамическую аллокацию**.
- Обычно опирается на `typeid`, т.е. может требовать RTTI (зависит от реализации и флагов компиляции).
- Хранит `std::decay_t<T>`: массивы и функции «decay»-ятся, ссылки напрямую не хранятся (используйте `std::reference_wrapper` / `std::ref`).

## 3. Сравнение

| Критерий | `std::variant<Ts...>` | `std::any` |
|---|---|---|
| Множество типов | Закрытое, известно компилятору | Открытое, любой `CopyConstructible` тип |
| Проверка типов | Компилятор (`visit`, `get<T>`) + рантайм (`get_if`) | Только рантайм |
| Хранение | Внутри объекта: `max(sizeof(Ts))` + индекс | Фиксированный буфер (SBO) + возможная куча |
| Аллокации | Обычно нет | Возможны |
| Скорость доступа | Высокая: `visit` часто превращается в `switch`/таблицу переходов и инлайнится | Ниже: косвенный вызов операций, проверка `typeid` |
| Диспетчеризация | `std::visit`, `switch (v.index())` | `any_cast` + `if/else` по `type()` |
| Ошибка неверного доступа | `std::bad_variant_access`, `get_if` → `nullptr` | `std::bad_any_cast`, `any_cast(&)` → `nullptr` |
| Копирование | Условное: зависит от альтернатив | Обязательно копируемый тип |
| Move-only типы | Да | Нет |
| Сравнение | `==`, `<`, `<=>` (если у альтернатив) | Нет |
| `constexpr` | Да (при подходящих альтернативах) | Нет (C++17–23) |
| RTTI | Не нужен | Обычно нужен (`typeid`) |
| «Пустое» состояние | Только `valueless_by_exception` (аварийное) или `monostate` | Штатное: `has_value() == false` |
| Конструктор по умолчанию | Первая альтернатива (или `monostate`) | Пустой `any` |
| Расширяемость набора типов | Только изменением типа | В любой момент, без изменения типа контейнера |
| Типичная ниша | Суммы типов, AST, состояния, `Result<T,E>` | Плагины, property bag, динамические API, FFI |

## 4. Внутреннее устройство и цена

### `std::variant`

- Размер: `max(sizeof(Ts)...)` с учётом выравнивания плюс дискриминант (индекс). Для небольших наборов индекс занимает 1 байт, но реализация вправе взять больше. Плюс возможный padding.
- Цена `std::visit`: обычно компилируется в `switch` по индексу или таблицу переходов; при небольшом числе альтернатив хорошо инлайнится и оптимизируется.
- Цена `std::get<T>` / `get_if`: проверка индекса, O(1), без RTTI.
- Копирование/перемещение — это покомпонентная операция над активной альтернативой, без стирания типа.

### `std::any`

- Размер фиксирован (обычно несколько указателей, например 16–32 байта в зависимости от стандартной библиотеки) независимо от хранимого типа.
- Крупные объекты кладутся в кучу; мелкие могут попасть в SBO.
- Каждая операция (копирование, уничтожение, извлечение) идёт через сохранённые указатели на функции — это косвенный вызов.
- `any_cast` сравнивает `typeid`, т.е. это рантайм-проверка при каждом извлечении.
- Итог: `any` удобен, но заметно дороже `variant` по скорости и может аллоцировать память.

## 5. Подводные камни

### `std::variant`

- **`valueless_by_exception()`**: если при смене альтернативы конструктор/перемещение нового значения бросит исключение, `variant` может остаться без значения. Тогда `index() == std::variant_npos`, а `get`/`visit` бросают `std::bad_variant_access`. Это редкое, но реальное состояние — учитывайте его в критичном коде.
- **`std::get<T>` требует уникальности**: если тип повторяется среди альтернатив, используйте `std::get<I>`.
- **Нет неявных преобразований при извлечении**: `get<double>` не сработает, если активен `int`.
- **Визитор должен покрывать все альтернативы** — это и преимущество (забыть вариант не даст компилятор), и неудобство (добавление альтернативы ломает сборку — впрочем, это часто именно то, что нужно).
- **Рекурсивные типы** напрямую невозможны: используйте `std::vector<Value>` или `std::unique_ptr`.
- `variant` с `monostate` — удобный способ получить «пустое» значение, но не путайте его с аварийным `valueless_by_exception`.

### `std::any`

- **Нет статической проверки**: ошибка типа обнаруживается только в рантайме.
- **Точное совпадение типов**: `any_cast<Base*>` не сработает для хранимого `Derived*`; приведений нет.
- **Требуется копируемость**: move-only типы не подходят; для них нужен собственный type erasure или `unique_ptr<Base>`.
- **Ссылки не хранятся**: `std::any a = x;` скопирует `x`; для ссылочной семантики — `std::ref(x)` / `std::reference_wrapper`.
- **Нет сравнения и хеширования** — сначала извлеките значение.
- **Производительность**: возможные аллокации и косвенные вызовы; в горячем коде `any` обычно неуместен.
- **RTTI**: типичные реализации используют `typeid`; при экзотических настройках сборки это может быть ограничением.
- `any` не выражает «набор допустимых типов»: любой код, получивший `any`, вынужден защищаться от любого типа.

## 6. Как выбирать

**Берите `std::variant`, если:**

- набор типов известен и закрыт;
- важны производительность, отсутствие аллокаций, value-семантика;
- нужна проверка полноты обработки на этапе компиляции;
- вы моделируете сумму типов: состояние, событие, AST, `Result<T, E>`;
- нужны move-only альтернативы.

**Берите `std::any`, если:**

- набор типов принципиально открыт (плагины, скрипты, внешние API, property bag);
- тип становится известен только в рантайме, и заранее перечислить его нельзя;
- гибкость важнее скорости;
- нужен простой способ протащить «произвольное значение» через слабо типизированную границу.

**Не берите ни то, ни другое, если:**

- тип на самом деле один — хватит `std::optional<T>`;
- нужен полиморфизм с открытым набором наследников — обычная иерархия с виртуальными функциями или type erasure через `std::function`/собственный интерфейс;
- нужен именно «результат или ошибка» — в C++23 есть `std::expected<T, E>`, который выражает намерение точнее, чем `variant`.

## 7. Связь с другими инструментами

- `std::variant` — это развитие `union` в сторону типобезопасности; `std::any` — развитие `void*` в сторону владения и знания типа.
- `std::variant` + `std::visit` — статический аналог паттерна «посетитель» без виртуальных функций.
- `std::any` идейно близок к динамически типизированным языкам и к `boost::any`.
- `std::variant<std::monostate, T>` — «опциональный» вариант; `std::optional<T>` — более точный инструмент, когда альтернатива всего одна.
- `std::variant` с `std::vector`/`std::unique_ptr` позволяет строить рекурсивные структуры (деревья выражений, JSON).

---

## 8. Итог

`std::variant` и `std::any` — не взаимозаменяемые «контейнеры любого типа», а инструменты для разных задач:

- **`variant`** — про **контроль и производительность**: закрытый набор типов, проверка на этапе компиляции, отсутствие стирания типа, предсказуемая память. Идеален для моделирования данных и состояний.
- **`any`** — про **максимальную гибкость**: открытый набор типов, позднее связывание, простота интеграции. Плата — рантайм-проверки, возможные аллокации и потеря статических гарантий.

Практическое правило: **если можете перечислить типы — почти всегда `variant`; если не можете — `any` (или собственный type erasure).**
