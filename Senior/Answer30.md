# 30. Что такое rvalue и lvalue?

## Коротко

**lvalue** — это выражение, которое обозначает объект или функцию и обладает **идентичностью**: у него есть место в памяти (адрес), и это место сохраняется при вычислении выражения. Про такие выражения говорят «locator value» — значение-локатор.

**rvalue** — это выражение, которое не является lvalue. В современном C++ (C++11 и новее) rvalue — это **prvalue** или **xvalue**: выражение, обозначающее значение, ресурсы которого можно «переместить» (обычно потому, что объект скоро прекратит существование).

Названия происходят от `lvalue = left value`, `rvalue = right value`: исторически lvalue могло стоять слева от `=`, rvalue — справа. Но **определение через позицию в присваивании неверно**: `const int x` — lvalue, хотя слева от `=` стоять не может; результат `x = 5` — тоже lvalue, хотя стоит справа; `std::move(x)` — rvalue, хотя обозначает именованный объект. Поэтому в C++ категории определяются семантически, а не синтаксически.

---

## 1. Как это устроено в C

В C стандарт формально определяет только **lvalue** (C11, 6.3.2.1):

> lvalue — выражение (не типа `void`), которое потенциально обозначает объект.

Дополнительно есть понятие **modifiable lvalue** — lvalue, которое можно присваивать: не массив, не неполный тип, не `const`-квалифицированный тип и не структура/объединение с `const`-членом.

Термин **rvalue** в C строго не определён — это разговорное обозначение выражения, которое не является lvalue. В C нет ссылок и перемещения, поэтому различие нужно в основном для:

- присваивания (`=`, `+=`, …) — слева требуется modifiable lvalue;
- унарного `&` — требует lvalue;
- `++`/`--` — требуют modifiable lvalue;
- `sizeof` — не применяет lvalue-преобразование;
- распада массива и функции в указатель.

```c
int x = 1;       // x — lvalue
int y = x + 2;   // x + 2 — rvalue (не lvalue)
int *p = &x;     // & требует lvalue
```

Важное понятие C — **lvalue conversion**: почти везде, где используется lvalue (кроме `sizeof`, `&`, `++`, `--`, левого операнда `.` и левого операнда присваивания), оно преобразуется в значение хранящегося объекта и перестаёт быть lvalue.

```c
int x = 1;
int y = x;   // здесь x подвергается lvalue conversion: читается значение
```

В C++ аналогичное преобразование называется **lvalue-to-rvalue conversion**.

## 2. C++03: lvalue и rvalue

В C++03 было только две категории:

- **lvalue** — выражение, обозначающее объект или функцию;
- **rvalue** — всё остальное.

Ссылки в C++03:

```cpp
int x = 1;
int& r = x;             // OK: lvalue-ссылка связывается с lvalue
// int& bad = 1;        // ошибка: 1 — rvalue
const int& cr = 1;      // OK: const lvalue-ссылка связывается и с rvalue
```

Именно возможность `const T&` связываться с временными объектами позволила C++03 обходиться без отдельного вида ссылок. Но копирование «тяжёлых» объектов из временных оставалось дорогим, и в C++11 появились rvalue-ссылки и move-семантика. Вместе с ними пришлось формально разделить rvalue на подкатегории.

---

## 3. C++11: пять категорий значений

Стандарт C++11 вводит следующую иерархию (раздел [basic.lval]):

- **glvalue** (generalized lvalue) — выражение, вычисление которого определяет **идентичность** объекта, битового поля или функции;
- **prvalue** (pure rvalue) — выражение, вычисление которого **инициализирует** объект или битовое поле либо вычисляет значение операнда оператора; у prvalue нет идентичности;
- **xvalue** (eXpiring value, «истекающее значение») — glvalue, обозначающее объект или битовое поле, ресурсы которого можно **переиспользовать** (обычно потому, что объект близок к концу времени жизни);
- **lvalue** — glvalue, не являющееся xvalue;
- **rvalue** — prvalue или xvalue.

Иерархия:

```text
                 expression
        ┌────────────┴────────────┐
     glvalue                   rvalue
     ┌───┴───┐               ┌───┴───┐
  lvalue   xvalue         xvalue  prvalue
        └───────┬───────────────┘
             (xvalue входит в обе)
```

То есть:

- `expression = glvalue ∪ rvalue`;
- `glvalue = lvalue ∪ xvalue`;
- `rvalue = prvalue ∪ xvalue`;
- `xvalue` — пересечение `glvalue` и `rvalue`.

**Ключевая мысль:** категория значения — это свойство **выражения**, а не типа. Тип и категория ортогональны. Например, переменная типа `int&&` — это выражение категории **lvalue**, хотя её тип — rvalue-ссылка.

## 4. Сравнительная таблица

| Свойство | lvalue | xvalue | prvalue |
|---|---|---|---|
| Идентичность (адрес объекта) | есть | есть | нет (до материализации) |
| Взять адрес оператором `&` | да | нет | нет |
| Связывается с `T&` | да | нет | нет |
| Связывается с `const T&` | да | да | да |
| Связывается с `T&&` | нет | да | да |
| Ресурсы можно переместить | нет (нужен `std::move`) | да | да |
| Типичные примеры | `x`, `*p`, `++x`, `s.m` | `std::move(x)`, `static_cast<T&&>(x)` | `42`, `x + y`, `f()`, `x++` |

Пояснения:

- у xvalue адрес объекта обычно существует, но **оператор `&`** к xvalue неприменим, потому что требует lvalue;
- `const T&` — единственная lvalue-ссылка, которая связывается с rvalue (и с prvalue, и с xvalue);
- `T&&` связывается и с prvalue, и с xvalue.

## 5. Примеры выражений каждой категории

### lvalue

```cpp
int x = 10;
int arr[3] = {1, 2, 3};
int* p = &x;
struct S { int m; } s;

x;          // lvalue: имя переменной
*p;         // lvalue: разыменование
arr[0];     // lvalue: элемент массива (arr — lvalue)
s.m;        // lvalue: член lvalue-объекта
++x;        // lvalue: результат префиксного ++
x = 5;      // lvalue: результат присваивания
"hello";    // lvalue: строковый литерал — массив const char[6]
```

В C++ строковый литерал — **lvalue** (тип `const char[N]`), в отличие от числовых литералов. В C строковый литерал тоже lvalue, но типа `char[N]` (изменять его — UB).

### prvalue

```cpp
42;             // prvalue: целочисленный литерал
true;           // prvalue
nullptr;        // prvalue
x + 1;          // prvalue: результат вычисления
&x;             // prvalue: результат унарного &
x++;            // prvalue: результат постфиксного ++
f();            // prvalue, если f возвращает T по значению
std::string("hi"); // prvalue: временный объект
S{1, 2};        // prvalue: агрегатная инициализация
[] { return 1; }; // prvalue: лямбда-выражение
new int(5);     // prvalue: указатель
this;           // prvalue: указатель this
```

### xvalue

```cpp
std::move(x);                 // xvalue: приведение к T&&
static_cast<int&&>(x);        // xvalue: явное приведение
std::move(s).m;               // xvalue: член xvalue-объекта
f();                          // xvalue, если f возвращает T&&
```

Функция, возвращающая rvalue-ссылку, даёт xvalue:

```cpp
int&& get();
get();   // xvalue
```

## 6. Как определяется категория выражения

Можно запомнить несколько правил:

1. **Имя переменной** — lvalue. Исключение: перечислители (`enum`) — prvalue.
2. **`*p`** — lvalue.
3. **`a[i]`** — lvalue, если `a` — lvalue (для встроенного `operator[]`).
4. **`s.m`** — lvalue, если `s` — lvalue; xvalue, если `s` — xvalue; xvalue, если `s` — prvalue.
5. **`&x`** — prvalue.
6. **`++x`** — lvalue, **`x++`** — prvalue.
7. **Результат присваивания** (`x = y`, `x += y`) — lvalue.
8. **Вызов функции** зависит от возвращаемого типа:
   - `T&` → lvalue;
   - `T&&` → xvalue;
   - `T` → prvalue.
9. **Приведение типа**:
   - `static_cast<T>(e)` → prvalue;
   - `static_cast<T&>(e)` → lvalue;
   - `static_cast<T&&>(e)` → xvalue.
10. **`?:`**: если оба операнда — lvalue одного типа, результат lvalue; если оба — xvalue, результат xvalue; иначе prvalue.
11. **Оператор запятая** `(a, b)` имеет категорию правого операнда.
12. **`this`** — prvalue (указатель).

## 7. Ссылки и привязка к категориям

Правила привязки ссылок:

```cpp
int x = 1;

int& r1 = x;              // OK: lvalue
// int& r2 = 1;           // ошибка: rvalue
const int& r3 = 1;        // OK: const T& связывается с prvalue
int&& r4 = 1;             // OK: T&& связывается с prvalue
// int&& r5 = x;          // ошибка: x — lvalue

int&& r6 = std::move(x);  // OK: xvalue
```

Важно: **именованная rvalue-ссылка сама является lvalue**:

```cpp
void f(int&& x) {
    // x имеет тип int&&, но выражение x — lvalue!
    int& r = x;               // OK
    int&& r2 = std::move(x);  // OK: снова делаем xvalue
}
```

Это одна из самых частых ошибок: внутри функции, принимающей `T&&`, параметр `x` — lvalue. Чтобы передать его дальше как rvalue, нужно `std::move(x)` (или `std::forward<T>(x)` в шаблоне).

---

## 8. `std::move` — это не перемещение

`std::move` — всего лишь приведение к rvalue-ссылке. Реализация примерно такая:

```cpp
template<class T>
constexpr std::remove_reference_t<T>&& move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}
```

Само по себе `std::move(x)` **ничего не перемещает** и не меняет `x`. Оно лишь превращает lvalue `x` в xvalue, чтобы перегрузка выбрала move-конструктор или move-присваивание. Само перемещение выполняет соответствующий конструктор/оператор.

```cpp
std::string a = "hello";
std::string b = std::move(a); // вызывается move-конструктор string
// a теперь в допустимом, но неопределённом состоянии
```

`std::move` от `const`-объекта даёт `const T&&`, который не связывается с `T&&` move-конструктора, поэтому выбирается копирование:

```cpp
const std::string s = "hi";
std::string t = std::move(s); // копирование, а не перемещение
```

`std::move` от prvalue избыточен: `std::move(std::string("hi"))` — то же самое, что `std::string("hi")`.

---

## 9. Move-семантика и перегрузка

Именно категории значений позволяют выбирать между копированием и перемещением:

```cpp
struct S {
    S(const S&);             // копирование
    S(S&&) noexcept;         // перемещение
};

S a;
S b = a;              // copy: a — lvalue
S c = std::move(a);   // move: xvalue
S d = S{};            // move/elision: prvalue
```

Перегрузка функций:

```cpp
void h(int&);    // для lvalue
void h(int&&);   // для rvalue

int x = 0;
h(x);              // h(int&)
h(1);              // h(int&&)
h(std::move(x));   // h(int&&)
```

Если есть только `void h(const int&)`, она примет и lvalue, и rvalue. Если есть и `const int&`, и `int&&`, для rvalue предпочтительнее `int&&`.

## 10. Perfect forwarding и ссылки в шаблонах

В шаблоне `T&&` — это не обязательно rvalue-ссылка. Если `T` выводится, работает **forwarding reference** (универсальная ссылка):

```cpp
template<class T>
void relay(T&& arg) {
    target(std::forward<T>(arg));
}
```

- вызов `relay(x)` с lvalue `int`: `T = int&`, параметр имеет тип `int&`;
- вызов `relay(42)`: `T = int`, параметр имеет тип `int&&`.

Работает это благодаря **схлопыванию ссылок** (reference collapsing):

- `T& &` → `T&`
- `T& &&` → `T&`
- `T&& &` → `T&`
- `T&& &&` → `T&&`

`std::forward<T>` — условное приведение: если `T` — lvalue-ссылка, оно оставляет выражение lvalue; иначе превращает в xvalue. В отличие от `std::move`, `std::forward` требует явного указания `T` и не «перемещает» lvalue.

```cpp
template<class T>
void wrapper(T&& x) {
    g(std::forward<T>(x)); // сохраняет исходную категорию
}
```

Важно: `T&&` является forwarding reference только если `T` — параметр шаблона функции, который выводится. В `std::vector<T>&&` или в шаблоне класса `template<class T> struct X { void f(T&&); };` это обычная rvalue-ссылка.

## 11. `decltype` и категории

`decltype` различает объявленный тип и категорию выражения:

```cpp
int x = 0;

decltype(x)   a = 1;   // int: имя переменной — особый случай
decltype((x)) b = x;   // int&: (x) — lvalue-выражение
decltype(42)  c = 0;   // int: prvalue
decltype(std::move(x)) d = 0; // int&&: xvalue
```

Правило:

- если `e` — неparenthesized id-expression или доступ к члену, называющий переменную, `decltype(e)` даёт **объявленный тип**;
- иначе: lvalue → `T&`, xvalue → `T&&`, prvalue → `T`.

Поэтому `decltype((x))` — это `int&`, а `decltype(x)` — `int`. Это часто используется в generic-коде и в `decltype(auto)`.

## 12. Время жизни временных объектов

Привязка `const T&` или `T&&` к prvalue **продлевает жизнь** временного объекта до конца жизни ссылки:

```cpp
const std::string& s = std::string("hi"); // временный живёт, пока жива s
int&& r = 42;                             // аналогично
```

Но есть исключения: ссылка, возвращённая из функции, не продлевает жизнь; привязка к подобъекту и некоторые другие случаи требуют аккуратности. Классическая ошибка:

```cpp
const std::string& bad() {
    return std::string("hi"); // висячая ссылка: временный уничтожен при выходе
}
```

## 13. C++17: prvalue — это не объект

До C++17 prvalue класса можно было представлять как временный объект, который затем копируется/перемещается. В C++17 семантика изменилась: **prvalue — это инициализатор**, а не объект. Объект появляется только при **материализации** (temporary materialization conversion) — например, когда prvalue связывается со ссылкой или когда у него запрашивают член.

Практическое следствие — **гарантированное устранение копирования** (guaranteed copy elision):

```cpp
struct X {
    X() = default;
    X(const X&) = delete;
    X(X&&) = delete;
};

X make();
X x = make(); // C++17: OK, копирование/перемещение не требуется
              // C++14: ошибка — конструктор копирования/перемещения должен быть доступен
```

В C++17 `X x = make();` инициализирует `x` напрямую из prvalue; ни копирования, ни перемещения нет. Аналогично `return X();` в функции, возвращающей `X`, инициализирует результат напрямую.

При этом **NRVO** (named return value optimization) для именованной локальной переменной по-прежнему не гарантирован, хотя и разрешён. Поэтому `return std::move(local);` обычно является пессимизацией: оно запрещает NRVO, а если NRVO и так не применился, компилятор всё равно бы выбрал перемещение.

## 14. Частые заблуждения

1. **«lvalue — то, что слева от `=`».** Неверно: `const int x` — lvalue, но не может быть слева; `x = 5` — lvalue, хотя стоит справа. В C++ категория определяется семантикой, а не позицией.

2. **«rvalue — это временный объект».** Не всегда: `std::move(x)` — xvalue, обозначающее **именованный** объект `x`. А в C++17 prvalue вообще не объект до материализации.

3. **«rvalue нельзя изменять».** Можно, если это объект классового типа: `std::move(s) = "abc";` компилируется и вызывает `operator=` у `s`. Для встроенных типов `std::move(i) = 5;` — ошибка, так как встроенный `operator=` требует modifiable lvalue, а xvalue — не lvalue. Но `int&& r = ...; r = 5;` работает, потому что `r` — lvalue.

4. **«`std::move` перемещает».** Нет, это только приведение к `T&&`. Перемещение делает move-конструктор или move-присваивание.

5. **«Переменная типа `T&&` — это rvalue».** Нет: именованная переменная всегда lvalue. `T&&` — это тип, а не категория выражения.

6. **«`T&&` всегда rvalue-ссылка».** В шаблоне функции с выводом `T` это forwarding reference, которая может стать и `T&`.

7. **«`const T&&` — хороший способ включить перемещение».** Обычно нет: `std::move(const_obj)` даёт `const T&&`, а move-конструктор ожидает `T&&`, поэтому выбирается копирование.

## 15. Итог

| Вопрос | Ответ |
|---|---|
| Что такое lvalue? | Выражение с идентичностью, обозначающее объект/функцию; можно взять адрес; в C++11 — glvalue, не являющееся xvalue |
| Что такое rvalue? | Выражение без идентичности (prvalue) или объект, ресурсы которого можно переиспользовать (xvalue); в C++11 — prvalue или xvalue |
| Что такое xvalue? | «Истекающее» glvalue: `std::move(x)`, приведение к `T&&`, член xvalue-объекта; имеет идентичность, но допускает перемещение |
| Что такое prvalue? | Чистое значение: литерал, результат вычисления, вызов функции, возвращающей `T`; не имеет идентичности |
| Зачем это нужно? | Для перегрузки, move-семантики, perfect forwarding, `decltype`, времени жизни временных объектов и гарантированного устранения копирования в C++17 |
| Чем C отличается? | В C нет ссылок и move-семантики; формально определено только lvalue, rvalue — неформальный термин |

Если совсем сжато: **lvalue — это «где лежит объект», prvalue — это «само значение», xvalue — это «объект, который можно забрать»**. В C++11 и новее именно эти категории определяют, какая перегрузка выберется — копирующая или перемещающая.
