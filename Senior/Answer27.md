# 27. Расскажите о специализации шаблонов.

## 1. Что это такое и зачем нужно

Шаблон (первичный шаблон, *primary template*) описывает целое семейство типов или функций по одному общему «рецепту». Но иногда для части этого семейства нужна другая реализация: более эффективная, с другим набором членов, с сохранением инвариантов конкретного типа и т.п.

**Специализация шаблона (template specialization)** — это механизм, который позволяет для некоторого подмножества аргументов шаблона задать **отдельную реализацию**, отличную от реализации первичного шаблона.

Ключевая мысль: специализация — это *не* перегрузка (overload) и *не* инстанцирование (instantiation). Это правило вида «если аргументы шаблона такие-то, то использовать вот этот код».

В C++ есть два вида специализации:

| Вид | Что фиксируется | Остаётся ли шаблоном |
|---|---|---|
| **Явная (полная) специализация** — explicit / full specialization | все аргументы шаблона | нет, это обычный тип/функция |
| **Частичная специализация** — partial specialization | только часть аргументов (или на аргументы накладывается «образец») | да, это снова шаблон |

## 2. Полная (явная) специализация

Синтаксис: ключевое слово `template`, затем **пустой** список параметров `<>`, затем объявление с конкретными аргументами.

### 2.1. Шаблон класса

```cpp
#include <iostream>
#include <vector>

template <class T>
struct Array {                  // первичный шаблон
    T* data = nullptr;
    std::size_t size = 0;

    void print() const { std::cout << "generic\n"; }
};

template <>                     // полная специализация: аргументов не осталось
struct Array<bool> {
    std::vector<bool> bits;     // совсем другая внутренняя структура

    void print() const { std::cout << "bool\n"; }
};
```

После `template <>` список параметров пуст: все аргументы уже заданы в `<...>`.

Полная специализация — это **самостоятельный класс**: она не наследует члены первичного шаблона, может иметь другой размер, другой набор конструкторов и методов. Если нужен тот же интерфейс — его придётся описать заново.

Специализацию можно только **объявить**, без определения:

```cpp
template <> struct Array<void>;   // объявление; использование потребует определения
```

### 2.2. Шаблон функции

```cpp
template <class T>
void print(const T& value) { std::cout << value; }

template <>
void print<std::string>(const std::string& s) {
    std::cout << '"' << s << '"';
}
```

Аргументы шаблона в явной специализации можно не писать — они выводятся из типа функции:

```cpp
template <> void print<std::string>(const std::string&); // явно
template <> void print(const std::string&);             // T выведен как std::string
```

Обе записи эквивалентны.

### 2.3. Переменный шаблон (C++14)

```cpp
template <class T> constexpr bool is_void_v = false;
template <>        constexpr bool is_void_v<void> = true;
```

### 2.4. Члены шаблона класса

```cpp
template <class T>
struct Box {
    void f() { /* ... */ }
    static int count;
    template <class U> void g(U);
};

template <class T> int Box<T>::count = 0;   // определение статического поля первичного шаблона

template <> void Box<int>::f() { /* ... */ }          // член полной специализации
template <> int  Box<int>::count = 42;                // с инициализатором — это определение
template <> template <>                               // два уровня: класс + член-шаблон
void Box<int>::g<char>(char) { /* ... */ }
```

`template <>` пишется столько раз, сколько уровней шаблонов задействовано (внешний шаблон + член-шаблон).

## 3. Частичная специализация

Частичная специализация фиксирует лишь часть аргументов, оставляя остальные параметрами шаблона. Формально она сама является шаблоном.

### 3.1. Синтаксис

```cpp
template <class T, class U>
struct Pair { /* ... */ };          // первичный шаблон

template <class T>
struct Pair<T, T> { /* ... */ };    // частичная: оба аргумента совпадают

template <class T, class U>
struct Pair<T*, U*> { /* ... */ };  // частичная: оба аргумента — указатели
```

Правила:

- частичная специализация возможна **только для шаблонов классов** (а также переменных шаблонов); для шаблонов функций её нет;
- в списке параметров частичной специализации остаются только незафиксированные параметры;
- она **не может иметь аргументов по умолчанию**;
- её список аргументов не должен совпадать с неявным списком аргументов первичного шаблона (`template <class T> struct Pair<T>` — ошибка: это не специализация);
- она должна быть **более специализированной**, чем первичный шаблон.

### 3.2. Классические примеры

```cpp
template <class T> struct IsPointer          { static constexpr bool value = false; };
template <class T> struct IsPointer<T*>      { static constexpr bool value = true;  };

template <class T> struct RemoveConst        { using type = T; };
template <class T> struct RemoveConst<const T>{ using type = T; };

template <class T> struct IsArray            { static constexpr bool value = false; };
template <class T> struct IsArray<T[]>       { static constexpr bool value = true;  };
template <class T, std::size_t N>
struct IsArray<T[N]>                         { static constexpr bool value = true;  };
```

Частичная специализация по нетиповым параметрам тоже допустима:

```cpp
template <class T, std::size_t N>
struct Storage<T[N]> { /* массив фиксированного размера */ };
```

В стандартной библиотеке частичными специализациями являются, например:

- `std::vector<bool, Allocator>` — зафиксирован `bool`, аллокатор остаётся параметром;
- `std::hash` — первичный шаблон без пригодного определения плюс специализации для поддерживаемых типов;
- `std::tuple_size`, `std::tuple_element` — первичный только объявлен, специализации дают значения;
- `std::numeric_limits<T>` — общее определение с `is_specialized == false` и специализации для арифметических типов.

### 3.3. Рекурсия и «базовый случай»

Исторически главный приём метапрограммирования: рекурсивный шаблон + полная специализация как условие выхода.

```cpp
template <unsigned N>
struct Factorial {
    static constexpr unsigned value = N * Factorial<N - 1>::value;
};

template <>
struct Factorial<0> {                 // базовый случай
    static constexpr unsigned value = 1;
};

static_assert(Factorial<5>::value == 120);
```

## 4. Как компилятор выбирает специализацию

### 4.1. Шаблоны классов

1. Собираются все объявления: первичный шаблон, все частичные и полные специализации.
2. Отбрасываются те, которые не подходят под заданные аргументы.
3. **Полная специализация имеет безусловный приоритет** над частичными.
4. Среди подходящих частичных выбирается **самая специализированная**. Если две подходят и ни одна не специализированнее другой — ошибка неоднозначности (ambiguous partial specializations).

### 4.2. Шаблоны функций — важное отличие

Явная специализация шаблона функции **не является отдельным кандидатом в разрешении перегрузок**. Сначала обычным образом выбирается функция (обычная или первичный шаблон), и только потом, если выбор пал на шаблон и для выведенных аргументов существует явная специализация, используется её тело.

```cpp
template <class T> void f(T);      // #1 первичный шаблон
template <>        void f<int>(int); // #2 явная специализация

void f(int);                        // #3 обычная функция

f(0);       // #3: нешаблонная функция предпочтительнее шаблона
f<>(0);     // #2
f<int>(0);  // #2
```

Практическое следствие: специализация не делает функцию «лучше» — она лишь подменяет реализацию уже выбранного шаблона. Отсюда классическая ловушка:

```cpp
template <class T> void g(T);
template <>        void g(int*);   // специализация для int*

g(nullptr);   // T = std::nullptr_t, специализация g<int*> не применяется
```

## 5. Специализация и инстанцирование

Это разные вещи, их часто путают:

| Запись | Смысл |
|---|---|
| `X<int> x;` | неявное инстанцирование из первичного шаблона |
| `template class X<int>;` | явное инстанцирование (explicit instantiation definition) |
| `extern template class X<int>;` | явное объявление инстанцирования: подавить неявное в этой TU (C++11) |
| `template <> class X<int> { ... };` | явная специализация: своя реализация |

**Ключевое правило:** явная специализация должна быть объявлена **до первого использования**, которое вызвало бы неявное инстанцирование, — и так в каждой единице трансляции. Иначе программа ill-formed, причём диагностика не требуется (IFNDR):

```cpp
// a.cpp
#include "X.h"
void use() { X<int> x; }          // здесь X<int> уже неявно инстанцирован
template <> struct X<int> { };    // ОШИБКА: специализация после инстанцирования
```

Почему это критично: в одной единице трансляции может оказаться специализация, в другой — инстанс первичного шаблона. Это нарушение ODR и «необъяснимые» баги при линковке. По той же причине объявление специализации должно быть видно в точке вызова: иначе компилятор сгенерирует код из первичного шаблона, а специализацию просто проигнорирует.

Отдельные тонкости:

- явная специализация шаблона функции **не становится `inline` автоматически** (даже если первичный шаблон `inline`), поэтому в заголовке её нужно помечать `inline`, иначе ODR;
- явная специализация статического поля-данного является **определением**, только если содержит инициализатор: `template <> int Box<int>::count = 42;` — определение, `template <> int Box<int>::count;` — объявление;
- специализация объявляется **на уровне пространства имён**, внутри класса её писать нельзя;
- специализация должна находиться в том же пространстве имён, что и сам шаблон (для членов — в пространстве имён объемлющего класса);
- **alias-шаблоны специализировать нельзя** (ни полностью, ни частично).

## 6. Специализация шаблонов стандартной библиотеки

Стандарт разрешает добавлять специализации шаблонов `std` только при соблюдении условий: специализация должна зависеть хотя бы от одного пользовательского типа и удовлетворять требованиям исходного шаблона. Объявлять её нужно **внутри `namespace std`**.

Канонический пример — точка кастомизации `std::hash`:

```cpp
struct Point { int x, y; };

namespace std {
template <>
struct hash<Point> {
    std::size_t operator()(const Point& p) const noexcept {
        return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);
    }
};
}
```

Аналогично специализируют `std::numeric_limits`, `std::formatter` (C++20), `std::char_traits`, `std::tuple_size`/`std::tuple_element` для своих кортежеподобных типов.

Для `swap` предпочтительнее не специализировать `std::swap`, а определить свою перегрузку `swap` в пространстве имён пользовательского типа — её найдёт ADL.

## 7. Где специализация реально нужна

- метапрограммирование и type traits (`IsPointer<T*>`, `RemoveConst<const T>`);
- «базовый случай» рекурсивных вычислений на шаблонах (`Factorial<0>`);
- оптимизация под конкретный тип (в библиотеках — `memcpy`-версии алгоритмов, `std::vector<bool>`);
- единообразная обработка особых типов: `void`, `bool`, указателей, массивов, ссылок;
- точки кастомизации: `std::hash`, `std::formatter`, `std::numeric_limits`;
- хранение метаданных о типе, когда первичный шаблон намеренно оставлен без определения — тогда использование неспециализированного типа даёт ошибку компиляции (удобный «статический assert»):

```cpp
template <class T> struct TypeName;      // только объявлен, определения нет

template <> struct TypeName<int>    { static const char* get() { return "int"; } };
template <> struct TypeName<double> { static const char* get() { return "double"; } };

// TypeName<long>::get();  // ошибка: используется неполный тип — так и задумано
```

## 8. Частые ошибки и подводные камни

1. **Попытка частично специализировать шаблон функции.**
   ```cpp
   template <class T> void f(T);      // первичный
   template <class T> void f(T*);     // это НЕ специализация, а перегрузка
   ```
   Частичной специализации функций в языке нет — только перегрузки, SFINAE, `if constexpr` или концепты.

2. **Специализация после первого использования** — см. раздел 5; ошибка коварна тем, что может не диагностироваться.

3. **Забытый `template <>`.** Получается не специализация, а новая сущность (перегрузка или отдельный класс), которая может вообще не использоваться.

4. **Специализация функции в заголовке без `inline`** — множественное определение при линковке.

5. **Специализация внутри класса или в чужом пространстве имён** — нельзя.

6. **Ожидание, что полная специализация унаследует интерфейс.** Она самостоятельна: другой набор членов, другой размер, другие конструкторы.

7. **Неоднозначность частичных специализаций** — если подходят несколько и ни одна не специализированнее, компилятор обязан выдать ошибку.

8. **Специализация с аргументами по умолчанию** — у частичной специализации их быть не может.

9. **Расчёт на то, что специализация участвует в разрешении перегрузок** — для функций она этого не делает (см. 4.2), поэтому объявление специализации должно быть видно в точке вызова.

10. **Специализация шаблона с внутренним связыванием / в анонимном пространстве имён** — риск ODR-нарушений; шаблон и его специализации должны иметь согласованное связывание.

## 9. Альтернативы в современном C++

Для шаблонов функций специализация часто не лучший инструмент. Альтернативы:

- **`if constexpr` (C++17)** — «специализация» поведения внутри одной функции:
  ```cpp
  template <class T>
  void serialize(const T& v) {
      if constexpr (std::is_pointer_v<T>) { /* ... */ }
      else                                { /* ... */ }
  }
  ```
- **перегрузки + SFINAE** (`std::enable_if`, `std::void_t`);
- **концепты и `requires` (C++20)** — в том числе *ограниченные частичные специализации*:
  ```cpp
  template <class T> struct S { /* generic */ };
  template <std::integral T> struct S<T> { /* только для целочисленных */ };
  ```
- **tag dispatch** — выбор реализации по типу-метке;
- **`std::variant` + `std::visit`** — «специализация по альтернативе» во время выполнения.

Для шаблонов классов частичная специализация по-прежнему основной и незаменимый инструмент.

## 10. Сводная таблица

| Свойство | Полная специализация | Частичная специализация |
|---|---|---|
| Синтаксис | `template <>` + конкретные аргументы | `template <...>` с незафиксированными параметрами |
| Шаблоны классов | да | да |
| Шаблоны функций | да | **нет** |
| Переменные шаблоны | да | да |
| Остаётся шаблоном | нет | да |
| Аргументы по умолчанию | допустимы | **недопустимы** |
| Участвует в разрешении перегрузок (для функций) | нет | — |
| Приоритет выбора | выше частичных | выше первичного шаблона |
| Типичное применение | базовый случай рекурсии, traits, `std::hash` | `T*`, `const T`, `T[N]`, `vector<bool>` |

## 11. Краткое резюме

Специализация шаблонов позволяет для части множества допустимых аргументов подставить собственную реализацию. **Полная специализация** (`template <>`) фиксирует все аргументы и превращает шаблон в обычный класс или функцию; она имеет приоритет над всеми частичными. **Частичная специализация** (`template <...>` с незафиксированными параметрами) доступна только для шаблонов классов и переменных, сама остаётся шаблоном и выбирается по принципу «самая специализированная из подходящих». Для шаблонов функций частичной специализации не существует — вместо неё используют перегрузки, `if constexpr`, SFINAE или концепты. Главные практические требования: специализация должна быть объявлена до первого использования, вызывающего инстанцирование, в каждой единице трансляции, и должна находиться в том же пространстве имён, что и исходный шаблон; специализация функции не наследует `inline` и не участвует в разрешении перегрузок как отдельный кандидат.
