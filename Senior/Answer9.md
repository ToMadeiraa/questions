# 9. Что такое метапрограммирование? С помощью чего реализуется на С++?

## Определение

**Метапрограммирование** — это приём программирования, при котором программа рассматривает код (в том числе свой собственный) как данные: порождает, преобразует, анализирует или выбирает код по некоторым правилам. Программа как бы «пишет программу» — на этапе компиляции или на этапе выполнения.

Ключевая идея применительно к C++: **перенести как можно больше вычислений и решений с этапа выполнения на этап компиляции**. Компилятор становится «вычислителем»: он раскрывает шаблоны, считает `constexpr`-функции, выбирает перегрузки и специализации — и в готовый бинарник попадает уже результат, а не механизм его получения. Отсюда знаменитый принцип C++: *zero-cost abstractions* — абстракция не должна стоить дороже написанного вручную кода.

В широком смысле метапрограммирование есть в любой развитой языковой экосистеме: макросы Lisp, `metaclass` и декораторы в Python, процедурные макросы Rust, source generators в C#, аннотации и APT в Java. В C++ оно реализовано на нескольких независимых «уровнях», и именно их комбинация даёт характерный стиль языка.

## Уровни (механизмы) реализации в C++

### 1. Препроцессор — текстовое метапрограммирование

Самый примитивный уровень: `#define`, `#include`, условная компиляция `#if`, склейка токенов `##`, строкизация `#`. Это подстановка текста до всякого анализа типов, поэтому инструмент мощный, но небезопасный.

Классический приём — **X-макросы**, когда один список используется для генерации нескольких сущностей (enum, таблицы строк, switch):

```cpp
#define COLORS(X) X(Red) X(Green) X(Blue)

enum class Color {
#define AS_ENUM(name) name,
    COLORS(AS_ENUM)
#undef AS_ENUM
};

// где-то рядом — автоматически согласованный to_string
const char* to_string(Color c) {
#define AS_STR(name) case Color::name: return #name;
    switch (c) { COLORS(AS_STR) }
#undef AS_STR
    return "?";
}
```

Плюс: не нужно вручную синхронизировать список и его обработчики. Минус: макросы не знают областей видимости, типов и не отлаживаются; в современном C++ их стараются заменять шаблонами, `constexpr` и `if constexpr`.

### 2. Шаблоны — классическое шаблонное метапрограммирование (TMP)

Шаблоны — это, по сути, функциональный язык, «случайно» встроенный в C++: параметрами могут быть типы, целые константы, шаблоны и наборы параметров, а «функциями» служат частичные специализации. Вычисления выполняются на типах и целых числах в момент инстанцирования.

Исторический пример — факториал, вычисляемый компилятором:

```cpp
template <unsigned N>
struct factorial {
    static constexpr unsigned long long value = N * factorial<N - 1>::value;
};

template <>
struct factorial<0> {
    static constexpr unsigned long long value = 1ULL;
};

static_assert(factorial<10>::value == 3628800ULL);
```

Здесь нет ни одной операции времени выполнения: `factorial<10>::value` — просто константа. Основные строительные блоки этого уровня:

- **Специализация и частичная специализация** — аналог сопоставления с образцом (pattern matching) и ветвления.
- **`std::integral_constant`** и производные (`std::true_type`, `std::false_type`) — «значения на уровне типов».
- **Type traits** (`<type_traits>`) — библиотека запросов и преобразований над типами: `std::is_pointer`, `std::remove_reference`, `std::decay`, `std::void_t`, `std::conditional`.
- **Variadic templates** и **fold expressions** (C++17) — работа с произвольными наборами параметров.
- **`std::index_sequence`** — генерация индексов для обхода кортежей и массивов.
- **CRTP** (Curiously Recurring Template Pattern) — «статический полиморфизм» без виртуальных функций.
- **Expression templates** — ленивое построение выражений и их слияние (так устроены Eigen, Blaze, некоторые реализации `std::valarray`).

Пример своего type trait:

```cpp
template <class T> struct is_pointer        : std::false_type {};
template <class T> struct is_pointer<T*>    : std::true_type  {};

static_assert(is_pointer<int*>::value);
static_assert(!is_pointer<int>::value);
```

Пример CRTP:

```cpp
template <class Derived>
struct Base {
    void run() { static_cast<Derived*>(this)->impl(); }  // вызов без vtable
};

struct D : Base<D> {
    void impl() { /* ... */ }
};
```

### 3. SFINAE и перегрузка — метапрограммирование отбора

**SFINAE** (Substitution Failure Is Not An Error) — правило: если подстановка шаблонных аргументов в сигнатуру не удалась, это не ошибка компиляции, а лишь повод отбросить данную перегрузку. На этом построен огромный пласт техник: включение/выключение функций по свойствам типа, «if на типах».

```cpp
template <class T,
          class = std::enable_if_t<std::is_integral_v<T>>>
void f(T) { /* только для целых */ }
```

Сюда же относятся `std::enable_if`, `std::void_t`, detection idiom, `tag dispatch`, проверки «есть ли у типа метод `foo`». С появлением `if constexpr` и concepts необходимость в трюках с SFINAE резко снизилась, но в старом и библиотечном коде они повсюду.

### 4. `constexpr`-вычисления — метапрограммирование значениями

Начиная с C++11 (`constexpr`), C++14 (ослабленный `constexpr`), C++17 (`if constexpr`) и C++20 (`consteval`, `constinit`, `constexpr`-аллокации, `std::vector`/`std::string` в constexpr) вычисления на этапе компиляции стали обычными функциями, а не «извращениями» на шаблонах:

```cpp
constexpr unsigned long long factorial(unsigned n) {
    return n <= 1 ? 1ULL : n * factorial(n - 1);
}
static_assert(factorial(10) == 3628800ULL);

consteval int square(int x) { return x * x; }  // только compile-time (C++20)
```

**`if constexpr`** — это «ветвление по типам», которое отбрасывает невыбранную ветку и тем самым снимает необходимость в специализациях:

```cpp
template <class T>
void print(const T& v) {
    if constexpr (std::is_pointer_v<T>)
        std::cout << *v;
    else
        std::cout << v;
}
```

### 5. Concepts и `requires` (C++20) — метапрограммирование ограничениями

Концепты описывают требования к типу декларативно и проверяются компилятором с человекочитаемыми ошибками. Это официальная замена большей части SFINAE-магии:

```cpp
template <class T>
concept Integral = std::is_integral_v<T>;

template <Integral T>
T twice(T x) { return x + x; }
```

Плюс: перегрузки выбираются по «насколько тип соответствует концепту» (subsumption), а сообщения об ошибках указывают, какое именно требование нарушено.

### 6. Рефлексия (C++26) — метапрограммирование, смотрящее на код

Долгое время в C++ не было способа «заглянуть» в структуру типа: узнать имена полей, перебрать члены, сгенерировать сериализацию. Это обходили внешними генераторами (protobuf, Qt `moc`, парсер-генераторы) или библиотеками-хаками (`Boost.PFR`, `magic_enum`, `fmt` с ручными адаптерами).

В **рабочий черновик C++26** принято статическое отражение (P2996): оператор `^^` даёт «метазначение» сущности, а пространство `std::meta` позволяет её анализировать — вплоть до генерации новых функций и типов на этапе компиляции.

```cpp
// C++26: перебор нестатических полей типа
constexpr auto members =
    std::meta::nonstatic_data_members_of(^^Point, std::meta::access_context::current());
```

Это делает возможным «настоящее» метапрограммирование: автоматическую сериализацию, `operator==`, парсеры аргументов командной строки — без макросов и внешних кодогенераторов.

### 7. Внешняя кодогенерация и библиотеки

- **Генераторы кода вне языка**: protobuf/gRPC, Qt `moc`, ANTLR, `lex`/`yacc`, скрипты, порождающие `.h`/`.cpp`. Формально это тоже метапрограммирование — просто «компилятор метауровня» вынесен в отдельный шаг сборки.
- **Библиотеки TMP**: Boost.MPL (тяжёлый, «до C++11»), Boost.Hana (современный, типобезопасные вычисления над типами и значениями), Brigand, metal, `boost::pfr`.

## Зачем это нужно: практическая польза

- **Производительность без потерь**: вычисления уходят в компилятор, рантайм-накладных расходов нет; статический полиморфизм (CRTP, concepts) вместо виртуальных вызовов; expression templates устраняют временные объекты и сливают циклы.
- **Типобезопасность**: ошибки ловятся на компиляции (`static_assert`, concepts), а не в тестах.
- **Устранение дублирования**: один шаблон обслуживает десятки типов; X-макросы и рефлексия синхронизируют списки сущностей.
- **DSL внутри C++**: выражения вида `a + b * c` для матриц, запросы к БД, форматные строки (`std::format`) — всё это парсится и проверяется компилятором.

## Цена и подводные камни

- **Время компиляции**: инстанцирование шаблонов и `constexpr`-вычисления могут расти лавинообразно; это главная причина, по которой тяжёлый TMP выносят в отдельные TU и предкомпилированные заголовки.
- **Качество ошибок**: у шаблонов и SFINAE сообщения исторически огромные и невнятные (concepts это сильно улучшили).
- **Сложность чтения и отладки**: код исполняется «в голове компилятора», отладчик на этапе компиляции не работает; нужны `static_assert` как «юнит-тесты» метауровня.
- **Раздувание бинарника**: каждая инстанциация — отдельный код; отсюда `extern template` и вынос в `.cpp`.
- **Макросы** ломают области видимости, типы и инструменты (IDE, рефакторинг) — применять только там, где нет альтернативы.

## Итоговая карта механизмов

| Механизм | Когда появился | Что даёт | Типичное применение |
|---|---|---|---|
| Препроцессор, X-макросы | C (1970-е) | текстовая генерация кода | enum ↔ строки, платформенные ветки |
| Шаблоны, специализация | C++98 | вычисления на типах | type traits, обобщённые контейнеры, TMP |
| SFINAE, `enable_if` | C++98/11 | отбор перегрузок по свойствам типа | ограничения, detection idiom |
| `constexpr` / `consteval` | C++11 / C++20 | вычисления значениями на компиляции | таблицы, хеши, проверки |
| `if constexpr` | C++17 | ветвление по типам в одной функции | замена специализаций |
| Concepts / `requires` | C++20 | декларативные ограничения | читаемые API, короткие ошибки |
| Рефлексия P2996 | C++26 (черновик) | анализ и генерация сущностей | сериализация, `==`, биндинги |
| Внешняя кодогенерация | — | порождение исходников | protobuf, moc, парсеры |

**Короткий ответ:** метапрограммирование — это программирование, где код порождает и преобразует код, а вычисления и решения переносятся на этап компиляции. В C++ оно реализуется, прежде всего, **шаблонами** (специализация, variadic, type traits, SFINAE, CRTP, expression templates), **`constexpr`/`consteval` и `if constexpr`**, **concepts** (C++20), **препроцессором**, а в перспективе — **статической рефлексией C++26**; вспомогательно используются внешние генераторы кода и библиотеки вроде Boost.Hana.
