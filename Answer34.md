# Вопрос 34. Как сonst влияет на переменную?

> **Кратко:** `const` делает объект доступным только для чтения через это имя: после инициализации запись запрещена, и компилятор обязан её отвергнуть. Ограничение накладывается на сам объект, а не на память: тот же объект может быть доступен через не-const имя и меняться. `const` входит в тип, влияет на связывание, на перегрузку и на контракты интерфейсов.

---

## Что именно обещает const

```cpp
#include <cstdlib>

const int limit = 100;         // инициализация обязательна
// limit = 200;                // ошибка: выражение не является изменяемым lvalue

int x = 1;
const int& r = x;              // через r записывать нельзя
x = 2;                         // объект изменился: r теперь читается как 2

const int n = std::rand();     // допустимо: const не значит «известно на компиляции»
```

- `const`-объект **обязан быть инициализирован** — другого способа задать значение нет.
- Запрет действует на запись **через данное имя**, а не на объект: `r` нельзя использовать для изменения `x`, но сам `x` меняется свободно.
- `const` **не означает константу времени компиляции**: `const int n = std::rand();` — законный код, но `n` нельзя использовать как размер массива в стандартном C++.
- `const` **не глубокий**: `const std::vector<int>` нельзя изменить целиком, но если внутри лежат указатели, данные по ним остаются изменяемыми (в `const`-методах такие члены видны как `int* const`, а не `const int*`).

## const и связывание: ловушка глобальных

В C++ (в отличие от C) `const`-переменная на уровне пространства имён по умолчанию имеет **внутреннее связывание** — как будто объявлена `static`.

```cpp
// config.cpp
const int kMaxUsers = 100;      // внутреннее связывание: из другого .cpp имя не видно
```

Другой `.cpp` эту переменную не увидит, а если объявит свою — получит отдельный объект. Чтобы сделать её общей:

```cpp
// config.h
inline constexpr int kMaxUsers = 100;   // C++17: одно определение на программу
// или
extern const int kMaxUsers;             // объявление; определение — в config.cpp
```

| Форма | Связывание | Одно определение | Где уместна |
|---|---|---|---|
| `const int k = 5;` в области файла | внутреннее | у каждой TU своё | деталь реализации `.cpp` |
| `static const int k = 5;` | внутреннее | у каждой TU своё | то же, но явно |
| `extern const int k = 5;` | внешнее | да | общая константа, C++98-стиль |
| `inline constexpr int k = 5;` | внешнее | да | предпочтительно в C++17 |

## const в указателях и ссылках

```cpp
int value = 1;

int*       p1 = &value;   // можно менять и значение, и указатель
const int* p2 = &value;   // нельзя менять значение через p2
int* const p3 = &value;   // нельзя менять указатель, значение — можно
const int* const p4 = &value;  // нельзя ничего
```

`const int*` и `int const*` — одно и то же: `const` относится к `int`. Читать объявление удобно справа налево: `p4` — константный указатель на константный `int`.

| Объявление | `*p = 5` | `p = &other` |
|---|---|---|
| `int* p` | можно | можно |
| `const int* p` | нельзя | можно |
| `int* const p` | можно | нельзя |
| `const int* const p` | нельзя | нельзя |

Тонкость для функций: **верхний** `const` параметра по значению отбрасывается из типа функции.

```cpp
void f(const int v);   // то же, что void f(int v); перегрузить по этому признаку нельзя
void g(const int& v);  // а это уже другой тип: ссылка на const
```

Для параметров дорогих типов `const T&` — стандартный способ принять объект без копирования и без права записи.

## const-члены класса

У `const`-метода `this` имеет тип `const T*`, поэтому все нестатические члены внутри видны как константные.

```cpp
#include <cstddef>
#include <vector>

class Buffer {
public:
    std::size_t size() const { return data_.size(); }   // можно звать у const-объекта

    int&       at(std::size_t i)       { return data_.at(i); }
    const int& at(std::size_t i) const { return data_.at(i); }

    void push(int v) { data_.push_back(v); }            // не const: меняет состояние

private:
    std::vector<int> data_;
};
```

Добавление `const` к методу — совместимое изменение (старый код продолжает работать); снятие `const` — ломающее, потому что const-объекты перестанут компилироваться.

## const, constexpr, consteval, constinit

| Ключевое слово | Значение известно на компиляции | Разрешает запись | Область применения |
|---|---|---|---|
| `const` | не обязательно | нет | объекты, параметры, методы, указатели |
| `constexpr` | да (объект обязан быть вычислен на компиляции) | нет | объекты и функции |
| `consteval` | да, только на компиляции | нет | функции (immediate) |
| `constinit` | гарантирует статическую инициализацию | да | статические переменные |

Правило: **`const` — про право записи, `constexpr` — про время вычисления**. `const int a = readConfig();` законно, но не является константным выражением; `constexpr int b = square(6);` вычислит компилятор, и `static_assert(b == 36)` пройдёт. `constexpr` для объекта подразумевает `const`, обратное неверно.

## mutable: логическая константность

`mutable` разрешает менять поле из `const`-метода, когда изменение не видно снаружи (кэш, счётчик обращений, мьютекс).

```cpp
class CachedValue {
public:
    int get() const {
        if (!ready_) { value_ = 42; ready_ = true; }   // mutable-поля меняются в const-методе
        return value_;
    }
private:
    mutable bool ready_ = false;
    mutable int  value_ = 0;
};
```

`mutable` не делает код потокобезопасным: разделяемый кэш, меняемый из `const`-метода, — такая же гонка данных. Для многопоточного случая рядом кладут `mutable std::mutex` и захватывают его.

## const_cast и когда он опасен

```cpp
void legacy_api(char* s);            // старый C-API без const

void wrapper(const std::string& s) {
    legacy_api(const_cast<char*>(s.c_str()));   // законно, если API не пишет в строку
}

const int ci = 42;
int* bad = const_cast<int*>(&ci);
// *bad = 0;   // UB: объект объявлен const, запись в него — неопределённое поведение
```

Снимать `const` можно, но **записывать** — только если исходный объект не был объявлен `const`. Иначе поведение не определено, и оптимизатор вправе «не заметить» запись.

## Типичные ошибки

1. **Считать `const` константой времени компиляции.** `const int n = f();` законно, но `int a[n];` — нет; для этого нужен `constexpr`.
2. **Путать `const int*` и `int* const`.** Первое — про данные, второе — про указатель; читайте справа налево.
3. **Пытаться перегрузить функцию по `const` параметра по значению.** `f(int)` и `f(const int)` — одна и та же функция.
4. **Удивляться, что глобальная `const` не видна из другого `.cpp`.** У неё внутреннее связывание; нужны `extern` или `inline`.
5. **Писать через `const_cast` в объект, объявленный `const`,** — UB, а не «грязный хак».
6. **Считать `const`-метод потокобезопасным.** Изменение `mutable`-полей и чтение разделяемых данных требуют синхронизации.
7. **Забыть `const`-версию аксессора.** Тогда метод нельзя вызвать у const-объекта, и приходится либо копировать объект, либо снимать `const`.
8. **Возвращать `const T` по значению** и удивляться, что не работает перемещение.
9. **Думать, что `const&` защищает от изменений извне.** Ссылка запрещает запись через себя, но объект может меняться через другие имена и другие потоки.

## Что добавить на собеседовании

- `const` — это в первую очередь **документация и контракт**: «этот метод не меняет наблюдаемое состояние», «эта функция не будет менять аргумент».
- Практика: параметры дорогих типов — `const T&`, наблюдатели — `const`-методы, локальные переменные — `const` по умолчанию; это ловит ошибки на компиляции.
- Различать `const`, `constexpr`, `consteval`, `constinit` — вопрос задают, чтобы проверить, чувствуете ли вы разницу между «нельзя писать» и «известно на компиляции».
- Помнить про связывание глобальных `const` и про `inline constexpr` в заголовках (C++17).
- Подчеркнуть: `const` не даёт ни неизменяемости разделяемых данных, ни потокобезопасности — только запрет записи через конкретное имя.

## Итог

| Аспект | Суть |
|---|---|
| Что делает | запрещает изменять объект через это имя после инициализации |
| Инициализация | обязательна; значение может быть вычислено в рантайме |
| Тип | `const` входит в тип: влияет на перегрузку, ссылки и указатели |
| Глобальные `const` | внутреннее связывание; для общей константы — `extern` или `inline constexpr` |
| Методы | `const`-метод видит члены как константные; исключение — `mutable` |
| Родственные | `constexpr` (компиляция), `consteval` (только компиляция), `constinit` (статическая инициализация) |
| Границы | не глубокая константность, не потокобезопасность, не защита от изменения через другие имена |
