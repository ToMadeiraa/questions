# Вопрос 31. Что делает директива include?

> **Кратко:** `#include` — директива препроцессора, которая заменяет строку с директивой содержимым указанного файла, поэтому объявления из заголовка становятся видимы в текущей единице трансляции. Работает она до синтаксического разбора и только с текстом: не создаёт связей между объектными файлами, не импортирует имена и не проверяет типы. Практический смысл директивы — дать компилятору объявления, нужные для разбора кода, а определения оставить линкеру.

---

## Суть операции: подстановка, а не подключение

`#include` не «подключает библиотеку». Препроцессор находит файл, обрабатывает его собственные директивы и подставляет получившийся текст на место строки `#include`, после чего продолжает разбор уже за вставленным фрагментом. Файл проходит препроцессирование заново и рекурсивно — заголовок может включать другие заголовки.

Результат — **единица трансляции**: сплошной поток токенов без директив, который и разбирает компилятор. Отдельного «объекта-заголовка» не существует: заголовок не компилируется сам по себе и не попадает в бинарник.

Отсюда два следствия, важных для ответа:

- заголовок разбирается заново в каждой единице трансляции, куда его включили;
- всё, что заголовок определил (включая макросы), действует до конца файла, а не «внутри include».

---

## Зачем это нужно: раздельная компиляция

Каждый `.cpp` компилируется независимо. Чтобы проверить вызов, компилятору нужно **объявление** сущности, но не её определение. `#include` — способ доставить объявления в единицу трансляции.

```cpp
// math.h — интерфейс: только объявления
#pragma once

int  square(int x);          // тип известен, тела нет
bool isEven(int x);
```

```cpp
// math.cpp — реализация: определения
#include "math.h"

int  square(int x) { return x * x; }
bool isEven(int x) { return x % 2 == 0; }
```

```cpp
// main.cpp
#include "math.h"           // компилятор узнаёт сигнатуры
#include <iostream>

int main() {
    std::cout << square(7) << '\n';   // вызов проверен по объявлению
}
```

`main.cpp` не содержит тела `square`, и это нормально: адрес функции подставит линкер, соединив `main.o` и `math.o`.

| Сущность | Объявление | Определение | Где место |
|---|---|---|---|
| Функция | `int f(int);` | `int f(int x) { ... }` | объявление — `.h`, определение — `.cpp` |
| Переменная | `extern int n;` | `int n = 0;` | объявление — `.h`, определение — `.cpp` |
| Класс | `class A;` (неполный тип) | `class A { ... };` | определение — `.h` |
| `inline`-функция | — | тело в заголовке | `.h` |
| Шаблон | — | тело в заголовке | `.h`, иначе не инстанцируется |
| Константа | — | `inline constexpr int k = 1;` | `.h` (C++17) |
| Статический член класса | `static int count_;` | `int Widget::count_ = 0;` | определение — `.cpp` (до C++17) |

## Что директива делает и чего не делает

| Утверждение | На самом деле |
|---|---|
| «include подключает библиотеку» | вставляет текст; библиотека подключается на этапе линковки |
| «include создаёт функцию или переменную» | повторяет объявление; объект создаётся определением |
| «раз заголовок включён, символ есть в программе» | символ появится, только если где-то есть определение |
| «include проверяет, что файл корректен» | проверяется лишь доступность файла; содержимое разбирается в контексте включающего файла |
| «include импортирует имена» | вставляет их в текущую область видимости, никакого пространства имён не появляется |
| «include защищает от повторного включения» | не защищает — защиту пишут в самом заголовке |
| «include ускоряет сборку» | наоборот: каждый заголовок разбирается в каждой единице трансляции |

Именно поэтому одинаковый заголовок, включённый в 300 `.cpp`, разбирается 300 раз — это основная статья расходов на сборку в C++.

## Две независимые стадии: компиляция и линковка

```
math.h ──include──> main.cpp ──> main.o ─┐
math.cpp ──────────────────────> math.o ─┴──> линкер ──> программа
```

| Симптом | Кто сообщает | Причина | Лечение |
|---|---|---|---|
| `undefined reference to 'square(int)'` | линкер | объявление включили, определение не собрали или не прилинковали | добавить `.cpp` в сборку или библиотеку в командную строку |
| `multiple definition of 'counter'` | линкер | определение переменной в заголовке попало в две единицы трансляции | `inline` (C++17) или `extern` в `.h` + определение в одном `.cpp` |
| `redefinition of 'struct A'` | компилятор | заголовок без защиты включён дважды | include guard или `#pragma once` |
| код собирается только при «правильном» порядке include | компилятор | заголовок не самодостаточен | включить нужное внутри самого заголовка |
| программа падает, хотя всё собралось | — | в заголовке определение с нарушением ODR, линкер выбрал одно из них | вынести определение в `.cpp` |

Главная мысль: `#include` отвечает только за первую стадию. Ошибки линковки директивой не лечатся — они лечат составом сборки.

## Формы записи

```cpp
#include <vector>        // поиск в системных каталогах (и в -I)
#include "config.h"      // сначала каталог текущего файла, затем системные
```

Порядок поиска определяется реализацией: у GCC и Clang кавычки дают «каталог текущего файла → `-iquote` → `-I` → системные», у MSVC — «каталог текущего файла → `/I` → `INCLUDE`». «Текущий файл» — тот, в котором стоит директива, а не тот, с которого началась компиляция.

С C++17 наличие заголовка можно проверить без ошибки:

```cpp
#if defined(__has_include)
#  if __has_include(<optional>)
#    include <optional>
#  endif
#endif
```

## Контракт заголовка

- **Заголовок самодостаточен**: компилируется, даже если включён первой строкой файла. Проверяется привычкой ставить свой заголовок первым в парном `.cpp`.
- **Заголовок не определяет не-inline сущности**: функции — `inline`, переменные — `inline` (C++17) или `extern`, шаблоны и `constexpr`-функции допускают повторение по правилам ODR.
- **Include what you use**: включайте то, что используете, а не то, что «случайно уже включили выше».
- **Минимизируйте включения**: указатель или ссылка на тип требуют лишь предварительного объявления.

```cpp
// widget.h — тяжёлый заголовок рендерера не тянем
#pragma once

class Renderer;                     // достаточно неполного типа

class Widget {
public:
    explicit Widget(Renderer& r) : renderer_(&r) {}
    void draw() const;              // тело — в widget.cpp
private:
    Renderer* renderer_;            // нужен только указатель
};
```

```cpp
// widget.cpp
#include "widget.h"
#include "renderer.h"               // полный тип нужен здесь

void Widget::draw() const { renderer_->render(); }
```

## Цена и альтернатива

Каждое включение — повторный разбор, поэтому в больших проектах борются за каждое: сокращают транзитивные зависимости, выносят реализацию в `.cpp`, применяют предкомпилированные заголовки (`.pch`) и include-what-you-use.

Принципиальное решение — **модули C++20**: интерфейс модуля компилируется один раз, а `import` приносит только экспортированные имена. Но `#include` останется надолго: он нужен для C-совместимых заголовков и для макросов, которые модули не экспортируют.

## Типичные ошибки

1. **Путать include с линковкой.** «Заголовок подключил — значит функция доступна»: нет, нужен объектный файл с определением.
2. **Определение переменной в заголовке без `inline`.** Две единицы трансляции — два символа, ошибка линкера (или тихая ODR-ошибка).
3. **Заголовок без защиты от повторного включения** — «ромб» включений даёт `redefinition`.
4. **Полагаться на транзитивные включения.** Работает до первого изменения в чужом заголовке.
5. **Включать заголовок внутри `namespace`** или между `extern "C" {` и `}` — меняет область видимости и связывание чужих объявлений.
6. **`#include <bits/stdc++.h>`** — нестандартный заголовок GCC: медленно, непереносимо, маскирует реальные зависимости.
7. **Включать `.cpp`** — почти всегда дублирование символов.
8. **Держать тяжёлые зависимости в заголовке**, из-за чего правка в них пересобирает половину проекта.

---

## Что добавить на собеседовании

- Чётко развести три стадии — препроцессор, компилятор, линкер — и показать, что `#include` относится только к первой.
- Сформулировать главный принцип: «include делает объявление видимым, но не создаёт символ».
- Связать директиву с ODR: почему в заголовке нужны `inline`, `extern`, шаблоны и `constexpr`.
- Назвать практическую цену и инструменты: forward declaration, PCH, include-what-you-use, модули.
- Упомянуть, что `#include` — единственный способ поделиться макросами, и поэтому он не исчезнет вместе с переходом на модули.
