# 75. Как работает `std::unique_ptr`

`std::unique_ptr` — это умный указатель из C++11, который реализует семантику **исключительного владения** (unique ownership) динамически выделенным объектом или массивом объектов. Он хранит сырой указатель и гарантирует автоматическое освобождение ресурса при выходе из области видимости, при этом **запрещая копирование** и разрешая только **перемещение**.

## Основной принцип работы

`std::unique_ptr` управляет объектом через хранящийся указатель. Уничтожение управляемого объекта происходит с использованием связанного **делетера** (deleter) в следующих случаях:

1.  Сам объект `unique_ptr` уничтожается (например, выходит из области видимости).
2.  Объекту `unique_ptr` присваивается другой указатель через `operator=` или вызывается метод `reset()`.

По умолчанию используется делетер `std::default_delete`, который вызывает оператор `delete` (или `delete[]` для массивов), уничтожая объект и освобождая память.

`unique_ptr` может не владеть никаким объектом — в этом случае он называется **пустым** (empty) и хранит `nullptr`.

## Ключевая особенность: только перемещение, без копирования

Класс удовлетворяет требованиям `MoveConstructible` и `MoveAssignable`, но **не** удовлетворяет `CopyConstructible` и `CopyAssignable`. Это означает:

-   **Копирование запрещено**: конструктор копирования и оператор копирующего присваивания явно удалены (`= delete`). Попытка скопировать `unique_ptr` вызовет ошибку компиляции.
-   **Перемещение разрешено**: владение можно передать другому `unique_ptr` с помощью `std::move`. После перемещения исходный указатель становится пустым (`nullptr`).

Именно эта модель владения гарантирует, что ресурс не будет освобожден дважды, и делает `unique_ptr` таким же эффективным, как сырой указатель (нулевые накладные расходы).

## Создание и использование

### Предпочтительный способ: `std::make_unique` (C++14+)

Начиная с C++14, рекомендуется создавать `unique_ptr` через вспомогательную функцию `std::make_unique`, которая обеспечивает безопасность исключений и устраняет необходимость явного указания `new`:

```cpp
// Одиночный объект
auto ptr = std::make_unique<MyClass>(args...);

// Массив (C++14)
auto arr = std::make_unique<int[]>(10); // массив из 10 элементов, инициализированных нулями
```

### Прямое создание

```cpp
std::unique_ptr<MyClass> ptr(new MyClass(args...));
```

## Передача владения

Поскольку копирование невозможно, `unique_ptr` передается по значению только с использованием семантики перемещения:

```cpp
std::unique_ptr<MyClass> p1 = std::make_unique<MyClass>();
std::unique_ptr<MyClass> p2 = std::move(p1); // владение переходит к p2, p1 становится nullptr
```

Это также означает, что `unique_ptr` можно возвращать из функций по значению (компилятор применит перемещение) и хранить в контейнерах STL, таких как `std::vector`, которые поддерживают перемещение.

## Специализация для массивов

`std::unique_ptr<T[]>` — это частичная специализация для управления массивами, выделенными через `new[]`. Она использует `delete[]` и предоставляет доступ к элементам через `operator[]`.

## Важные нюансы

### Наследование и виртуальный деструктор

Если `T` является производным классом от базового `B`, то `std::unique_ptr<T>` неявно преобразуется в `std::unique_ptr<B>`. Однако делетер по умолчанию для `unique_ptr<B>` вызовет `delete` для типа `B`. Если деструктор `B` **не является виртуальным**, это приведет к **неопределенному поведению** (undefined behavior). В отличие от `std::shared_ptr`, который запоминает исходный тип при создании, `unique_ptr` полагается на виртуальность деструктора.

### Пользовательский делетер

`unique_ptr` позволяет указать собственный делетер, что делает его пригодным для управления ресурсами, отличными от памяти, выделенной через `new` (например, файловые дескрипторы, сокеты, объекты в shared memory).

### Неполный тип и идиома pImpl

`unique_ptr` можно создавать для неполного типа `T` (например, для реализации идиомы pImpl). Однако при использовании делетера по умолчанию тип `T` должен быть **полным** в тех местах, где вызывается делетер: в деструкторе, операторе перемещающего присваивания и методе `reset()`.

## Резюме

`std::unique_ptr` — это инструмент с нулевыми накладными расходами для выражения исключительного владения. Его главные правила:
- **Один владелец** — никакого копирования, только перемещение.
- **Автоматическое освобождение** — деструктор вызывает делетер.
- **Предпочтительное создание** — через `std::make_unique`.
- **Осторожность с полиморфизмом** — для базовых классов нужен виртуальный деструктор.

Это наиболее популярный умный указатель в современном C++, используемый по умолчанию, когда не требуется разделяемое владение (для которого есть `std::shared_ptr`).
