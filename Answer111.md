# 111. Может ли деструктор быть виртуальным?

## Краткий ответ

**Да, деструктор может и часто должен быть виртуальным.** Более того, это один из ключевых механизмов корректного удаления объектов через указатель на базовый класс.

## Зачем нужен виртуальный деструктор

Если объект производного класса удаляется через указатель (или ссылку) на базовый класс, то при **невиртуальном** деструкторе будет вызван только деструктор базового класса. Это приводит к **неопределённому поведению** (undefined behavior) и утечкам ресурсов: деструктор производного класса не выполнится.

```cpp
class Base {
public:
    ~Base() { std::cout << "~Base\n"; }  // НЕ виртуальный!
};

class Derived : public Base {
public:
    ~Derived() { std::cout << "~Derived\n"; }
};

int main() {
    Base* p = new Derived();
    delete p;  // Вызовется только ~Base() — UB и утечка!
}
```

Если сделать деструктор базового класса виртуальным, то при `delete p` сработает механизм динамического связывания, и будут вызваны **оба** деструктора — сначала `~Derived()`, затем `~Base()`.

```cpp
class Base {
public:
    virtual ~Base() { std::cout << "~Base\n"; }
};
// ...
delete p;  // ~Derived, затем ~Base — корректно
```

## Правило

Если класс предназначен для полиморфного использования (то есть от него наследуются и объекты удаляются через указатель на базу), его деструктор **должен быть виртуальным**.

## Важные нюансы

1. **Виртуальный деструктор не обязан быть чисто виртуальным.** Но если сделать его чисто виртуальным (`virtual ~Base() = 0;`), всё равно нужно **определить тело** этого деструктора вне класса, иначе линковка производных классов упадёт — ведь деструктор базового класса всё равно вызывается при разрушении объекта.

```cpp
class Base {
public:
    virtual ~Base() = 0;  // чисто виртуальный
};
Base::~Base() {}          // тело обязательно!
```

2. **Виртуальность наследуется.** Если деструктор базового класса виртуальный, деструкторы всех производных классов автоматически тоже виртуальные (даже без ключевого слова `virtual`).

3. **Цена.** Виртуальный деструктор добавляет в класс таблицу виртуальных функций (vtable/vptr) и накладные расходы на вызов — поэтому не стоит делать деструктор виртуальным «на всякий случай» в классах, от которых не наследуются (например, в `final`-классах или маленьких value-типах).

4. **Нельзя делать виртуальным деструктор в `constexpr`-контексте** (до C++20), а также комбинировать с некоторыми спецификаторами неуместно.

## Итог

| Ситуация | Деструктор |
|---|---|
| Класс используется полиморфно (удаление через `Base*`) | **Обязательно виртуальный** |
| Класс не предназначен для наследования / `final` | Виртуальный не нужен |
| Абстрактный базовый класс | Виртуальный (можно чисто виртуальный с телом) |

Таким образом, ответ на вопрос: **да, деструктор может быть виртуальным, и в полиморфных иерархиях это необходимо для корректного освобождения ресурсов.**
