# Вопрос 15. Что такое конструкторы? Какие типы знаете?

> **Кратко:** конструктор — это специальная функция-член, которая вызывается при создании объекта и приводит его в корректное состояние: инициализирует поля, захватывает ресурсы, проверяет инварианты. Конструктор **не имеет возвращаемого типа** и **не наследуется автоматически**; у класса может быть несколько конструкторов, различающихся параметрами.

---

## Что такое конструктор

Конструктор вызывается неявно при определении переменной, при `new`, при создании временного объекта и при копировании/перемещении. Объект считается созданным только после того, как конструктор отработал: если он бросил исключение, объект **не создан**, но уже сконструированные базы и поля корректно разрушаются.

```cpp
#include <stdexcept>

class Ratio {
public:
    Ratio(int num, int den) : num_(num), den_(den) {
        if (den == 0)
            throw std::invalid_argument("denominator == 0");  // объект не будет создан
    }
    int num() const { return num_; }
    int den() const { return den_; }

private:
    int num_;
    int den_;
};
```

### Что конструктор может и чего не может

| Ограничение | Пояснение |
|---|---|
| Нет возвращаемого типа | `void Ratio(...)` — ошибка; `return;` в теле допустим, `return value;` — нет |
| Не может быть `virtual` | конструкторы не виртуальны; вызов `virtual`-функции из конструктора не уходит в наследника |
| Не может быть `const` / `volatile` / `static` | он работает с ещё не созданным, не константным объектом |
| Не наследуется сам | базовые подтягиваются явно: `using Base::Base;` |
| Может быть шаблоном | подробно разобрано в вопросе 16 |
| Может бросать исключения | штатный способ сообщить, что объект создать нельзя |

## Порядок инициализации

Порядок фиксирован и **не зависит от порядка записи в списке инициализации**:

1. виртуальные базовые классы, затем обычные базовые — в порядке объявления в списке наследования;
2. нестатические поля — **в порядке объявления в классе**;
3. тело конструктора.

```cpp
class Widget {
public:
    // Список написан как b_, a_ — но инициализация всё равно пойдёт по объявлению: a_, затем b_.
    Widget(int x) : b_(x), a_(b_ + 1) {}   // ОШИБКА: a_ читает ещё не инициализированный b_
private:
    int a_;
    int b_;
};
```

Компиляторы предупреждают об этом (`-Wreorder` в GCC/Clang). Правило: писать список инициализации в том же порядке, что и объявление полей.

## Виды конструкторов

| Вид | Типичная сигнатура | Назначение |
|---|---|---|
| По умолчанию | `X()` | создание «пустого» объекта; генерируется, если нет других объявленных конструкторов |
| Параметризованный | `X(int, std::string)` | инициализация значениями |
| Копирующий | `X(const X&)` | копия существующего объекта (memberwise copy) |
| Перемещающий | `X(X&&) noexcept` | «забирает» ресурс у временного объекта |
| Делегирующий | `X(int) : X() {}` | один конструктор вызывает другой того же класса |
| Наследующий | `using Base::Base;` | подтягивает конструкторы базы в наследника |
| Из `initializer_list` | `X(std::initializer_list<T>)` | инициализация списком `{...}` |
| Преобразующий | `X(int)` | разрешает неявное `X x = 5;`; `explicit` это запрещает |
| `constexpr` / `consteval` | `constexpr X(int)` | создание объектов на этапе компиляции |
| Приватный / защищённый | `private: X();` | фабрика, синглтон, запрет создания снаружи |

```cpp
#include <cstddef>
#include <initializer_list>
#include <utility>
#include <vector>

class Buffer {
public:
    Buffer() = default;                                    // 1) по умолчанию

    explicit Buffer(std::size_t n) : data_(n, '\0') {}     // 2) параметризованный + explicit

    Buffer(std::size_t n, char fill) : Buffer(n) {         // 3) делегирующий
        for (char& c : data_) c = fill;
    }

    Buffer(std::initializer_list<char> init)               // 4) из списка инициализации
        : data_(init) {}

    Buffer(const Buffer& other) : data_(other.data_) {}    // 5) копирующий

    Buffer(Buffer&& other) noexcept                        // 6) перемещающий
        : data_(std::move(other.data_)) {}

private:
    std::vector<char> data_;
};
```

## Копирующий и перемещающий конструкторы

**Копирующий** создаёт новый объект как memberwise-копию: для каждого поля вызывается его копирующий конструктор. Если класс владеет «сырым» ресурсом, нужна **глубокая** копия, иначе два объекта освободят один указатель. **Перемещающий** принимает `X&&` и обычно «угоняет» внутренние буферы, оставляя источник в валидном, но неопределённом состоянии.

```cpp
#include <cstring>

class Str {
public:
    explicit Str(const char* s) : data_(new char[std::strlen(s) + 1]) {
        std::strcpy(data_, s);
    }
    Str(const Str& other) : data_(new char[std::strlen(other.data_) + 1]) {
        std::strcpy(data_, other.data_);          // глубокая копия
    }
    Str(Str&& other) noexcept : data_(other.data_) {
        other.data_ = nullptr;                    // источник больше не владеет ресурсом
    }
    ~Str() { delete[] data_; }

private:
    char* data_;
};
```

> **Важно:** `noexcept` у перемещающего конструктора — не украшение. `std::vector` при перевыделении перемещает элементы, только если перемещение объявлено `noexcept` (или копирование недоступно), иначе копирует их ради гарантии строгого исключения.

## `= default`, `= delete` и приватный конструктор

```cpp
class Socket {
public:
    Socket() = default;                  // «верните сгенерированное поведение»
    Socket(const Socket&) = delete;      // копирование запрещено: сокет уникален
    Socket& operator=(const Socket&) = delete;
};
```

Приватный конструктор вместе со статической фабрикой ограничивает способы создания объекта (`Connection::create(...)`, синглтон): снаружи объект просто нечем создать.

## Список инициализации против присваивания в теле

| Способ | Что происходит | Когда применять |
|---|---|---|
| `X(int v) : a_(v) {}` | **инициализация** поля нужным значением | всегда, по умолчанию |
| `X(int v) { a_ = v; }` | инициализация по умолчанию, затем присваивание | только если поле нельзя инициализировать в списке |

Для `const`-полей, ссылок и полей без конструктора по умолчанию список инициализации — единственный вариант. Для членов-классов он ещё и эффективнее: экономит одну операцию.

## Типичные ошибки

1. **Объявили любой конструктор — и `X x;` перестал компилироваться**: неявный конструктор по умолчанию не генерируется, если объявлен хотя бы один другой. Лечится `X() = default;`.
2. **Ошибка в порядке инициализации**: поле читает другое поле, которое ещё не инициализировано.
3. **Присваивание в теле вместо списка инициализации** — лишняя работа и невозможность инициализировать `const`/ссылку.
4. **Поверхностное копирование** «сырого» указателя: двойное освобождение и висячие указатели. Правило трёх/пяти/нуля.
5. **Отсутствие `explicit`** у конструктора с одним аргументом — неявные преобразования и неожиданное участие в перегрузке.
6. **`std::vector<int> v(3)` против `std::vector<int> v{3}`**: первое — три нуля, второе — один элемент со значением 3.
7. **Исключение из конструктора без RAII**: ресурсы, захваченные «сырыми» вызовами до броска, утекают.
8. **Виртуальный вызов в конструкторе** — уходит в текущий класс, а не в наследника; отсюда же запрет на «виртуальный конструктор».

## Что добавить на собеседовании

- **Правило нуля**: если класс не управляет ресурсом напрямую, не пишите ни деструктор, ни копирование/перемещение — контейнеры и умные указатели сделают работу.
- **Правило пяти**: объявление деструктора подавляет генерацию перемещающих операций, поэтому «нулевой» класс обычно требует явного `= default` для них.
- **`explicit` почти всегда** для конструкторов с одним аргументом; в C++20 доступен условный `explicit(bool)`.
- **Copy elision**: с C++17 `X x = X();` и возврат prvalue не вызывают ни копирующий, ни перемещающий конструктор — это гарантия языка, а не оптимизация. **NSDMI** (`int timeout_ = 30;`, C++11) при этом сокращают число нужных конструкторов.

## Итог

| Понятие | Суть |
|---|---|
| Конструктор | Функция-член без возвращаемого типа, приводящая объект в корректное состояние |
| По умолчанию | `X()` — генерируется только при отсутствии других объявленных конструкторов |
| Копирующий | `X(const X&)` — создаёт копию; для владеющих ресурсом нужна глубокая |
| Перемещающий | `X(X&&) noexcept` — переносит ресурс, источник остаётся валидным и пустым |
| Делегирующий | Один конструктор вызывает другой, чтобы не дублировать логику |
| Наследующий | `using Base::Base;` подтягивает конструкторы базы |
| Из `initializer_list` | Перехватывает инициализацию `{...}` и имеет приоритет |
| `explicit` | Запрещает неявное преобразование через конструктор |
| Порядок | Базы → поля по объявлению → тело конструктора |
