# 147. Разница между IPv4 и IPv6

## 1. Размер адресного пространства

**IPv4** использует 32-битные адреса, что даёт теоретически около **4,3 млрд** (2³²) уникальных адресов. Адрес записывается в десятично-точечной нотации: `192.168.0.1`.

**IPv6** использует 128-битные адреса — это **3,4 × 10³⁸** (2¹²⁸) адресов. Запись — в шестнадцатеричной форме, разделённой двоеточиями: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`. Существует сокращённая форма (`::` для групп нулей).

Именно исчерпание IPv4-адресов (IPv4 address exhaustion) стало главной причиной разработки IPv6.

## 2. Формат заголовка пакета

| Параметр | IPv4 | IPv6 |
|---|---|---|
| Длина заголовка | 20–60 байт (переменная) | 40 байт (фиксированная) |
| Контрольная сумма заголовка | Есть | Отсутствует (возложена на канальный/транспортный уровень) |
| Фрагментация | Маршрутизаторами и отправителем | Только отправителем |
| Опции | Встроены в заголовок | Вынесены в расширенные заголовки (extension headers) |
| Поле «Protocol» | Есть | Заменено полем «Next Header» |

Фиксированный заголовок IPv6 упрощает и ускоряет обработку пакетов маршрутизаторами.

## 3. Конфигурация адресов

- **IPv4**: адрес обычно назначается вручную или через **DHCP**. Требуется NAT для экономии адресов.
- **IPv6**: поддерживает **SLAAC** (Stateless Address Autoconfiguration) — устройство может самостоятельно сформировать адрес на основе префикса сети и MAC-адреса (или случайного идентификатора). DHCPv6 существует, но не обязателен.

## 4. NAT и маршрутизация

IPv4 массово использует **NAT** (Network Address Translation), что усложняет сквозные соединения (peer-to-peer, VoIP, игровые серверы).

IPv6 изначально проектировался без необходимости NAT — каждое устройство может иметь глобально маршрутизируемый адрес. Это упрощает end-to-end связность.

## 5. Безопасность

- **IPsec** был разработан как *обязательная* часть IPv6 (хотя на практике поддержка не всегда включена).
- В IPv4 IPsec — опциональное расширение.
- При этом сам по себе IPv6 не «безопаснее» автоматически — это зависит от конфигурации.

## 6. Качество обслуживания (QoS)

IPv6 имеет поле **Flow Label** в заголовке, позволяющее помечать потоки пакетов для приоритизации без разбора содержимого пакета. В IPv4 аналогичная функциональность реализуется через поле ToS/DSCP.

## 7. Multicast и broadcast

- **IPv4** поддерживает broadcast (широковещание).
- **IPv6** отказался от broadcast; вместо него используется **multicast** (в т.ч. специальные группы `ff02::1` — все узлы, `ff02::2` — все маршрутизаторы) и **anycast**.

## 8. Поддержка мобильности

IPv6 имеет встроенную поддержку **Mobile IPv6** (MIPv6), позволяющую устройству сохранять постоянный адрес при смене сети. В IPv4 это реализуется через надстройки (Mobile IP).

## 9. Совместимость и сосуществование

IPv4 и IPv6 — **несовместимые протоколы**; узел IPv4 не может напрямую общаться с узлом IPv6. Для перехода используются механизмы:

- **Dual Stack** — устройство поддерживает оба протокола одновременно;
- **Туннелирование** (6in4, Teredo, ISATAP);
- **Трансляция** (NAT64/DNS64).

## 10. Пример на C++: определение версии IP-адреса

При программировании сетей на C++ (например, с Berkeley sockets) версия определяется полем в структуре адреса:

```cpp
#include <sys/socket.h>
#include <netinet/in.h>
#include <iostream>

void printIpVersion(const sockaddr* addr) {
    if (addr->sa_family == AF_INET) {
        const auto* a = reinterpret_cast<const sockaddr_in*>(addr);
        std::cout << "IPv4\n";
        // a->sin_addr содержит 32-битный адрес
    } else if (addr->sa_family == AF_INET6) {
        const auto* a = reinterpret_cast<const sockaddr_in6*>(addr);
        std::cout << "IPv6\n";
        // a->sin6_addr содержит 128-битный адрес (in6_addr)
    } else {
        std::cout << "Другой семейство адресов\n";
    }
}
```

Структуры `sockaddr_in` (для IPv4) и `sockaddr_in6` (для IPv6) различаются размером поля адреса (`in_addr` — 4 байта, `in6_addr` — 16 байт) и наличием дополнительных полей (например, `sin6_flowinfo`, `sin6_scope_id`).

## Краткая сводная таблица

| Критерий | IPv4 | IPv6 |
|---|---|---|
| Длина адреса | 32 бита | 128 бит |
| Формат записи | `192.168.1.1` | `2001:db8::1` |
| Размер заголовка | 20–60 байт | 40 байт (фикс.) |
| Контрольная сумма | Да | Нет |
| Broadcast | Да | Нет (multicast/anycast) |
| NAT | Широко используется | Не требуется |
| Автоконфигурация | DHCP | SLAAC + DHCPv6 |
| IPsec | Опционально | Обязателен по стандарту |
| Фрагментация | Роутерами и хостами | Только хостами |
