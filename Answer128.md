# 128. Разница между `std::vector` и `std::list` в C++

## Краткое введение

`std::vector` и `std::list` — два контейнера стандартной библиотеки STL с принципиально разной внутренней структурой. `vector` — динамический массив, `list` — двусвязный список. Отсюда вытекают все различия в производительности и областях применения.

---

## 1. Внутреннее устройство

**`std::vector`** хранит элементы **непрерывно** в одном блоке памяти (по сути — обёртка над динамическим массивом). При нехватке места выделяется новый блок (обычно в 1.5–2 раза больше), элементы копируются/перемещаются туда, старый освобождается.

**`std::list`** — **двусвязный список**: каждый элемент хранится в отдельном узле, содержащем значение, указатели на предыдущий и следующий узлы. Узлы разбросаны по памяти произвольно.

```
vector: [ A ][ B ][ C ][ D ]   — одна непрерывная область

list:   A <-> B <-> C <-> D    — узлы в разных местах памяти
```

---

## 2. Сравнение по операциям

| Операция | `vector` | `list` |
|---|---|---|
| Доступ по индексу `[]`, `at()` | **O(1)** | **O(n)** (нет `operator[]` вообще) |
| Вставка/удаление в конец (`push_back`/`pop_back`) | Амортизированно **O(1)** | **O(1)** |
| Вставка/удаление в начало | **O(n)** | **O(1)** |
| Вставка/удаление в середину (по итератору) | **O(n)** (сдвиг элементов) | **O(1)** (перестановка указателей) |
| Поиск элемента | **O(n)** | **O(n)** |
| Обход (итерация) | **Быстро** (кэш, локальность) | **Медленно** (прыжки по памяти) |
| Инвалидация итераторов при вставке | Возможна полная (при реаллокации) | Только итератор на удалённый элемент |

### Важные нюансы

- У `vector` **нет** `push_front`/`pop_front` — вставка в начало требует сдвига всех элементов.
- У `list` **нет** `operator[]` — доступ только через итераторы.
- Вставка в середину `vector` по итератору — это O(n) на сдвиг, а у `list` — O(1), **но** чтобы дойти до нужной позиции, всё равно нужно O(n). Поэтому «вставка в середину списка» выгодна только если итератор на позицию уже получен (например, в цикле обхода).
- `vector` **кэш-дружелюбен**: элементы лежат рядом, процессор эффективно использует кэш и предвыборку. `list` из-за разброса узлов страдает от промахов кэша, поэтому даже O(n) обход у него на практике заметно медленнее.

---

## 3. Память

- `vector` — минимум накладных расходов: только сами элементы + запас ёмкости (`capacity`). Компактно.
- `list` — каждый узел хранит **два указателя** дополнительно (на 32-битной системе +8 байт, на 64-битной +16 байт на элемент), плюс накладные расходы аллокатора на каждое выделение. Памяти тратится существенно больше, аллокаций много.

---

## 4. Когда что использовать

### Лучше `std::vector`, когда:
- нужен **быстрый доступ по индексу**;
- элементы в основном **добавляются/удаляются в конце**;
- важен **быстрый обход** и производительность в целом (кэш!);
- нужно экономить память;
- нужна совместимость с функциями, ожидающими непрерывный массив (`.data()`, указатели, C-API).

**Практическое правило:** по умолчанию в C++ выбирайте `vector` — в подавляющем большинстве задач он быстрее даже там, где теоретически список должен выигрывать, из-за эффектов кэша.

### Лучше `std::list`, когда:
- часто **вставляете/удаляете в произвольных местах**, и итератор на место уже есть (например, хранение итераторов, удаление во время обхода);
- нужны **стабильные итераторы и ссылки** на элементы при модификациях контейнера (кроме удалённого элемента);
- важна вставка/удаление **в начало**;
- элементы **очень большие и дорогие в копировании**, а перемещать узлы дешевле, чем сдвигать массив;
- нужны операции **splice, merge, sort** на уровне списка (у `list` есть свои эффективные `sort()`, `merge()`, `splice()`).

### Альтернативы
- `std::deque` — если нужны быстрые вставки и в начало, и в конец, плюс доступ по индексу.
- `std::forward_list` — односвязный список, ещё экономнее по памяти, если нужен обход только вперёд.

---

## 5. Пример

```cpp
#include <vector>
#include <list>
#include <iostream>

int main() {
    // vector: быстрый доступ по индексу и обход
    std::vector<int> v = {1, 2, 3, 4, 5};
    std::cout << v[2] << "\n";        // O(1)
    v.push_back(6);                   // амортизированно O(1)

    // list: быстрая вставка в середину по известному итератору
    std::list<int> l = {1, 2, 3, 4, 5};
    auto it = l.begin();
    std::advance(it, 2);              // O(n) — дошли до 3-го элемента
    l.insert(it, 100);                // O(1) — вставка по итератору
    l.push_front(0);                  // O(1) — вставка в начало

    for (int x : l) std::cout << x << " ";
    std::cout << "\n";
}
```

---

## 6. Итог

| Критерий | Победитель |
|---|---|
| Доступ по индексу | `vector` |
| Обход и общая производительность | `vector` |
| Память | `vector` |
| Вставка/удаление в конец | `vector` (амортизированно) |
| Вставка/удаление в начало и середину (по итератору) | `list` |
| Стабильность итераторов/ссылок | `list` |

**Вывод:** `vector` — выбор по умолчанию для большинства задач. `list` оправдан, когда действительно нужны частые вставки/удаления в произвольных местах с уже имеющимися итераторами или важна стабильность ссылок на элементы.
