# Вопрос 48. Какие есть операции с указателями?

> **Кратко:** Указатель поддерживает операции, которые имеют смысл для адреса: получить адрес (`&`), разыменовать (`*`, `->`, `[]`), сдвинуть на N элементов (арифметика масштабируется на `sizeof(T)`), сравнить, привести к другому типу и вызвать функцию через указатель. Складывать и умножать указатели нельзя, а арифметика корректна только внутри одного массива (включая `one-past-the-end`).

---

## Взятие адреса и разыменование

`&x` возвращает адрес объекта и требует lvalue (у `&42` адреса нет), `*p` даёт сам объект как lvalue, `p->m` — его член. При перегруженном `operator&` настоящий адрес возвращает `std::addressof(x)`.

---

## Полный набор операций

| Операция | Синтаксис | Результат | Когда определена |
|---|---|---|---|
| Взятие адреса | `&x` | `T*` | `x` — lvalue |
| Разыменование | `*p` | `T&` | `p` указывает на существующий объект |
| Доступ к члену | `p->m` | тип `m` | `p` указывает на объект, `p != nullptr` |
| Индексирование | `p[i]` | `T&` | эквивалентно `*(p + i)` |
| Сложение с целым | `p + n`, `n + p` | `T*` | `p` — элемент массива или `one-past-the-end` |
| Вычитание целого | `p - n` | `T*` | то же |
| Инкремент / декремент | `++p`, `p--` | `T*` | то же |
| Разность указателей | `p2 - p1` | `std::ptrdiff_t` | оба указывают в один массив |
| Сравнение на равенство | `p1 == p2`, `p1 != p2` | `bool` | всегда |
| Сравнение порядка | `p1 < p2`, `p1 >= p2` | `bool` | осмысленно в пределах одного массива |
| Присваивание | `p = q` | `T*&` | после проверки типов |
| Приведение типа | `static_cast`, `reinterpret_cast` | другой тип | см. ниже |
| Логическая проверка | `if (p)`, `!p` | `bool` | всегда: контекстное преобразование в `bool` |
| Вызов функции | `fp(args)` | тип возврата | `fp != nullptr` |
| Доступ к члену через указатель на член | `obj.*pm`, `ptr->*pm` | тип члена | объект существует |
| Освобождение памяти | `delete p`, `delete[] p` | `void` | `p` получен из `new` / `new[]` |

## Арифметика указателей: масштабирование

Ключевая деталь: `p + 1` сдвигает адрес не на 1 байт, а на `sizeof(*p)` байт.

```cpp
#include <cstddef>
#include <cstdint>
#include <cstdio>

int main() {
    int arr[4] = {10, 20, 30, 40};

    int* p = arr;
    std::printf("%td\n", reinterpret_cast<const char*>(p + 1) -
                         reinterpret_cast<const char*>(p));   // 4 = sizeof(int)

    int* last = arr + 4;             // one-past-the-end: разыменовывать нельзя
    std::ptrdiff_t count = last - arr;  // 4 — число элементов, а не байт

    std::printf("%td, %d\n", count, arr[3]);  // 4, 40
}
```

Правила корректности:

- указатель должен указывать на элемент массива либо на позицию сразу за последним;
- `p + n` вне `[begin, end]` — **undefined behavior**, даже без разыменования;
- разность двух указателей — только для одного массива, иначе UB;
- `nullptr + 0` корректно и даёт `nullptr`, `nullptr + 1` — UB;
- `p[-1]` легально, если элемент существует (например, `arr[2]` и `p = arr + 2`).

## Индексирование и приоритеты

```cpp
int arr[3] = {1, 2, 3};
int* p = arr;

int a = *p++;      // *(p++): a = 1, p смотрит на arr[1]
int b = (*p)++;    // b = 2, arr[1] стало 3
int c = *++p;      // ++p, затем *: c = 3, p на arr[2]

int d = 2[arr];    // то же, что arr[2]: p[i] == *(p + i)
```

---

## Сравнение и разность

| Выражение | Смысл | Оговорка |
|---|---|---|
| `p == nullptr` | проверка на пустоту | предпочтительнее, чем `p == 0` |
| `p1 == p2` | один и тот же адрес | определено всегда |
| `p1 < p2` | порядок в массиве | для разных объектов результат **unspecified** |
| `p2 - p1` | число элементов между | только внутри одного массива |
| `std::less<T*>` | «полный порядок» для ассоциативных контейнеров | в C++20 гарантия полного порядка для указателей убрана |

## Присваивание и преобразования

```cpp
int  x = 1;
const int* pc = &x;         // добавление const — неявно
// int* p = pc;             // ошибка: снятие const неявно запрещено
int* p = const_cast<int*>(pc);   // явно, и только если объект изначально не const

void* v = p;                // любой T* -> void* неявно
int*  q = static_cast<int*>(v);  // void* -> T* требует явного приведения

char* raw = reinterpret_cast<char*>(p);   // переинтерпретация байтов объекта
std::uintptr_t addr = reinterpret_cast<std::uintptr_t>(p);  // адрес как число
```

Допустимые неявные преобразования указателей: `T*` → `void*`, `T*` → `const T*`, `Derived*` → `Base*` (при public-наследовании), указатель → `bool`.

---

## Указатели на функции

```cpp
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int (*op)(int, int) = &add;   // & необязателен: имя функции затухает до указателя
op = sub;
int r = op(7, 3);             // вызов без явного разыменования; (*op)(7, 3) тоже верно
```

Через указатель на функцию работают колбэки и таблицы обработчиков; в современном C++ удобнее `std::vector<std::function<int(int,int)>>` — обёртка принимает любой вызываемый объект с нужной сигнатурой.

## Указатели на члены класса

Это отдельный вид указателя: он хранит не адрес, а смещение внутри объекта.

```cpp
struct Point {
    int x;
    int y;
    int sum() const { return x + y; }
};

int  Point::* pm  = &Point::y;            // указатель на член-данное
int (Point::* pmf)() const = &Point::sum; // указатель на функцию-член

Point pt{1, 2};
Point* ptr = &pt;

pt.*pm = 10;        // pt.y = 10
(ptr->*pmf)();      // 11 — вызов через объект
```

---

## Чего с указателями делать нельзя

| Выражение | Почему нельзя |
|---|---|
| `p + q` | сумма двух адресов не имеет смысла |
| `p * 2`, `p / 2` | не определено |
| `++v` для `void*` | `void` — неполный тип, размер неизвестен (в GCC это расширение) |
| `p + 1` для указателя на одиночный объект | выход за границы объекта — UB |
| сравнение `p < q` из разных массивов | результат unspecified, полагаться нельзя |
| разыменование `one-past-the-end` | UB |
| `delete` указателя не из `new` | UB |
| арифметика по `nullptr` | UB (кроме `+ 0`) |

---

## Типичные ошибки

1. **Считать `p + 1` сдвигом на байт** — сдвиг на `sizeof(*p)`.
2. **Выходить за границы массива «на один»** и разыменовывать `end`: сам указатель `end` легален, `*end` — нет.
3. **Брать разность указателей из разных массивов** и удивляться странному результату: это UB, а не «расстояние в памяти».
4. **Забывать про приоритет**: `*p++` и `(*p)++` делают разное.
5. **Инкрементировать `void*`** — код перестаёт быть переносимым (в C++ это ошибка компиляции).
6. **Сравнивать указатели через `<` для поиска «кто раньше в памяти»** — для несвязанных объектов это не гарантировано.
7. **Хранить адрес в `int`** вместо `std::uintptr_t`.

---

## Что добавить на собеседовании

- Полезно явно сказать, что арифметика указателей — это арифметика **в элементах**, и что она определена только для массивов; именно поэтому в STL работают полуинтервалами `[first, last)`.
- `std::ptrdiff_t` для разности, `std::size_t` для размеров — разные типы, и это не случайно.
- Указатель на член класса — самостоятельная категория: нельзя привести к `void*` и нельзя сложить с числом.
- `std::less` для указателей в контейнерах — деталь, которая показывает понимание, что `<` у указателей не полный порядок (в C++20 гарантия убрана).
- Логическое продолжение темы — умные указатели: те же операции, но с владением и без ручного `delete`.

---

## Итог

| Группа | Операции |
|---|---|
| Доступ | `&x`, `*p`, `p->m`, `p[i]` |
| Арифметика | `p ± n`, `++p`, `p--`, `p2 - p1` (в элементах, внутри массива) |
| Сравнение | `==`, `!=` — всегда; `<`, `>` — в пределах массива |
| Преобразования | `T*` → `void*`, `T*` → `const T*`, `Derived*` → `Base*`, `static_cast`, `reinterpret_cast` |
| Вызов | указатель на функцию `fp(args)`, указатель на член `obj.*pm`, `ptr->*pm` |
| Управление памятью | `new` / `delete`, `new[]` / `delete[]` |
| Запрещено | сложение указателей, умножение, арифметика по `nullptr`, разыменование `end` |
