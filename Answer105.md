# 105. Переопределённые virtual-функции и конструкторы в C++

## 1. Вызов переопределённой virtual-функции из конструктора

### Что происходит

При вызове виртуальной функции из конструктора (или деструктора) **виртуальный механизм работает не полностью** — вызывается версия функции, определённая в текущем классе (том, чей конструктор выполняется), а **не** переопределённая версия в производном классе.

Причина: во время выполнения конструктора базового класса объект ещё не «дорос» до производного типа. Динамический тип объекта на этом этапе — это тип конструируемого в данный момент класса. Виртуальная таблица (vtable) указывает на функции текущего класса, а не самого производного.

### Пример

```cpp
#include <iostream>

class Base {
public:
    Base() {
        print();  // Вызовется Base::print(), а НЕ Derived::print()
    }
    virtual void print() const {
        std::cout << "Base::print()\n";
    }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    Derived() {
        print();  // Здесь уже вызовется Derived::print()
    }
    void print() const override {
        std::cout << "Derived::print()\n";
    }
};

int main() {
    Derived d;
}
```

**Вывод:**
```
Base::print()
Derived::print()
```

В конструкторе `Base` вызывается `Base::print()`, хотя объект создаётся как `Derived`. В конструкторе `Derived` вызов уже идёт в `Derived::print()`.

### Важные следствия

- **Нет ошибки компиляции** (если функция не чисто виртуальная) — просто вызывается «не та» версия. Это классическая ловушка.
- Если вызвать **чисто виртуальную** функцию из конструктора базового класса — это **неопределённое поведение** (undefined behavior). На практике часто приводит к аварийному завершению (вызов `pure virtual method called`), потому что в vtable на этом этапе стоит заглушка.
- Такое же поведение — при вызове виртуальных функций из **деструктора** (только «в обратную сторону»: в деструкторе `Derived` — версия `Derived`, в деструкторе `Base` — версия `Base`).
- Аналогично ведёт себя вызов виртуальной функции из **списка инициализации** члена-конструктора базового класса.

### Как правильно

Если нужна полиморфная инициализация — используйте **двухфазную инициализацию** (отдельный метод `init()`/`initialize()`, вызываемый после полного конструирования) или **фабричные функции**. Также помогает передача нужных данных в конструктор базового класса явно.

## 2. Может ли конструктор быть виртуальным?

**Нет, конструктор не может быть виртуальным.** Это прямо запрещено стандартом языка.

### Причины

1. **Виртуальность требует готового объекта.** Чтобы вызвать виртуальную функцию, нужен объект с настроенной vtable (vptr). Но vptr устанавливается как раз **в конструкторе**, после того как память выделена. На момент вызова конструктора объекта ещё нет — есть только «сырая» память.

2. **Конструктор вызывается для создания объекта, а не через указатель/ссылку на существующий объект.** Виртуальный вызов имеет смысл, когда есть указатель/ссылка на базовый тип, но объект производного типа уже существует. Конструктор же вызывается явно с указанием конкретного типа (`Derived d;` или `new Derived`), и компилятор **всегда знает**, какой конструктор нужен.

3. **Логическое противоречие.** Если бы конструктор был виртуальным, для его вызова понадобился бы уже сконструированный объект, чтобы определить, какую версию вызывать, — но объект ещё не существует. Замкнутый круг.

### Что разрешено

- **Виртуальный деструктор — можно и нужно** (если класс используется полиморфно), чтобы при `delete` через указатель на базовый тип вызывался правильный деструктор.
- **Виртуальные конструкторы эмулируются** через паттерн **Factory Method** (фабричные функции, возвращающие `std::unique_ptr<Base>`), либо через идиому **clone()** для копирования полиморфных объектов.

```cpp
class Base {
public:
    virtual ~Base() = default;                       // OK, нужно
    // virtual Base() {}                             // ОШИБКА компиляции
    virtual std::unique_ptr<Base> clone() const = 0; // эмуляция «виртуального конструктора»
};
```

### Итоговая таблица

| Вопрос | Ответ |
|---|---|
| Виртуальный вызов из конструктора | Работает, но вызывает версию **текущего** класса, не производного |
| Чисто виртуальная функция из конструктора | **Неопределённое поведение** |
| Конструктор виртуальный? | **Нет, запрещено** |
| Деструктор виртуальный? | **Да, можно и рекомендуется** при полиморфном использовании |
