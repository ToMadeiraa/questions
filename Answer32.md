# Вопрос 32. Как работают макросы?

> **Кратко:** макрос — это имя, которое препроцессор заменяет на заранее заданную последовательность токенов ещё до синтаксического разбора, поэтому он работает с текстом, а не с типами и объектами. Различают объектно-подобные (`#define N 10`) и функционально-подобные (`#define F(x) ...`) макросы; у вторых аргументы подставляются в тело, после чего результат сканируется заново. Отсутствие типов, области видимости и отладочной информации — источник и силы макросов (кодогенерация, условная компиляция), и их главных опасностей.

---

## Где работают макросы: до компилятора

Раскрытие макросов — фаза 4 трансляции. На входе у препроцессора поток токенов, на выходе тоже поток токенов: синтаксического дерева ещё нет, типов ещё нет, областей видимости ещё нет. Поэтому макрос не может «знать» ничего о коде, в который он подставляется, и не подчиняется ни блокам, ни классам, ни пространствам имён.

Таблица макросов у каждой единицы трансляции своя и заполняется по мере чтения файла:

| Источник определения | Когда действует |
|---|---|
| предопределённые (`__cplusplus`, `__FILE__`, `__LINE__`) | с начала файла |
| ключи командной строки (`-DNDEBUG`, `/DUNICODE`) | с начала файла, для всех единиц трансляции |
| `#define` в самом файле | со строки определения до `#undef` или конца файла |
| `#define` во включённом заголовке | начиная с точки включения — то есть «протекает» ко всем, кто включил заголовок |
| `#undef` | снимает определение до конца файла |

Макрос — не сущность языка: он не попадает ни в таблицу символов, ни в отладочную информацию. Компилятор видит только результат подстановки.

## Как происходит подстановка

| Шаг | Действие препроцессора |
|---|---|
| 1 | находит в потоке токенов идентификатор, для которого есть определение |
| 2 | для объектно-подобного макроса подставляет тело; для функционально-подобного требует `(` следующим токеном (в определении пробел перед `(` запрещён, при вызове — допустим) |
| 3 | собирает аргументы, балансируя скобки; запятые внутри `()` и `{}` аргумент не разделяют |
| 4 | раскрывает каждый аргумент, если он не используется с `#` или `##` |
| 5 | подставляет результаты в тело вместо имён параметров |
| 6 | сканирует полученный текст заново — уже вместе с остатком файла |

```cpp
#define LIMIT 100
#define ENABLED LIMIT            // цепочка раскрывается по шагам
#define INCREMENT(x) ((x) + 1)

int  a = ENABLED;                // → 100
int  b = INCREMENT(LIMIT);       // → ((100) + 1): аргумент раскрыт до подстановки
```

Самовложенность запрещена: имя, встреченное внутри собственного раскрытия, помечается и больше не раскрывается — иначе подстановка была бы бесконечной. Поэтому рекурсивных макросов не бывает, а «вычислить» что-то макросами можно только до определённого предела.

## Что макрос умеет

| Возможность | Пример | Зачем |
|---|---|---|
| подставить константу | `#define BUFFER 4096` | размеры, флаги, версии |
| подставить выражение | `#define SQR(x) ((x)*(x))` | короткая запись до появления `constexpr` |
| вести себя как оператор | `do { ... } while (false)` | проверки, логирование |
| превратить аргумент в строку | `#x` | имя сущности в сообщении об ошибке |
| склеить токены | `a##b` | сгенерировать идентификатор |
| принять пакет аргументов | `__VA_ARGS__`, `__VA_OPT__` | логгеры, обёртки |
| исключить код из сборки | `#if`, `#ifdef` | платформы, отладочные сборки |
| сообщить о месте вызова | `__LINE__`, `__FILE__` | диагностика, `assert` |

## Приёмы, которые встречаются в реальном коде

### Макрос-оператор: `do { ... } while (false)`

```cpp
#include <stdexcept>

#define CHECK(cond)                                       \
    do {                                                  \
        if (!(cond)) throw std::runtime_error(#cond);      \
    } while (false)

// CHECK(x > 0);  — ведёт себя как один оператор, безопасен в if без скобок
```

Без обёртки `if (c) CHECK(x); else ...` сломался бы: `else` привязался бы к внутреннему `if`.

### Уникальные имена: `__COUNTER__`

```cpp
#define CONCAT_IMPL(a, b) a##b
#define CONCAT(a, b)      CONCAT_IMPL(a, b)   // обёртка раскрывает аргументы до склейки
#define UNIQUE(prefix)    CONCAT(prefix, __COUNTER__)
```

`__COUNTER__` — расширение компиляторов, но поддержано всеми основными; счётчик уникален в пределах единицы трансляции.

### X-макросы: один список — много сущностей

```cpp
#define COLOR_LIST(X) \
    X(Red)            \
    X(Green)          \
    X(Blue)

#define AS_ENUM(name) Color_##name,
enum Color { COLOR_LIST(AS_ENUM) };
#undef AS_ENUM

#define AS_CASE(name) case Color_##name: return #name;
const char* toColorName(Color c) {
    switch (c) { COLOR_LIST(AS_CASE) }
    return "unknown";
}
#undef AS_CASE
```

Список описан один раз: добавили цвет — обновились и `enum`, и преобразование в строку.

### Детект возможностей и атрибуты

```cpp
#if defined(__has_cpp_attribute)
#  if __has_cpp_attribute(nodiscard)
#    define ATTR_NODISCARD [[nodiscard]]
#  endif
#endif
#ifndef ATTR_NODISCARD
#  define ATTR_NODISCARD
#endif
```

## Отладка макросов

- результат подстановки виден в `g++ -E -P file.cpp`, `clang++ -E`, MSVC `/P /Fiout.i`;
- сообщение об ошибке содержит «in expansion of macro» — по нему видна цепочка раскрытий (у Clang помогает `-fmacro-backtrace-limit=0`);
- `#pragma message("...")` и `#error` проверяют предположения о сборке;
- точки останова внутри макроса нет: отладчик видит только раскрытый код, шагнуть «в макрос» невозможно.

## Макрос против альтернатив

| Потребность | Макрос | Альтернатива | Что выбрать |
|---|---|---|---|
| константа | `#define N 10` | `inline constexpr int N = 10;` | `constexpr` |
| маленькая функция | `#define SQR(x)` | `constexpr`-функция, шаблон | функция |
| `min`/`max` | `#define MAX(a,b)` | `std::max`, `std::clamp` | стандартная функция |
| размер массива | `#define SIZE(a)` | `std::size(a)` | `std::size` |
| лог с местом вызова | `#define LOG(...)` | `std::source_location` (C++20) | макрос или `source_location` |
| имя сущности строкой | `#define STR(x) #x` | рефлексии в C++ пока нет | макрос |
| склейка идентификаторов | `a##b` | нет | макрос |
| условная компиляция | `#if` | `if constexpr` — только для типов | макрос |

Правило: **макрос допустим там, где нужна работа с токенами или с самой сборкой**; всё, что выражается языком, лучше выразить языком.

## Гигиена макросов

- Имена — заглавными и с префиксом проекта: `APP_LOG`, а не `log`.
- В функционально-подобном макросе **каждый параметр и всё тело** в скобках.
- Не передавайте в макрос выражения с побочными эффектами: `SQR(i++)` — двойное вычисление и UB.
- Многооператорное тело — только через `do { ... } while (false)`.
- После использования — `#undef`, чтобы не протекать к клиентам.
- В заголовках определяйте макросы только при необходимости: они влияют на всё, что включено после.

---

## Типичные ошибки

1. **Считать макрос функцией.** Он не проверяет типы, не имеет области видимости и не виден отладчику.
2. **Пробел между именем и `(`** в определении — макрос становится объектно-подобным.
3. **Забыть скобки** вокруг параметров или тела: `#define NEG(x) -x` на `NEG(a + b)` даёт `-a + b`.
4. **Побочные эффекты в аргументах** — `MAX(i++, j++)` инкрементирует дважды.
5. **Короткие имена в заголовке** (`min`, `max`, `check`) ломают чужой код, включая стандартный.
6. **Точка с запятой в конце `#define`** — она попадёт в каждую подстановку.
7. **Запятая в аргументе шаблона** (`f(std::pair<int,int>{1,2})`) — препроцессор увидит лишний аргумент; помогает `using P = std::pair<int,int>;` или скобки.
8. **Использование `({ ... })`** (statement expressions GCC) — непереносимо, MSVC это не примет.
9. **Макрос вместо `constexpr`/`inline`** там, где хватает средств языка.

## Что добавить на собеседовании

- Назвать точное место: фаза 4, до разбора, работа с токенами — отсюда все свойства.
- Объяснить конвейер раскрытия (сбор аргументов → предраскрытие → подстановка → rescan) и запрет самовложенности.
- Показать, что `#` и `##` блокируют предраскрытие аргумента, — это неочевидно и часто спрашивается.
- Признать, что «макрос быстрее функции» — миф: `inline`/`constexpr` дают тот же эффект без рисков.
- Перечислить, что останется макросами: условная компиляция, `#if`-арифметика, строкизация, склейка, детект возможностей.

## Итог

| Аспект | Суть |
|---|---|
| Когда работает | фаза 4, до синтаксического разбора; только токены |
| Виды | объектно-подобный и функционально-подобный (в определении `(` сразу за именем) |
| Механизм | аргументы → предраскрытие → подстановка → rescan; самовложенность запрещена |
| Область действия | от `#define` до `#undef` или конца единицы трансляции, включая всё включённое позже |
| Сильные стороны | кодогенерация, строкизация, склейка, условная компиляция, контекст вызова |
| Слабые стороны | нет типов, области видимости и отладки; двойное вычисление; протекание имён |
| Замена | `constexpr`, `inline`, шаблоны, `std::source_location`, `std::size`, `std::clamp` |
