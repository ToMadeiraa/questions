# 90. Обработка ошибок в С++. Какие конструкции используют при обработке exception?

В C++ обработка исключений реализуется с помощью трех ключевых конструкций: **`try`**, **`throw`** и **`catch`**. Они позволяют отделить код, который может привести к ошибке, от кода, который эту ошибку обрабатывает, и передавать управление вверх по стеку вызовов.

### 🔑 Основные конструкции

1. **`try` (блок попытки)**: Этот блок заключается в фигурные скобки и содержит код, который потенциально может сгенерировать исключение. Если внутри блока `try` возникает исключение, управление немедленно передается соответствующему обработчику `catch`.
2. **`throw` (выброс исключения)**: Оператор `throw` используется для явного сигнала о возникновении исключительной ситуации. В качестве операнда можно использовать объект любого типа (обычно это класс, унаследованный от `std::exception`). Выброс исключения прерывает нормальное выполнение текущей функции и начинает "раскрутку стека".
3. **`catch` (обработчик)**: Блоки `catch` следуют сразу за блоком `try` и предназначены для перехвата и обработки исключений. Каждый блок `catch` указывает тип исключения, которое он может обработать. Когда исключение перехвачено, выполняется код внутри соответствующего блока `catch`.

### 📝 Синтаксис и пример использования

Ниже приведен типичный пример с комментариями:

```cpp
#include <iostream>
#include <stdexcept>

void riskyFunction(int value) {
    if (value < 0) {
        // Выброс исключения с сообщением
        throw std::invalid_argument("Значение не может быть отрицательным");
    }
    if (value == 0) {
        // Выброс исключения другого типа
        throw std::runtime_error("Деление на ноль недопустимо");
    }
    std::cout << "Результат: " << 100 / value << std::endl;
}

int main() {
    try {
        // Код, который может вызвать исключение
        riskyFunction(-5);
        // Если исключение выброшено, код ниже не выполнится
        std::cout << "Этот текст не будет напечатан" << std::endl;
    }
    catch (const std::invalid_argument& e) {
        // Обработка конкретного типа исключения
        std::cerr << "Ошибка аргумента: " << e.what() << std::endl;
    }
    catch (const std::runtime_error& e) {
        // Обработка другого типа
        std::cerr << "Ошибка выполнения: " << e.what() << std::endl;
    }
    catch (...) {
        // Перехват всех остальных исключений (должен быть последним)
        std::cerr << "Произошло неизвестное исключение" << std::endl;
    }
    
    return 0;
}
```

### 💡 Важные детали и рекомендации

* **Перехват по константной ссылке**: Рекомендуется перехватывать исключения по константной ссылке (`catch (const std::exception& e)`), чтобы избежать ненужного копирования и сохранить полиморфное поведение объекта исключения.
* **Порядок обработчиков**: Блоки `catch` проверяются в порядке их следования. Поэтому обработчики для более специфичных (производных) типов должны стоять **перед** обработчиками для базовых типов. В противном случае производный тип будет перехвачен обработчиком базового типа.
* **`catch (...)`**: Обработчик с многоточием перехватывает исключения любого типа. Он должен быть **последним** в списке обработчиков. Его следует использовать с осторожностью, так как он не дает информации о типе исключения.
* **Повторный выброс (`throw;`)**: Внутри блока `catch` можно использовать `throw;` без операнда, чтобы повторно выбросить текущее исключение. Это полезно, если обработчик выполнил лишь часть действий (например, логирование) и хочет передать исключение вышестоящему обработчику, сохраняя его исходный тип.

### 🧩 Дополнительные аспекты (C++11 и новее)

* **`noexcept`**: Начиная с C++11, спецификатор `noexcept` указывает, что функция не должна генерировать исключения. Если такое исключение все же возникнет, будет вызвана функция `std::terminate`. Это позволяет компилятору проводить более агрессивную оптимизацию.
* **Иерархия исключений**: Стандартная библиотека предоставляет базовый класс `std::exception` и ряд производных от него классов (например, `std::runtime_error`, `std::logic_error`, `std::bad_alloc`). Создание собственных классов исключений путем наследования от `std::exception` (или его потомков) является хорошей практикой, так как позволяет использовать единый интерфейс (метод `what()`) для получения информации об ошибке.
