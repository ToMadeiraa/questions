# 148. Сколько памяти необходимо для хранения IPv4?

## Краткий ответ

Для хранения IPv4-адреса достаточно **4 байт (32 бита)** — именно столько занимает сам адрес, поскольку IPv4 использует 32-битную адресацию.

## Подробное объяснение

### 1. Размер самого адреса

IPv4-адрес — это 32-битное число. Соответственно:

- **32 бита = 4 байта** — минимально необходимое место для «сырого» адреса.

Именно поэтому в сетевых структурах (например, `struct in_addr` из `<netinet/in.h>`) адрес хранится как `uint32_t`:

```cpp
#include <cstdint>

struct in_addr {
    uint32_t s_addr;  // 4 байта
};
```

### 2. В составе `sockaddr_in`

При работе с сокетами адрес обычно хранится в структуре `sockaddr_in`:

```cpp
#include <netinet/in.h>

struct sockaddr_in {
    sa_family_t    sin_family;  // 2 байта (обычно)
    in_port_t      sin_port;    // 2 байта (uint16_t)
    struct in_addr sin_addr;    // 4 байта
    unsigned char  sin_zero[8]; // 8 байт выравнивания/заполнения
};
```

Итого `sockaddr_in` обычно занимает **16 байт**, но из них на сам IPv4-адрес приходится только **4 байта**.

### 3. Различные представления и их размер

| Представление | Размер | Примечание |
|---|---|---|
| Бинарный адрес (`uint32_t` / `in_addr`) | 4 байта | Каноническое хранение |
| Строковое представление (`"192.168.0.1"`) | до 16 байт (15 символов + `'\0'`) | Максимум: `"255.255.255.255"` = 15 символов |
| `sockaddr_in` | обычно 16 байт | Включает порт и семейство |
| `sockaddr_storage` | достаточно для любого семейства | Используется для универсальности |

### 4. Строковое представление

Если хранить адрес как строку в стиле C:

- Максимальная длина `"255.255.255.255"` — **15 символов**;
- С завершающим нулём — **16 байт**.

```cpp
char ip[] = "255.255.255.255";  // 16 байт с '\0'
```

Если использовать `std::string`, то добавляются накладные расходы самой строки (обычно 24–32 байта на объект в типичных реализациях, плюс динамическая память под содержимое).

## Итог

- **Минимум для хранения адреса IPv4 — 4 байта (32 бита).**
- При хранении в виде строки — до **16 байт**.
- В составе сетевых структур (`sockaddr_in`) — **4 байта** на адрес, но вся структура занимает ~16 байт.

На практике для эффективного хранения множества адресов (например, в таблицах маршрутизации или базах) используют именно 32-битное целое (`uint32_t`), что даёт 4 байта на запись.
