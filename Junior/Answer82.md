# 82. Явное и неявное приведение типов в C++

Приведение типов (type conversion) — это процесс преобразования значения одного типа в значение другого типа. В C++ преобразования делятся на **неявные** (выполняются компилятором автоматически) и **явные** (указываются программистом).

### Неявное приведение типов

Неявное преобразование происходит без явного указания оператора приведения. Компилятор выполняет его автоматически, когда это необходимо для согласования типов в выражении, при передаче аргументов в функцию, при инициализации переменных и в других контекстах.

Типичные случаи неявных преобразований:
- Арифметические преобразования (например, `int` → `double`, `float` → `int` с потерей дробной части).
- Преобразование указателя на производный класс в указатель на базовый класс (upcast) — безопасно и выполняется автоматически.
- Преобразование массива в указатель на его первый элемент.
- Вызов конструктора с одним аргументом (converting constructor) для создания объекта из значения другого типа.
- Вызов пользовательской функции преобразования (`operator T()`), если она не помечена как `explicit`.

**Проблема неявных преобразований** заключается в том, что компилятор может выполнить преобразование там, где программист этого не ожидал, что приводит к трудноуловимым ошибкам. Классический пример — неявное преобразование в `bool` и обратно, которое может сделать объект класса пригодным для использования в целочисленных контекстах, где он не должен применяться .

Начиная с C++11, ключевое слово `explicit` можно применять не только к конструкторам, но и к **функциям преобразования** (`explicit operator T()`), запрещая их использование в неявных преобразованиях .

### Явное приведение типов

Явное приведение (cast) указывается программистом и позволяет принудительно изменить тип выражения. В C++ существует два синтаксических подхода: **C-style cast** и **C++-style cast** (четыре специализированных оператора).

#### C-style cast: `(type)expression`

Унаследован от C. Обладает широкими возможностями, но небезопасен: компилятор пытается применить комбинацию `static_cast`, `const_cast` и `reinterpret_cast` в определённом порядке, выбирая первую подходящую операцию . Из-за отсутствия явного указания намерений автора и слабой проверки типов в современном C++ не рекомендуется.

#### Функциональная форма: `type(expression)`

Для встроенных типов эквивалентна C-style cast. Для пользовательских типов вызывает соответствующий конструктор. Например, `int(3.14)` эквивалентно `(int)3.14`, а `MyClass(42)` вызывает конструктор `MyClass(int)` .

## Функции явного приведения типов в C++

C++ предлагает четыре именованных оператора приведения, каждый из которых имеет строго определённое назначение и уровень безопасности.

### `static_cast<new_type>(expression)`

**Назначение:** преобразования, которые компилятор может проверить на этапе компиляции и которые логически обоснованы.

**Применение:**
- Преобразования между арифметическими типами (`double` → `int`, `int` → `double`).
- Преобразование `void*` в указатель на конкретный тип и обратно.
- Восходящее преобразование указателей/ссылок (производный → базовый).
- Нисходящее преобразование (базовый → производный), **но без проверки времени выполнения** — программист берёт ответственность на себя.
- Вызов явных конструкторов и явных операторов преобразования.

**Ограничение:** не может снимать квалификаторы `const`/`volatile` и не выполняет проверку типа во время выполнения. Если выполнить `static_cast` к производному типу для объекта, который на самом деле не является этим производным типом, поведение не определено .

```cpp
double d = 3.99;
int i = static_cast<int>(d);  // i == 3, дробная часть отбрасывается
```

### `dynamic_cast<new_type>(expression)`

**Назначение:** безопасное преобразование указателей и ссылок в иерархии наследования с проверкой во время выполнения.

**Применение:** только для полиморфных типов (классов, имеющих хотя бы одну виртуальную функцию). Используется преимущественно для нисходящего преобразования (downcast) и перекрёстных преобразований (crosscast).

**Поведение при неудаче:** для указателей возвращает `nullptr`; для ссылок генерирует исключение `std::bad_cast`. Это делает `dynamic_cast` предпочтительным инструментом, когда успех преобразования не гарантирован и требуется безопасная обработка ошибки .

```cpp
Base* basePtr = getObject();
Derived* derivedPtr = dynamic_cast<Derived*>(basePtr);
if (derivedPtr) {
    // преобразование успешно
}
```

### `const_cast<new_type>(expression)`

**Назначение:** единственный оператор, способный снимать или добавлять квалификаторы `const` и `volatile`.

**Применение:** используется в ситуациях, когда необходимо передать константный объект в функцию, которая по историческим причинам принимает неконстантный указатель, но гарантированно не модифицирует объект. Также применяется для перегрузки функций, различающихся только квалификатором `const`.

**Опасность:** модификация объекта, который изначально был объявлен как `const`, через снятый `const_cast` приводит к неопределённому поведению .

```cpp
void legacyFunction(char* str);  // не модифицирует str, но принимает char*

const char* msg = "hello";
legacyFunction(const_cast<char*>(msg));  // допустимо, если функция не пишет
```

### `reinterpret_cast<new_type>(expression)`

**Назначение:** низкоуровневая переинтерпретация битового представления. Не выполняет никаких проверок и преобразований значений.

**Применение:**
- Преобразование указателя в целочисленный тип и обратно.
- Преобразование между указателями на несвязанные типы.
- Работа с бинарными данными, сериализация, системное программирование.

**Опасность:** результат зависит от платформы и архитектуры. Использование `reinterpret_cast` без глубокого понимания представления данных в памяти легко приводит к неопределённому поведению. Это самый опасный из четырёх операторов, и его применение должно быть минимизировано .

```cpp
uintptr_t addr = reinterpret_cast<uintptr_t>(ptr);
```

### Сводная таблица

| Оператор | Проверка времени выполнения | Снятие `const` | Типичное применение |
|---|---|---|---|
| `static_cast` | Нет (только компиляция) | Нет | Арифметика, upcast, void* |
| `dynamic_cast` | Да | Нет | Безопасный downcast в полиморфной иерархии |
| `const_cast` | Нет | Да | Снятие/добавление `const`/`volatile` |
| `reinterpret_cast` | Нет | Нет | Низкоуровневая переинтерпретация битов |

В современном C++ рекомендуется отдавать предпочтение именованным операторам (`static_cast` и др.) вместо C-style cast, поскольку они явно выражают намерение программиста и позволяют компилятору и инструментам анализа кода выявлять потенциально опасные преобразования.
