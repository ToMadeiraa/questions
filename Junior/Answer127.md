# 127. Что такое сложность алгоритма и от чего она зависит?

## Определение

**Сложность алгоритма** — это характеристика, описывающая, как растут затраты ресурсов (времени выполнения или используемой памяти) при увеличении размера входных данных. Это способ оценить эффективность алгоритма независимо от конкретной машины, компилятора и прочих аппаратных деталей.

Сложность принято выражать **асимптотически** — через функцию от размера входа `n`, обычно с использованием **O-нотации** (big-O), которая описывает верхнюю границу роста.

Выделяют два основных вида сложности:

- **Временная сложность** (time complexity) — сколько операций выполнит алгоритм в зависимости от `n`.
- **Пространственная сложность** (space complexity) — сколько дополнительной памяти потребует алгоритм в зависимости от `n`.

## От чего зависит сложность

### 1. От количества входных данных (размера входа `n`)
Основной фактор. Сложность описывает именно **скорость роста** затрат при росте `n`, а не абсолютное время. Например, алгоритм O(n²) на малых входах может быть быстрее алгоритма O(n log n), но проигрывает на больших.

### 2. От выбранного алгоритма и его структуры
Разные алгоритмы решения одной задачи имеют разную сложность:
- Линейный поиск — O(n), бинарный поиск — O(log n);
- Пузырьковая сортировка — O(n²), быстрая сортировка — в среднем O(n log n);
- Наивное умножение матриц — O(n³), алгоритм Штрассена — O(n^2.81).

### 3. От структуры данных
Используемые структуры определяют стоимость операций:
- `std::vector` — доступ по индексу O(1), поиск O(n);
- `std::map` (красно-чёрное дерево) — поиск/вставка O(log n);
- `std::unordered_map` (хэш-таблица) — в среднем O(1), в худшем O(n).

### 4. От рассматриваемого случая
Для одного алгоритма различают:
- **лучший случай** (best case),
- **средний случай** (average case),
- **худший случай** (worst case).

Например, быстрая сортировка: средний случай O(n log n), худший (при неудачном выборе опорного элемента) — O(n²). Обычно указывают именно худший или средний случай.

### 5. От модели вычислений и аппаратуры (для практики)
Асимптотика абстрактна, но реальное время зависит от констант, кэш-эффектов, параллелизма. Два алгоритма с одинаковой O-оценкой могут работать по-разному на практике.

### 6. От объёма дополнительной памяти
Алгоритм может быть быстрым по времени, но требовать много памяти (например, сортировка слиянием — O(n) дополнительной памяти против O(1) у сортировки выбором).

## Основные классы сложности (по возрастанию роста)

| Обозначение | Название | Пример |
|---|---|---|
| O(1) | константная | доступ к элементу массива по индексу |
| O(log n) | логарифмическая | бинарный поиск |
| O(n) | линейная | линейный поиск, проход по массиву |
| O(n log n) | линейно-логарифмическая | сортировка слиянием, `std::sort` |
| O(n²) | квадратичная | пузырьковая сортировка, вложенные циклы |
| O(n³) | кубическая | наивное умножение матриц |
| O(2ⁿ) | экспоненциальная | перебор подмножеств, наивный Фибоначчи |
| O(n!) | факториальная | перебор перестановок (задача коммивояжёра) |

## Пример на C++

```cpp
#include <iostream>
#include <vector>

// O(n) — один проход по массиву
int sum(const std::vector<int>& v) {
    int s = 0;
    for (int x : v) s += x;
    return s;
}

// O(n^2) — вложенные циклы
bool hasDuplicates(const std::vector<int>& v) {
    for (size_t i = 0; i < v.size(); ++i)
        for (size_t j = i + 1; j < v.size(); ++j)
            if (v[i] == v[j]) return true;
    return false;
}

// O(log n) — бинарный поиск в отсортированном массиве
int binarySearch(const std::vector<int>& v, int target) {
    int lo = 0, hi = static_cast<int>(v.size()) - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (v[mid] == target) return mid;
        if (v[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

## Итог

Сложность алгоритма — это асимптотическая оценка роста затрат (времени и памяти) при увеличении размера входных данных. Она зависит прежде всего от:
- размера входа `n`;
- выбранного алгоритма и его логики;
- используемых структур данных;
- рассматриваемого случая (лучший/средний/худший);
- требований к дополнительной памяти.

Понимание сложности позволяет осознанно выбирать алгоритмы и структуры данных, а не полагаться только на «работает — и ладно».
