# Вопрос 2. Что такое сложность алгоритма?

> **Кратко:** сложность алгоритма — это оценка того, как растут затраты (время работы или дополнительная память) при увеличении размера входных данных `n`. Она описывает **асимптотическое** поведение, то есть рост при `n → ∞`, и позволяет сравнивать алгоритмы независимо от компьютера, компилятора и конкретных констант.

---

## Зачем это нужно

Два алгоритма, решающие одну задачу, могут отличаться радикально. При `n = 10^6` разница между `O(n^2)` и `O(n log n)` — это часы против долей секунды.

Оценка сложности позволяет:

- выбрать алгоритм и структуру данных **до** написания кода;
- понять, где узкое место и какой объём данных алгоритм «переварит»;
- объяснить, почему одно решение лучше другого, не прибегая к «у меня так быстрее».

---

## O-нотация

Формально `f(n) = O(g(n))`, если существуют константы `C > 0` и `n0`, такие что для всех `n ≥ n0` выполнено:

```
f(n) ≤ C · g(n)
```

То есть `g(n)` — **верхняя граница** роста с точностью до константы. O-нотация игнорирует:

- константные множители: `2n` и `100n` — это `O(n)`;
- младшие члены: `n^2 + n` — это `O(n^2)`.

**Родственные обозначения:**

| Обозначение | Смысл |
|---|---|
| `O(g(n))` | верхняя граница (не быстрее чем) |
| `Ω(g(n))` | нижняя граница (не медленнее чем) |
| `Θ(g(n))` | точная граница: и `O`, и `Ω` |
| `o(g(n))` | строго меньший рост |

---

## Классы сложности

| Класс | Название | Типичные примеры |
|---|---|---|
| `O(1)` | константная | доступ к элементу массива по индексу, вставка в хеш-таблицу (в среднем) |
| `O(log n)` | логарифмическая | бинарный поиск, операции в сбалансированном дереве (`std::map`), поиск в куче |
| `O(n)` | линейная | один проход по массиву, поиск максимума, `std::find` |
| `O(n log n)` | линейно-логарифмическая | сортировка слиянием, heapsort, `std::sort` (в среднем) |
| `O(n^2)` | квадратичная | пузырьковая/вставочная сортировка, двойной цикл по всем парам |
| `O(n^3)` | кубическая | наивное умножение матриц, Флойд–Уоршелл |
| `O(2^n)` | экспоненциальная | перебор подмножеств, наивная задача коммивояжёра |
| `O(n!)` | факториальная | перебор перестановок |

Порядок роста: `O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)`.

---

## Примеры на C++

**`O(1)` — доступ по индексу:**

```cpp
int x = v[i];
```

**`O(log n)` — бинарный поиск:**

```cpp
#include <cstddef>
#include <vector>

bool binarySearch(const std::vector<int>& v, int key) {
    std::size_t lo = 0, hi = v.size();
    while (lo < hi) {
        std::size_t mid = lo + (hi - lo) / 2;   // без переполнения
        if (v[mid] < key) lo = mid + 1;
        else              hi = mid;
    }
    return lo < v.size() && v[lo] == key;
}
```

**`O(n)` — один проход:**

```cpp
int sum(const std::vector<int>& v) {
    int s = 0;
    for (int x : v) s += x;
    return s;
}
```

**`O(n^2)` — все пары:**

```cpp
for (std::size_t i = 0; i < n; ++i)
    for (std::size_t j = i + 1; j < n; ++j)
        check(a[i], a[j]);
```

**`O(n log n)` — сортировка:**

```cpp
#include <algorithm>
std::sort(v.begin(), v.end());
```

## Время и память

Говорят отдельно о **временной** сложности (число операций) и **пространственной** (объём дополнительной памяти).

| Алгоритм | Время | Память |
|---|---|---|
| Сортировка слиянием | `O(n log n)` | `O(n)` |
| Heapsort | `O(n log n)` | `O(1)` (in-place) |
| Быстрая сортировка | `O(n log n)` в среднем, `O(n^2)` в худшем | `O(log n)` на стек рекурсии |

Рекурсивные алгоритмы тратят память на стек вызовов: глубина рекурсии — тоже часть пространственной сложности. Например, наивная рекурсивная реализация Фибоначчи — `O(2^n)` по времени и `O(n)` по памяти стека.

---

## Худший, средний и лучший случай

| Случай | Что означает | Когда важен |
|---|---|---|
| **Худший** (worst case) | гарантия сверху | системы реального времени, оценка «не залипнет ли» |
| **Средний** (average) | усреднение по распределению входов | типичная практика, но требует предположений о данных |
| **Лучший** (best case) | минимальные затраты | обычно малоинтересен, полезен для понимания поведения |

Классический пример: у quicksort худший случай `O(n^2)`, средний — `O(n log n)`. У вставочной сортировки лучший случай — `O(n)` на почти отсортированном массиве, худший — `O(n^2)`.

---

## Амортизированная сложность

Это средняя стоимость операции в **последовательности** операций, даже если отдельная операция может быть дорогой.

Классический пример — `push_back` у `std::vector`:

- обычно `O(1)`;
- при перевыделении — `O(n)` (копирование/перемещение всех элементов);
- **амортизированно** — `O(1)`, потому что дорогие перевыделения случаются всё реже (ёмкость растёт геометрически).

Так же работают операции с `std::string` и хеш-таблицами при rehash.

> **Важно:** амортизированная `O(1)` не означает «каждый вызов быстрый». Она означает, что в среднем на длинной серии вызовов стоимость на операцию ограничена константой.

---

## Как оценивать сложность на практике

1. Понять, какие операции считаются элементарными, и сколько раз они выполняются в зависимости от `n`.
2. Для циклов — перемножить число итераций; для вложенных — перемножить глубины.
3. Для рекурсии — записать рекуррентное соотношение:

```
T(n) = 2·T(n/2) + O(n)   →  O(n log n)   (merge sort)
T(n) = T(n-1) + O(1)     →  O(n)
T(n) = 2·T(n-1) + O(1)   →  O(2^n)
```

4. Отбросить константы и младшие члены.
5. Учесть вложенные структуры: поиск в `std::map` — `O(log n)`, но если внутри ещё и обход — сложности перемножаются.

## Сложность операций контейнеров (для практики)

| Операция | `vector` | `list` | `map` / `set` | `unordered_map` |
|---|---|---|---|---|
| Доступ по индексу | `O(1)` | `O(n)` | — | — |
| Поиск | `O(n)` | `O(n)` | `O(log n)` | `O(1)` в среднем, `O(n)` в худшем |
| Вставка в конец | амортиз. `O(1)` | `O(1)` | `O(log n)` | `O(1)` в среднем |
| Вставка в середину | `O(n)` | `O(1)` по итератору | `O(log n)` | — |
| Удаление | `O(n)` | `O(1)` по итератору | `O(log n)` | `O(1)` в среднем |

> «Сложность контейнера» без указания операции бессмысленна: у `vector` доступ `O(1)`, а вставка в середину — `O(n)`.

## Важные оговорки

- **Асимптотика не учитывает константы и кэш.** При небольших `n` линейный алгоритм с большим коэффициентом может проигрывать «плохому» асимптотически, но с малой константой. Поэтому на практике важны и профилирование, и локальность данных.
- **O-нотация по умолчанию — про худший случай**, но для хеш-таблиц обычно называют средний `O(1)`, а худший — `O(n)` при коллизиях.
- **Сложность зависит от операции** и от того, что считать «единицей работы» (сравнение, обращение к памяти, байт).
- **Память тоже ресурс:** алгоритм `O(n log n)` с `O(n)` дополнительной памяти может быть неприемлем там, где нужен in-place.

---

## Типичные ошибки

1. **Путать `O` с точным временем.** «`O(n)` быстрее `O(n^2)`» верно асимптотически, но не обязательно для конкретного `n = 10`.
2. **Забывать про память** и стек рекурсии: алгоритм может быть быстрым, но съесть всю память.
3. **Считать `O(n^2)` и `O(n^2 + n)` разными классами** — это одно и то же.
4. **Игнорировать амортизацию** и считать `push_back` всегда `O(1)` без оговорки.
5. **Забывать про худший случай хеш-таблиц** (`O(n)` при коллизиях) и про то, что `unordered_map` в среднем быстрее, но не гарантирует порядок.
6. **Говорить «vector быстрее list» без контекста** — зависит от операции, размера и паттерна доступа.
7. **Считать сложность по строкам кода**, а не по числу выполненных операций.

---

## Что добавить на собеседовании

- O-нотация — это про **рост**, а не про секунды; на практике её дополняют профилированием и замерами.
- Полезно помнить типичные ловушки: `std::map` — `O(log n)`, `std::unordered_map` — `O(1)` в среднем, но с худшим `O(n)`; `std::vector::push_back` — амортизированно `O(1)`.
- Хороший ответ показывает связь теории с практикой: «Я выбираю контейнер по сложности операций, которые в горячем пути, а потом проверяю профилировщиком — иногда кэш и аллокации важнее асимптотики».
- Можно упомянуть, что для реальных задач важны также константы, локальность данных и стоимость аллокаций.

## Итог

| Понятие | Суть |
|---|---|
| Сложность | Оценка роста затрат при росте `n` |
| `O(g(n))` | Верхняя граница роста с точностью до константы |
| Временная / пространственная | Операции / дополнительная память |
| Худший / средний / лучший | Гарантия / типичный случай / оптимистичный случай |
| Амортизированная | Средняя стоимость на серию операций |
| Практика | Асимптотика + константы + кэш + профилирование |
