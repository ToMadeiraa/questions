# 104. Наследование от класса без виртуального конструктора

## Краткий ответ

**Ничего страшного не произойдёт**: в C++ конструкторы **не могут быть виртуальными** в принципе. Поэтому формулировка «базовый класс не имеет виртуального конструктора» применима к *любому* классу — виртуальных конструкторов в языке просто не существует. Наследоваться от такого класса можно совершенно нормально.

## Почему конструкторы не бывают виртуальными

Виртуальный вызов возможен только тогда, когда объект уже существует и у него есть vptr (указатель на таблицу виртуальных функций). Но конструктор как раз и **создаёт** объект — на момент его вызова объекта ещё нет, а значит, и динамический тип неизвестен. Поэтому язык запрещает объявлять конструкторы `virtual`.

```cpp
class Base {
public:
    virtual Base(); // ошибка компиляции: конструктор не может быть виртуальным
};
```

## Что обычно имеют в виду под этим вопросом

Скорее всего, вопрос про **виртуальный деструктор**. Это классическая ловушка, и вот здесь последствия реальны и серьёзны.

### Проблема: удаление через указатель на базовый класс

```cpp
class Base {
public:
    Base()  { std::cout << "Base ctor\n"; }
    ~Base() { std::cout << "Base dtor\n"; }  // НЕ виртуальный!
};

class Derived : public Base {
public:
    Derived() { std::cout << "Derived ctor\n"; }
    ~Derived() { std::cout << "Derived dtor\n"; }  // не будет вызван!
};

int main() {
    Base* p = new Derived();
    delete p;   // НЕОПРЕДЕЛЁННОЕ ПОВЕДЕНИЕ
}
```

**Что произойдёт:** вызовется только `~Base()`, а `~Derived()` — **нет**. Если в `Derived` есть ресурсы (динамическая память, файлы, дескрипторы), они не освободятся → **утечка ресурсов**. Формально это **неопределённое поведение** (UB).

### Правило

> Если класс предназначен для полиморфного использования (удаление через указатель/ссылку на базовый класс), его деструктор **должен быть виртуальным**.

```cpp
class Base {
public:
    virtual ~Base() = default;   // правильно
};
```

После этого `delete p;` корректно вызовет `~Derived()`, а затем `~Base()`.

## А если базовый класс не предполагает полиморфного удаления?

Если вы **не** собираетесь удалять объекты производных классов через указатель на базу, виртуальный деструктор не обязателен. Но добавлять его полезно, если класс задуман как основа для наследования, — цена невелика (одна запись в vtable).

Также напомню: **виртуальный деструктор не делает класс абстрактным**. Если нужен абстрактный базовый класс, используйте чистый виртуальный деструктор:

```cpp
class Base {
public:
    virtual ~Base() = 0;   // чисто виртуальный деструктор
};
Base::~Base() = default;   // определение всё равно обязательно
```

## Итог

| Что имелось в виду | Последствия |
|---|---|
| «Конструктор не виртуальный» | Ничего: виртуальных конструкторов в C++ не бывает, наследование работает штатно |
| «Деструктор не виртуальный» + удаление через указатель на базу | UB, не вызывается деструктор наследника, утечки ресурсов |
| «Деструктор не виртуальный», но удаление по конкретному типу | Всё корректно, проблемы нет |

**Вывод:** наследоваться от класса без виртуального конструктора можно всегда — это норма. Следите лишь за тем, чтобы у базового класса был **виртуальный деструктор**, если объекты предполагается удалять полиморфно.
