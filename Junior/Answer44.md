# Вопрос 44. Какая разница между calloc и malloc?

> **Кратко:** `malloc(n)` выделяет `n` байт **неинициализированной** памяти, а `calloc(nmemb, size)` — `nmemb * size` байт, **обнулённых** побайтово. Обе функции берут память из одной кучи, возвращают `void*` либо `NULL` и освобождаются через `free`. Разница не только в обнулении: `calloc` сам перемножает аргументы с проверкой переполнения и для больших блоков нередко получает уже нулевые страницы от ОС, поэтому связка `malloc` + `memset` далеко не всегда быстрее.

---

## Сигнатуры и общий контракт

```cpp
#include <cstddef>
#include <cstdlib>

void* std::malloc(std::size_t size);                     // ровно size байт
void* std::calloc(std::size_t nmemb, std::size_t size);  // nmemb * size байт, нули
void* std::realloc(void* ptr, std::size_t newSize);
void  std::free(void* ptr);
```

Общее у `malloc` и `calloc`:

- обе возвращают указатель, выровненный под любой тип (`alignof(std::max_align_t)`), либо `nullptr` при неудаче;
- память берётся из одного аллокатора, поэтому `realloc` и `free` работают с блоками от любой из них;
- конструкторы не вызываются: для типа с нетривиальным конструктором нужен `new` или placement new;
- в C++ `void*` не преобразуется к `T*` неявно — нужен `static_cast`; в C приведение не требуется.

---

## Главное различие

| Свойство | `malloc` | `calloc` |
|---|---|---|
| Аргументы | один: число байт | два: элементов × размер |
| Содержимое | не инициализировано | все биты нулевые |
| Проверка переполнения | нет | есть |
| Типичное применение | буфер, в который сразу пишут | массивы, таблицы, «пустые» структуры |
| Освобождение | `free` | `free` |

---

## Зачем у calloc два аргумента

Разделение на `nmemb` и `size` существует, чтобы функция сама перемножила их и проверила переполнение: `calloc(SIZE_MAX, 4)` не должен вернуть крошечный блок — POSIX требует здесь `NULL`, и распространённые реализации (glibc, musl) произведение проверяют. У `malloc` такой возможности нет: он получает уже посчитанный размер, и переполнение происходит ещё до вызова — классическая уязвимость.

```cpp
#include <cstddef>
#include <cstdlib>
#include <limits>

void allocate(std::size_t n) {
    // Плохо: произведение может переполниться, и мы получим маленький блок
    // int* bad = static_cast<int*>(std::malloc(n * sizeof(int)));

    // Хорошо: произведение считает calloc и сам проверяет переполнение
    int* ok = static_cast<int*>(std::calloc(n, sizeof(int)));
    if (!ok) return;                 // n == 0 или не хватило памяти

    // Хорошо: ручная проверка, если нужен именно malloc
    if (n > std::numeric_limits<std::size_t>::max() / sizeof(int)) {
        std::free(ok);
        return;                      // переполнение при умножении
    }
    int* raw = static_cast<int*>(std::malloc(n * sizeof(int)));
    if (!raw) {
        std::free(ok);
        return;
    }

    std::free(ok);
    std::free(raw);
}
```

## Обнуление: кто и за что платит

`calloc` не всегда платит за полноценный `memset`:

- крупный запрос аллокатор обычно обслуживает свежими страницами (`mmap`), а они по определению нулевые — обнулять нечего, экономия ещё и на страницах, которые никогда не будут затронуты;
- маленький блок из повторно используемой арены уже содержит мусор, и `calloc` честно вызывает `memset` — здесь `malloc` + `memset` стоит примерно столько же.

```cpp
#include <cstddef>
#include <cstdlib>
#include <cstring>

void fill(std::size_t n) {
    // нули сразу, без отдельного memset
    int* zeroed = static_cast<int*>(std::calloc(n, sizeof(int)));
    if (!zeroed) return;

    // мусор: читать до записи нельзя
    int* raw = static_cast<int*>(std::malloc(n * sizeof(int)));
    if (!raw) {
        std::free(zeroed);
        return;
    }
    std::memset(raw, 0, n * sizeof(int));   // та же семантика, но платим всегда

    std::free(zeroed);
    std::free(raw);
}
```

---

## Что именно означает «нули»

`calloc` обнуляет **биты**, а не значения:

- для `double` это `0.0` только на платформах с IEEE-754, то есть практически везде;
- для указателей стандарт C не гарантирует, что «все биты нули» — это нулевой указатель, хотя при плоской адресации это так;
- для структур обнуляются и байты выравнивания (padding), поэтому `memcmp` двух `calloc`-объектов с одинаковыми полями даст равенство.

Практический вывод: переносимо полагаться на нули можно для целочисленных типов; для остального нужна либо проверенная платформа, либо явная инициализация.

---

## Крайние случаи

- `malloc(0)` может вернуть `NULL` или уникальный указатель, который допустимо передать в `free`. Оба поведения законны, поэтому трактовать `NULL` как ошибку при нулевом размере нельзя.
- `calloc(0, n)` и `calloc(n, 0)` — та же история: `NULL` либо уникальный указатель.
- `calloc(sizeof(T), n)` формально эквивалентен `calloc(n, sizeof(T))`, но читается как «сколько байт × сколько раз» и путает на ревью.
- При нехватке памяти возвращается `NULL`, а в POSIX выставляется `errno = ENOMEM`; исключений эти функции не бросают.

## Что использовать в C++

| C | C++ |
|---|---|
| `malloc(n * sizeof(T))` | `std::vector<T> v(n);` |
| `calloc(n, sizeof(T))` | `std::vector<T> v(n, T{});` |
| `malloc` + `free` | `std::make_unique<T[]>(n)` |
| `realloc` | `std::vector::reserve` + `push_back` |

```cpp
#include <memory>
#include <string>
#include <vector>

void cppWay(std::size_t n) {
    std::vector<int> v(n);                  // n нулей, память освободится сама
    auto arr = std::make_unique<int[]>(n);  // value-initialization: тоже нули
    std::string s(n, '\0');                 // n нулевых символов

    (void)v; (void)arr; (void)s;
}
```

`malloc` и `calloc` остаются нужны в двух случаях: обёртки над C-библиотеками, которые освобождают память сами через `free`, и код, где требуется именно «сырая» память без конструкторов (например, собственный пул или арена).

## Типичные ошибки

1. **Не проверять `NULL`** — для больших запросов отказ вполне реален.
2. **`memset` после `calloc`** — двойная работа и лишние обращения к памяти.
3. **`malloc(n * sizeof(T))` без проверки переполнения** — молчаливый короткий блок и запись за его границу.
4. **Считать, что `calloc` переносимо гарантирует нулевые указатели и `0.0`**.
5. **Двойной `free`, `free` середины блока, утечка** — аллокатор этого не прощает.
6. **Смешивать семейства:** `new` + `free` или `malloc` + `delete` — UB.
7. **Читать память `malloc` до записи** — для нетривиальных типов там вообще нет объекта.
8. **Трактовать `malloc(0) == NULL` как ошибку** — нулевой размер не является отказом.

---

## Что добавить на собеседовании

- `calloc` — это «выделить и обнулить» одной операцией, причём для больших массивов обнуление может быть бесплатным за счёт нулевых страниц ОС; это неочевидный, но верный аргумент в пользу `calloc`.
- Проверка переполнения произведения — реальная причина предпочесть `calloc`, когда размеры приходят извне (парсинг файла, сетевой протокол).
- Ни `malloc`, ни `calloc` не создают объекты C++: они дают память, а не время жизни; для нетривиального типа это UB, а не «просто не вызвался конструктор».
- В современном C++ сырые аллокации вытеснены контейнерами и умными указателями, а `malloc` остаётся на границе с C API.

---

## Итог

| Критерий | `malloc` | `calloc` |
|---|---|---|
| Что делает | выделяет `size` байт | выделяет `nmemb * size` байт и обнуляет |
| Содержимое | мусор | побайтовые нули |
| Переполнение | не проверяет | проверяет произведение |
| Стоимость | только выделение | выделение плюс обнуление (иногда бесплатно) |
| Когда выбирать | буфер под немедленную запись | массив, таблица, счётчики, флаги |
| Освобождение | `free` | `free` |
