# 129. Разница между `std::set`, `std::map` и `std::unordered_multimap`

`std::set`, `std::map` и `std::unordered_multimap` — это три разных ассоциативных контейнера в C++. Их ключевые различия сводятся к трём вопросам: **что хранится** (ключ или пара ключ-значение), **упорядочены ли элементы** (красно-чёрное дерево или хеш-таблица) и **уникальны ли ключи** (допускаются ли повторяющиеся ключи).

### Сравнение основных характеристик

| Характеристика | `std::set` | `std::map` | `std::unordered_multimap` |
| :--- | :--- | :--- | :--- |
| **Что хранит** | Только **ключи** (Key) | **Пары ключ-значение** (Key-Value) | **Пары ключ-значение** (Key-Value) |
| **Внутренняя реализация** | Сбалансированное двоичное дерево поиска (обычно красно-чёрное) | Сбалансированное двоичное дерево поиска (обычно красно-чёрное) | Хеш-таблица (Hash Table) |
| **Упорядоченность ключей** | **Упорядочены** (по умолчанию по возрастанию) | **Упорядочены** (по умолчанию по возрастанию ключа) | **Не упорядочены** (зависит от хеш-функции) |
| **Уникальность ключей** | **Уникальные** (повторы запрещены) | **Уникальные** (повторы запрещены) | **Не уникальные** (допускаются несколько одинаковых ключей) |
| **Сложность доступа** | Логарифмическая O(log n) | Логарифмическая O(log n) | В среднем константная O(1), в худшем случае O(n) |

### Подробный разбор

**1. `std::set` — множество, содержащее только ключи**

`std::set` можно понимать как математическое множество. Его интересует только «есть элемент или нет», а не то, какое значение с ним связано. Поскольку в основе лежит красно-чёрное дерево, при вставке элементы автоматически упорядочиваются по возрастанию. Если нужно убрать дубликаты и сохранить порядок (например, запомнить уже посещённые ID), это лучший выбор. Контейнер не поддерживает обращение по индексу `[]`, как `map`, потому что хранить значение негде.

**2. `std::map` — упорядоченный словарь**

`std::map` — самый часто используемый ассоциативный контейнер. Он хранит `std::pair<const Key, T>`. Ключи уникальны и упорядочены. Благодаря упорядоченности можно эффективно выполнять поиск по диапазону (например, найти все элементы с ключом от 10 до 20). Поддерживается `operator[]`, но нужно помнить: если ключа нет, `[]` по умолчанию вставит новый элемент (значение инициализируется по умолчанию), а метод `at()` при отсутствии ключа выбрасывает исключение.

**3. `std::unordered_multimap` — неупорядоченный словарь с повторяющимися ключами**

Название содержит три характеристики:
*   **unordered** — в основе лежит хеш-таблица, элементы не сортируются. Поиск обычно быстрее, чем в `map` (в среднем O(1)), но теряется упорядоченность, поэтому поиск по диапазону невозможен.
*   **multi** — допускается несколько одинаковых ключей. Например, можно хранить одного автора и несколько его книг (ключ — имя автора, значение — название книги).
*   Поскольку ключи могут повторяться, контейнер **не поддерживает** `operator[]` (непонятно, какое значение возвращать по индексу); обычно используется `equal_range` для получения всех значений, соответствующих ключу.

### Как выбрать

*   Если нужно только **убрать дубликаты** и **важен порядок**: используйте `std::set`.
*   Если нужно **находить значение по ключу** и **важен порядок** (или нужен поиск по диапазону): используйте `std::map`.
*   Если нужно **находить значение по ключу**, **порядок не важен**, **допускается несколько значений для одного ключа** и важна **средняя скорость поиска**: используйте `std::unordered_multimap`.
