# Вопрос 40. Что такое алгоритмы сортировки и какие вы знаете?

> **Кратко:** сортировка — это перестановка элементов в порядке, заданном отношением порядка, за минимальное число сравнений и перемещений. Алгоритмы делятся на квадратичные (вставками, обменом, выбором), гарантирующие `O(n log n)` (слиянием, быстрая, пирамидальная), линейные при целочисленных ключах (подсчётом, поразрядная) и гибридные, которые применяет стандартная библиотека. Выбирают их по четырём критериям: сложность в худшем случае, устойчивость, дополнительная память и поведение на почти отсортированных данных.

---

## Свойства, по которым сравнивают сортировки

| Свойство | Что означает | Почему важно |
|---|---|---|
| Сложность | рост числа сравнений и перемещений от `n` | определяет применимость на больших данных |
| Устойчивость | равные элементы сохраняют взаимный порядок | обязательна при сортировке по нескольким ключам |
| In-place | дополнительная память `O(1)` или `O(log n)` | важно при жёстком лимите памяти |
| Адаптивность | быстрее на почти упорядоченных данных | типичный реальный случай |

---

## Классификация

| Группа | Идея | Представители |
|---|---|---|
| Вставками | элемент вставляется в упорядоченный префикс | insertion sort, Shell sort |
| Обменом | меняются местами стоящие не в порядке пары | bubble sort, quicksort |
| Выбором | из неотсортированной части берётся минимум | selection sort, heapsort |
| Слиянием | половины сортируются и сливаются | merge sort, Timsort |
| Распределением | раскладка по карманам без сравнений | counting, radix, bucket sort |
| Гибриды | переключение стратегий по размеру и глубине | introsort (`std::sort`), pdqsort |

---

## Сводка сложностей

| Алгоритм | Лучшее | Среднее | Худшее | Память | Устойчив |
|---|---|---|---|---|---|
| Вставками | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | да |
| Пузырьком | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | да |
| Выбором | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | нет |
| Слиянием | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | да |
| Быстрая | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(log n)` стек | нет |
| Пирамидальная | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | нет |
| Подсчётом | `O(n + k)` | `O(n + k)` | `O(n + k)` | `O(n + k)` | да |
| Поразрядная | `O(d(n + k))` | `O(d(n + k))` | `O(d(n + k))` | `O(n + k)` | да |

`k` — диапазон ключей, `d` — число разрядов. Лучшее `O(n)` у пузырьковой сортировки достигается только с флагом «обменов не было».

## Квадратичные сортировки

**Вставками** — единственная из квадратичных, которую имеет смысл применять: она устойчива, адаптивна и на массивах в десятки элементов обгоняет «умные» алгоритмы. Именно её используют как базовый случай в гибридах. Во всех примерах ниже предполагаются `<algorithm>`, `<iterator>` и `<vector>`.

```cpp
template <class It>
void insertionSort(It first, It last) {
    for (It i = first; i != last; ++i)
        // сдвигаем влево, пока элемент строго меньше предыдущего:
        // нестрогое сравнение сломало бы устойчивость
        for (It j = i; j != first && *j < *(j - 1); --j)
            std::iter_swap(j, j - 1);
}
```

**Выбором** делает ровно `n - 1` обмен, что полезно при дорогом перемещении элемента, но она неустойчива. **Пузырьком** — учебный пример: `O(n²)` обменов, в рабочем коде не применяется.

## Сортировка слиянием

Делим массив пополам, сортируем половины, сливаем. Гарантированные `O(n log n)` при любых входных данных и устойчивость — главные достоинства; цена — `O(n)` дополнительной памяти.

```cpp
template <class It>
void mergeSort(It first, It last) {
    using T = typename std::iterator_traits<It>::value_type;
    const auto n = std::distance(first, last);
    if (n < 2) return;

    const auto mid = std::next(first, n / 2);
    mergeSort(first, mid);
    mergeSort(mid, last);

    std::vector<T> merged;                  // буфер на один уровень рекурсии
    merged.reserve(static_cast<std::size_t>(n));
    std::merge(first, mid, mid, last, std::back_inserter(merged));  // std::merge устойчив
    std::move(merged.begin(), merged.end(), first);
}
```

## Быстрая сортировка

Выбираем опорный элемент, разбиением ставим меньшие слева, большие справа, рекурсивно сортируем части. В среднем `O(n log n)` с малой константой и хорошей локальностью, в худшем — `O(n²)`.

```cpp
template <class It>
void quickSort(It first, It last) {
    while (std::distance(first, last) > 1) {
        // опорный — средний элемент: защита от вырождения на упорядоченных данных
        std::iter_swap(first + std::distance(first, last) / 2, last - 1);
        const auto pivot = *(last - 1);
        It less = first;                     // граница элементов, меньших pivot
        for (It it = first; it != last - 1; ++it)
            if (*it < pivot) std::iter_swap(it, less++);
        std::iter_swap(less, last - 1);      // pivot на окончательное место

        // рекурсия в меньшую часть, цикл в большую: глубина стека O(log n)
        if (std::distance(first, less) < std::distance(less + 1, last)) {
            quickSort(first, less);   first = less + 1;
        } else {
            quickSort(less + 1, last); last = less;
        }
    }
}
```

Разбиение Хоара (два встречных индекса) делает в среднем втрое меньше обменов, чем приведённое разбиение Ломуто. Против худшего случая применяют случайный выбор опорного и переключение на другую сортировку при глубокой рекурсии.

---

## Пирамидальная сортировка

Строим двоичную кучу максимумов за `O(n)`, затем `n` раз меняем корень с последним элементом и восстанавливаем кучу за `O(log n)`. Итог — гарантированные `O(n log n)` и `O(1)` памяти, но плохая локальность и неустойчивость. В C++ готовая реализация — `std::make_heap` плюс `std::sort_heap`.

Именно heapsort служит страховкой в introsort: если глубина рекурсии quicksort превысила `2·log₂n`, переключаются на неё и сохраняют гарантию `O(n log n)`.

## Линейные сортировки (без сравнений)

Если ключ — целое число из диапазона `[0, k)`, сравнивать не нужно: считаем частоты и восстанавливаем порядок.

```cpp
std::vector<int> countingSort(const std::vector<int>& v, int maxKey) {
    std::vector<std::size_t> cnt(static_cast<std::size_t>(maxKey) + 1, 0);
    for (int x : v) ++cnt[static_cast<std::size_t>(x)];
    for (std::size_t i = 1; i < cnt.size(); ++i)
        cnt[i] += cnt[i - 1];              // cnt[x] — сколько элементов ≤ x
    std::vector<int> out(v.size());
    for (auto it = v.rbegin(); it != v.rend(); ++it)  // с конца — ради устойчивости
        out[--cnt[static_cast<std::size_t>(*it)]] = *it;
    return out;
}
```

**Поразрядная сортировка** применяет устойчивый подсчёт по каждому разряду: `d` проходов, итого `O(d(n + k))`. Для 32-битных чисел при основании 256 это 4 прохода, и на больших массивах она обгоняет `std::sort`. **Карманная** распределяет элементы по диапазонам и сортирует каждый карман — выгодна при равномерном распределении.

---

## Что даёт стандартная библиотека C++

| Задача | Средство | Сложность |
|---|---|---|
| Полная сортировка | `std::sort` | `O(N log N)` сравнений (гарантия с C++11) |
| Устойчивая сортировка | `std::stable_sort` | `O(N log N)`, при нехватке памяти `O(N log²N)` |
| Первые `k` элементов | `std::partial_sort` | `O(N log k)` |
| `k`-й элемент на месте | `std::nth_element` | `O(N)` в среднем |
| Сортировка списка | `std::list::sort` | `O(N log N)`, устойчива |
| Проверка порядка | `std::is_sorted` | `O(N)` |

---

## Нижняя граница для сортировок сравнениями

Алгоритм на сравнениях описывается деревом решений: `n!` перестановок требуют не менее `log₂(n!) = Θ(n log n)` сравнений в худшем случае. Линейные сортировки обходят барьер только потому, что используют структуру ключа — его числовое значение, а не результат сравнения.

---

## Типичные ошибки

1. **Нестрогий компаратор** (`<=`, вычитание со знаком) — нарушение строгого слабого порядка, undefined behavior.
2. **`std::sort` для `std::list`** — нет итераторов произвольного доступа, нужен `list::sort`.
3. **Ожидание устойчивости от `std::sort`** — она не гарантирована, нужен `std::stable_sort`.
4. **Переполнение в компараторе** вида `return a.x - b.x < 0` на больших значениях.
5. **Сортировка «тяжёлых» объектов по значению** вместо массива индексов или указателей.
6. **Игнорирование почти отсортированных данных** — здесь адаптивные алгоритмы дают кратный выигрыш.

---

## Что добавить на собеседовании

- Разделять «знаю алгоритмы» и «умею выбрать»: в большинстве случаев нужен `std::sort`, а `std::stable_sort` или `std::nth_element` — под конкретное требование.
- Понимать, что `std::sort` — это introsort: quicksort, переключение на heapsort при глубокой рекурсии и insertion sort на малых отрезках.
- Называть реальные критерии: устойчивость, память, адаптивность, локальность данных, стоимость перемещения элементов; уметь объяснить нижнюю границу `Ω(n log n)`.

## Итог

| Алгоритм | Когда применять |
|---|---|
| Вставками | маленькие массивы, почти отсортированные данные, база гибридов |
| Выбором | критично число обменов, устойчивость не нужна |
| Слиянием | нужна устойчивость или гарантия `O(n log n)`; списки и внешняя сортировка |
| Быстрая | универсальный выбор по скорости и памяти, основа `std::sort` |
| Пирамидальная | нужна гарантия `O(n log n)` при `O(1)` памяти |
| Подсчётом | целые ключи в узком диапазоне |
| Поразрядная | целые ключи фиксированной длины, большие `n` |
| `std::sort` / `std::stable_sort` | практический дефолт в C++; ручная реализация нужна редко |
