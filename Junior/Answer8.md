# Вопрос 8. Что такое Unicode?

> **Кратко:** Unicode — международный стандарт кодирования текста, который сопоставляет **каждому символу всех письменностей мира** уникальный номер — кодовую точку. Сам по себе он не задаёт способ хранения в байтах: для этого служат кодировки UTF-8, UTF-16 и UTF-32. Стандарт также определяет свойства символов и алгоритмы (нормализация, сортировка, двунаправленный текст).

---

## 1. Проблема, которую он решает

До Unicode каждая страна жила со своими 8-битными кодовыми страницами (CP1251, CP866, KOI8-R, Shift-JIS, GB2312). Следствия:

- один и тот же текст нельзя было корректно совместить с текстом на другом языке, а 256 кодов мало для иероглифов (только CJK требует десятков тысяч);
- не было единого способа представить эмодзи, математические символы, исторические письменности.

Unicode вводит **единое пространство кодов**, в котором помещаются все языки одновременно, а кодировки UTF-* задают лишь форму хранения этих кодов в байтах.

---

## 2. Три разных понятия

Их постоянно путают, и это первое, что стоит развести:

| Понятие | Что это | Пример |
|---|---|---|
| **Набор символов** (character set) | какие символы существуют | Unicode, ASCII |
| **Кодовая точка** (code point) | номер символа в наборе | `U+0416` — «Ж» |
| **Кодировка** (encoding) | как номер записать в байтах | UTF-8: `0xD0 0x96` |

`U+0416` — это запись кодовой точки в hex. Символ «Ж» в UTF-8 занимает 2 байта, в UTF-16 — 2 байта, в UTF-32 — 4 байта. Кодовая точка одна и та же.

---

## 3. Пространство кодов

Диапазон допустимых значений — `U+0000..U+10FFFF`, всего **1 114 112** позиций, разбитых на 17 плоскостей по 65 536:

| Плоскость | Диапазон | Содержимое |
|---|---|---|
| 0 (BMP) | `U+0000..U+FFFF` | латиница, кириллица, греческий, CJK, пунктуация |
| 1 (SMP) | `U+10000..U+1FFFF` | эмодзи, исторические письменности, музыка |
| 2 (SIP) | `U+20000..U+2FFFF` | дополнительные иероглифы CJK |
| 14 (SSP) | `U+E0000..U+EFFFF` | теги, variation selectors |
| 15..16 | `U+F0000..U+10FFFF` | private use areas |

Диапазон `U+D800..U+DFFF` (2 048 позиций) — **суррогаты**: они зарезервированы под UTF-16 и символов не кодируют; плоскости 3–13 не назначены. Всего назначено около 150 тысяч символов.

**Подмножества:** `U+0000..U+007F` — ровно ASCII (Basic Latin), `U+0080..U+00FF` — Latin-1 Supplement.

---

## 4. Кодировки

| Кодировка | Единица | Размер символа | ASCII-совместима | Типичное применение |
|---|---|---|---|---|
| **UTF-8** | байт | 1–4 байта | да | веб, Linux, файлы, сети |
| **UTF-16** | 16-битное слово | 2 или 4 байта | нет | Windows API, Java, .NET |
| **UTF-32** | 32-битное слово | всегда 4 байта | нет | внутренняя обработка, ICU |

**UTF-8** — победитель по распространённости. Шаблоны байтов:

| Кодовая точка | Байты | Шаблон |
|---|---|---|
| `U+0000..U+007F` | 1 | `0xxxxxxx` |
| `U+0080..U+07FF` | 2 | `110xxxxx 10xxxxxx` |
| `U+0800..U+FFFF` | 3 | `1110xxxx 10xxxxxx 10xxxxxx` |
| `U+10000..U+10FFFF` | 4 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

Свойства UTF-8, за которые его любят:

- ASCII-совместимость: чистый латинский текст — те же байты, что и в ASCII, а внутри многобайтовой последовательности нет `0x00`, поэтому C-строки и `std::string` работают без изменений;
- самосинхронизация: любой байт `10xxxxxx` — продолжение, поиск можно начинать с любого места;
- побайтовое сравнение строк даёт тот же порядок, что и сравнение по кодовым точкам;
- **перекодирование из UTF-16 невозможно «наивно»**: суррогатная пара `D800..DFFF` в UTF-8 запрещена, а избыточные (overlong) формы недопустимы.

**UTF-16** кодирует BMP одним словом, остальное — парой суррогатов: `cp - 0x10000`, старший `0xD800 + (x >> 10)`, младший `0xDC00 + (x & 0x3FF)`.

## 5. Разбор UTF-8 в коде

```cpp
#include <cstddef>
#include <string_view>

// Длина UTF-8-последовательности по ведущему байту; 0 — невалидный байт.
std::size_t utf8Length(unsigned char lead) {
    if (lead < 0x80)           return 1;   // 0xxxxxxx
    if ((lead & 0xE0) == 0xC0) return 2;   // 110xxxxx
    if ((lead & 0xF0) == 0xE0) return 3;   // 1110xxxx
    if ((lead & 0xF8) == 0xF0) return 4;   // 11110xxx
    return 0;                              // 10xxxxxx и 11111xxx — ошибка
}

// Число кодовых точек в строке, а не байт и не «символов» на экране.
std::size_t codePointCount(std::string_view s) {
    std::size_t count = 0;
    for (std::size_t i = 0; i < s.size();) {
        const std::size_t len = utf8Length(static_cast<unsigned char>(s[i]));
        if (len == 0 || i + len > s.size()) break;      // битая или обрезанная строка
        for (std::size_t k = 1; k < len; ++k)
            if ((static_cast<unsigned char>(s[i + k]) & 0xC0) != 0x80)
                return count;                            // нарушен шаблон продолжения
        i += len;
        ++count;
    }
    return count;
}
```

Кодирование обратно строится по тем же шаблонам — от младших групп бит к старшим:

```cpp
#include <cstdint>
#include <string>

std::string encodeUtf8(char32_t cp) {
    if (cp < 0x80) return std::string(1, static_cast<char>(cp));
    const int n = cp < 0x800 ? 2 : cp < 0x10000 ? 3 : 4;    // длина последовательности
    std::string out(n, '\0');
    for (int i = n - 1; i > 0; --i) {
        out[i] = static_cast<char>(0x80 | (cp & 0x3F));     // байт-продолжение
        cp >>= 6;
    }
    out[0] = static_cast<char>((0xFF << (8 - n)) | cp);     // ведущий байт: 110/1110/11110
    return out;
}
```

## 6. Unicode в C++

| Тип / литерал | Стандарт | Единица хранения |
|---|---|---|
| `char`, `"..."` | C++98 | байт в кодировке реализации |
| `u8"..."`, `char8_t`, `std::u8string` | C++11 / C++20 | байт UTF-8 |
| `char16_t`, `u"..."`, `std::u16string` | C++11 | слово UTF-16 |
| `char32_t`, `U"..."`, `std::u32string` | C++11 | слово UTF-32 |
| `wchar_t`, `L"..."` | C++98 | платформозависимо: 2 байта в Windows, 4 в Linux |

```cpp
#include <string>

std::u8string utf8  = u8"Привет";   // C++20: char8_t, 12 байт
std::u16string utf16 = u"Привет";    // 6 слов UTF-16
std::u32string utf32 = U"Привет";    // 6 слов UTF-32
static_assert(sizeof(char8_t) == 1);
```

Важно: `std::codecvt` и `std::wstring_convert` объявлены устаревшими в C++17, а стандартного перекодировщика UTF-8 ↔ UTF-16 в библиотеке нет — на практике берут ICU или `iconv`. `wchar_t` не портируем: одна и та же строка имеет разную длину на Windows и Linux.

## 7. Кодовая точка — ещё не «символ» на экране

| Уровень | Что это | Пример |
|---|---|---|
| Байт | единица хранения | `0xD0 0x96` |
| Кодовая точка | номер символа | `U+0416` |
| Графемный кластер | то, что видит человек | «й», «é», флаг, эмодзи-семейство |

- «й» может быть одним кодом `U+0439` или парой `U+0438 U+0306`;
- «é» — `U+00E9` либо `U+0065 U+0301`;
- флаг — два regional indicator, эмодзи-семейство — несколько кодов, соединённых `U+200D` (ZWJ).

Поэтому существуют формы нормализации: **NFC** (композиция), **NFD** (декомпозиция), NFKC/NFKD (совместимость). Две строки, выглядящие одинаково, могут сравниваться как разные, если не привести их к одной форме.

---

## Типичные ошибки

1. **Считать Unicode кодировкой.** Unicode — набор символов и правила; байты задаёт UTF-8/16/32.
2. **Путать байты и символы**: `std::string::size()` считает байты, а `s[1]` может попасть в середину UTF-8-последовательности.
3. **Считать 1 кодовая точка = 1 символ.** Диакритика, ZWJ-последовательности и флаги ломают это допущение.
4. **Применять `std::toupper`/`std::isalpha` к многобайтовым символам.** Они работают с байтами и локалью, а не с Unicode.
5. **Игнорировать нормализацию** при сравнении ввода и **брать `wchar_t` за «универсальный Unicode»** — на Windows это UTF-16, на Linux UTF-32.

---

## Что добавить на собеседовании

- Unicode-стандарт определяет не только коды, но и **свойства** символов (категория, регистр, направление письма) и алгоритмы: нормализация, collation (сортировка с учётом языка), bidi для арабицы и иврита.
- UTF-8 выиграл исторически из-за совместимости с ASCII и с C-строками — старые протоколы и файлы не пришлось менять.
- Есть практические ловушки: BOM `EF BB BF`, переполнение при подсчёте длины буфера (4 байта на кодовую точку — верхняя граница), атаки на основе похожих символов (гомоглифы).
- В C++20 появился `char8_t`, что отделило UTF-8 от «просто байтов» на уровне типов.

---

## Итог

| Понятие | Суть |
|---|---|
| Unicode | стандарт: символы мира + их свойства и алгоритмы |
| Кодовая точка | номер символа, `U+0000..U+10FFFF` |
| UTF-8 | 1–4 байта, ASCII-совместима, самосинхронизирующаяся |
| UTF-16 | 2 или 4 байта, суррогатные пары вне BMP |
| UTF-32 | всегда 4 байта, простота в ущерб размеру |
| В C++ | `char8_t`/`u8string`, `char16_t`, `char32_t`, `wchar_t` (непортируем) |
| Главная тонкость | байты ≠ кодовые точки ≠ графемные кластеры |
