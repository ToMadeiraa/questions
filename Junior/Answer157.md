# 157. Для чего используют файловые дескрипторы?

## Определение

**Файловый дескриптор** (file descriptor, FD) — это целое неотрицательное число, которое операционная система (в POSIX-системах: Linux, macOS, Unix) выдаёт процессу для идентификации открытого ресурса ввода-вывода. Через это число процесс обращается к файлу, сокету, каналу (pipe), устройству и т.п.

По сути, файловый дескриптор — это **индекс в таблице открытых файлов процесса**, которая хранится в ядре ОС. Программа не работает с внутренними структурами ядра напрямую, а передаёт в системные вызовы (`read`, `write`, `close` и др.) именно номер дескриптора.

## Для чего нужны файловые дескрипторы

1. **Единый механизм доступа к разным ресурсам.** В POSIX «всё есть файл»: обычные файлы, каталоги, сокеты, pipes, терминалы, устройства (`/dev/*`) адресуются одинаково — через дескриптор. Это позволяет писать универсальный код: одна и та же функция `read()` работает и с файлом, и с сокетом.

2. **Абстракция над файловой системой.** Программа не знает, где физически лежит файл и как устроено хранилище. Ядро по номеру дескриптора находит нужную структуру (`struct file`), смещение, права доступа и режим открытия.

3. **Управление жизненным циклом ресурса.** Открытие (`open`) возвращает дескриптор, закрытие (`close`) освобождает его. Пока дескриптор открыт, ресурс удерживается; при завершении процесса ОС автоматически закрывает все его дескрипторы.

4. **Разделение прав и режимов доступа.** Режим (чтение/запись/дополнение) задаётся при открытии и ассоциируется с дескриптором. Права проверяются один раз при `open`, а не при каждом чтении.

5. **Мультиплексирование ввода-вывода.** Дескрипторы позволяют одному потоку ждать готовности сразу многих ресурсов через `select`, `poll`, `epoll` — это основа сетевых серверов и асинхронного I/O.

6. **Перенаправление потоков.** Стандартные потоки ввода/вывода/ошибок — это тоже дескрипторы с фиксированными номерами: `0` (stdin), `1` (stdout), `2` (stderr). Их можно подменять (`dup2`), реализуя перенаправление (`>`), конвейеры (`|`) и т.д.

7. **Межпроцессное взаимодействие.** Дескрипторы сокетов и pipe используются для обмена данными между процессами; при `fork()` дочерний процесс наследует таблицу дескрипторов родителя.

8. **Экономия ресурсов и повторное использование.** Один и тот же открытый файл может использоваться несколькими дескрипторами (через `dup`), разделяя смещение; несколько процессов могут держать дескрипторы на один файл.

## Стандартные дескрипторы

| Номер | Имя | Назначение |
|-------|-----|------------|
| 0 | stdin | стандартный ввод |
| 1 | stdout | стандартный вывод |
| 2 | stderr | стандартный вывод ошибок |

## Отличие от файлового указателя в C++

Важно не путать два уровня абстракции:

- **Файловый дескриптор** — низкоуровневый целочисленный идентификатор в ядре ОС (POSIX API: `open`, `read`, `write`, `close`, `lseek`).
- **`std::fstream` / `FILE*`** — высокоуровневые обёртки стандартной библиотеки C/C++, которые внутри себя хранят файловый дескриптор (или его аналог) и добавляют буферизацию, форматирование, обработку ошибок.

В Windows аналогом дескриптора является **хэндл** (`HANDLE`), получаемый через `CreateFile`.

## Пример на C++ (POSIX)

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <iostream>

int main() {
    // open возвращает файловый дескриптор (>= 0) или -1 при ошибке
    int fd = open("data.txt", O_RDONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }

    char buf[256];
    ssize_t n = read(fd, buf, sizeof(buf)); // работаем через дескриптор
    if (n > 0)
        std::cout.write(buf, n);

    close(fd); // освобождаем дескриптор
    return 0;
}
```

## Ограничения

- Число открытых дескрипторов у процесса ограничено (`ulimit -n` в Linux); при утечке дескрипторов (`open` без `close`) новые открытия начинают падать с ошибкой `EMFILE`.
- Дескриптор действителен только в рамках процесса (хотя может наследоваться при `fork`/`exec`).
- Номер дескриптора может быть переиспользован ОС после `close`, поэтому работа с уже закрытым дескриптором — ошибка (возможно обращение к другому ресурсу).

## Итог

Файловые дескрипторы нужны, чтобы **унифицированно и безопасно адресовать открытые ресурсы ввода-вывода из пространства пользователя**, делегируя ядру ОС всю работу по поиску файла, проверке прав, буферизации на уровне ФС и управлению жизненным циклом. Это фундаментальная абстракция POSIX, на которой строятся файловый ввод-вывод, сети, IPC и перенаправление потоков.
