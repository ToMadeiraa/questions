# 97. Как работают inline-функции? Может ли такая функция быть рекурсивной?

## Как работают inline-функции

Ключевое слово `inline` в C++ изначально задумывалось как **рекомендация компилятору** выполнить подстановку тела функции непосредственно в точку вызова вместо генерации инструкции `call`. Это позволяет устранить накладные расходы на вызов функции (сохранение регистров, передачу аргументов, возврат управления), но потенциально увеличивает размер исполняемого файла, поскольку код функции дублируется в каждой точке вызова.

Однако современное понимание `inline` в C++ существенно шире. Компилятор **не обязан** выполнять подстановку — это именно рекомендация, а не директива. Компилятор может проигнорировать `inline`, если функция слишком большая, её адрес используется где-то в программе, или по иным причинам оптимизации. Более того, компилятор вправе встроить (inline) функцию, которая **не** помечена ключевым словом `inline`, если сочтёт это полезным.

Главное **семантическое** следствие использования `inline` в современном C++ — это разрешение **множественных определений** в разных единицах трансляции. Если функция объявлена `inline`, её определение может появляться в нескольких translation units (обычно через заголовочный файл), при условии что все определения идентичны. Это позволяет обойти правило одного определения (ODR) и определять функции прямо в заголовках, не получая ошибок линковки.

Функции, определённые **внутри тела класса**, неявно являются `inline`. Также неявно inline являются функции, объявленные как `constexpr` или `consteval`.

## Может ли inline-функция быть рекурсивной?

**Да, синтаксически может.** Компилятор не выдаст ошибку, если вы объявите рекурсивную функцию с ключевым словом `inline`. Однако **фактическая подстановка тела функции в точку вызова для рекурсивной функции, как правило, невозможна** или сильно ограничена.

Причина фундаментальна: рекурсивная функция вызывает саму себя, и если компилятор попытается полностью раскрыть (inline) каждый вызов, процесс может стать бесконечным. Компиляторы решают эту проблему по-разному:

1. **Отказ от inline-подстановки**: Наиболее распространённое поведение — компилятор просто игнорирует рекомендацию `inline` для рекурсивной функции и генерирует обычный вызов. Документация Microsoft прямо указывает, что рекурсивные функции являются одним из случаев, когда компилятор может создать отдельный экземпляр функции вместо inline-подстановки.

2. **Частичная подстановка (разворачивание)**: Компилятор может встроить несколько верхних уровней рекурсии, а начиная с некоторой глубины сгенерировать обычный рекурсивный вызов. Это похоже на разворачивание цикла. Например, при вызове `f(5)` компилятор может подставить тело для `f(5)`, внутри которого останется вызов `f(4)`, и так далее до некоторого предела.

3. **Оптимизация хвостовой рекурсии**: Если рекурсивный вызов является **хвостовым** (tail recursion), то есть возврат из функции происходит непосредственно после рекурсивного вызова без дополнительных операций, компилятор может преобразовать рекурсию в цикл. Цикл уже может быть встроен в точку вызова без проблем. Некоторые компиляторы (например, MSVC) имеют специальные прагмы для управления глубиной разворачивания рекурсивных inline-функций.

4. **Вычисление на этапе компиляции**: Если рекурсивная функция вызывается с **константными аргументами** и компилятор достаточно умён (или функция объявлена `constexpr`), он может полностью вычислить результат на этапе компиляции и подставить готовое значение, вообще не генерируя кода функции.

**Практический вывод**: писать `inline` для рекурсивной функции обычно не имеет смысла. Ключевое слово не заставит компилятор сделать невозможное, а в лучшем случае будет проигнорировано. Если вы хотите, чтобы рекурсивная функция вычислялась на этапе компиляции, используйте `constexpr` (начиная с C++11/14), а не `inline`.
