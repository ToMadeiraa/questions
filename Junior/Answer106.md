# 106. Чисто виртуальные функции в C++: реализация и вызов из конструктора

## 1. Может ли чисто виртуальная функция иметь реализацию?

**Да, может.** В C++ чисто виртуальная функция (объявленная с `= 0`) может иметь тело (реализацию), но с важным синтаксическим ограничением: **определение должно быть вынесено за пределы тела класса**.

### Ключевые правила

1. **Синтаксис объявления и определения разделены.** Вы не можете написать `virtual void f() = 0 { ... }` — компилятор выдаст ошибку, так как спецификатор `= 0` не может соседствовать с телом функции в объявлении.

2. **Определение пишется отдельно:**
   ```cpp
   class Base {
   public:
       virtual void f() = 0;  // объявление: класс остаётся абстрактным
   };
   
   void Base::f() {  // определение чисто виртуальной функции
       // какая-то реализация
   }
   ```

3. **Класс остаётся абстрактным.** Наличие реализации у чисто виртуальной функции **не делает класс конкретным**. Вы по-прежнему не можете создавать объекты `Base`. Производные классы обязаны переопределить `f()` (или остаться абстрактными).

### Зачем это нужно?

Наиболее частый вариант использования — **чисто виртуальный деструктор**. Базовый класс должен иметь деструктор для корректного разрушения подобъекта, но вы хотите сделать класс абстрактным. Решение: объявить деструктор чисто виртуальным и **обязательно** предоставить его определение, иначе линковщик выдаст ошибку.

```cpp
class Base {
public:
    virtual ~Base() = 0;  // чисто виртуальный деструктор
};

Base::~Base() {}  // определение обязательно!
```

### Как вызвать реализацию из производного класса?

Только с использованием **полного квалифицированного имени**:

```cpp
class Derived : public Base {
public:
    void f() override {
        Base::f();  // явный вызов реализации из Base
        // дополнительная логика Derived
    }
};
```

Обычный виртуальный вызов `f()` внутри `Derived` вызовет `Derived::f`, а не `Base::f`.

## 2. Что произойдёт при вызове чисто виртуальной функции из конструктора?

**Поведение не определено (undefined behavior).** Это верно **независимо от того, имеет ли чисто виртуальная функция определение или нет**.

### Почему это происходит?

При создании объекта производного класса порядок таков:
1. Сначала вызывается конструктор **базового** класса.
2. Затем конструктор производного класса.

В момент выполнения конструктора `Base` объект ещё **не является** объектом типа `Derived`. Таблица виртуальных функций (vtable) указывает на версии методов **базового** класса. Если `Base::f` объявлена чисто виртуальной, вызов `f()` из конструктора `Base` попытается выполнить виртуальный вызов для функции, у которой в контексте базового класса нет финального переопределения — это недопустимо.

> Важно: речь идёт именно о **виртуальном вызове** (то есть обычный вызов `f()` или `this->f()`). Если вы явно квалифицируете вызов как `Base::f()`, это уже **не виртуальный вызов**, и он безопасен (при условии, что определение существует).

### Практические следствия

- **Компилятор может выдать предупреждение или ошибку** (зависит от компилятора и настроек), но стандарт C++ квалифицирует это как UB.
- **Не полагайтесь на то, что вызовется реализация из базового класса**, даже если она есть. Поведение программы в этом случае непредсказуемо.
- **Не полагайтесь на то, что вызовется переопределение из производного класса** — к моменту выполнения конструктора базы производный класс ещё не сконструирован, и его vtable не активна.

### Безопасная альтернатива

Если вам нужно поведение, зависящее от типа, но выполняемое на этапе конструирования, используйте **явный квалифицированный вызов** к реализации базового класса (если она существует):

```cpp
class Base {
public:
    Base() {
        Base::f();  // НЕ виртуальный вызов, безопасно
    }
    virtual void f() = 0;
};

void Base::f() { /* реализация */ }
```

Но помните: в этом случае **никогда не будет** вызвана версия `f()` из производного класса, даже если объект создаётся как `Derived`. Если нужна логика производного класса — вынесите её в отдельный метод, вызываемый после завершения конструирования (например, из конструктора `Derived` или через паттерн «двухфазная инициализация»).

## Краткая сводка

| Вопрос | Ответ |
|---|---|
| Может ли pure virtual function иметь реализацию? | **Да**, но определение — только вне тела класса |
| Делает ли реализация класс конкретным? | **Нет**, класс остаётся абстрактным |
| Как вызвать реализацию из наследника? | `Base::f()` — полное квалифицированное имя |
| Что будет при вызове из конструктора? | **Undefined Behavior**, даже если реализация есть |
