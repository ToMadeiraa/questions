# Вопрос 50. Как определить размер структур?

> **Кратко:** Размер структуры даёт `sizeof`, но он почти никогда не равен сумме размеров полей: между полями и в конце добавляются байты выравнивания (padding), а результат округляется до кратного выравниванию структуры. Управлять размером можно порядком полей, `alignas`, `#pragma pack` / `__attribute__((packed))` и `[[no_unique_address]]`; измерить — через `sizeof`, `alignof` и `offsetof`.

---

## Алгоритм вычисления

1. `alignof(поле)` — требуемое выравнивание поля (у скалярных типов обычно равно размеру).
2. Смещение поля = текущая позиция, округлённая **вверх** до `alignof(поле)`; разница и есть padding.
3. `alignof(struct)` = максимум из выравниваний полей.
4. `sizeof(struct)` = позиция после последнего поля, округлённая **вверх** до `alignof(struct)`.

Отсюда главное правило: **`sizeof` всегда кратен `alignof`**, иначе второй элемент массива структур оказался бы невыровненным.

---

## Разбор на примере

```cpp
struct Bad {          // sizeof == 12 на x86-64
    char a;           // offset 0, размер 1
    int  b;           // offset 4: перед ним 3 байта padding
    char c;           // offset 8, размер 1
};                    // 9 -> 12: ещё 3 байта хвостового padding
```

| Поле | `sizeof` поля | `alignof` | Смещение | Padding перед полем |
|---|---|---|---|---|
| `a` | 1 | 1 | 0 | 0 |
| `b` | 4 | 4 | 4 | 3 |
| `c` | 1 | 1 | 8 | 0 |
| хвост | — | — | 9 | 3 |
| **итого** | | **4** | | **6** |

Полезных данных 6 байт из 12 — половина объекта уходит на выравнивание. Те же поля в другом порядке дают 8 байт:

```cpp
struct Good {         // sizeof == 8
    int  b;           // offset 0
    char a;           // offset 4
    char c;           // offset 5
};                    // 6 -> 8: 2 байта хвостового padding
```

Компилятор **не переставляет** поля: порядок объявления — часть контракта типа, оптимизировать приходится вручную.

---

## Порядок полей: 24 против 16 байт

```cpp
struct Original {         // sizeof == 24
    char   a;
    int    b;
    char   c;
    double d;             // 8 байт padding перед ним
};

struct Reordered {        // sizeof == 16: тот же набор полей
    double d;
    int    b;
    char   a;
    char   c;
};

static_assert(sizeof(Original)  == 24);
static_assert(sizeof(Reordered) == 16);
```

Правило: **сортировать поля по убыванию выравнивания** — сначала `double` и указатели, потом `int`, потом `char`/`bool`. На массиве из миллиона объектов лишние 8 байт на элемент превращаются в 8 МБ и в лишние промахи кэша.

---

## Типичные размеры на x86-64

| Определение | `sizeof` | Комментарий |
|---|---|---|
| `struct {}` | 1 | пустая структура |
| `struct { char a; int b; char c; }` | 12 | 6 байт padding |
| `struct { int b; char a; char c; }` | 8 | 2 байта в хвосте |
| `struct { double d; char c; }` | 16 | 7 байт в хвосте |
| `struct { int* p; int x; }` | 16 | указатель 8 байт + padding |
| `struct { virtual ~S(); int x; }` | 16 | 8 байт `vptr` + `int` + padding |
| `struct { uint8_t; uint32_t; uint16_t; }` при `pack(1)` | 7 | поля невыровнены |

На 32-битной цели с 4-байтными указателями числа будут другими: размер — свойство ABI платформы, а не языка.

## Как измерить: `sizeof`, `alignof`, `offsetof`

```cpp
#include <cstddef>
#include <cstdint>
#include <type_traits>

struct Packet {
    std::uint8_t  type;
    std::uint32_t id;
    std::uint16_t flags;
};

static_assert(std::is_standard_layout_v<Packet>);   // offsetof применим
static_assert(alignof(Packet) == 4);
static_assert(sizeof(Packet) == 12);                // 1 + 3 pad + 4 + 2 + 2 pad
static_assert(offsetof(Packet, id)    == 4);
static_assert(offsetof(Packet, flags) == 8);
```

`sizeof` — константа времени компиляции, поэтому проверки размера через `static_assert` ничего не стоят в runtime. `offsetof` определён для standard-layout типов, для остальных он conditionally-supported. Печатать размер положено через `%zu`: тип результата — `std::size_t`.

---

## Как управлять размером

**`alignas` — увеличить выравнивание (и размер):**

```cpp
struct alignas(16) Vec4 { float v[4]; };    // sizeof == 16, alignof == 16
struct alignas(64) Padded { int value; };   // sizeof == 64: размер кратен выравниванию
```

Так «горячие» данные разносят по разным кэш-линиям, чтобы избежать ложного разделения (false sharing).

**Упаковка — убрать padding:**

```cpp
#pragma pack(push, 1)
struct WireHeader {          // ровно 7 байт — формат протокола
    std::uint8_t  type;      // offset 0
    std::uint32_t id;        // offset 1
    std::uint16_t flags;     // offset 5
};
#pragma pack(pop)
static_assert(sizeof(WireHeader) == 7);
```

`pack` не стандартизован (в GCC/Clang аналог — `__attribute__((packed))`), поля лежат невыровненно, и обращение к ним медленнее. Значения безопаснее читать через `std::memcpy`, а не через указатель на упакованное поле.

**`[[no_unique_address]]` (C++20) — пустое поле-член занимает 0 байт:**

```cpp
struct Empty {};
struct WithTag { int id; [[no_unique_address]] Empty tag; };   // sizeof == 4
```

В MSVC нужно писать `[[msvc::no_unique_address]]`.

## Что не входит в `sizeof`

| Сущность | Входит в размер? |
|---|---|
| Нестатические поля данных | да |
| `static`-поля | нет: живут отдельно от объекта |
| Функции-члены | нет: код общий для всех объектов |
| `vptr` при наличии виртуальных функций | да, скрытый указатель |
| Память, на которую указывает поле-указатель | нет, только сам указатель (8 байт) |
| Padding | да |

Отдельные случаи: поле-ссылка занимает как указатель; `union` имеет размер наибольшего члена с округлением до выравнивания; битовые поля пакуются в единицы хранения (`struct { unsigned a : 1; }` → 4 байта); пустая **база** не увеличивает размер (empty base optimization), а пустое поле-член — увеличивает (1 байт + padding).

---

## Типичные ошибки

1. **Считать `sizeof(struct)` суммой `sizeof` полей** — забывают padding и хвостовое округление.
2. **Проверять размер через `sizeof(Struct*)`** — это размер указателя, а не структуры.
3. **Полагаться на конкретные числа без `static_assert`** и не учитывать платформу и `#pragma pack` из чужого заголовка.
4. **Упаковывать всё подряд** ради экономии: на строгих архитектурах невыровненный доступ медленнее или приводит к аппаратному исключению.
5. **Сравнивать структуры через `memcmp`** при наличии padding: байты заполнения не инициализированы.
6. **Забывать, что `#pragma pack` действует до `pop`**, и менять разметку всех последующих структур в заголовке.

---

## Что добавить на собеседовании

- Назвать причину padding: требования процессора к выравниванию плюс необходимость, чтобы `sizeof` был кратен `alignof` для массивов структур.
- Показать практический приём — сортировку полей по убыванию выравнивания — и сразу выигрыш 24 → 16 байт.
- Упомянуть `static_assert(sizeof(T) == N)` и `#pragma pack` как способ зафиксировать формат протокола или файла.
- Знать, что `offsetof` требует standard-layout, а `memcpy` — trivially copyable; в C++20 для этого есть `std::bit_cast`.
- Отметить, что точные размеры — часть ABI, поэтому в переносимом коде их проверяют, а не предполагают.

|---|---|
| Как узнать размер | `sizeof(Struct)` / `sizeof obj`; результат — `std::size_t`, печать `%zu` |
| Равен ли сумме полей | нет: padding между полями + хвостовое округление |
| Кратность | `sizeof` всегда кратен `alignof` структуры |
| `alignof` структуры | максимум из выравниваний полей |

| Как убрать padding | `#pragma pack(1)` / `__attribute__((packed))`, ценой невыровненного доступа |
| Как увеличить | `alignas(N)` — например, для выравнивания по кэш-линии |
| Что не входит | статические поля, методы, память по указателям |
