# Вопрос 19. Что такое специализация шаблона? Частичная специализация шаблона?

> **Кратко:** специализация — это замена общей реализации шаблона частной для конкретного набора аргументов. **Полная (явная) специализация** задаёт код для фиксированного списка аргументов (`template<> struct X<int>`), а **частичная** — для целого семейства типов, подходящих под образец (`template<class T> struct X<T*>`), и допустима только для шаблонов классов и шаблонов переменных.

---

## Зачем нужна специализация

Первичный шаблон пишется «сразу для всех типов», поэтому для отдельных типов он может быть **неоптимальным** (общее копирование — для указателей, `vector<bool>` — для `bool`), **некорректным** (общий код может просто не компилироваться) или **неполным по смыслу** (свой хеш, свой способ сериализации).

Специализация — это **статический выбор реализации на этапе компиляции**: компилятор подбирает наиболее подходящую версию шаблона по аргументам.

---

## 1. Полная (явная) специализация

Начинается с `template<>` — пустой список параметров, все аргументы заданы явно.

```cpp
// Первичный шаблон: общий случай
template <typename T>
struct TypeName {
    static constexpr const char* value = "unknown";
};

// Полная специализация для конкретного типа
template <>
struct TypeName<int> {
    static constexpr const char* value = "int";
};

static_assert(TypeName<int>::value[0] == 'i');   // выбрана специализация
```

Специализация — **отдельная сущность**, а не перегрузка: она не обязана быть похожей на первичный шаблон (другой набор членов, другие базовые классы, другой размер). Она должна быть объявлена **до первого использования**, которое вызвало бы неявную инстанциацию, — иначе программа некорректна, причём диагностика не обязательна. Находится она в том же пространстве имён, что и первичный шаблон (или в объемлющем), а `inline` для функции-специализации нужно указывать явно.

---

## 2. Специализация функций: важный нюанс

```cpp
#include <iostream>

template <typename T>
void print(const T& value) { std::cout << value << '\n'; }

template <>                                    // явная специализация
void print<bool>(const bool& value) {
    std::cout << (value ? "true" : "false") << '\n';
}

int main() {
    print(42);        // инстанцируется print<int>
    print(true);      // выбрана явная специализация print<bool>
}
```

**Ключевое:** специализация **не участвует в разрешении перегрузок**. Сначала среди всех функций (включая первичный шаблон) выбирается лучшая, и только если выбранной оказалась именно эта шаблонная функция — подставляется её специализация. Поэтому для функций практически всегда лучше **обычная перегрузка**: она участвует в разрешении перегрузок и находится через ADL.

```cpp
inline void print(bool value) { std::cout << (value ? "true" : "false") << '\n'; }
```

## 3. Частичная специализация

**Частичная специализация** задаёт реализацию не для одного типа, а для **семейства** типов, подходящих под образец: указатели, ссылки, `const T`, массивы, `Pair<T, T>`, `vector<T>`.

```cpp
template <typename T>
struct IsPointer {                             // первичный шаблон
    static constexpr bool value = false;
};

template <typename T>
struct IsPointer<T*> {                         // T — параметр частичной специализации
    static constexpr bool value = true;
};

static_assert(!IsPointer<int>::value);
static_assert(IsPointer<int*>::value);
```

Специализировать можно и по значению параметра, не являющегося типом:

```cpp
template <typename T, std::size_t N>
struct Buffer { T data[N]; };

template <typename T>
struct Buffer<T, 0> {                          // N == 0: массив нулевой длины недопустим
    T* data() noexcept { return nullptr; }
};

static_assert(sizeof(Buffer<int, 4>) == 4 * sizeof(int));
```

**Ограничения:**

- частичная специализация **невозможна для шаблонов функций** — используют перегрузки, tag-dispatch, SFINAE или `if constexpr`;
- частично специализировать отдельную функцию-член класса-шаблона нельзя (только класс целиком либо полная специализация члена);
- одна из подходящих частичных специализаций должна быть **строго более специализированной**, иначе компилятор сообщит о неоднозначности.

---

## 4. Порядок выбора версии

| Шаг | Что рассматривается | Пример |
|---|---|---|
| 1 | Полная специализация, если аргументы совпали точно | `X<int>` |
| 2 | Самая специализированная из подходящих частичных | `X<T*>`, `X<const T>` |
| 3 | Первичный шаблон | `X<T>` |

Между частичными специализациями выбор делает **частичное упорядочение** (partial ordering): компилятор проверяет, выводится ли образец одной специализации из образца другой.

## 5. Специализация члена, шаблоны переменных, C++20

```cpp
template <typename T>                          // в Printer объявлено print(const T&) const
void Printer<T>::print(const T& value) const { /* общая версия */ }

template <>                                    // полная специализация члена класса-шаблона
inline void Printer<bool>::print(const bool& value) const { /* ... */ }
```

Шаблоны переменных (C++14) тоже допускают частичную специализацию, а в C++20 частичная специализация может быть ограничена концептом:

```cpp
template <typename T>
inline constexpr bool is_pointer_v = false;

template <typename T>
inline constexpr bool is_pointer_v<T*> = true;          // частичная специализация

template <typename T> struct Serializer;                // первичный шаблон
template <typename T> requires std::integral<T>
struct Serializer<T> { /* только для целых типов */ };   // C++20: ограниченная
```

## 6. Практический пример: свой `std::hash`

Стандартная библиотека сама построена на специализациях (`std::numeric_limits`, `std::tuple_size`, `std::formatter`). Для своего типа нужно специализировать `std::hash`, иначе `unordered_map` не скомпилируется:

```cpp
struct Point {
    int x = 0, y = 0;
    bool operator==(const Point& o) const { return x == o.x && y == o.y; }
};

template <>                                    // полная специализация в namespace std
struct std::hash<Point> {
    std::size_t operator()(const Point& p) const noexcept {
        const std::size_t hx = std::hash<int>{}(p.x);
        const std::size_t hy = std::hash<int>{}(p.y);
        return hx ^ (hy + 0x9e3779b97f4a7c15ULL + (hx << 6) + (hx >> 2));
    }
};

std::unordered_map<Point, int> cache;          // теперь работает
```

Специализация должна быть видна до первого использования, поэтому её место — в заголовке.

## Типичные ошибки

1. **Путать специализацию с перегрузкой.** Для функций специализация не участвует в разрешении перегрузок — поведение может оказаться не тем, что ожидали.
2. **Пытаться частично специализировать шаблон функции.** Язык это запрещает; нужна перегрузка или класс-помощник.
3. **Объявлять специализацию после её первого использования.** Формально ill-formed, диагностика не обязательна — ошибка «плавающая» и зависит от порядка `#include`.
4. **Забыть `inline` у функции-специализации в заголовке** — множественные определения при линковке.
5. **Неоднозначные частичные специализации.** Классика: `X<T*>` и `X<const T>` для `X<const int*>` — обе подходят, и ни одна не более специализирована.
6. **Считать, что специализация экономит размер кода.** Каждая инстанциация — свой код; специализация лишь выбирает, какой именно.

---

## Что добавить на собеседовании

- Специализация — инструмент **статического полиморфизма**: выбор реализации по типу без `virtual` и без накладных расходов в рантайме.
- Специализации — основа `type_traits` (`std::is_pointer`, `std::remove_reference` — это частичные специализации); в C++20 их частично вытесняют `if constexpr` и `concepts`.
- Стоит сказать про **порядок объявления**: заголовок со специализацией должен включаться до места использования — типичная причина «работает в одном файле и не работает в другом».
- Хорошо звучит мысль, что специализация — **не «перегрузка по типу»**, а отдельная сущность со своими правилами ODR, и что она не заменяет перегрузку там, где нужен ADL.

## Итог

| Понятие | Что задаёт | Синтаксис | Где допустима |
|---|---|---|---|
| Первичный шаблон | Общий случай для всех типов | `template<class T> struct X` | Всегда |
| Полная специализация | Ровно один набор аргументов | `template<> struct X<int>` | Классы, функции, переменные |
| Частичная специализация | Семейство типов по образцу | `template<class T> struct X<T*>` | Только классы и шаблоны переменных |
| Ограниченная (C++20) | Семейство по концепту | `template<class T> requires C<T> struct X<T>` | Классы и шаблоны переменных |
| Порядок выбора | Полная → самая специализированная частичная → первичный | — | — |
