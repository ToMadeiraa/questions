# 66. Особенности статических полей класса

## Определение

**Статическое поле** (static data member) — это поле класса, которое принадлежит **самому классу**, а не его отдельным объектам. Оно объявляется с ключевым словом `static` внутри класса.

```cpp
class Counter {
public:
    static int count;  // объявление статического поля
    Counter() { ++count; }
};

int Counter::count = 0;  // определение вне класса (обязательно)
```

## Ключевые особенности

### 1. Общая память для всех объектов

Статическое поле существует **в единственном экземпляре** и разделяется всеми объектами класса:

```cpp
Counter a, b, c;
// Counter::count == 3 — одно поле на всех
```

### 2. Не входит в размер объекта

Статическое поле **не хранится** внутри объекта, поэтому не влияет на `sizeof`:

```cpp
class A {
    int x;              // 4 байта
    static int y;       // не учитывается в sizeof(A)
};
// sizeof(A) == 4
```

### 3. Требуется определение вне класса

Объявление внутри класса (кроме исключений, см. ниже) — это **только декларация**. Память под поле нужно выделить определением вне класса:

```cpp
class Foo {
    static int x;  // декларация
};
int Foo::x = 42;   // определение (без static!) — обязательно ровно одно
```

### 4. Исключения из правила определения

Можно **не** писать внешнее определение в следующих случаях:

- **`static const` / `static constexpr` целочисленного типа** (и `constexpr` любого литерального типа) инициализированные прямо в классе, если не требуется брать их адрес (ODR-use):

```cpp
class Config {
    static const int MAX = 100;            // OK без определения
    static constexpr double PI = 3.14159;  // OK без определения
};

// Но при взятии адреса — определение нужно:
const int* p = &Config::MAX;  // потребует определения
```

- **`static inline`** (C++17) — можно инициализировать в классе, внешнее определение не нужно:

```cpp
class Config {
    inline static int value = 42;  // C++17
};
```

### 5. Доступ через класс или объект

Обращаться к статическому полю можно как через имя класса, так и через объект (второй способ не рекомендуется):

```cpp
Counter::count = 5;   // предпочтительно
a.count = 5;          // работает, но вводит в заблуждение
```

### 6. Не имеет `this`

Внутри статических функций-членов (и при инициализации статических полей) **нет указателя `this`**, поэтому статические поля доступны напрямую.

### 7. Модификаторы доступа и наследование

- Подчиняется обычным правилам `public`/`protected`/`private`.
- **Наследуется**, но не копируется: у базового и производного классов — **одно и то же** статическое поле (если оно не перекрыто собственным полем с тем же именем в производном классе).

```cpp
struct Base { static int x; };
struct Derived : Base {};
int Base::x = 10;

Derived::x;      // == 10, то же самое поле
```

### 8. Порядок инициализации

Статические поля с динамической инициализацией инициализируются в порядке определения (в пределах одной единицы трансляции). Это порождает проблему **«static initialization order fiasco»** при инициализации одного статического объекта другим из другой единицы трансляции. Решения: локальные статические переменные (thread-safe с C++11) или `constexpr`/`inline`-инициализация.

### 9. Нестатические инициализаторы в объявлении

До C++11 статические не-`const` поля нельзя было инициализировать в объявлении класса. С C++17 через `inline static` — можно.

## Сводная таблица

| Свойство | Характеристика |
|---|---|
| Принадлежность | Классу, а не объекту |
| Количество экземпляров | Один на всю программу |
| Влияние на `sizeof` | Нет |
| Определение вне класса | Требуется (кроме `const`/`constexpr`/`inline`) |
| Доступ | Через `Class::field` или `obj.field` |
| Наследование | Общее для всей иерархии |

## Типичные применения

- Счётчики созданных объектов;
- Константы и параметры конфигурации;
- «Singleton»-подобные данные;
- Фабричные реестры и общие ресурсы.
