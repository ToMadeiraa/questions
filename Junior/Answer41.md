# Вопрос 41. Какие алгоритмы работы со строками знаете?

> **Кратко:** «алгоритмы над строками» — это поиск подстроки, сравнение и хеширование, расстояние между строками, поиск палиндромов, разбор и нормализация текста. Практическая разница между ними в асимптотике: наивный поиск даёт `O(n·m)`, KMP и Z-функция — `O(n + m)`, Бойер–Мур в среднем уходит ниже `n`. Отдельный слой — кодировки: `std::string` хранит байты, а не символы, и для Unicode нужны другие инструменты.

---

## Поиск подстроки: от наивного к линейному

Наивный алгоритм прикладывает образец к каждой позиции текста. В худшем случае (текст `aaaa...a`, образец `aaa...ab`) это `O(n·m)` — именно эту деградацию устраняют остальные алгоритмы.

| Алгоритм | Подготовка | Поиск | Память | Когда выбирать |
|---|---|---|---|---|
| Наивный | — | `O(n·m)` | `O(1)` | короткие строки, простой код |
| KMP | `O(m)` | `O(n)` | `O(m)` | потоковый ввод, гарантия линейности |
| Z-функция | `O(n + m)` | `O(n + m)` | `O(n + m)` | все вхождения, периоды, границы |
| Рабин–Карп | `O(m)` | `O(n)` в среднем | `O(1)` | много образцов одной длины, 2D-поиск |
| Бойер–Мур | `O(m + σ)` | `O(n/m)` в среднем | `O(σ)` | длинные образцы, большой алфавит |
| Ахо–Корасик | `O(Σm)` | `O(n + вхождения)` | `O(Σm)` | словарь образцов за один проход |

`n` — длина текста, `m` — образца, `σ` — размер алфавита.

---

## KMP: префикс-функция

Идея: при несовпадении не начинать заново, а сдвинуть образец на длину наибольшего собственного суффикса, совпадающего с префиксом. Эта информация хранится в префикс-функции `π[i]`.

```cpp
#include <cstddef>
#include <string>
#include <vector>

// pi[i] — длина наибольшего собственного префикса s[0..i], являющегося его суффиксом
std::vector<std::size_t> prefixFunction(const std::string& s) {
    std::vector<std::size_t> pi(s.size(), 0);
    for (std::size_t i = 1, k = 0; i < s.size(); ++i) {
        while (k > 0 && s[i] != s[k]) k = pi[k - 1];   // откат по границам
        if (s[i] == s[k]) ++k;
        pi[i] = k;
    }
    return pi;
}

std::size_t kmpSearch(const std::string& text, const std::string& pat) {
    if (pat.empty()) return 0;
    const auto pi = prefixFunction(pat);
    for (std::size_t i = 0, k = 0; i < text.size(); ++i) {
        while (k > 0 && text[i] != pat[k]) k = pi[k - 1];
        if (text[i] == pat[k]) ++k;
        if (k == pat.size()) return i - k + 1;         // первое вхождение
    }
    return std::string::npos;
}
```

Префикс-функция полезна и сама по себе: `π[n-1]` — длина наибольшего бордера, через неё ищется минимальный период строки (`n - π[n-1]`, если `n` на него делится).

## Z-функция и хеширование

`Z[i]` — длина наибольшего общего префикса строки и её суффикса, начинающегося в `i`; вычисляется за `O(n)` и даёт все вхождения образца, если искать в строке `pat + '#' + text`.

**Рабин–Карп** сравнивает не символы, а полиномиальные хеши подстрок: `h[i+1] = h[i]·base + s[i]`, а хеш следующего окна пересчитывается за `O(1)`. Хеш не гарантирует равенство, поэтому при совпадении обязательна проверка подстроки; для защиты от подбора используют двойное хеширование или случайную базу.

## Расстояние между строками

**Расстояние Левенштейна** — минимальное число вставок, удалений и замен, переводящих одну строку в другую. Классическое ДП `O(n·m)`, с двумя строками таблицы — `O(m)` памяти.

```cpp
#include <algorithm>
#include <cstddef>
#include <string>
#include <vector>

std::size_t editDistance(const std::string& a, const std::string& b) {
    std::vector<std::size_t> prev(b.size() + 1), cur(b.size() + 1);
    for (std::size_t j = 0; j <= b.size(); ++j) prev[j] = j;   // a[0..0) → b[0..j)

    for (std::size_t i = 1; i <= a.size(); ++i) {
        cur[0] = i;
        for (std::size_t j = 1; j <= b.size(); ++j) {
            const std::size_t cost = (a[i - 1] == b[j - 1]) ? 0 : 1;
            cur[j] = std::min({prev[j] + 1,             // удаление из a
                               cur[j - 1] + 1,          // вставка в a
                               prev[j - 1] + cost});    // замена или совпадение
        }
        std::swap(prev, cur);
    }
    return prev[b.size()];
}
```

Родственные задачи: **LCS** — наибольшая общая подпоследовательность, та же таблица без замен; **расстояние Хэмминга** — число различающихся позиций строк равной длины, `O(n)`; **Джаро–Винклер** — метрика похожести для нечёткого сравнения имён.

## Палиндромы

Проверка двумя указателями — `O(n)` времени и `O(1)` памяти. Поиск **самого длинного** палиндрома за линейное время — алгоритм **Манакера**: он строит радиусы для строки с разделителями (`#a#b#a#`) и переиспользует уже вычисленные значения. Для разовой проверки Манакер не нужен: хватает центрального расширения за `O(n²)`.

## Разбор и нормализация

```cpp
#include <string_view>
#include <vector>

// Возвращает view на части строки: копий нет, но исходная строка должна жить дольше результата
std::vector<std::string_view> split(std::string_view s, char sep) {
    std::vector<std::string_view> out;
    std::size_t start = 0;
    while (true) {
        const auto pos = s.find(sep, start);
        if (pos == std::string_view::npos) {
            out.push_back(s.substr(start));
            break;
        }
        out.push_back(s.substr(start, pos - start));
        start = pos + 1;
    }
    return out;
}
```

| Операция | Рекомендация |
|---|---|
| Строка в число | `std::from_chars` — без локали, без исключений, быстрее `stoi` |
| Число в строку | `std::to_chars` — не аллоцирует память |
| Срез без копирования | `std::string_view` |
| Склейка многих частей | `reserve` суммы длин, затем `+=` |
| Поиск подстроки | `find` или `std::search` с searcher'ом (C++17) |

`std::string::find` в реализациях обычно оптимизирован (`memchr` по первому символу), но гарантии линейности у него нет — в худшем случае это наивный поиск. В C++17 появились готовые searcher'ы:

```cpp
#include <algorithm>
#include <functional>

const auto searcher =
    std::boyer_moore_horspool_searcher(pattern.begin(), pattern.end());
const auto it = std::search(text.begin(), text.end(), searcher);  // итератор на вхождение
```

## Unicode: почему байты — не символы

| Уровень | Что это | В `std::string` |
|---|---|---|
| Байт (code unit) | элемент `char` | одна позиция |
| Кодовая точка | символ Unicode | 1–4 байта в UTF-8 |
| Графемный кластер | то, что видит пользователь (буква + диакритика) | несколько кодовых точек |

Следствия: `s.size()` — число байт, а не символов; `substr` может разрезать UTF-8 последовательность; `std::toupper` из `<cctype>` работает с байтами, а для отрицательных `char` это UB — нужен `static_cast<unsigned char>`. Для реальной работы с Unicode берут ICU или utf8cpp.

---

## Типичные ошибки

1. **Отрицательный `char` в `<cctype>`** — undefined behavior; всегда приводить к `unsigned char`.
2. **`std::string_view` на временную строку** — висячая ссылка, view не владеет данными.
3. **`s.length() - 1` в условии цикла** при `size_t` — для пустой строки получается огромное число, а не `-1`.
4. **`while (!s.empty()) s = s.substr(1);`** — `O(n²)` из-за копирований; нужен индекс или `remove_prefix`.
5. **Байты считаются символами** при работе с UTF-8.
6. **Наивный поиск в цикле по большому тексту** — `O(n·m)` там, где нужен KMP или searcher.
7. **Доверие хешу без проверки** — коллизии дают ложные вхождения.
8. **`std::stoi` без проверки** — исключение или необработанный хвост; `from_chars` возвращает код ошибки.

## Что добавить на собеседовании

- Показывать цену выбора: «наивный поиск достаточен для коротких строк, KMP нужен, когда важна гарантия линейности на потоковых данных».
- Упомянуть, что `std::search` в C++17 принимает searcher — это готовый Бойер–Мур без собственной реализации.
- Отделять уровень байтов от уровня символов: большинство ошибок в строках — именно смешение этих уровней.
- Называть практический набор: `string_view`, `from_chars`/`to_chars`, `reserve`, отказ от `substr` в горячих путях.

## Итог

| Задача | Алгоритм | Сложность |
|---|---|---|
| Поиск подстроки, простой случай | наивный / `find` | `O(n·m)` в худшем |
| Поиск подстроки с гарантией | KMP, Z-функция | `O(n + m)` |
| Поиск подстроки в среднем | Бойер–Мур(-Хорспул) | `O(n/m)` |
| Много образцов сразу | Ахо–Корасик | `O(n + вхождения)` |
| Поиск через хеш | Рабин–Карп | `O(n)` в среднем |
| Различие строк | Левенштейн, LCS, Хэмминг | `O(n·m)`, `O(n·m)`, `O(n)` |
| Длинный палиндром | Манакер | `O(n)` |
| Разбор и числа | `split`, `from_chars`, `to_chars` | `O(n)` |
