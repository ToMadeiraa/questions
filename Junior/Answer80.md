# 80. Возврат ссылки на временный объект в C++

## Краткий ответ

Если вернуть ссылку на временный (локальный) объект, программа получит **висячую ссылку (dangling reference)** — обращение к ней является **неопределённым поведением (undefined behavior)**. Программа может «работать» случайно, а может упасть или выдать мусор — компилятор не обязан диагностировать это.

## Пример проблемы

```cpp
const std::string& bad() {
    std::string s = "hello";
    return s;          // s — локальный объект, уничтожается при выходе
}                      // s разрушен здесь

int main() {
    const std::string& r = bad();   // r ссылается на уже уничтоженный объект
    std::cout << r;                 // UB: чтение мусора / падение
}
```

К моменту возврата из `bad()` локальная переменная `s` уже разрушена (вызван деструктор), а ссылка `r` указывает в освобождённую память стека.

## Почему это UB, а не ошибка компиляции

Стандарт C++ разрешает возвращать ссылку — синтаксически это корректно. Обнаружение «времени жизни» объекта выходит за рамки того, что обязан проверять компилятор. Некоторые компиляторы (GCC/Clang с `-Wreturn-local-addr`, `-Wdangling-reference`) выдают **предупреждение**, но это не гарантировано.

## Важные нюансы

1. **Временный объект, созданный в выражении `return`**, живёт до конца полного выражения — но не дольше:
```cpp
const std::string& bad2() {
    return std::string("temp");  // временный объект уничтожается
}                                // сразу после return — тоже висячая ссылка
```

2. **Продление жизни (lifetime extension)** не работает при возврате из функции. Оно действует только при прямой привязке `const T&` или `T&&` к временному объекту в том же выражении:
```cpp
const std::string& ok = std::string("temp"); // продление жизни — корректно
```

3. **Ссылка на `static`/глобальный объект — безопасна**, т.к. время жизни не заканчивается:
```cpp
const std::string& good() {
    static std::string s = "ok";
    return s;   // корректно
}
```

4. **Ссылка на объект, переданный снаружи, — безопасна**, если вызывающий гарантирует его жизнь:
```cpp
const std::string& identity(const std::string& s) { return s; }
```

## Как правильно

| Ситуация | Решение |
|---|---|
| Нужно вернуть новый объект | Возвращать **по значению** (работает RVO/move) |
| Нужен доступ к члену объекта | Вернуть ссылку на член **живого** объекта (`*this`, параметр) |
| Нужен долгоживущий объект | `static`, умные указатели (`std::shared_ptr`), контейнер-владелец |
| Нужна «ссылочная» семантика | `std::reference_wrapper<T>` (при гарантии жизни) |

```cpp
std::string good() {
    return std::string("hello");   // возврат по значению — безопасно
}
```

## Итог

Возврат ссылки на временный/локальный объект — классическая ловушка: **висячая ссылка и undefined behavior**. Правило: ссылку можно возвращать только на объект, чьё время жизни **переживает** вызов функции (статический объект, член живого объекта, объект вызывающего). В остальных случаях возвращайте значение.
