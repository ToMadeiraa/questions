# 150. Сколько максимально может быть портов?

С теоретической точки зрения протокола, **в TCP или UDP максимальное количество портов составляет 65536 (диапазон номеров портов 0–65535)**. Это значение определяется 16-битным полем порта в заголовке протокола и не зависит от операционной системы или языка программирования.

## Почему 65536?

Поле порта в заголовках TCP и UDP имеет длину **16 бит**. 16 бит могут представлять \(2^{16} = 65536\) различных значений, то есть номера портов от 0 до 65535. Это аппаратное/протокольное ограничение, которое не может быть преодолено программно.

Следует отметить:
- **TCP и UDP используют независимые пространства портов**. TCP-порт 8080 и UDP-порт 8080 — это два разных порта, они не конфликтуют между собой.
- Порт 0 зарезервирован и обычно не используется для обычной связи, поэтому фактически доступных портов 65535.

## Почему это не означает, что «одновременно может быть только 65535 соединений»?

Многие ошибочно полагают, что количество портов ограничивает количество соединений. На самом деле **порт — это локальный адресный идентификатор транспортного уровня**, а соединение однозначно определяется **четырёхэлементной группой**:

> (исходный IP, исходный порт, целевой IP, целевой порт)

Пока четырёхэлементная группа уникальна, соединение может быть установлено. Следовательно:
- Как **сервер**: один и тот же локальный порт (например, 80) может одновременно принимать соединения от десятков тысяч клиентов, поскольку исходные IP/порты клиентов различаются.
- Как **клиент**: если целевые IP/порты различаются, локальный порт может быть повторно использован в разных соединениях.

Таким образом, 65536 — это **количество номеров портов**, а не жёсткий предел количества соединений.

## Что означает «ограничение портов» на практике?

Хотя теоретически существует 65536 номеров портов, на практике одновременно используемое количество портов обычно значительно меньше, главным образом из-за:

| Уровень ограничения | Описание |
|---------------------|----------|
| Привилегированные порты | Порты 0–1023 обычно зарезервированы для системных служб |
| Зарегистрированные порты | Порты 1024–49151 выделяются IANA для конкретных приложений |
| Эфемерные порты | Порты 49152–65535 динамически выделяются операционной системой для клиентских соединений |
| Ограничения ОС/приложений | Например, в Windows по умолчанию `MaxUserPort` равен 5000 (можно изменить до 65534); фактический предел также зависит от файловых дескрипторов, памяти и других ресурсов |

## Дополнение, связанное с C++

В сетевом программировании на C++ при вызове `bind()` для привязки порта тип порта обычно равен `unsigned short` (16 бит), что полностью соответствует 16-битному полю порта протокола. Если вы попытаетесь передать значение больше 65535, произойдёт переполнение или усечение, что приведёт к непредвиденному поведению. Поэтому **на уровне кода не существует понятия «более 65536 портов»**, если только вы не разрабатываете собственный протокол прикладного уровня для обхода ограничений транспортного уровня.

**Краткий ответ**: в TCP/UDP максимальное количество портов составляет **65536** (0–65535), это определяется 16-битным полем протокола; TCP и UDP учитываются раздельно, фактически доступно 65535 (порт 0 зарезервирован).
