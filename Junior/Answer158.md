## 158. Стандартные файловые дескрипторы процесса

В операционных системах семейства UNIX/Linux каждый процесс при запуске автоматически получает три открытых файловых дескриптора, которые называются **стандартными потоками ввода-вывода**. Они имеют фиксированные номера и предназначены для организации базового взаимодействия программы с внешним миром.

### Таблица стандартных дескрипторов

| Номер | Имя потока | Назначение | Макрос в C/C++ | Поток в C++ |
| :--- | :--- | :--- | :--- | :--- |
| **0** | Стандартный ввод (stdin) | Чтение входных данных (по умолчанию с клавиатуры/терминала) | `STDIN_FILENO` | `std::cin` |
| **1** | Стандартный вывод (stdout) | Запись результатов работы программы (по умолчанию на экран/терминал) | `STDOUT_FILENO` | `std::cout` |
| **2** | Стандартный вывод ошибок (stderr) | Запись диагностических сообщений и ошибок (по умолчанию на экран/терминал) | `STDERR_FILENO` | `std::cerr` |

### Ключевые особенности и различия

**1. Уровни абстракции: FILE* vs Дескрипторы**
Важно различать стандартные дескрипторы и стандартные потоки C/C++.
*   **Файловые дескрипторы** (числа `0`, `1`, `2`) — это низкоуровневый интерфейс ядра ОС. Для работы с ними в C используются системные вызовы `read()`, `write()`, `close()`.
*   **Потоки (`stdin`, `stdout`, `stderr`)** — это высокоуровневые обёртки (тип `FILE*` в C) с буферизацией. В C++ предпочтительнее использовать объекты `std::cin`, `std::cout`, `std::cerr`.
*   Связь между ними можно получить через функцию `fileno(stdin)`, которая вернёт `0` (это POSIX-расширение, не входит в стандарт C).

**2. Буферизация**
Поведение стандартных потоков при выводе различается, что критично для отладки:
*   **`stdout`** обычно **буферизован**. При выводе в терминал используется построчная буферизация (данные появляются при встрече `\n` или при переполнении буфера). При перенаправлении в файл или канал буферизация может быть полной (блоками).
*   **`stderr`** **не буферизован**. Это сделано для того, чтобы сообщения об ошибках появлялись немедленно, даже если программа аварийно завершилась до сброса буфера `stdout`.

### Как посмотреть стандартные дескрипторы в Linux

Вы можете увидеть, куда именно указывают стандартные дескрипторы конкретного процесса, заглянув в виртуальную файловую систему `proc`. Для этого используется каталог `/proc/[PID]/fd/`.

Например, для текущего процесса (вашей оболочки) можно выполнить команду, которая покажет символические ссылки:
```bash
ls -l /proc/self/fd/
```
Вывод обычно выглядит так (где `0`, `1`, `2` — это номера дескрипторов, а справа — куда они ведут):
```text
lrwx------ 1 user user 64 Oct 28 10:00 0 -> /dev/pts/0
lrwx------ 1 user user 64 Oct 28 10:00 1 -> /dev/pts/0
lrwx------ 1 user user 64 Oct 28 10:00 2 -> /dev/pts/0
```
В данном примере все три потока направлены на псевдотерминал (`/dev/pts/0`).

### Перенаправление (Redirection)

Главная сила стандартных дескрипторов в том, что их можно переназначать до запуска программы с помощью командной оболочки (shell).

*   `program > file.txt` — перенаправляет **stdout** (1) в файл. Программа не будет ничего печатать на экран.
*   `program 2> error.log` — перенаправляет **stderr** (2) в файл (полезно для отделения ошибок от нормального вывода).
*   `program < input.txt` — перенаправляет **stdin** (0) на чтение из файла.
*   `program > out.txt 2>&1` — перенаправляет **stdout** в файл, а затем перенаправляет **stderr** туда же, куда указывает **stdout** (то есть в файл `out.txt`).

### Итог для ответа на экзамене/собеседовании

Стандартные файловые дескрипторы — это числа `0`, `1` и `2`, которые ядро назначает процессу для ввода, вывода и вывода ошибок соответственно. В C++ для работы с ними используются объекты `std::cin`, `std::cout` и `std::cerr`, которые являются буферизованными обёртками. Ключевое отличие `cerr` от `cout` заключается в отсутствии буферизации, что гарантирует немедленный вывод сообщений об ошибках.
