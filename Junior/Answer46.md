# Вопрос 46. Что такое указатель?

> **Кратко:** указатель — это объект, значением которого является адрес другого объекта или функции. Тип указателя включает тип указываемой сущности, поэтому разыменование и арифметика интерпретируют память правильно. Указатели дают косвенный доступ к данным, позволяют передавать крупные объекты без копирования и строить динамические структуры, но требуют внимания к времени жизни: висячие указатели и утечки — главный источник ошибок в C и C++.

---

## Определение и модель памяти

Память процесса — линейное адресное пространство, каждый байт которого имеет номер. Указатель хранит такой номер, но не как «просто число», а вместе с типом:

- `int* p` — «указатель на `int`», а `*p` — lvalue этого типа, то есть сам объект;
- `&x` даёт адрес `x`, и типы `p` и `&x` совпадают;
- `nullptr` — значение «никуда не указывает».

Указатель — самостоятельный объект: у него есть собственный адрес, его можно копировать, менять и хранить в контейнере. Этим он принципиально отличается от ссылки.

---

## Размер и представление

```cpp
#include <iostream>

int main() {
    int x = 42;
    int* p = &x;

    std::cout << sizeof(p) << '\n';   // 8 на 64-битной платформе, 4 на 32-битной
    std::cout << *p << '\n';          // 42 — разыменование
    *p = 43;                          // запись через указатель меняет сам x
    std::cout << &p << '\n';          // адрес самого указателя, не равный p
}
```

Размер не фиксирован стандартом: на массовых платформах `sizeof(T*)` равен размеру машинного слова и одинаков для всех объектных типов, но указатель на функцию может иметь другое представление.

---

## Базовые операции

| Операция | Смысл | Пример |
|---|---|---|
| `&obj` | получить адрес объекта | `int* p = &x;` |
| `*p` | разыменовать, получить объект | `*p = 10;` |
| `p->member` | доступ к члену через указатель | `ptr->size()` |
| `p + n` | сдвиг на `n` элементов, не байт | `p + 1` смещает на `sizeof(T)` |
| `q - p` | число элементов между указателями | результат `std::ptrdiff_t` |
| `p == q`, `p < q` | сравнение адресов | поиск, сортировка |
| `nullptr` | «не указывает никуда» | проверка перед разыменованием |

Арифметика определена только внутри массива, включая адрес «на один за последним»; выход за эти границы — undefined behavior.

## Указатели и массивы

```cpp
int a[5] = {1, 2, 3, 4, 5};
int* p = a;                                     // распад массива до указателя на элемент 0
int third = *(p + 2);                           // 3: сдвиг на 2 * sizeof(int) байт
int same  = p[2];                               // то же: p[i] эквивалентно *(p + i)
static_assert(sizeof(a) == 5 * sizeof(int));    // 20 байт — размер всего массива
// sizeof(p) == 8 — размер указателя, длина массива потеряна
(void)third; (void)same;
```

Массив в параметре функции тоже распадается до указателя: `void f(int data[10])` — это `void f(int*)`, поэтому размер передают отдельным аргументом или используют `std::span` (C++20). Указатель `a + 5` допустим как адрес за последним элементом, но разыменовывать его нельзя.

## Указатели и ссылки

| Свойство | Указатель | Ссылка |
|---|---|---|
| Может быть «нулевым» | да, `nullptr` | нет: обязана ссылаться на объект |
| Можно переприсвоить | да | нет, привязка навсегда |
| Арифметика | есть | нет |
| `sizeof` | размер указателя | размер объекта |
| `&` | адрес самого указателя | адрес объекта, на который ссылается |

```cpp
void swapPtr(int* a, int* b) { int t = *a; *a = *b; *b = t; }
// swapPtr(&x, &y) — по вызову видно, что аргументы могут измениться
```

## const и указатели

```cpp
int value = 10;

const int* p1 = &value;         // указатель на const int: *p1 = 5 нельзя, p1 = &other можно
int* const p2 = &value;         // const-указатель: p2 = &other нельзя, *p2 = 5 можно
const int* const p3 = &value;   // нельзя ни то, ни другое
```

Правило чтения: `const` слева от `*` относится к данным, справа — к самому указателю.

## nullptr против NULL и 0

```cpp
void f(int);
void f(void*);

f(0);         // f(int): 0 — целочисленная константа
f(nullptr);   // f(void*): явный нулевой указатель типа std::nullptr_t
// f(NULL)     — в зависимости от определения NULL возможна неоднозначность
```

`nullptr` введён в C++11: у него собственный тип `std::nullptr_t`, он неявно преобразуется к любому указательному типу, но не к целочисленному. `NULL` — макрос, обычно `0` или `0L`, поэтому в перегрузках ведёт себя как число.

## Опасности

- **Висячий указатель (dangling):** объект разрушен, адрес остался.
- **Use-after-free:** обращение к памяти после `delete`/`free`.
- **Двойное освобождение** и `delete` указателя не на начало блока.
- **Неинициализированный указатель:** читает мусор со стека.
- **Утечка:** указатель потерян, память не освобождена.

```cpp
int* bad() {
    int local = 5;
    return &local;                 // адрес локальной переменной — висячий указатель
}

void useAfterFree() {
    int* p = new int(1);
    delete p;
    *p = 2;                        // use-after-free: UB
}
```

## Виды указателей

| Вид | Пример | Назначение |
|---|---|---|
| Указатель на объект | `int*` | адрес переменной или элемента |
| Указатель на `const` | `const int*` | доступ только на чтение |
| `void*` | `void*` | нетипизированный адрес, нужен обратный `cast` |
| Указатель на функцию | `void (*cb)(int)` | колбэки, таблицы переходов |
| Указатель на член класса | `int C::*` | смещение внутри объекта |
| Умный указатель | `std::unique_ptr<T>` | владение с автоматическим освобождением |

`void*` нельзя разыменовать напрямую, но в нём можно хранить адрес любого объекта и потом привести обратно — на этом построен `malloc`.

---

## Умные указатели — замена владеющему сырому указателю

```cpp
#include <memory>

auto up = std::make_unique<int>(42);   // единственный владелец, освободит память сам
auto sp = std::make_shared<int>(42);   // разделяемое владение со счётчиком ссылок
std::weak_ptr<int> wp = sp;            // наблюдает, не продлевает время жизни
```

Идиома современного C++: сырой указатель означает «наблюдаю, не владею», а владение выражается `unique_ptr`/`shared_ptr`. Утечки и двойное освобождение становятся структурно маловероятными.

---

## Типичные ошибки

1. **Возврат адреса локальной переменной** — указатель висячий сразу после возврата.
2. **Разыменование `nullptr`** — UB, а не исключение; проверка обязательна, если указатель может быть нулевым.
3. **Путать `p` и `&p`** при передаче в функцию, ожидающую `T**`.
4. **Считать `sizeof(ptr)` размером массива** — после распада длина неизвестна.
5. **Смешивать владение и наблюдение:** два владельца одного сырого указателя и двойной `delete`.
6. **Забывать `delete`/`free`** или применять `delete` к массиву без `[]`.

---

## Что добавить на собеседовании

- Указатель — это адрес **плюс тип**; тип определяет, сколько байт читать и на сколько сдвигаться, поэтому `void*` требует явного приведения.
- В C++ указатели почти всегда означают наблюдение, а владение выражается умными указателями и контейнерами (RAII, правило нуля).
- Практическое правило: после `delete`/`free` обнулять указатель и не хранить «полувалидные» адреса.

## Итог

| Вопрос | Ответ |
|---|---|
| Что это | Объект, хранящий адрес другого объекта или функции |
| Что в типе | Тип указываемой сущности плюс сам факт «указатель» |
| Размер | Размер машинного слова (8 байт на 64-битной платформе) |
| Ключевые операции | `&`, `*`, `->`, `+`/`-` в пределах массива, сравнение |
| Отличие от ссылки | Может быть нулевым, переприсваивается, поддерживает арифметику |
| Нулевое значение | `nullptr` (C++11), а не `NULL` и не `0` |
| Главные риски | Висячие указатели, утечки, выход за границы, use-after-free |
| Современная практика | Сырой указатель — наблюдение; владение — `unique_ptr`/`shared_ptr` |
