# 132. Разница между мьютексом и семафором

Оба примитива синхронизации используются для организации доступа к общим ресурсам из нескольких потоков/процессов, но имеют принципиально разную природу и область применения.

## Основное различие

| Характеристика | Мьютекс (mutex) | Семафор (semaphore) |
|---|---|---|
| **Назначение** | Взаимное исключение (mutual exclusion) | Управление доступом к ресурсам, сигнализация |
| **Счётчик** | Бинарный: занят / свободен | Целочисленный счётчик (может быть > 1) |
| **Владелец** | Есть понятие «владельца»: блокировать/освобождать должен один и тот же поток | Понятия владельца нет: один поток может уменьшить счётчик, другой — увеличить |
| **Повторный захват** | Обычно не рекурсивный (std::mutex): повторный lock тем же потоком — UB/дедлок. Бывает рекурсивный (std::recursive_mutex) | Нет понятия повторного захвата |
| **Освобождение из другого потока** | Нельзя (для std::mutex) | Можно |
| **Типичные операции** | `lock()` / `unlock()` | `wait()` (P, down) / `post()` (V, up) |
| **Значения** | 0 или 1 (занят/свободен) | 0..N |

## Подробнее о мьютексе

- Реализует **взаимное исключение**: гарантирует, что критическую секцию в каждый момент выполняет не более одного потока.
- Обычно связан с потоком-владельцем: только поток, захвативший мьютекс, имеет право его освободить. Это позволяет реализовать дополнительные механизмы (например, `std::condition_variable` работает именно с мьютексом).
- Часто поддерживает **priority inheritance** (наследование приоритета) для борьбы с инверсией приоритетов — это важно в системах реального времени.
- В C++: `std::mutex`, `std::recursive_mutex`, `std::timed_mutex`, `std::shared_mutex` (RW-lock).

```cpp
#include <mutex>

std::mutex m;
int shared_counter = 0;

void increment() {
    std::lock_guard<std::mutex> lock(m); // захват
    ++shared_counter;
} // автоматическое освобождение при выходе из области видимости
```

## Подробнее о семафоре

- Содержит **счётчик**. Операция `wait()` (P) уменьшает счётчик; если он равен 0 — блокирует поток. Операция `post()` (V) увеличивает счётчик и будит ожидающий поток.
- **Два вида**:
  - *Считающий (counting)* — счётчик может быть > 1: ограничивает число одновременных «держателей» ресурса (например, пул из N соединений).
  - *Бинарный (binary)* — счётчик 0/1. Внешне похож на мьютекс, но **без владельца** и без наследования приоритета.
- Используется также для **сигнализации между потоками** (например, producer–consumer: `post()` говорит «данные готовы»).
- В C++20: `std::counting_semaphore<N>`, `std::binary_semaphore`.

```cpp
#include <semaphore>
#include <thread>

// Ограничиваем одновременный доступ к ресурсу 3 потоками
std::counting_semaphore<3> sem(3);

void worker() {
    sem.acquire();   // wait / P
    // ... работа с ресурсом (не более 3 потоков одновременно) ...
    sem.release();   // post / V
}
```

Пример сигнализации:

```cpp
std::binary_semaphore ready{0};

// Поток-производитель
ready.release();  // сообщаем, что данные готовы

// Поток-потребитель
ready.acquire();  // ждём сигнала
```

## Ключевые отличия в практике

1. **Владение.** Мьютекс — про «кто держит», семафор — про «сколько доступно». Именно поэтому мьютекс нельзя (в общем случае) освободить из чужого потока, а семафор — можно.
2. **Инверсия приоритетов.** Мьютексы обычно её решают (priority inheritance), семафоры — нет.
3. **Мьютекс нельзя использовать для сигнализации** корректно из другого потока (в C++ — нельзя unlock из другого потока). Для «разбудить другой поток» применяют condition_variable или семафор.
4. **Семафор — более общий примитив**: бинарный семафор может эмулировать мьютекс (но без владельца и priority inheritance), а мьютекс не может эмулировать считающий семафор.
5. **Производительность.** Мьютекс обычно оптимизирован под кратковременные критические секции (futex, spinlock-гибриды). Семафор — под более общие сценарии.

## Когда что выбирать

- **Мьютекс** — защита критической секции, разделяемых данных, инвариантов объекта; работа совместно с `condition_variable`.
- **Семафор** — ограничение количества одновременных исполнителей (пул ресурсов, throttling), сигнализация о событиях, producer–consumer с буфером ограниченного размера (хотя в C++ чаще берут condition_variable + очередь).

## Краткая формулировка для ответа

> Мьютекс — это бинарный примитив взаимного исключения с понятием владельца, предназначенный для защиты критических секций: захватить и освободить его должен один и тот же поток. Семафор — это счётчик (возможно, больше единицы) без владельца, реализующий операции wait/post: он ограничивает число одновременных доступов к ресурсу и/или служит для сигнализации между потоками; уменьшать и увеличивать счётчик могут разные потоки. По сути, бинарный семафор может эмулировать мьютекс, но мьютекс не может эмулировать считающий семафор.
