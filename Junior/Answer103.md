# 103. Передача наследника по значению в функцию, принимающая базовый класс

## Краткий ответ

Произойдёт **срезка объекта** (object slicing, «слайсинг»): от объекта-наследника останется только та часть, которая относится к базовому классу. Все дополнительные поля наследника будут «отрезаны», а виртуальные функции будут вызываться как у базового класса (потеряется полиморфизм).

## Подробно

### Что происходит механически

Когда функция объявлена так:

```cpp
void foo(Base b);   // приём по значению
```

а вызывается так:

```cpp
Derived d;
foo(d);
```

компилятор создаёт **новый объект типа `Base`** (копию), инициализируя его копией базовой подобъекта `d`. Для этого используется конструктор копирования `Base(const Base&)`, который «не знает» о полях наследника. В результате:

1. **Копируются только поля базового класса.** Поля, добавленные в `Derived`, теряются.
2. **Тип объекта в функции — `Base`, а не `Derived`.** Внутри `foo` `b` — это полноценный объект `Base`.
3. **Полиморфизм не работает.** Даже если `foo` вызывает виртуальную функцию, переопределённую в `Derived`, вызовется версия `Base`, потому что динамический тип объекта — `Base`.
4. **`dynamic_cast` к `Derived` вернёт `nullptr`** — объекта-наследника внутри функции просто нет.

### Пример

```cpp
#include <iostream>
#include <string>

struct Base {
    int x = 1;
    virtual void print() const { std::cout << "Base: x=" << x << "\n"; }
    virtual ~Base() = default;
};

struct Derived : Base {
    std::string name = "derived";   // доп. поле
    void print() const override { std::cout << "Derived: x=" << x
                                            << ", name=" << name << "\n"; }
};

void byValue(Base b) {           // приём ПО ЗНАЧЕНИЮ
    b.print();                   // вызовется Base::print
}

void byRef(const Base& b) {      // приём по ссылке
    b.print();                   // вызовется Derived::print
}

int main() {
    Derived d;
    d.x = 42;

    byValue(d);      // Вывод: Base: x=42     — name потерян, полиморфизм потерян
    byRef(d);        // Вывод: Derived: x=42, name=derived — всё корректно
}
```

### Почему это опасно

- **Потеря данных**: поля наследника тихо исчезают, программа может работать не так, как задумано, без ошибок компиляции.
- **Нарушение полиморфизма**: переопределённые виртуальные функции не вызываются — классическая ловушка.
- **Трудно заметить**: код компилируется без предупреждений (хотя некоторые компиляторы и статические анализаторы умеют предупреждать о слайсинге).
- **`sizeof`**: внутри функции `sizeof(b)` вернёт размер `Base`, а не `Derived`.

### Как избежать

| Способ | Пример | Комментарий |
|---|---|---|
| Передавать по ссылке | `void foo(const Base& b)` | Предпочтительно, без копирования |
| Передавать по указателю | `void foo(const Base* b)` | Тоже сохраняет полиморфизм |
| Умные указатели | `void foo(const std::unique_ptr<Base>& p)` | Для владеющих объектов |
| Запретить копирование базы | `Base(const Base&) = delete;` | Радикально, но ломает копирование |
| `clone()`-паттерн | виртуальный `clone()` возвращает копию нужного типа | Если нужна именно копия |

**Правило**: если функция принимает полиморфный базовый класс и должна работать с наследниками — принимайте его **по ссылке или указателю**, а не по значению.

### Аналогичная проблема с контейнерами

Тот же слайсинг возникает при попытке хранить наследников в контейнере базового типа:

```cpp
std::vector<Base> v;
v.push_back(Derived{});   // слайсинг! в векторе лежит Base
```

Для полиморфного хранения нужны `std::vector<std::unique_ptr<Base>>` или аналогичные обёртки.
