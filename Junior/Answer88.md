# 88. Можно ли выбрасывать exception из конструктора?

**Да, можно.** В C++ конструктор не является исключением из правил обработки исключений. Более того, это распространённая практика: если объект не может быть корректно инициализирован, конструктор должен сигнализировать об этом, выбросив исключение. Это позволяет избежать создания «полуживых» объектов с невалидным состоянием.

Однако ключевой момент заключается в том, что происходит с уже сконструированными частями объекта при раскрутке стека.

## Что будет сконструировано и что будет разрушено?

Когда из конструктора выбрасывается исключение, объект считается **недостроенным**. Его собственный деструктор (`~ClassName()`) **не вызывается**, поскольку время жизни объекта так и не началось .

Тем не менее, все подобъекты (базовые классы и поля-члены), которые **уже успели успешно сконструироваться** к моменту выброса исключения, будут корректно разрушены в порядке, **обратном порядку их конструирования** .

Порядок конструирования в C++ строго определён:
1.  **Виртуальные базовые классы** (в порядке обхода слева направо и сверху вниз).
2.  **Прямые невиртуальные базовые классы** (в порядке объявления в списке наследования).
3.  **Нестатические поля-члены** (в порядке их объявления в классе).
4.  **Тело конструктора**.

### Примеры сценариев

Рассмотрим класс `Logger`, который содержит поля `config` и `outputFile` :

```cpp
class Logger {
    Config config;
    RotatingFile outputFile;
public:
    Logger(const string& configFile) 
        : config(configFile)      // (1)
        , outputFile(config)      // (2)
    {
        // (3) тело конструктора
        if (some_error) 
            throw std::runtime_error("Init failed"); 
    }
};
```

| Сценарий | Что сконструировано? | Что разрушено? |
| :--- | :--- | :--- |
| **Исключение в конструкторе `config`** | Ничего. | Ничего. `~Logger()` не вызывается. |
| **Исключение в конструкторе `outputFile`** | `config` (поле 1). | Вызывается `~Config()` для поля `config`. `~Logger()` не вызывается. |
| **Исключение в теле `Logger`** | `config` и `outputFile`. | Вызываются `~RotatingFile()` и `~Config()` (в обратном порядке). `~Logger()` не вызывается. |

### Важное замечание про `function-try-block`

Если вы используете `function-try-block` (конструкцию `try : member(init) { ... } catch(...) { ... }`) в конструкторе, есть особенность: к моменту входа в блок `catch` все уже сконструированные поля и базовые классы **уже разрушены** . Поэтому **нельзя** обращаться к нестатическим полям или базовым классам внутри такого `catch`-блока — это приведёт к неопределённому поведению (undefined behavior) .

## Резюме

1.  **Можно ли?** Да, это стандартный способ сообщить о неудаче конструирования.
2.  **Что разрушается?** Только те подобъекты (базы и поля), чьи конструкторы **успешно завершились** до момента выброса исключения.
3.  **Что не разрушается?** Сам объект (его деструктор не вызывается).
4.  **Порядок разрушения:** Строго обратный порядку успешного конструирования.
