# Вопрос 26. Как работает директива define?

> **Кратко:** `#define` создаёт макрос — имя, которое препроцессор заменяет на заданный текст при каждом вхождении в файле. Макросы бывают объектно-подобными (`#define N 10`) и функционально-подобными (`#define F(x) ...`), у которых параметры подставляются по аргументам вызова. Замена чисто текстовая: аргументы предварительно раскрываются, подставляются в тело, а результат сканируется заново — без типов, областей видимости и проверок.

---

## Два вида макросов

```cpp
#define BUFFER_SIZE 4096                    // объектно-подобный: имя → текст
#define SQUARE(x) ((x) * (x))               // функционально-подобный: имя(параметры) → текст
```

Ключевое различие — **скобка**: у функционально-подобного макроса `(` должна идти сразу за именем, без пробела.

```cpp
#define BAD (x) ((x) * (x))
// здесь определено имя BAD с телом "(x) ((x) * (x))" — макрос без параметров
```

Функционально-подобный макрос раскрывается только там, где за именем следует `(`. Если написать `auto p = SQUARE;`, имя останется идентификатором, и компилятор скажет, что такого имени нет.

---

## Алгоритм раскрытия

| Шаг | Что делает препроцессор |
|---|---|
| 1 | собирает аргументы до парной `)`, разделяя их запятыми **только на верхнем уровне скобок** |
| 2 | раскрывает каждый аргумент как самостоятельный текст — кроме параметров, используемых с `#` или `##` |
| 3 | подставляет результат в тело вместо имён параметров |
| 4 | сканирует полученный текст заново вместе с остатком файла и раскрывает новые макросы |

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define LIMIT 10

int m = MAX(LIMIT, y);   // → ((10) > (y) ? (10) : (y))
```

`LIMIT` раскрылся на шаге 2, потому что параметр не используется с `#`/`##`.

---

## Самовложенность запрещена

Макрос не раскрывается внутри собственного раскрытия — иначе подстановка была бы бесконечной.

```cpp
#define SIZE (SIZE + 1)

int x = SIZE;   // → (SIZE + 1): внутренний SIZE уже не раскрывается
```

Это называют «синей краской»: имя, встреченное в процессе своего же раскрытия, помечается и больше не трогается. Поэтому рекурсивные макросы в C++ невозможны, а попытка «посчитать» что-то макросами упирается в этот предел.

---

## Операторы `#` и `##`

**Строкизация** `#` превращает аргумент в строковый литерал; аргумент при этом **не раскрывается**:

```cpp
#define STR_IMPL(x) #x
#define STR(x) STR_IMPL(x)      // двухуровневая обёртка — иначе раскрытия не будет
#define VERSION 1.2

const char* a = STR(VERSION);   // "1.2"
const char* b = STR_IMPL(VERSION); // "VERSION" — аргумент не раскрывался
```

**Склейка** `##` соединяет два соседних токена в один; результат обязан быть корректной лексемой, иначе поведение не определено:

```cpp
#define DECLARE(type, name) \
    type get_##name() const { return name##_; }   // name##_ — склейка: id + _

struct User {
    int id_;
    DECLARE(int, id)     // развернётся в int get_id() const { return id_; }
};
```

## Вариадические макросы

```cpp
#define LOG(fmt, ...) std::printf(fmt, __VA_ARGS__)                // C++11: пакет аргументов
#define LOG2(fmt, ...) std::printf(fmt __VA_OPT__(,) __VA_ARGS__)  // C++20: запятая только при непустом пакете

LOG("value = %d\n", 42);   // std::printf("value = %d\n", 42);
LOG2("start\n");           // без __VA_OPT__ получилась бы лишняя запятая
```

`__VA_ARGS__` подставляет весь пакет, `__VA_OPT__(x)` подставляет `x` только если пакет непуст (для `std::printf` нужен `#include <cstdio>`). До C++20 пустой пакет давал висячую запятую — классическая ошибка переносимых логгеров.

---

## Область действия: её нет

`#define` не подчиняется ни блокам, ни пространствам имён, ни классам:

```cpp
#define max(a, b) ((a) > (b) ? (a) : (b))

int x = std::max(1, 2);   // → std::((1) > (2) ? (1) : (2)) — синтаксическая ошибка
```

Макрос начинает действовать с момента определения и до `#undef` или конца единицы трансляции, в том числе **в файлах, включённых после него**. Отсюда правило: не определять макросы с короткими и «человеческими» именами в заголовках; снимается определение строкой `#undef max`.

---

## Почему макросы опасны

| Проблема | Пример | Что происходит |
|---|---|---|
| Двойное вычисление | `#define SQR(x) ((x)*(x))`, `SQR(i++)` | `i` инкрементируется дважды — UB |
| Приоритет операций | `#define NEG(x) -x`, `NEG(a + b)` | получается `-a + b` |
| Нет скобок вокруг тела | `#define DOUBLE(x) x * 2`, `DOUBLE(a + b)` | `a + b * 2` |
| Запятые в аргументах | `MAX(std::pair<int,int>{1,2}, p)` | препроцессор видит три аргумента |
| Составной оператор | `#define INIT() a = 1; b = 2;` | `if (c) INIT(); else ...` — `else` относится к чужому `if` |
| Отсутствие отладки | любой макрос | в отладочной информации макроса нет, шаг в него невозможен |
| Протекание имён | `#define min(a,b)` в заголовке | ломает `std::min` у всех клиентов |

Аккуратная версия того же макроса выглядит так — и всё равно проигрывает функции:

```cpp
#define SQR(x) ((x) * (x))   // скобки ставим вручную, двойное вычисление остаётся

template <class T>
constexpr T sqr(T x) { return x * x; }   // типобезопасно, аргумент вычисляется один раз
```

Если макрос необходим как оператор (например, проверка условия), его оборачивают в `do { ... } while (false)`, чтобы он вёл себя как один оператор:

```cpp
#include <stdexcept>

#define CHECK(cond)                                                  \
    do { if (!(cond)) throw std::runtime_error(#cond); } while (false)
```

## Чем заменять в современном C++

| Макрос | Замена |
|---|---|
| `#define N 10` | `constexpr int N = 10;` (в заголовке — `inline constexpr`) |
| `#define SQR(x)` | `constexpr`-функция или шаблон функции |
| `#define MIN(a,b)` | `std::min`, `std::clamp` |
| `#define ARRAY_SIZE(a)` | `std::size(a)` |
| `#define LOG(...)` | функция с `std::source_location` (C++20) |
| `#define PI 3.14` | `std::numbers::pi` (C++20) |

---

## Где `#define` действительно уместен

- **include guards** — `#ifndef`/`#define`/`#endif` вокруг заголовка;
- **условная компиляция** — `#ifdef _WIN32`, feature-test-макросы, стандартный `NDEBUG` для `assert`;
- **строкизация и склейка** — единственный способ получить имя сущности строкой (`#x`) или собрать идентификатор (`a##b`);
- **диагностика места вызова** — `__FILE__`, `__LINE__` и макросы вокруг них (до `std::source_location`);
- **кодогенерация** — X-макросы со списком полей или команд.

---

## Типичные ошибки

1. **Пробел перед `(`** в определении функционального макроса — макрос перестаёт принимать аргументы.
2. **Отсутствие скобок** вокруг параметров и всего тела — самая частая причина «макрос работает не так».
3. **Макрос с побочными эффектами в аргументе** — `SQR(i++)`, `MAX(f(), g())`.
4. **Короткие имена в заголовке** (`min`, `max`, `small`, `check`) — протекают к клиентам и ломают их код.
5. **Точка с запятой в конце `#define`** — она попадёт в подстановку: `#define N 10;`.
6. **Макрос вместо константы или функции** там, где хватает `constexpr`/`inline`.

---

## Что добавить на собеседовании

- Точно описать конвейер: сбор аргументов → предраскрытие → подстановка → rescan; именно поэтому `STR(VERSION)` нужно оборачивать в два макроса.
- Объяснить, что `#` и `##` блокируют предраскрытие аргумента — это неочевидно и часто спрашивается.
- Сказать, что макрос не имеет области видимости, не проверяется на типы и не виден отладчику, и что он действует на всё, что включено после него.
- Привести правило «макрос — только то, что нельзя выразить средствами языка», и назвать `constexpr`, шаблоны, `std::source_location`, `__VA_OPT__` как современную замену.
