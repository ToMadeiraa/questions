# 84. Ленивые вычисления в C++

**Ленивые вычисления (lazy evaluation)** — это стратегия вычислений, при которой выражение не вычисляется до тех пор, пока его результат действительно не понадобится. В отличие от энергичных (eager) вычислений, где значение вычисляется сразу в момент определения, ленивый подход откладывает работу и позволяет избежать ненужных затрат, если результат так и не будет использован .

В C++ ленивые вычисления не являются встроенной семантикой языка по умолчанию (в отличие, например, от Haskell), однако существует несколько механизмов и идиом, позволяющих реализовать эту стратегию на разных уровнях.

---

## 1. Встроенные формы ленивых вычислений

### 1.1. Короткое замыкание логических операторов

Самый простой и фундаментальный пример ленивости в C++ — это поведение операторов `&&`, `||` и тернарного оператора `?:`. Они вычисляют операнды слева направо и останавливаются, как только результат становится известен:

```cpp
if (ptr != nullptr && ptr->value > 10) {
    // если ptr == nullptr, второе условие не вычисляется
}
```

Это встроено в язык и позволяет избегать дорогостоящих или опасных операций, таких как разыменование нулевого указателя .

### 1.2. Отложенное выполнение в `std::async`

Стандартная библиотека предоставляет явный механизм ленивого запуска задачи через `std::async` с политикой `std::launch::deferred`:

```cpp
auto future = std::async(std::launch::deferred, [] {
    return expensive_computation();
});

// expensive_computation() НЕ вызывается здесь

// Вызов get() или wait() запускает вычисление в текущем потоке
auto result = future.get();
```

При использовании `deferred` задача не выполняется в отдельном потоке; она откладывается до первого вызова `get()` или `wait()` на возвращённом `std::future`. Повторные обращения возвращают уже готовый результат мгновенно .

### 1.3. Ленивые диапазоны (C++20 Ranges)

Представления (views) в C++20 позволяют строить цепочки преобразований без немедленного создания промежуточных контейнеров. Например, `std::views::filter` и `std::views::transform` не выполняют никаких действий при создании, а вычисляют элементы по мере итерации:

```cpp
auto even_squares = numbers 
    | std::views::filter([](int n) { return n % 2 == 0; })
    | std::views::transform([](int n) { return n * n; });

// Фильтрация и возведение в квадрат происходят только при обходе even_squares
```

Это классический пример ленивой композиции, которая экономит память и вычисления .

## 2. Идиомы и паттерны реализации ленивости

Помимо встроенных механизмов, ленивые вычисления в C++ реализуются через несколько распространённых паттернов.

### 2.1. Ленивые значения через лямбды и кэширование (мемоизация)

Обёртка, которая хранит лямбду и вычисляет её результат только при первом обращении, а затем кэширует:

```cpp
template <typename F>
class LazyValue {
    mutable std::optional<decltype(std::declval<F>()())> cache;
    F compute;
public:
    explicit LazyValue(F f) : compute(std::move(f)) {}
    
    const auto& get() const {
        if (!cache) {
            cache = compute();
        }
        return *cache;
    }
};
```

Этот подход полезен для дорогих вычислений, результат которых может быть использован многократно или не использован вовсе .

### 2.2. Выражения-шаблоны (Expression Templates)

Используются в библиотеках линейной алгебры (например, Eigen) для отложенного построения выражений. Вместо вычисления промежуточных матриц оператор `+` или `*` возвращает лёгкий объект-«рецепт», который материализуется только при присваивании результата:

```cpp
// C = A + B + C теоретически может быть вычислено за один проход
// без создания временных матриц для (A + B)
```

Это позволяет компилятору или библиотеке оптимизировать всю цепочку выражений целиком .

### 2.3. Ленивая инициализация (Lazy Initialization)

Создание объекта или загрузка ресурса откладывается до первого обращения. В C++ это часто реализуется через локальные статические переменные (которые инициализируются потокобезопасно начиная с C++11), `std::call_once` или умные указатели:

```cpp
// Потокобезопасная ленивая инициализация
static MyResource& getInstance() {
    static MyResource instance; // создаётся при первом вызове
    return instance;
}
```

Используется для тяжёлых объектов, которые могут не понадобиться в данной сессии программы .

## 3. Преимущества и недостатки

**Преимущества:**
- Избегание ненужных вычислений, если результат не используется.
- Возможность работать с потенциально бесконечными последовательностями (генераторы, ленивые списки).
- Экономия памяти за счёт отсутствия промежуточных контейнеров.
- Разделение описания вычисления и момента его выполнения.

**Недостатки и риски:**
- Накладные расходы на индирекцию (проверка флага, вызов лямбды), которые могут быть неоправданны для дешёвых операций.
- Непредсказуемый порядок побочных эффектов, если вычисление откладывается.
- Сложность отладки и понимания времени жизни захваченных ссылок в лямбдах.
- Возможные утечки ресурсов или взаимные блокировки при неаккуратной ленивой инициализации в многопоточной среде .

---

## Резюме

Ленивые вычисления в C++ — это не единая языковая конструкция, а набор подходов, позволяющих отложить выполнение до момента необходимости. Базовый уровень обеспечивают короткое замыкание и тернарный оператор; стандартная библиотека добавляет `std::async` с `deferred` и ленивые диапазоны; продвинутые техники включают лямбды с кэшированием, выражения-шаблоны и ленивую инициализацию. Выбор конкретного механизма зависит от задачи: для асинхронных операций подходит `std::async`, для обработки последовательностей — Ranges, для оптимизации математических выражений — expression templates, а для общих случаев отсрочки — обёртки на основе лямбд.
