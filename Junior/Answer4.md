# Вопрос 4. Объясните такие структуры данных, как стек и очередь.

> **Кратко:** Стек и очередь — это **абстрактные типы данных**, то есть наборы операций с правилом доступа, а не конкретный способ хранения. Стек работает по принципу **LIFO** (последним пришёл — первым вышел), очередь — по принципу **FIFO** (первым пришёл — первым вышел). Обе структуры реализуются и на массиве, и на связном списке, но выбор реализации определяет кэш-локальность, стоимость роста и стабильность ссылок на элементы.

---

## 1. Стек (LIFO)

Стек — структура, в которой добавление и извлечение возможны только с одного конца, называемого **вершиной** (top).

| Операция | Смысл | Сложность |
|---|---|---|
| `push(x)` | положить на вершину | `O(1)` |
| `pop()` | снять с вершины | `O(1)` |
| `top()` / `peek()` | посмотреть вершину без снятия | `O(1)` |
| `empty()` / `size()` | пустота и количество | `O(1)` |

**Реализации:** на массиве (или `std::vector`) вершина — последний элемент, `push_back` амортизированно `O(1)`, лучшая кэш-локальность; на связном списке — `push_front` за `O(1)`, но каждая операция тянет аллокацию узла и «прыжки» по памяти.

```cpp
#include <stdexcept>
#include <vector>

// Стек фиксированной ёмкости: переполнение — контролируемая ошибка, а не UB
class IntStack {
public:
    explicit IntStack(std::size_t capacity) : data_(capacity) {}

    void push(int value) {
        if (size_ == data_.size()) throw std::overflow_error("overflow");
        data_[size_++] = value;                  // вершина — data_[size_ - 1]
    }
    int pop() {
        if (empty()) throw std::underflow_error("empty");
        return data_[--size_];
    }
    int top() const {
        if (empty()) throw std::underflow_error("empty");
        return data_[size_ - 1];
    }
    bool empty() const { return size_ == 0; }

private:
    std::vector<int> data_;
    std::size_t size_ = 0;
};
```

Аналог из стандартной библиотеки — `std::stack`, адаптер над `std::deque`.

## 2. Очередь (FIFO)

Очередь добавляет элементы в **хвост** (back) и извлекает из **головы** (front).

| Операция | Смысл | Сложность |
|---|---|---|
| `push(x)` / `enqueue` | в хвост | `O(1)` |
| `pop()` / `dequeue` | из головы | `O(1)` |
| `front()` / `back()` | первый / последний элемент | `O(1)` |

Наивная реализация на массиве плоха: сдвиг всех элементов после каждого `pop` даёт `O(n)`. Правильное решение — **кольцевой буфер** с двумя индексами.

```cpp
#include <stdexcept>
#include <vector>

// Кольцевой буфер: голова и хвост ходят по кругу, сдвига элементов нет
class RingQueue {
public:
    explicit RingQueue(std::size_t capacity) : buf_(capacity + 1) {}  // слот в резерв

    void push(int value) {
        std::size_t next = (tail_ + 1) % buf_.size();
        if (next == head_) throw std::overflow_error("queue is full");
        buf_[tail_] = value;
        tail_ = next;
    }
    int pop() {
        if (head_ == tail_) throw std::underflow_error("queue is empty");
        int value = buf_[head_];
        head_ = (head_ + 1) % buf_.size();
        return value;
    }

private:
    std::vector<int> buf_;
    std::size_t head_ = 0;   // индекс головы
    std::size_t tail_ = 0;   // куда писать следующий элемент
};
```

Альтернативы: связный список с указателями на голову и хвост (`O(1)` без фиксированной ёмкости) и `std::deque` — набор блоков фиксированного размера.

## 3. Адаптеры стандартной библиотеки

`std::stack`, `std::queue` и `std::priority_queue` — **адаптеры контейнеров**: они не хранят данные сами, а оборачивают готовый контейнер и ограничивают его интерфейс.

| Адаптер | Контейнер по умолчанию | Требования к контейнеру |
|---|---|---|
| `std::stack<T>` | `std::deque<T>` | `back()`, `push_back()`, `pop_back()` |
| `std::queue<T>` | `std::deque<T>` | `front()`, `back()`, `push_back()`, `pop_front()` |
| `std::priority_queue<T>` | `std::vector<T>` | произвольный доступ + алгоритмы кучи |

```cpp
std::stack<int, std::vector<int>> st;   // контейнер — второй параметр шаблона
st.push(1);
int top = st.top();                     // 1 — пришёл последним
std::queue<int> q;                      // FIFO: front() — первый пришедший
q.push(1);
int front = q.front();                  // 1
```

> `pop()` у адаптеров ничего не возвращает: значение сначала получают через `top()`/`front()`. Так проще давать строгие гарантии безопасности исключений.

## 4. Где применяются

| Стек | Очередь |
|---|---|
| Стек вызовов функций, кадры, локальные переменные | Обход графа и дерева в ширину (BFS) |
| Проверка парности скобок, разбор выражений, ОПЗ | Планировщики задач, пул потоков |
| Отмена действий (undo), история навигации | Буферы ввода-вывода, сетевые пакеты |
| Обход в глубину в итеративной форме | Очередь сообщений, обработка событий |

Родственные структуры: **дек** (`std::deque`) — вставка и удаление с обоих концов за `O(1)`; **очередь с приоритетом** — извлекается максимальный элемент за `O(log n)`; **монотонный стек** — выталкивает «ненужные» элементы (задача «следующий больший элемент»); **блокирующая очередь** — `push`/`pop` ждут на мьютексе и `condition_variable`, основа producer-consumer.

## 5. Очередь на двух стеках

Классическое мини-задание: очередь из двух стеков — `in_` для добавления и `out_` для извлечения. Переливание происходит только когда `out_` пуст, поэтому каждая операция амортизированно `O(1)`.

```cpp
#include <stack>
#include <utility>

template <typename T>
class QueueOfStacks {                     // FIFO, собранная из двух LIFO
public:
    void push(T v) { in_.push(std::move(v)); }
    T pop() {
        if (out_.empty())                 // переливаем только по необходимости
            while (!in_.empty()) { out_.push(std::move(in_.top())); in_.pop(); }
        T v = std::move(out_.top());      // порядок восстановлен
        out_.pop();
        return v;
    }
private:
    std::stack<T> in_, out_;
};
```

## 6. Практические замечания

- **Переполнение стека вызовов** — это не про `std::stack`, а про стек потока: глубокая рекурсия исчерпывает ограниченный объём (обычно единицы мегабайт), итеративная версия на `vector` безопаснее.
- **Кольцевой буфер и условие «пусто/полно»**: если хранить только `head` и `tail`, приходится жертвовать одним слотом либо держать счётчик.
- **Перевыделение в `std::stack` на `vector`** инвалидирует ссылки, полученные ранее из `top()`.
- **Потокобезопасности нет**: адаптеры STL не синхронизированы, для producer-consumer нужен мьютекс и `std::condition_variable`.

---

## Типичные ошибки

1. **Путать `std::stack` с «стеком» как областью памяти** — совпадает только дисциплина доступа.
2. **Реализовывать очередь на массиве со сдвигом** — `pop` за `O(n)` вместо `O(1)`.
3. **Вызывать `top()`/`front()` у пустой структуры** — у STL это UB, а не исключение.
4. **Ожидать, что `pop()` вернёт значение** — он возвращает `void`.
5. **Рассчитывать на итераторы у адаптеров** — их намеренно нет.
6. **Ошибка на единицу в кольцевом буфере**: пусто `head == tail`, полно `(tail + 1) % size == head` — нужен отдельный слот.
7. **Рекурсия вместо явного стека** там, где глубина не ограничена сверху.

---

## Что добавить на собеседовании

- Подчеркнуть разницу между **ADT и реализацией**: LIFO/FIFO — контракт операций, а не «массив» или «список».
- Упомянуть, что `std::stack` и `std::queue` — **адаптеры**, и контейнер можно подменить: `std::stack<int, std::vector<int>>`.
- Знать амортизированную сложность `push_back` у `vector` и объяснить, почему стек на `vector` обычно быстрее списка.
- Быть готовым написать **кольцевой буфер** и **очередь на двух стеках** — стандартные мини-задания; на практике BFS идёт на очереди, DFS — на стеке.

## Итог

| Критерий | Стек | Очередь |
|---|---|---|
| Принцип | LIFO | FIFO |
| Вход и выход | Один и тот же конец | Разные концы |
| Операции | `push`, `pop`, `top` | `push`, `pop`, `front`, `back` |
| Сложность операций | `O(1)` | `O(1)` |
| Хранение | Массив, `vector`, список | Кольцевой буфер, `deque`, список |
| STL | `std::stack` (адаптер) | `std::queue` (адаптер) |
| Применение | Рекурсия, undo, скобки, DFS | BFS, планировщики, буферы, сообщения |
