# 113. Виртуальный деструктор в C++

## Краткий ответ

Виртуальный деструктор используется для **корректного удаления объектов производных классов через указатель (или ссылку) на базовый класс**. Без него при удалении полиморфного объекта через указатель базового типа вызывается только деструктор базового класса, что приводит к **неопределённому поведению** и **утечкам ресурсов** (утечки памяти, незакрытые файлы, неосвобождённые дескрипторы и т.п.).

## Проблема, которую он решает

Рассмотрим пример **без** виртуального деструктора:

```cpp
#include <iostream>

class Base {
public:
    Base()  { std::cout << "Base ctor\n"; }
    ~Base() { std::cout << "Base dtor\n"; }   // НЕ виртуальный!
};

class Derived : public Base {
public:
    Derived()  { std::cout << "Derived ctor\n"; }
    ~Derived() { std::cout << "Derived dtor\n"; }
};

int main() {
    Base* p = new Derived();
    delete p;   // Вызывается только ~Base()!
}
```

Вывод:

```
Base ctor
Derived ctor
Base dtor
```

Деструктор `Derived` **не был вызван** — это неопределённое поведение (undefined behavior). Если `Derived` владеет ресурсами (динамическая память, файлы, мьютексы), они не освобождаются.

## Решение: сделать деструктор виртуальным

```cpp
class Base {
public:
    virtual ~Base() = default;   // виртуальный деструктор
};
```

Теперь при `delete p;` (где `p` — `Base*`, указывающий на `Derived`) механизм виртуальных функций вызовет **сначала** `~Derived()`, **затем** автоматически `~Base()`. Вывод:

```
Base ctor
Derived ctor
Derived dtor
Base dtor
```

## Когда нужен виртуальный деструктор

Виртуальный деструктор **обязателен**, если:

1. Класс предназначен для использования в качестве **базового** в иерархии наследования (полиморфный базовый класс).
2. Объекты производных классов могут **удаляться через указатель/ссылку на базовый класс** (например, хранятся в `std::vector<std::unique_ptr<Base>>` или `std::vector<Base*>`).

## Когда он не нужен

- Если класс **не наследуется** (помечен `final`) — виртуальный деструктор не нужен.
- Если удаление всегда происходит через указатель на **точный** тип объекта.
- Если класс не является полиморфным базовым классом — не стоит добавлять виртуальность «на всякий случай»: это добавляет vptr и накладные расходы.

## Важные нюансы

### 1. Деструктор по умолчанию не виртуален

Если класс имеет хотя бы одну виртуальную функцию, это **не делает** деструктор автоматически виртуальным — его нужно объявить явно.

### 2. Виртуальный деструктор и правило трёх/пяти

Если вы объявляете деструктор (виртуальный или нет), компилятор **не генерирует** неявно конструктор копирования и оператор присваивания (в старых стандартах; в C++11+ они генерируются, но помечаются как deprecated). Учитывайте это при проектировании класса.

### 3. Полиморфное удаление требует виртуального деструктора в базовом классе

Стандарт C++ (п. 5.3.5 `[expr.delete]`) прямо говорит: если удаляемый объект имеет тип, отличный от статического типа указателя, и у базового класса нет виртуального деструктора — поведение **не определено**.

### 4. `= default` и `= delete`

Современная практика — объявлять `virtual ~Base() = default;`. Если удаление через базовый указатель нежелательно, можно запретить его: `virtual ~Base() = delete;` (редко, но используется в некоторых паттернах, например в `Mixin`-классах).

## Пример из стандартной библиотеки

Классы с виртуальными деструкторами: `std::exception` и все его наследники (`std::runtime_error`, `std::logic_error`, ...). Поэтому `throw std::runtime_error(...)` и последующий `catch (const std::exception& e)` корректно уничтожают объект.

## Итог

| Ситуация | Нужен виртуальный деструктор? |
|---|---|
| Класс — базовый для полиморфной иерархии, удаление через `Base*` | **Да, обязательно** |
| Класс помечен `final` | Нет |
| Класс не наследуется | Нет |
| Наследуется, но удаление всегда по конкретному типу | Не обязательно (но часто разумно для защиты от ошибок) |

**Правило:** если класс может быть использован полиморфно (удалён через указатель на базу) — деструктор должен быть виртуальным. Это гарантирует вызов полной цепочки деструкторов и предотвращает утечки ресурсов и неопределённое поведение.
