# 70. Куча и стек в C++

## Стек (stack)

**Стек** — это область памяти, которая работает по принципу **LIFO** (Last In, First Out — «последним пришёл, первым вышел»). Это непрерывный участок памяти, выделяемый под нужды программы при её запуске (размер обычно фиксирован, например 1–8 МБ в зависимости от ОС).

### Принцип работы

- Память выделяется и освобождается **автоматически** при входе в функцию и выходе из неё.
- Указатель стека (`stack pointer`) сдвигается вверх при выделении и вниз при освобождении.
- В стеке хранятся:
  - локальные переменные;
  - параметры функций;
  - адреса возврата;
  - временные значения при вычислениях.

### Пример

```cpp
void foo() {
    int a = 10;      // выделяется в стеке
    double b = 3.14; // выделяется в стеке
    // при выходе из функции a и b автоматически освобождаются
}

void bar() {
    int arr[1000];   // 4000 байт в стеке — быстро, но стек ограничен
}
```

### Особенности стека

- **Очень быстрое** выделение/освобождение (просто сдвиг указателя).
- Размер ограничен и известен заранее → риск **переполнения стека** (stack overflow) при большой рекурсии или больших локальных массивах.
- Память **не фрагментируется**.
- Нельзя выделить память «вручную» во время выполнения произвольного размера (кроме `alloca`, который не рекомендуется).

## Куча (heap / free store)

**Куча** — это область памяти для **динамического** выделения. Память выделяется по запросу программы во время выполнения и освобождается вручную (или через умные указатели).

### Принцип работы

- Программа запрашивает память у операционной системы/менеджера памяти через операторы `new` / `malloc`.
- Менеджер кучи ищет подходящий свободный блок (списки свободных блоков, деревья, бинбинги и т. п.).
- Освобождение — через `delete` / `free` (или автоматически при уничтожении умного указателя).
- Размер кучи ограничен в основном объёмом доступной виртуальной памяти.

### Пример

```cpp
void foo() {
    int* p = new int(42);      // память выделена в куче
    int* arr = new int[1000];  // массив в куче
    // ...
    delete p;                  // обязательно освободить
    delete[] arr;
}

// Современный C++ — RAII и умные указатели:
void bar() {
    auto p = std::make_unique<int>(42);       // освободится автоматически
    auto arr = std::make_unique<int[]>(1000);
    auto shared = std::make_shared<double>(3.14);
}
```

### Особенности кучи

- **Медленнее** стека: поиск свободного блока, возможные системные вызовы.
- Размер памяти может быть **большим** и выделяться **динамически** во время работы.
- Возможна **фрагментация** памяти.
- Требует **ручного управления** → риск утечек памяти (leaks) и «висячих» указателей (dangling pointers), если не использовать RAII/умные указатели.
- Память живёт, пока её явно не освободят.

## Сравнительная таблица

| Критерий | Стек (stack) | Куча (heap) |
|---|---|---|
| Принцип | LIFO | Произвольное выделение/освобождение |
| Скорость | Очень высокая | Ниже (поиск блока, накладные расходы) |
| Управление | Автоматическое (компилятор) | Ручное (`new`/`delete`) или через RAII |
| Размер | Фиксированный, небольшой (МБ) | Большой, ограничен доступной памятью |
| Фрагментация | Нет | Возможна |
| Риски | Stack overflow | Утечки памяти, dangling pointers |
| Время жизни | До выхода из области видимости | Пока не освобождён явно |
| Что хранится | Локальные переменные, параметры, адреса возврата | Динамические объекты, массивы большого размера |

---

## Краткий итог

- **Стек** — быстрый, автоматический, ограниченный по размеру; идеален для локальных переменных с коротким временем жизни.
- **Куча** — гибкая, большая, но медленнее и требует управления; нужна для объектов, чьё время жизни превышает область видимости, и для больших объёмов данных.
- В современном C++ предпочтительно использовать **RAII и умные указатели** (`std::unique_ptr`, `std::shared_ptr`, `std::vector` и т. п.), чтобы сочетать гибкость кучи с безопасностью автоматического освобождения.
