# 123. Идиома remove-erase в C++

## Суть проблемы

В стандартной библиотеке C++ есть алгоритм `std::remove` (и его родственники `std::remove_if`, `std::unique` и т.п.), который, вопреки названию, **не удаляет элементы из контейнера**. Он лишь переставляет элементы так, чтобы «ненужные» оказались в конце, и возвращает итератор на новый логический конец диапазона.

Причина в том, что алгоритмы STL работают с **итераторами**, а не с самим контейнером: они не знают, как уменьшить размер контейнера (у вектора для этого есть `erase`, у списка — свой механизм и т.д.). Поэтому удаление выполняется в два шага — отсюда и название идиомы.

## Как это работает

Рассмотрим `std::vector<int>`:

```cpp
std::vector<int> v = {1, 2, 3, 2, 4, 2, 5};

// Шаг 1: remove переставляет "оставшиеся" элементы в начало,
// возвращает итератор на первый "удалённый" (логический конец)
auto newEnd = std::remove(v.begin(), v.end(), 2);
// v теперь: {1, 3, 4, 5, ?, ?, ?}  — размер всё ещё 7!
// newEnd указывает на позицию после 5

// Шаг 2: erase физически удаляет "хвост"
v.erase(newEnd, v.end());
// v теперь: {1, 3, 4, 5}, size == 4
```

### Что делает `std::remove` пошагово

`std::remove(first, last, value)` проходит по диапазону и «сдвигает» все элементы, **не равные** `value`, в начало, сохраняя их относительный порядок. Возвращает итератор за последним сохранённым элементом. Элементы после этого итератора находятся в **валидном, но неопределённом состоянии** — их значения не специфицированы.

## Каноническая запись идиомы

```cpp
v.erase(std::remove(v.begin(), v.end(), value), v.end());
```

Или в общем виде для произвольного предиката:

```cpp
v.erase(std::remove_if(v.begin(), v.end(), pred), v.end());
```

## Важные детали

### 1. Работает только с контейнерами с `erase(first, last)`

Идиома применима к **вектору, строке (`std::string`), декану, `std::list`, `std::forward_list`** (для последнего — своя форма). Она **не нужна и не применима** к ассоциативным контейнерам (`std::set`, `std::map`) и неупорядоченным (`std::unordered_*`) — у них есть собственный метод `erase(key)` и алгоритм `std::erase` (C++20), либо следует использовать `container.erase(container.find(...))`.

### 2. `std::list` и `std::forward_list` имеют свой `remove`/`remove_if`

У этих контейнеров есть **собственные методы-члены** `remove()` и `remove_if()`, которые удаляют элементы эффективнее (без копирования/перемещения):

```cpp
std::list<int> lst = {1, 2, 3, 2, 4};
lst.remove(2);        // правильно и эффективно
lst.remove_if(pred);
```

Идиома remove-erase для `std::list` тоже работает, но метод-член предпочтительнее.

### 3. C++20: `std::erase` и `std::erase_if`

В C++20 появились свободные функции, инкапсулирующие идиому:

```cpp
std::erase(v, value);      // для vector, string, deque, list...
std::erase_if(v, pred);    // для всех стандартных контейнеров
```

Теперь вместо `v.erase(std::remove(v.begin(), v.end(), x), v.end())` достаточно написать `std::erase(v, x)`. Это работает и для ассоциативных контейнеров.

### 4. Осторожно с `remove_if` и побочными эффектами

Предикат в `std::remove_if` может вызываться **несколько раз** для одного элемента (в некоторых реализациях) и не должен иметь побочных эффектов, влияющих на результат.

## Итоговая формула

```cpp
// До C++20 — классическая идиома:
container.erase(
    std::remove(container.begin(), container.end(), value),
    container.end()
);

// C++20+ — краткая форма:
std::erase(container, value);
std::erase_if(container, predicate);
```

**Ключевая идея:** алгоритмы STL не меняют размер контейнера — они только переставляют элементы; физическое удаление хвоста выполняет метод `erase`. Идиома remove-erase склеивает эти два шага в одну осмысленную операцию «удалить все элементы, удовлетворяющие условию».
