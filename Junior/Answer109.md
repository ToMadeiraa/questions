# 109. Порядок конструирования и разрушения классов в иерархии. Порядок инициализации полей класса

## 1. Порядок конструирования в иерархии наследования

При создании объекта производного класса конструкторы вызываются **сверху вниз** — от базового класса к производному:

1. **Виртуальные базовые классы** (в порядке их объявления при обходе иерархии слева направо, сверху вниз).
2. **Невиртуальные базовые классы** — в порядке их перечисления в списке наследования (`class D : public B1, public B2` → сначала `B1`, затем `B2`).
3. **Поля (члены) самого класса** — в порядке их **объявления в классе**, а не в порядке списка инициализации конструктора.
4. **Тело конструктора** самого класса.

```cpp
#include <iostream>

struct B1 { B1() { std::cout << "B1()\n"; } };
struct B2 { B2() { std::cout << "B2()\n"; } };

struct D : public B1, public B2 {
    int a;
    int b;
    // В списке инициализации порядок обратный, но реальный порядок — по объявлению!
    D() : b(2), a(1) {
        std::cout << "D()\n";
    }
};

int main() {
    D d;
}
```

Вывод:
```
B1()
B2()
D()
```

> **Важно:** поля `a` и `b` инициализируются в порядке объявления (`a`, затем `b`), даже если в списке инициализации указано иначе. Компиляторы (например, GCC с `-Wall`) выдают предупреждение `-Wreorder`, если порядок в списке не совпадает с порядком объявления.

## 2. Порядок инициализации полей класса

Поля инициализируются **строго в порядке их объявления в классе**, независимо от порядка в списке инициализации конструктора.

```cpp
struct S {
    int x;
    int y;
    S() : y(10), x(y) {}  // ОШИБКА ЛОГИКИ: x инициализируется первым,
                          // но y ещё не инициализирован!
};
```

Здесь `x` получит **неопределённое значение** (читается неинициализированный `y`), потому что `x` объявлен раньше `y`.

## 3. Порядок разрушения

Разрушение происходит **строго в обратном порядке** относительно конструирования:

1. **Тело деструктора** производного класса.
2. **Поля производного класса** — в порядке, **обратном** порядку объявления.
3. **Базовые классы** — в порядке, **обратном** порядку конструирования (т.е. сначала последний в списке наследования).
4. **Виртуальные базовые классы** — в обратном порядке.

```cpp
#include <iostream>

struct B1 { ~B1() { std::cout << "~B1()\n"; } };
struct B2 { ~B2() { std::cout << "~B2()\n"; } };

struct D : public B1, public B2 {
    int a, b;
    ~D() { std::cout << "~D()\n"; }
};

int main() {
    D d;
}
```

Вывод:
```
~D()
~B2()
~B1()
```

## 4. Сводная таблица

| Этап | Конструирование | Разрушение |
|------|-----------------|------------|
| Виртуальные базы | в порядке обхода иерархии | в обратном порядке |
| Невиртуальные базы | в порядке списка наследования | в обратном порядке |
| Поля класса | в порядке объявления | в обратном порядке объявления |
| Тело конструктора/деструктора | последним | первым |

## 5. Практические следствия и типичные ошибки

- **Порядок в списке инициализации не влияет на реальный порядок** — он диктуется объявлением полей. Чтобы избежать ошибок, **всегда пишите список инициализации в том же порядке, что и объявление полей**.
- Если поле `y` инициализируется значением поля `x`, убедитесь, что `x` объявлено **раньше** `y`.
- **Виртуальные базовые классы** инициализируются конструктором **самого производного** класса (most-derived), а не промежуточных — это важно при ромбовидном наследовании.
- При разрушении через указатель на базовый класс **деструктор базового класса должен быть виртуальным**, иначе деструктор производного класса не вызовется (UB).
- Члены, не указанные в списке инициализации, инициализируются по умолчанию: для встроенных типов — **неинициализированы** (мусор), для классов — вызывается конструктор по умолчанию.

```cpp
struct Base {
    virtual ~Base() = default;  // обязательно для полиморфного удаления
};
struct Derived : Base {
    ~Derived() override { /* ... */ }
};
```
