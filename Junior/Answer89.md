# 89. Что такое memory leak (утечка памяти)?

## Определение

**Memory leak (утечка памяти)** — это ситуация, когда программа выделяет память в куче (heap), но не освобождает её после того, как необходимость в ней отпала. В результате занятая память остаётся недоступной для повторного использования ни программой, ни операционной системой, пока процесс не завершится.

В C++ это особенно актуально, поскольку язык не имеет сборщика мусора (garbage collector), и программист сам отвечает за освобождение динамически выделенной памяти.

## Как возникает утечка

### 1. Отсутствие `delete`/`delete[]` для `new`/`new[]`

```cpp
void leak() {
    int* p = new int(42);   // память выделена
    // ... работа с p ...
    // delete p;            // забыли освободить — утечка
}
```

### 2. Потеря указателя на выделенную память

```cpp
int* p = new int(10);
p = new int(20);   // старый адрес потерян — утечка 4 байт
delete p;
```

### 3. Утечка при исключениях (exception safety)

```cpp
void f() {
    int* p = new int[100];
    g();               // если g() бросит исключение,
    delete[] p;        // эта строка не выполнится — утечка
}
```

### 4. Неверное освобождение (несоответствие `new`/`delete`)

```cpp
int* p = new int[10];
delete p;      // ошибка: нужно delete[] — неопределённое поведение
```

### 5. Утечки в структурах данных

```cpp
struct Node { int data; Node* next; };

void removeAll(Node* head) {
    while (head) {
        head = head->next;   // потеряли указатель на текущий узел
    }                        // ни один узел не удалён — утечка всей цепочки
}
```

## Последствия

- **Рост потребления памяти** — процесс занимает всё больше RAM со временем.
- **Деградация производительности** — из-за фрагментации и роста рабочего набора.
- **Отказ в выделении памяти** — `std::bad_alloc` или аварийное завершение (особенно на 32-битных системах).
- **Падение долгоживущих процессов** — серверов, демонов, игр.

Особенно опасны утечки в циклах и долго работающих программах: даже «маленькая» утечка в несколько байт за итерацию может за часы исчерпать всю доступную память.

## Способы предотвращения

### 1. RAII и умные указатели (главный принцип)

```cpp
#include <memory>

void noLeak() {
    auto p = std::make_unique<int>(42);   // удалится автоматически
    auto arr = std::make_unique<int[]>(100);
    auto shared = std::make_shared<std::string>("text");
}   // всё освобождается при выходе из области видимости
```

- `std::unique_ptr` — единоличное владение.
- `std::shared_ptr` — разделяемое владение со счётчиком ссылок.
- `std::weak_ptr` — невладеющая ссылка (разрывает циклы в `shared_ptr`).

### 2. Стандартные контейнеры вместо ручного управления

```cpp
std::vector<int> v(100);          // вместо new int[100]
std::string s = "hello";          // вместо new char[...]
```

### 3. Правило трёх/пяти и корректные деструкторы

Если класс владеет ресурсом — реализуйте деструктор, конструктор копирования, оператор присваивания (или запретите копирование через `= delete`).

### 4. Инструменты обнаружения утечек

| Инструмент | Платформа | Особенности |
|---|---|---|
| **Valgrind (memcheck)** | Linux | `valgrind --leak-check=full ./prog` |
| **AddressSanitizer (ASan)** | GCC/Clang | `-fsanitize=address -g` |
| **Visual Studio Debugger** | Windows | CRT debug heap: `_CrtDumpMemoryLeaks()` |
| **Dr. Memory** | Windows/Linux | аналог Valgrind |
| **cppcheck / clang-tidy** | кроссплатформенно | статический анализ |

### 5. Современный C++ и дисциплина кода

- Избегайте «голых» `new`/`delete` в прикладном коде.
- Используйте `std::make_unique`/`std::make_shared` вместо `new`.
- Соблюдайте **rule of zero**: если класс не управляет ресурсами напрямую — не пишите деструктор/копирование.
- Внимательно относитесь к циклическим ссылкам в `shared_ptr` (используйте `weak_ptr`).

## Важное уточнение: «утечка» vs «просто не освобождённая память при завершении»

Память, не освобождённая к моменту завершения процесса, ОС всё равно вернёт себе — это не считается практической проблемой. Опасна утечка **во время работы** программы, когда память перестаёт быть доступной, а процесс продолжает жить.

## Итог

Memory leak — это потеря контроля над выделенной динамической памятью, ведущая к неограниченному росту потребления RAM. В C++ основная защита — **RAII и умные указатели**, отказ от ручного `new`/`delete`, а для поиска уже существующих утечек — **Valgrind, AddressSanitizer и статические анализаторы**.
