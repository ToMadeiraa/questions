# 108. Как запретить наследовать класс в C++

## Краткий ответ

В C++ (начиная с C++11) для запрета наследования используется ключевое слово **`final`**, указываемое после имени класса:

```cpp
class MyClass final {
    // ...
};
```

Попытка унаследовать от такого класса вызовет **ошибку компиляции**:

```cpp
class Derived : public MyClass { }; // ошибка: cannot derive from 'final' base
```

## Подробнее

### 1. Спецификатор `final` (C++11 и новее)

`final` — контекстно-зависимый спецификатор, который применим к классам и виртуальным функциям. Для класса он означает: «от этого класса нельзя наследовать».

```cpp
class Base final {
public:
    void foo() {}
};

// class Child : public Base {}; // Ошибка компиляции
```

Особенности:
- Ставится **после имени класса** (перед двоеточием, если есть базовые классы): `class X final : public Y { };`
- Проверяется на этапе компиляции — нулевые накладные расходы во время выполнения.
- Может применяться и к `struct`: `struct S final { };`
- Если класс объявлен `final`, но от него всё же пытаются наследовать, компилятор выдаёт диагностику (в GCC/Clang — `cannot derive from 'final' base`).

### 2. Старый способ до C++11: приватный конструктор

До появления `final` (C++98/03) распространённым приёмом было сделать конструкторы класса **приватными** (или защищёнными — тогда наследование возможно, но только для «дружественных» классов). Производный класс не сможет вызвать конструктор базового класса, и наследование станет невозможным.

```cpp
class NonInheritable {
private:
    NonInheritable() {}          // конструктор недоступен снаружи
    NonInheritable(const NonInheritable&) {}
public:
    static NonInheritable create() { return NonInheritable(); }
};

// class Derived : public NonInheritable { }; // Ошибка: конструктор приватный
```

Недостатки такого подхода:
- Класс нельзя создать напрямую снаружи (нужны фабричные методы/друзья);
- Возможны обходные пути (например, через `friend`-классы);
- Менее явно и читаемо, чем `final`.

### 3. Сравнение способов

| Способ | Стандарт | Явность | Ограничения |
|---|---|---|---|
| `final` | C++11 | Явный, самодокументируемый | Нет (кроме запрета наследования) |
| Приватный конструктор | C++98 | Неявный | Усложняет создание объектов |

## Важные нюансы

- `final` **не делает класс абстрактным** и не мешает создавать его экземпляры — он лишь запрещает наследование.
- `final` также можно применять к **виртуальным функциям**, запрещая их переопределение в производных классах:

```cpp
class Base {
public:
    virtual void f() final; // нельзя переопределить в наследниках
};
```

- Спецификатор `final` не является зарезервированным словом — его можно использовать как идентификатор в других контекстах (например, имя переменной `int final = 5;` допустимо, хотя не рекомендуется).
- Если класс помечен `final`, компилятор может применять дополнительные оптимизации (например, девиртуализацию вызовов), поскольку точно знает, что наследников нет.

## Пример

```cpp
#include <iostream>

class Singleton final {
public:
    static Singleton& instance() {
        static Singleton s;
        return s;
    }
    void hello() const { std::cout << "Hello\n"; }
private:
    Singleton() = default;
};

// class Bad : public Singleton { }; // ошибка компиляции

int main() {
    Singleton::instance().hello();
}
```

## Итог

Для запрета наследования в современном C++ используйте спецификатор **`final`** — это самый простой, явный и безопасный способ, проверяемый на этапе компиляции. Приватный конструктор — устаревший приём, актуальный только для кода, который должен собираться под стандартом C++98/03.
