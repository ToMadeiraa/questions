# Вопрос 18. Что такое инстанциация шаблона?

> **Кратко:** инстанциация — это генерация конкретной сущности (класса или функции) из шаблона путём подстановки аргументов шаблона. Сам шаблон кодом не является: это «чертёж», а код появляется только в момент инстанциации — **неявной** (компилятор делает её сам при использовании) или **явной** (программист просит её директивой).

---

## Шаблон — это не код

```cpp
template <class T>
T maxOf(T a, T b) { return a < b ? b : a; }   // объявление шаблона, а не функция
```

Пока шаблон никто не использовал, в объектном файле нет ни одной его версии. Компилятор на этапе разбора проверяет только то, что **не зависит** от `T`: синтаксис и имена, видимые в точке определения. Всё, что зависит от `T`, проверяется позже — при подстановке.

---

## Неявная инстанциация

Компилятор инстанцирует шаблон сам, как только встречает его использование, требующее определения (ODR-use). Место, где это произошло, называется **точкой инстанциации** (point of instantiation).

```cpp
#include <string>

int    i = maxOf(3, 7);                 // инстанциация maxOf<int>
double d = maxOf(1.5, 0.5);             // инстанциация maxOf<double>
auto   s = maxOf(std::string{"a"}, std::string{"b"});   // инстанциация maxOf<std::string>
```

Для шаблона **класса** инстанцируется не всё сразу: при `Probe<int> p;` компилятор порождает объявления членов, а тела функций-членов — только когда они реально используются.

```cpp
template <class T>
struct Probe {
    void ok() { }                                // корректна для любого T
    void broken() { T::this_does_not_exist(); }  // ошибка только при вызове
};

Probe<int> p;      // OK: тела членов ещё не инстанцированы
p.ok();            // инстанцируется Probe<int>::ok()
// p.broken();     // а вот здесь — ошибка компиляции
```

## Явная инстанциация

Программист может заказать генерацию заранее — директива `template` без «угловых скобок» после неё, но с полной сигнатурой.

```cpp
// Явное определение (explicit instantiation definition) — здесь генерируется код
template class Stack<int>;
template int maxOf<int>(int, int);

// Явное объявление (explicit instantiation declaration, C++11) — «не генерируй здесь»
extern template class Stack<int>;
```

Классическое применение — вынести реализацию шаблона из заголовка (подробнее в вопросе 20):

```cpp
// stack.h
#pragma once
#include <vector>

template <class T>
class Stack {
public:
    void push(const T& v) { data_.push_back(v); }
    T pop() { T v = data_.back(); data_.pop_back(); return v; }

private:
    std::vector<T> data_;
};

extern template class Stack<int>;   // в этой TU код не генерировать
```

```cpp
// stack.cpp
#include "stack.h"

template class Stack<int>;          // единственное место, где генерируется Stack<int>
```

| Способ | Кто инициирует | Синтаксис | Где размещать |
|---|---|---|---|
| Неявная | компилятор при использовании | — | автоматически |
| Явное определение | программист | `template class X<int>;` | один `.cpp` |
| Явное объявление | программист | `extern template class X<int>;` | заголовок |

> **Важно:** явная инстанциация покрывает только перечисленные типы. Для остальных `T` шаблон всё равно будет инстанцирован неявно, а значит его определение должно быть доступно в заголовке.

---

## Что и когда инстанцируется

| Сущность | Триггер инстанциации |
|---|---|
| Функция-шаблон | ODR-use: вызов, взятие адреса |
| Класс-шаблон | нужен полный тип: объект, `sizeof`, наследование, поле |
| Функция-член класса-шаблона | обращение именно к этому члену |
| Статический член | ODR-use (обращение к значению) |
| Псевдоним и переменная-шаблон | использование имени |
| Аргументы шаблона по умолчанию | в момент подстановки |

---

## Двухфазный поиск имён

Инстанциация объясняет, почему шаблоны «ломаются» не там, где написаны, а там, где использованы.

```cpp
template <class T>
void call(T x) {
    helper(x);     // зависимое имя: ищется при инстанциации (ADL + точка определения)
    // unknown();  // не зависит от T — проверяется сразу при разборе шаблона: ошибка
}
```

| Категория имени | Когда связывается |
|---|---|
| Не зависит от параметров шаблона | сразу, при определении шаблона |
| Зависит от параметров шаблона | при инстанциации: обычный поиск в точке определения + ADL |

---

## Инстанциация и специализация — разные вещи

| | Инстанциация | Специализация |
|---|---|---|
| Кто выполняет | компилятор | программист |
| Что происходит | подстановка аргументов в общий шаблон | своя реализация под конкретные аргументы |
| Когда | в точке использования | в точке объявления |
| Результат | сгенерированный код из «чертежа» | код, написанный вручную |

Специализация **перехватывает** инстанциацию: если для `T = bool` есть специализация, компилятор возьмёт её, а не общий шаблон.

---

## Цена инстанциации

- **Время компиляции.** Каждая единица трансляции, где шаблон использован, генерирует код заново.
- **Размер кода (code bloat).** Один и тот же `std::vector<int>` компилируется в каждом `.cpp`; дубликаты схлопывает линкер (COMDAT / слабые символы), но время сборки уже потрачено.
- **Глубина рекурсии.** Шаблонное метапрограммирование — это цепочка инстанциаций; у компиляторов есть предел (у GCC `-ftemplate-depth` по умолчанию 900, у Clang — 1024), после которого — ошибка «template instantiation depth exceeded».
- **Диагностика.** Ошибка в шаблоне выдаётся с многострочным «backtrace» инстанциаций — читать нужно снизу вверх, от последней строки к первой.

---

## Типичные ошибки

1. **Путать инстанциацию со специализацией**: первое делает компилятор по общему шаблону, второе — программист вручную.
2. **Считать, что шаблон в заголовке «бесплатен»**: каждая TU его компилирует, и на больших проектах это основная статья времени сборки.
3. **`extern template` без явного определения** в каком-либо `.cpp` — получаем ошибку линковки «undefined reference».
4. **Ждать, что явная инстанциация скроет шаблон**: для типов вне списка клиент всё равно инстанцирует его сам и потребует определений в заголовке.
5. **Думать, что `Probe<int>` проверяет все тела членов** — тела инстанцируются по требованию, неиспользуемые ошибки не диагностируются.
6. **Ожидать ошибку в точке определения шаблона**, хотя она возникает в точке инстанциации.

---

## Что добавить на собеседовании

- **ODR**: все неявные инстанциации одного шаблона во всех TU должны быть идентичны; шаблоны имеют «inline-подобную» линковку, поэтому дубликаты безвредны.
- **Явная инстанциация** — рабочий способ уменьшить время сборки и скрыть реализацию в `.cpp` (см. вопрос 20).
- Для поиска дорогих инстанциаций используют `-ftime-report` (GCC), `-ftime-trace` (Clang) и `/ftime` (MSVC).
- В C++20 при неудачной подстановке проверяются **constraints** концептов — это происходит до инстанциации тела, что позволяет писать «SFINAE-friendly» перегрузки.
- Инстанциация — основа метапрограммирования: `std::tuple`, `std::variant`, рекурсивные шаблоны вычисляют значения и типы на этапе компиляции.

---

## Итог

| Понятие | Суть |
|---|---|
| Инстанциация | Подстановка аргументов в шаблон → конкретный класс или функция |
| Неявная | Компилятор делает сам при использовании (ODR-use) |
| Явное определение | `template class X<int>;` — код генерируется здесь |
| Явное объявление | `extern template class X<int>;` — код здесь не генерировать |
| Ленивость | Тела членов класса-шаблона инстанцируются по одному, по требованию |
| Точка инстанциации | Место использования; там же выдаются ошибки шаблона |
| Цена | Время компиляции, размер кода, глубина рекурсии инстанциаций |
