# 110. Способы инициализации полей класса в C++

В C++ существует несколько способов инициализации полей (членов) класса. Рассмотрим их подробно.

## 1. Инициализация в списке инициализации конструктора

Наиболее предпочтительный способ для нетривиальных типов. Список инициализации идёт после сигнатуры конструктора через двоеточие.

```cpp
class Point {
    int x;
    int y;
    std::string name;
public:
    Point(int x_, int y_, const std::string& n)
        : x(x_), y(y_), name(n) {}   // список инициализации
};
```

**Важно:** порядок инициализации определяется **порядком объявления полей в классе**, а не порядком в списке. Если порядок в списке не совпадает с порядком объявления — компилятор может выдать предупреждение (`-Wreorder`).

Это **единственный** способ инициализировать:
- поля-константы (`const`);
- поля-ссылки (`&`);
- поля без конструктора по умолчанию (например, другой класс без дефолтного конструктора);
- базовые классы.

## 2. Инициализация по умолчанию (default member initializer, C++11)

Значение по умолчанию задаётся прямо в объявлении поля. Применяется, если поле не инициализировано в списке инициализации конструктора.

```cpp
class Config {
    int timeout = 30;              // копирующая инициализация
    std::string name{"default"};   // прямая инициализация (braced)
    double ratio = 0.5;
    std::vector<int> data{1, 2, 3};
};
```

Это удобно и снижает дублирование кода между конструкторами.

## 3. Инициализация в теле конструктора (присваивание)

Формально это не инициализация, а **присваивание** — поле сначала создаётся конструктором по умолчанию, затем ему присваивается значение.

```cpp
class Point {
    int x;
    int y;
public:
    Point(int x_, int y_) {
        x = x_;   // присваивание, а не инициализация
        y = y_;
    }
};
```

Минусы: для классов это лишний вызов конструктора по умолчанию + оператора присваивания. Для `const` и ссылок такой способ **невозможен**.

## 4. Инициализация в объявлении через `{}` (равноценно п.2)

```cpp
class Widget {
    int a{0};
    int b{};
    int c = 0;
};
```

- `int b{};` — value-инициализация (для `int` даёт `0`);
- `int c = 0;` — копирующая инициализация.

## 5. Агрегатная инициализация

Если класс — агрегат (нет пользовательских конструкторов, нет приватных/защищённых нестатических полей, нет виртуальных функций, нет базовых классов — до C++17; в C++17+ правила смягчены), поля можно инициализировать списком в фигурных скобках:

```cpp
struct Point { int x; int y; };

Point p1{1, 2};        // агрегатная инициализация
Point p2 = {3, 4};
Point p3{};            // все поля value-инициализированы (нулями)
```

## 6. Инициализация статических полей

Статические поля не инициализируются в списке инициализации конструктора. Варианты:

**Внутри класса (только для `constexpr`/`inline` переменных, C++17):**

```cpp
class A {
    static inline int count = 0;      // C++17
    static constexpr int MAX = 100;   // константа времени компиляции
};
```

**Вне класса (в .cpp-файле):**

```cpp
// A.h
class A {
    static int count;
};

// A.cpp
int A::count = 0;
```

## 7. Инициализация через делегирующие конструкторы (C++11)

Один конструктор может вызывать другой, чтобы избежать дублирования инициализации:

```cpp
class Point {
    int x, y;
public:
    Point() : Point(0, 0) {}          // делегирование
    Point(int x_) : Point(x_, 0) {}
    Point(int x_, int y_) : x(x_), y(y_) {}
};
```

## Сравнительная таблица

| Способ | Когда применять | Ограничения |
|---|---|---|
| Список инициализации | Основной способ; обязателен для `const`, ссылок, полей без дефолтного конструктора | Порядок = порядку объявления |
| Default member initializer (C++11) | Значения по умолчанию, уменьшение дублирования | Перекрывается списком инициализации |
| Присваивание в теле | Простые типы, когда инициализация зависит от логики | Нельзя для `const`/ссылок; лишние операции |
| Агрегатная инициализация | Простые struct-агрегаты (POD-подобные) | Только для агрегатов |
| Делегирующие конструкторы | Устранение дублирования между конструкторами | — |
| Инициализация статических полей | `static`-поля | `inline`/`constexpr` — в классе, иначе вне класса |

## Рекомендации (best practices)

1. **Всегда предпочитайте список инициализации** телу конструктора.
2. **Держите порядок полей в списке инициализации таким же, как порядок их объявления** в классе.
3. **Используйте default member initializer** для значений по умолчанию, чтобы не дублировать их в каждом конструкторе.
4. **Применяйте `{}` (braced-init)** для предотвращения «сужения» типов (narrowing conversion), например `int x{3.5}` не скомпилируется.
5. Для агрегатов используйте агрегатную инициализацию — она проще и безопаснее.
6. **Не инициализируйте `static`-поля в списке инициализации конструктора** — это не скомпилируется.
