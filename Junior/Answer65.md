# 65. Что случится с функцией, если к ней добавить ключевое слово static? В контексте члена класса? В контексте метода класса?

Ключевое слово `static` в C++ имеет принципиально разное значение в зависимости от контекста. Если говорить кратко: для **свободной функции** (вне класса) оно меняет её **видимость** (линковку), а для **функции-члена класса** — меняет **способ её вызова** и **доступ к данным** (она перестаёт быть привязанной к конкретному объекту).

Ниже подробный разбор по трём случаям, которые вы упомянули.

### 1. Функция вне класса (в глобальной или файловой области видимости)

Если вы добавляете `static` к обычной функции, которая не является членом класса, вы меняете её **внешнюю линковку (external linkage)** на **внутреннюю (internal linkage)**.

*   **Что это значит:** Функция становится видимой только в пределах того файла (единицы трансляции), в котором она объявлена .
*   **Практический эффект:** Вы не можете вызвать эту функцию из другого `.cpp` файла. Если в другом файле есть функция с таким же именем, конфликта имён (ошибки линковки) не будет, так как они существуют независимо друг от друга.
*   **Замечание для C++:** В современном C++ для этих целей чаще используют анонимные пространства имён (`namespace { ... }`), но `static` для функций всё ещё работает и широко используется в унаследованном коде .

### 2. Функция-член класса (Метод класса)

В контексте класса `static` означает, что метод принадлежит **самому классу**, а не его конкретным экземплярам (объектам). Это принципиальное изменение семантики.

**Что происходит с функцией:**

*   **Отсутствие указателя `this`:** Самое главное изменение. Статический метод **не имеет неявного указателя `this`** . Он «не знает», с каким именно объектом был вызван.
*   **Вызов без объекта:** Вы можете вызывать такой метод, не создавая экземпляр класса. Для этого используется квалифицированное имя: `ИмяКласса::ИмяМетода()`. Вызов через объект (`obj.method()`) также возможен синтаксически, но компилятор просто проигнорирует объект .
*   **Доступ к членам класса:**
    *   Статический метод может обращаться **только к статическим** членам класса (данным и методам). Он не может напрямую обращаться к обычным (нестатическим) полям или методам, потому что для них нужен конкретный объект .
    *   Чтобы статический метод мог работать с обычными полями, ему нужно **явно передать** объект (по ссылке или указателю) в качестве параметра.
*   **Ограничения:** Статический метод **не может быть** `virtual`, `const` или `volatile` . Это логично: виртуальность подразумевает выбор метода в зависимости от типа объекта, а `const` гарантирует неизменность объекта, которого здесь нет.
*   **Указатели:** Адрес статического метода можно сохранить в обычный указатель на функцию, но **нельзя** сохранить в указатель на функцию-член класса .

**Пример:**

```cpp
class MyClass {
private:
    int instanceVar;
    static int staticVar;

public:
    // Статический метод
    static void staticMethod() {
        // instanceVar = 10; // ОШИБКА: нет this, нельзя обратиться к нестатическому полю
        staticVar = 10;      // ОК: статическое поле доступно
    }
    
    // Обычный метод
    void normalMethod() {
        instanceVar = 10;    // ОК
        staticVar = 20;      // ОК: статические члены доступны из обычных методов
    }
};

int main() {
    MyClass::staticMethod(); // ОК: вызов без объекта
    // MyClass::normalMethod(); // ОШИБКА: нужен объект
}
```

### 3. Уточнение по формулировке «член класса» vs «метод класса»

В вашем вопросе есть разделение: «В контексте члена класса? В контексте метода класса?». В терминологии C++ **метод класса** — это и есть **функция-член класса**. Если под «членом класса» вы имели в виду **данные-члены** (поля), то там логика такая же:

*   **Статическое поле данных:** Существует в единственном экземпляре для всего класса, а не для каждого объекта. Его нужно определять вне класса (кроме случаев `constexpr`/`inline` в новых стандартах) .

### Резюме

| Контекст | Что делает `static` | Ключевое следствие |
| :--- | :--- | :--- |
| **Свободная функция** | Меняет линковку на внутреннюю | Функция видна только в своём `.cpp` файле. |
| **Метод класса** | Убирает привязку к объекту (убирает `this`) | Вызывается как `Class::func()`, не имеет доступа к обычным полям. |
| **Поле класса** | Делает поле общим для всех объектов | Существует одна копия на весь класс, а не на каждый объект. |
