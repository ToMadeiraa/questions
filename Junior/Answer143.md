# 143. Уровни модели OSI

**OSI** (Open Systems Interconnection) — эталонная модель взаимодействия открытых систем, предложенная ISO в 1984 году. Она описывает, как данные передаются по сети, разбивая этот процесс на **7 уровней**. Каждый уровень выполняет свою задачу и предоставляет сервисы уровню выше, используя сервисы уровня ниже.

> **Важно:** модель OSI — это *логическая/эталонная* модель. В реальных сетях используется стек TCP/IP (4–5 уровней), но OSI удобна для объяснения и описания сетевых протоколов.

Уровни принято нумеровать снизу вверх (от «физики» к прикладным задачам):

| № | Уровень | Название | PDU (единица данных) |
|---|---------|----------|----------------------|
| 7 | Прикладной | Application | данные |
| 6 | Представления | Presentation | данные |
| 5 | Сеансовый | Session | данные |
| 4 | Транспортный | Transport | сегмент / датаграмма |
| 3 | Сетевой | Network | пакет |
| 2 | Канальный | Data Link | кадр (frame) |
| 1 | Физический | Physical | биты |

---

## 1. Физический уровень (Physical)

Самый нижний уровень. Отвечает за **передачу сырых битов** по физической среде.

- Определяет электрические, механические, оптические и функциональные характеристики среды.
- Типы сред: витая пара, коаксиальный кабель, оптоволокно, радиоканал.
- Параметры: уровни напряжения, скорость передачи, разъёмы, кодирование сигнала (NRZ, Manchester), модуляция.
- Примеры: Ethernet (витая пара), USB, RS-232, DSL, IEEE 802.11 (радио).

## 2. Канальный уровень (Data Link)

Обеспечивает **надёжную передачу кадров между двумя соседними узлами** (по одному звену).

- **Адресация** на уровне MAC-адресов (физические адреса устройств).
- **Формирование кадров** (framing): выделение границ кадра.
- **Обнаружение и исправление ошибок** (CRC, контрольные суммы).
- **Управление доступом к среде** (MAC): кто и когда может передавать (CSMA/CD, CSMA/CA).
- **Управление потоком** на уровне звена.
- Делится на два подуровня: **LLC** (Logical Link Control) и **MAC** (Media Access Control).
- Примеры: Ethernet (канальная часть), Wi-Fi (802.11), PPP, HDLC, ARP (частично).

## 3. Сетевой уровень (Network)

Отвечает за **маршрутизацию и доставку пакетов между разными сетями** (через несколько узлов).

- **Логическая адресация** (IP-адреса).
- **Маршрутизация**: выбор пути доставки пакета.
- **Фрагментация и сборка** пакетов.
- Работа с топологией сети, учёт загрузки каналов.
- Примеры: IP (IPv4/IPv6), ICMP, OSPF, BGP, RIP, IPX.

## 4. Транспортный уровень (Transport)

Обеспечивает **сквозную (end-to-end) передачу данных** между процессами на разных хостах.

- **Сегментация** данных и обратная сборка.
- **Адресация процессов** через порты.
- **Надёжность**: подтверждения, повторная передача, упорядочивание (TCP).
- **Управление потоком** и **управление перегрузкой**.
- Бывают соединение-ориентированные (TCP) и без установления соединения (UDP).
- Примеры: TCP, UDP, SCTP.

## 5. Сеансовый уровень (Session)

Управляет **сеансами связи** (диалогом) между приложениями.

- Установка, поддержание и завершение сеансов.
- **Синхронизация** (контрольные точки для возобновления передачи).
- Управление диалогом: кто говорит — по очереди или одновременно (half/full duplex).
- Восстановление после сбоев сеанса.
- На практике часто реализуется средствами прикладного уровня; примеры: RPC, NetBIOS, PPTP.

## 6. Уровень представления (Presentation)

Отвечает за **формат и кодирование данных**, чтобы приложение могло их интерпретировать.

- **Кодировки символов** (ASCII, UTF-8, EBCDIC).
- **Сжатие** данных.
- **Шифрование/дешифрование** (например, TLS на этом уровне в терминах OSI).
- Преобразование форматов (например, сериализация).
- Примеры: SSL/TLS (по классификации OSI), JPEG, MPEG, ASN.1.

## 7. Прикладной уровень (Application)

Самый верхний уровень — **интерфейс к сетевым сервисам для пользовательских приложений**. Важно: это не сами приложения, а протоколы, которыми они пользуются.

- Предоставляет сетевые сервисы: передача файлов, почта, веб, удалённый доступ.
- Примеры: HTTP/HTTPS, FTP, SMTP, POP3, IMAP, DNS, SSH, Telnet, SNMP, DHCP.

---

## Принципы работы модели

- **Инкапсуляция при передаче**: данные приложения на каждом уровне «оборачиваются» заголовком своего уровня (сверху вниз: данные → сегмент → пакет → кадр → биты).
- **Декапсуляция при приёме**: на принимающей стороне заголовки последовательно снимаются (снизу вверх).
- Каждый уровень **взаимодействует логически** с таким же уровнем на другом хосте (peer-to-peer) и **физически** — только с соседними уровнями на своём хосте.

```
Отправитель                     Получатель
 7 Прикладной  ───────────────►  7 Прикладной
 6 Представления ─────────────►  6 Представления
 5 Сеансовый   ───────────────►  5 Сеансовый
 4 Транспортный ──────────────►  4 Транспортный
 3 Сетевой     ───────────────►  3 Сетевой
 2 Канальный   ───────────────►  2 Канальный
 1 Физический  ═══ среда ═════   1 Физический
```

## Мнемоники для запоминания

- Снизу вверх (рус.): **Ф**изический, **К**анальный, **С**етевой, **Т**ранспортный, **С**еансовый, **П**редставления, **П**рикладной — «**Ф**изик **К**аждому **С**етевому **Т**ранспорту **С**казал **П**ривет **П**ользователю».
- Сверху вниз (англ.): **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing (Application, Presentation, Session, Transport, Network, Data Link, Physical).

## Краткий итог

Модель OSI даёт универсальный язык для описания сетевого взаимодействия: снизу — передача битов по среде (уровни 1–2), затем адресация и маршрутизация в объединённой сети (уровень 3), сквозная доставка между процессами (уровень 4) и, наконец, управление сеансами, форматами данных и прикладными сервисами (уровни 5–7).
