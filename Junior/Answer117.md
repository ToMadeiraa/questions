# 117. Семантика перемещения (move semantics) в C++

## Определение

**Семантика перемещения** — это механизм C++11, позволяющий «перемещать» ресурсы (динамическую память, файловые дескрипторы, сокеты и т.п.) из одного объекта в другой вместо их дорогостоящего копирования. Вместо побайтового/поэлементного копирования содержимого объект-источник передаёт владение своими ресурсами объекту-приёмнику, после чего остаётся в «опустошённом», но корректном (валидном) состоянии.

## Зачем это нужно

До C++11 при возврате объекта из функции или передаче по значению компилятор создавал **временные копии**, что при больших объёмах данных (например, `std::vector` на миллион элементов) приводило к существенным накладным расходам: выделение памяти + копирование всех элементов. Семантика перемещения устраняет эти затраты: ресурс просто «перевешивается» на новый объект, а источник обнуляется.

## Ключевые компоненты

### 1. rvalue-ссылки (`T&&`)

Ссылка, которая может связываться только с **временными объектами** (rvalue) — теми, чьё время жизни скоро закончится и чьи ресурсы безопасно «забрать».

```cpp
int x = 10;
int&& r = 42;        // OK: 42 — rvalue
// int&& r2 = x;     // ошибка: x — lvalue
```

### 2. Конструктор и оператор присваивания перемещения

```cpp
class Buffer {
    int* data;
    size_t size;
public:
    // Конструктор копирования (глубокое копирование)
    Buffer(const Buffer& other) : size(other.size) {
        data = new int[size];
        std::copy(other.data, other.data + size, data);
    }

    // Конструктор перемещения (забираем ресурсы)
    Buffer(Buffer&& other) noexcept
        : data(other.data), size(other.size) {
        other.data = nullptr;   // обнуляем источник
        other.size = 0;
    }

    // Оператор присваивания перемещения
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data;          // освобождаем свои ресурсы
            data = other.data;      // забираем чужие
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }
};
```

### 3. `std::move`

Функция `std::move` **не перемещает** ничего сама — она лишь приводит объект к rvalue-ссылке, «разрешая» компилятору выбрать конструктор/оператор перемещения.

```cpp
std::vector<int> a = {1, 2, 3, 4, 5};
std::vector<int> b = std::move(a);  // ресурсы a перешли в b
// a теперь пуст (но валиден)
```

## Правила выбора конструктора

| Что передаётся | Какой конструктор вызовется |
|---|---|
| lvalue (именованный объект) | копирования |
| rvalue (временный объект, `std::move(x)`) | перемещения (если есть, иначе — копирования) |

```cpp
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = v1;             // копирование
std::vector<int> v3 = std::move(v1);  // перемещение
std::vector<int> v4 = makeVector();   // перемещение (RVO / move)
```

## Важные детали

- **`noexcept`**: конструктор перемещения желательно помечать `noexcept` — тогда `std::vector` при реаллокации будет перемещать элементы, а не копировать (сильно быстрее).
- **Состояние после перемещения**: объект-источник остаётся **валидным, но неопределённым**. Для него гарантировано лишь то, что его можно безопасно уничтожить или присвоить ему новое значение. Опираться на конкретное содержимое (например, на `size() == 0`) нельзя, если это не гарантировано классом.
- **Правило пяти**: если класс определяет деструктор, конструктор/оператор копирования или перемещения — обычно нужно определить все пять (деструктор, копирующий и перемещающий конструкторы, копирующее и перемещающее присваивание).
- **Не перемещайте объекты, которые ещё нужны**: после `std::move(x)` использовать `x` по назначению нельзя (только переприсвоить или уничтожить).
- **`const`-объекты не перемещаются**: `std::move` от `const`-объекта даёт `const T&&`, который связывается с конструктором копирования, а не перемещения.

## Пример: почему это эффективно

```cpp
std::vector<int> createBigVector() {
    std::vector<int> v(1'000'000);
    return v;  // NRVO или перемещение — копирования нет
}

std::vector<int> result = createBigVector();  // дёшево
```

Без семантики перемещения возврат такого вектора по значению (при отключённой оптимизации) приводил бы к копированию миллиона элементов. С ней — к передаче нескольких указателей.

## Итог

Семантика перемещения — это способ избежать ненужного копирования ресурсоёмких объектов за счёт передачи владения ресурсами от временных объектов (rvalue) к новым. Она реализуется через rvalue-ссылки, конструкторы/операторы перемещения и `std::move`, и является одной из ключевых возможностей C++11, лежащей в основе эффективной работы стандартной библиотеки (контейнеры, `std::unique_ptr`, `std::string` и др.).
