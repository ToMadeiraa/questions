# 67. Какая особенность константных методов-членов класса?

## Определение

Константный метод-член — это метод класса, который объявляется с ключевым словом `const` **после** списка параметров:

```cpp
class Point {
    double x, y;
public:
    double getX() const { return x; }   // константный метод
    void setX(double v) { x = v; }      // неконстантный метод
};
```

## Ключевые особенности

### 1. Запрет изменения состояния объекта

Внутри константного метода **нельзя** изменять нестатические поля класса (кроме полей, помеченных `mutable`):

```cpp
class Counter {
    int count = 0;
public:
    int get() const {
        // count = 5;  // ОШИБКА компиляции: count изменён в const-методе
        return count;
    }
};
```

### 2. Тип указателя `this`

В константном методе `this` имеет тип `const Класс*`, а в неконстантном — `Класс*`. Это напрямую влияет на перегрузку по константности.

### 3. Участие в перегрузке (overloading)

Можно иметь **две версии** одного метода, отличающиеся только `const`. Компилятор выбирает версию по константности объекта, от имени которого вызывается метод:

```cpp
class Array {
    int data[10];
public:
    int& operator[](int i)       { return data[i]; }        // для неконстантных объектов
    const int& operator[](int i) const { return data[i]; }  // для константных объектов
};

Array a;
const Array ca;
a[0]  = 5;   // вызов неконстантной версии
ca[0] = 5;   // ОШИБКА: вызов const-версии, возвращающей const int&
```

### 4. Возможность вызова для константных объектов

**Только константные методы** можно вызывать у объекта, объявленного как `const`. Именно это часто является причиной необходимости помечать методы `const`:

```cpp
const Point p{1, 2};
p.getX();  // OK — метод const
// p.setX(3);  // ОШИБКА: неконстантный метод нельзя вызвать
```

### 5. Спецификатор `mutable`

Поле, объявленное `mutable`, разрешено изменять даже в константном методе. Применяется для кэширования, счётчиков доступа, мьютексов:

```cpp
class Cache {
    mutable bool valid = false;
    mutable int cachedValue;
public:
    int compute() const {
        if (!valid) { cachedValue = /*...*/; valid = true; } // допустимо
        return cachedValue;
    }
};
```

### 6. Константность неглубокая (shallow const)

`const`-метод гарантирует неизменность **самого объекта** (его полей), но **не** объектов, на которые он ссылается через указатели/ссылки:

```cpp
class Holder {
    int* ptr;
public:
    void modify() const {
        *ptr = 42;   // допустимо! Меняется объект, на который указывает ptr
        // ptr = nullptr;  // ОШИБКА: изменяется само поле ptr
    }
};
```

Для «глубокой» константности применяют умные указатели с поддержкой константности (например, `std::experimental::propagate_const`).

### 7. Совместимость с `const`-объектами и передачей по константной ссылке

Методы без `const` **невозможно** вызвать через `const T&`, что критично при передаче в функции:

```cpp
void print(const Point& p) {
    p.getX();  // работает только если getX() — const-метод
}
```

## Рекомендации

- **Помечайте `const` все методы, которые не меняют логическое состояние объекта** — это правило «const correctness».
- Константные методы должны быть потокобезопасны при параллельных вызовах (иначе `mutable`-кэш требует синхронизации).
- `const` — часть сигнатуры: его изменение меняет ABI и может сломать перегрузки.

## Резюме

| Свойство | Константный метод |
|---|---|
| Изменение полей | запрещено (кроме `mutable`) |
| Тип `this` | `const T*` |
| Вызов у `const`-объекта | разрешён |
| Перегрузка по `const` | возможна |
| Влияние на указатели внутри | не защищает данные по указателю |
