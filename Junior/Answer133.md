# 133. Что такое deadlock?

**Deadlock (взаимная блокировка)** — это ситуация в многопоточной (или многопроцессной) программе, при которой два или более потока навсегда блокируют друг друга, ожидая ресурсы, удерживаемые друг другом. Ни один из потоков не может продолжить выполнение, и программа «зависает».

## Условия возникновения (условия Коффмана)

Для возникновения deadlock необходимо одновременное выполнение **всех четырёх** условий:

1. **Взаимное исключение (mutual exclusion)** — ресурс может быть захвачен только одним потоком в единицу времени.
2. **Удержание и ожидание (hold and wait)** — поток, уже удерживающий хотя бы один ресурс, ожидает получения дополнительных ресурсов, занятых другими потоками.
3. **Отсутствие принудительного отбора (no preemption)** — ресурс нельзя отобрать у потока; он освобождается только добровольно.
4. **Циклическое ожидание (circular wait)** — существует замкнутая цепочка потоков, в которой каждый поток ожидает ресурс, удерживаемый следующим потоком в цепочке.

## Классический пример на C++

Два потока захватывают два мьютекса в разном порядке:

```cpp
#include <iostream>
#include <mutex>
#include <thread>

std::mutex mtx1, mtx2;

void threadA() {
    std::lock_guard<std::mutex> lock1(mtx1);  // захватили mtx1
    std::this_thread::sleep_for(std::chrono::milliseconds(10)); // имитация работы
    std::lock_guard<std::mutex> lock2(mtx2);  // ждём mtx2 — он занят потоком B
    std::cout << "Thread A\n";
}

void threadB() {
    std::lock_guard<std::mutex> lock2(mtx2);  // захватили mtx2
    std::this_thread::sleep_for(std::chrono::milliseconds(10));
    std::lock_guard<std::mutex> lock1(mtx1);  // ждём mtx1 — он занят потоком A
    std::cout << "Thread B\n";
}

int main() {
    std::thread t1(threadA);
    std::thread t2(threadB);
    t1.join();  // программа зависнет здесь навсегда
    t2.join();
}
```

Здесь возникает **циклическое ожидание**: поток A держит `mtx1` и ждёт `mtx2`, поток B держит `mtx2` и ждёт `mtx1`.

## Способы предотвращения

### 1. Упорядочивание захвата блокировок
Всегда захватывать мьютексы в одном и том же порядке во всех потоках:

```cpp
void threadA() {
    std::lock_guard<std::mutex> lock1(mtx1);
    std::lock_guard<std::mutex> lock2(mtx2);  // тот же порядок, что и в B
}

void threadB() {
    std::lock_guard<std::mutex> lock1(mtx1);
    std::lock_guard<std::mutex> lock2(mtx2);
}
```

### 2. `std::lock` и `std::scoped_lock` (C++17)
Атомарный захват нескольких мьютексов без риска взаимной блокировки:

```cpp
// C++11
void threadA() {
    std::lock(mtx1, mtx2);  // захватывает оба, избегая deadlock
    std::lock_guard<std::mutex> l1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> l2(mtx2, std::adopt_lock);
}

// C++17 — проще всего
void threadA() {
    std::scoped_lock lock(mtx1, mtx2);  // сам выбирает безопасную стратегию
}
```

### 3. Использование `std::try_lock` с таймаутом
Не блокироваться бесконечно, а пытаться захватить ресурс и при неудаче освобождать уже захваченные:

```cpp
if (mtx1.try_lock()) {
    if (mtx2.try_lock()) {
        // работа
        mtx2.unlock();
    }
    mtx1.unlock();  // если mtx2 не удалось — освобождаем mtx1
}
```

### 4. Иерархия блокировок (lock hierarchy)
Присвоить блокировкам уровни и разрешать захват только в порядке возрастания уровня.

### 5. Избегание удержания и ожидания
Захватывать все необходимые ресурсы сразу, а не по одному.

## Связанные понятия

- **Livelock (живая блокировка)** — потоки активно работают (не блокированы), но не продвигаются вперёд, «уступая» друг другу.
- **Starvation (голодание)** — поток не получает ресурс слишком долго из-за неблагоприятного планирования, но система в целом продвигается.

## Итог

Deadlock — это состояние вечного взаимного ожидания потоков, возникающее при одновременном выполнении четырёх условий Коффмана. Главные практические средства борьбы в C++: **единый порядок захвата мьютексов**, `std::scoped_lock`/`std::lock`, `try_lock` с таймаутом и иерархия блокировок.
