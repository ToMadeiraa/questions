# Вопрос 47. Каков размер указателя и от чего он зависит?

> **Кратко:** Размер указателя равен размеру адреса в адресном пространстве целевой платформы: 4 байта на 32-битной архитектуре и 8 байт на 64-битной в подавляющем большинстве реализаций. Он **не зависит** от типа, на который указывает, но зависит от разрядности цели, принятой ABI модели данных и флагов компиляции. Гарантий конкретного значения стандарт C++ не даёт — только требование, чтобы указатель вмещал любой адрес объектов данного типа.

---

## От чего зависит размер

| Фактор | Как влияет |
|---|---|
| Разрядность целевой архитектуры | x86 — 4 байта, x86-64 — 8, ARM Cortex-M — 4, AVR — 2 |
| Модель данных ABI (`ILP32`, `LP64`, `LLP64`) | задаёт ширину указателя наравне с шириной `int`/`long` |
| Параметры компилятора (`-m32`, `-m64`, `--target=...`) | переключают цель; кросс-компиляция может дать другой размер, чем у хоста |
| Особые виды указателей | указатели на члены класса и указатели на функции могут иметь другой размер |

От чего размер **не** зависит:

- от типа объекта: `sizeof(int*) == sizeof(double*) == sizeof(SomeClass*)` на одной платформе;
- от `const` / `volatile` в типе;
- от значения указателя: `nullptr` занимает столько же, сколько и валидный адрес;
- от конкретной ОС как таковой — ОС лишь фиксирует ABI, а `sizeof` определяется платформой.

---

## Модели данных

| Модель | `int` | `long` | указатель | Типичные системы |
|---|---|---|---|---|
| `ILP32` | 4 | 4 | 4 | 32-битные Linux и Windows, x32 ABI |
| `LP64` | 4 | 8 | 8 | 64-битные Linux и macOS |
| `LLP64` | 4 | 4 | 8 | 64-битная Windows (MSVC) |
| `ILP64` | 8 | 8 | 8 | редко, отдельные HPC-платформы |

Отсюда классический вопрос-ловушка: на 64-битной Windows `sizeof(long) == 4`, а `sizeof(void*) == 8`, поэтому указатель нельзя хранить ни в `int`, ни в `long` — только в `std::intptr_t` / `std::uintptr_t`.

---

## Указатель — это адрес, а не объект

`sizeof` различает указатель и то, на что он указывает:

```cpp
#include <cstddef>
#include <cstdio>

struct Widget { int a; double b; };   // sizeof == 16

int main() {
    Widget  w{};
    Widget* p = &w;
    Widget  arr[4]{};

    std::printf("%zu\n", sizeof p);      // 8 — размер самого указателя
    std::printf("%zu\n", sizeof *p);     // 16 — размер объекта Widget
    std::printf("%zu\n", sizeof arr);    // 64 — размер массива целиком
    std::printf("%zu\n", sizeof(Widget*));  // 8: имя типа, а не выражения
}
```

Мнемоника: `sizeof` — про **представление в памяти**, а не про «глубину» указателя. Указатель не «знает» размер своего объекта.

---

## Когда равенство размеров ломается

| Случай | Что происходит |
|---|---|
| Указатель на член-данное (`int C::*`) | хранит смещение, а не адрес; на Itanium ABI — 8 байт, при виртуальном наследовании больше |
| Указатель на функцию-член (`void (C::*)()`) | обычно 8 или 16 байт (адрес + поправка `this`) |
| Гарвардская архитектура (AVR, часть DSP) | адрес кода и адрес данных имеют разную ширину: указатель на функцию может занимать больше байт, чем `void*` |
| `CHERI` и capability-архитектуры | «жирный» указатель 128 бит: адрес + границы + права |
| x32 ABI на x86-64 | 64-битные регистры, но 32-битные указатели |
| дальние указатели 16-битного x86 (`far`) | 4 байта (сегмент + смещение) против 2 у `near` |

Поэтому утверждение «все указатели одного размера» — практическое наблюдение для плоских моделей памяти, а не гарантия стандарта. Преобразование указателя на функцию в `void*` тоже не гарантировано.

## Как узнать разрядность переносимо

```cpp
#include <climits>
#include <cstdint>

constexpr int kAddressBits = static_cast<int>(sizeof(void*) * CHAR_BIT);
static_assert(kAddressBits == 64 || kAddressBits == 32);

void configure() {
    if constexpr (sizeof(void*) == 8) {
        // 64-битная разметка структур, свои лимиты, другой протокол
    } else {
        // 32-битная
    }
}
```

| Способ | Что даёт |
|---|---|
| `sizeof(void*) * CHAR_BIT` | ширина адреса в битах |
| `INTPTR_MAX` / `UINTPTR_MAX` | пределы целого типа, вмещающего указатель |
| `_WIN64`, `_M_IX86`, `__x86_64__`, `__LP64__` | предопределённые макросы платформы |
| `std::uintptr_t` | целочисленный тип, гарантированно вмещающий указатель (опционален) |

---

## Практические следствия

- **Память.** Структура с указателем на 64-битной платформе на 4 байта больше; на массиве из миллиона элементов это 4 МБ и лишние промахи кэша.
- **Сериализация.** Указатели нельзя передавать между процессами, сохранять в файл и отправлять по сети: адрес имеет смысл только внутри одного адресного пространства.
- **ABI.** Смена 32/64 меняет разметку структур и бинарную совместимость библиотек; заголовок с указателем в публичном интерфейсе фиксирует разрядность.
- **Приведение к целому.** Только через `std::uintptr_t`; `int` и `long` на 64-битной Windows переполнятся.
- **Адресное пространство ≠ размер указателя.** На x86-64 виртуальные адреса обычно 48 бит, но указатель всё равно 8 байт.

---

## Типичные ошибки

1. **«Размер указателя зависит от типа»** — нет, зависит от платформы.
2. **Хранить указатель в `int`.** На 64-битной платформе это усечение и потеря старших битов адреса.
3. **Путать `sizeof(p)` и `sizeof(*p)`** либо ожидать, что `sizeof` для массива даст размер указателя (массив в выражении затухает до указателя, но только не в `sizeof`).
4. **Считать, что 64-битный указатель адресует 2^64 байт.** Реально доступно меньше, и переносить на разные платформы «магические» вычисления адресов нельзя.
5. **Ожидать 8 байт при сборке с `-m32`** или при кросс-компиляции под 32-битную цель.
6. **Считать `sizeof(void*)` равным `sizeof` указателя на функцию** — на экзотических архитектурах это не так.

---

## Что добавить на собеседовании

- Хорошо звучит связка: «указатель — это машинный адрес; на 32-битной платформе их 4 байта и адресуется 4 ГБ, на 64-битной — 8 байт, при этом полезных битов адреса обычно 48».
- Упомянуть LLP64 vs LP64 — это объясняет, почему на Windows `long` остался 4-байтным и почему появились `size_t` / `intptr_t` / `uintptr_t`.
- Показать, что различие реально важно: сериализация, ABI библиотек, экономия памяти на массивах структур, перенос кода с 32 на 64 бита (классические баги «указатель в int»).
- Для собеседования уровня Junior достаточно: `sizeof(void*)` — 4 или 8, от типа не зависит, зависит от платформы; знать про `uintptr_t`.

## Итог

| Вопрос | Ответ |
|---|---|
| Размер на 32-битной платформе | 4 байта |
| Размер на 64-битной платформе | 8 байт |
| Зависит от типа объекта | нет (кроме указателей на члены и экзотических архитектур) |
| Зависит от | разрядности цели, модели данных ABI, флагов компиляции |

| Переносимый способ получить | `sizeof(void*)`, `std::uintptr_t`, `std::intptr_t` |
| Влияние на программу | размер структур, ABI, сериализация, расход памяти |
