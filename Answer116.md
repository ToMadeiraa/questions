# 116. Как защитить объект от копирования в C++

В C++ по умолчанию для класса генерируются **конструктор копирования** и **оператор присваивания копированием**. Если нужно запретить копирование объекта, есть несколько подходов.

## 1. Удаление через `= delete` (современный C++, C++11 и новее)

Самый чистый и явный способ — пометить специальные функции как удалённые:

```cpp
class NonCopyable {
public:
    NonCopyable() = default;

    // Запрещаем копирование
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;

    // При необходимости разрешаем перемещение
    NonCopyable(NonCopyable&&) = default;
    NonCopyable& operator=(NonCopyable&&) = default;
};

int main() {
    NonCopyable a;
    // NonCopyable b = a;  // Ошибка компиляции
    // a = NonCopyable();  // (если оператор копирования удалён, а перемещения нет — ошибка)
}
```

При попытке скопировать объект компилятор выдаст **ошибку на этапе компиляции** с понятным сообщением: «use of deleted function».

## 2. Объявление без определения (классический способ, до C++11)

Функции объявляются `private` (или `protected`) и **не определяются**:

```cpp
class NonCopyable {
public:
    NonCopyable() = default;

private:
    NonCopyable(const NonCopyable&);            // объявлен, но не определён
    NonCopyable& operator=(const NonCopyable&); // объявлен, но не определён
};
```

- Для внешнего кода копирование запрещено (функции приватные).
- Если какая-то функция-член класса попытается скопировать объект, будет **ошибка линковки** (undefined reference).

Недостаток: ошибка возникает не сразу и не всегда понятна.

## 3. Наследование от `boost::noncopyable`

Библиотека Boost предоставляет готовый базовый класс:

```cpp
#include <boost/noncopyable.hpp>

class MyClass : private boost::noncopyable {
    // ...
};
```

В современном C++ (C++11+) `boost::noncopyable` внутри реализован именно через `= delete`.

## 4. Собственный базовый класс `NonCopyable`

Часто используют собственный «миксин»:

```cpp
class NonCopyable {
protected:
    NonCopyable() = default;
    ~NonCopyable() = default;

    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};

class Resource : private NonCopyable {
    // ...
};
```

Конструктор и деструктор — `protected`, чтобы нельзя было создать объект базового класса напрямую и чтобы наследники могли корректно создаваться/уничтожаться.

## Важные нюансы

- **Копирование vs перемещение.** Удаление копирования **не запрещает перемещение**. Если нужно запретить и его, удалите также move-конструктор и move-присваивание:

  ```cpp
  MyClass(MyClass&&) = delete;
  MyClass& operator=(MyClass&&) = delete;
  ```

- **Правило пяти.** Если вы объявляете/удаляете хотя бы одну из специальных функций (копирование, перемещение, деструктор), стоит явно определить или удалить остальные, чтобы избежать неожиданного поведения.

- **`= delete` предпочтительнее.** Это декларативный способ: ошибка возникает на этапе компиляции с ясным сообщением, а намерение программиста видно прямо в интерфейсе класса.

- **Разница между копированием и присваиванием.** Запрещать нужно **обе** операции: конструктор копирования (`T(const T&)`) и оператор присваивания (`T& operator=(const T&)`), иначе объект всё равно можно будет скопировать одним из способов.

## Итог

| Способ | Когда использовать |
|---|---|
| `= delete` | Современный C++, предпочтительный вариант |
| Private без определения | Легаси-код, C++03 |
| `boost::noncopyable` | Проекты с Boost |
| Собственный базовый класс | Удобно для группы классов |

Наиболее рекомендуемый способ в современном C++ — **явное удаление конструктора копирования и оператора присваивания копированием через `= delete`**.
