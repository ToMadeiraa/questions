# 61. Разница между `private`, `protected` и `public` в C++

## Общее назначение

Модификаторы доступа (`access specifiers`) определяют **уровень инкапсуляции** членов класса — кто может обращаться к полям, методам, конструкторам и вложенным типам. Они реализуют один из ключевых принципов ООП — **инкапсуляцию**, скрывая внутреннюю реализацию и предоставляя контролируемый интерфейс.

## Сравнительная таблица

| Модификатор | Доступ изнутри класса | Доступ из производного класса | Доступ извне (в коде пользователя) |
|---|---|---|---|
| `public` | ✅ Да | ✅ Да | ✅ Да |
| `protected` | ✅ Да | ✅ Да | ❌ Нет |
| `private` | ✅ Да | ❌ Нет | ❌ Нет |

## Подробно о каждом

### `public` — открытый доступ

Члены доступны **всем**: и внутри класса, и в производных классах, и во внешнем коде. Это публичный **интерфейс** класса — то, чем класс «обещает» пользоваться.

```cpp
class Point {
public:
    int x;          // доступно везде
    void move(int dx);  // доступно везде
};

Point p;
p.x = 10;           // OK
p.move(5);          // OK
```

**Где используется:** для описания API класса — методов, которые формируют контракт с пользователем, публичных констант, конструкторов.

---

### `protected` — защищённый доступ

Члены доступны внутри класса и **в производных классах**, но **недоступны снаружи**. Ключевой момент: доступ к `protected`-члену *базового* класса из производного возможен **только через объект производного типа** (или через `this`), но не через объект базового типа.

```cpp
class Base {
protected:
    int value;
};

class Derived : public Base {
public:
    void setValue(int v) {
        value = v;          // OK: доступ через this
    }
    void copyFrom(const Derived& other) {
        value = other.value; // OK: other имеет тип Derived
    }
    // void bad(const Base& b) { b.value = 1; } // ОШИБКА: доступ через Base запрещён
};
```

**Где используется:** когда нужно дать производным классам доступ к внутренним данным/помощникам, но скрыть их от внешнего мира. Часто применяется в иерархиях наследования, в шаблонах (CRTP), во вспомогательных методах.

> ⚠️ **Предостережение:** `protected`-данные-члены считаются спорной практикой (нарушают инкапсуляцию при наследовании). Обычно предпочитают `private`-данные + `protected`-методы доступа.

---

### `private` — закрытый доступ

Члены доступны **только внутри самого класса** (и его `friend`-функций/классов). Недоступны ни производным классам, ни внешнему коду.

```cpp
class Account {
private:
    double balance;   // скрыто от всех
    void validate();  // внутренний помощник

public:
    double getBalance() const { return balance; }
    void deposit(double sum) {
        validate();
        balance += sum;
    }
};
```

**Где используется:** для **внутренней реализации** — данных, вспомогательных методов, деталей, которые могут измениться без ломки API. Это значение по умолчанию для членов `class`.

## Значения по умолчанию

Важно помнить разницу между `class` и `struct`:

```cpp
class A { int x; };   // x — private (по умолчанию)
struct B { int x; };  // x — public  (по умолчанию)
```

Также по умолчанию **приватно наследование** в `class` (`class D : Base`) и **публично** в `struct` (`struct D : Base`).

## Дружественные объявления (`friend`)

`friend`-функция или `friend`-класс получают доступ к `private` и `protected` членам, как если бы были членами класса:

```cpp
class Matrix {
private:
    double* data;
    friend std::ostream& operator<<(std::ostream&, const Matrix&);
};
```

## Важные нюансы

1. **Модификаторы действуют на блок**, а не на отдельный член: после `private:` все последующие члены приватны, пока не встретится другой спецификатор.
2. **Порядок и повторение** спецификаторов произвольны; можно возвращаться к `public:` несколько раз.
3. **Доступ проверяется на этапе компиляции**, а не в рантайме — это чисто статическая защита.
4. **Инкапсуляция ≠ безопасность**: `private` защищает от случайного использования, но не от злонамеренного (через `reinterpret_cast`, `#define private public` и т.п.).
5. **`protected` и наследование:** производный класс видит `protected`-члены базового, но если наследование **приватное** (`class D : private Base`), то внутри `D` они становятся как `private` для дальнейших наследников.

## Практическая рекомендация

- **`private` по умолчанию** для данных и деталей реализации — это главный инструмент инкапсуляции.
- **`public`** — только для того, что составляет стабильный интерфейс класса.
- **`protected`** — когда действительно нужен доступ наследникам; используйте осознанно, предпочитая `protected`-методы, а не `protected`-данные.

Такая схема даёт **минимальный публичный контракт** и максимальную свободу менять реализацию без поломки пользовательского кода.
