# 68. Как изменить поле класса в константном методе класса

## Суть проблемы

Константный метод (`const` после списка параметров) даёт гарантию, что метод **не изменяет состояние объекта**. Внутри такого метода все нестатические поля класса рассматриваются как константные:

```cpp
class Example {
    int value;
public:
    void foo() const {
        value = 10; // Ошибка компиляции: assignment of member in read-only object
    }
};
```

Компилятор запрещает прямое изменение полей. Однако иногда это всё же необходимо (например, для ленивого кэширования, счётчиков обращений, мьютексов и т.п.). Есть два основных способа обойти ограничение.

---

## Способ 1: ключевое слово `mutable`

Поле, объявленное с ключевым словом `mutable`, можно изменять даже в константных методах:

```cpp
class Example {
    mutable int counter = 0;
    int data = 42;
public:
    int getData() const {
        ++counter; // OK: counter объявлено mutable
        return data;
    }
};
```

**Особенности:**
- `mutable` применяется только к нестатическим полям данных.
- Изменение `mutable`-поля не нарушает логическую константность объекта (с точки зрения внешнего наблюдателя объект не меняется).
- Классические примеры использования: кэш вычислений, счётчик вызовов, `std::mutex` для потокобезопасности.

---

## Способ 2: `const_cast` (снятие константности)

Можно явно снять константность с `this` внутри метода:

```cpp
class Example {
    int value = 0;
public:
    void setValue(int v) const {
        const_cast<Example*>(this)->value = v; // работает, но опасно
    }
};
```

Или через приведение поля:

```cpp
void setValue(int v) const {
    const_cast<int&>(value) = v;
}
```

**Важное предостережение:** этот способ корректен **только если объект изначально не был создан как константный**. Если объект действительно объявлен `const`, изменение через `const_cast` приводит к **неопределённому поведению** (UB):

```cpp
const Example e;
e.setValue(10); // UB!
```

Именно поэтому `mutable` — предпочтительный и безопасный способ.

---

## Чего делать нельзя

- Нельзя объявлять поле `mutable static` — `mutable` несовместим со `static`.
- Нельзя менять обычные (не `mutable`) поля в константном методе без `const_cast`.
- Не следует использовать `const_cast` для обхода константности «по-настоящему» константных объектов.

---

## Итоговая рекомендация

| Ситуация | Решение |
|---|---|
| Поле логически не является частью состояния (кэш, счётчик, мьютекс) | `mutable` |
| Нужно изменить обычное поле, объект гарантированно не `const` | `const_cast` (с осторожностью) |
| Объект действительно `const` | Изменять нельзя — пересмотреть дизайн класса |

Правильный подход в большинстве случаев — **`mutable`**: он выражает намерение явно, безопасен и не приводит к неопределённому поведению.
