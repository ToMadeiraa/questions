# 153. Что такое менеджер пакетов?

**Менеджер пакетов** (package manager) — это программный инструмент, который автоматизирует процесс установки, обновления, настройки и удаления программных пакетов (библиотек, зависимостей, утилит), а также отслеживает их версии и взаимные зависимости.

## Основные задачи менеджера пакетов

1. **Установка пакетов** — загрузка нужной библиотеки из репозитория и её интеграция в проект или систему.
2. **Управление зависимостями** — автоматическое разрешение дерева зависимостей: если пакет A требует пакеты B и C, менеджер сам их подтянет.
3. **Контроль версий** — фиксация конкретных версий пакетов и разрешение конфликтов между требованиями разных зависимостей (version resolution).
4. **Обновление** — получение новых версий пакетов с учётом совместимости.
5. **Удаление** — корректное удаление пакета и, при необходимости, «осиротевших» зависимостей.
6. **Воспроизводимость сборки** — фиксация точного набора версий (lock-файлы), чтобы проект собирался одинаково на разных машинах.

## Как это устроено

Менеджер пакетов обычно работает с **репозиторием** — хранилищем пакетов (центральным или локальным). В проекте есть **манифест** — файл с описанием зависимостей и их версий, и **lock-файл** — зафиксированный результат разрешения зависимостей.

```
манифест (что хотим)  →  разрешение зависимостей  →  lock-файл (что получилось)
                                                        ↓
                                             загрузка и установка пакетов
```

## Менеджеры пакетов в мире C++

В C++ долгое время не было единого стандартного менеджера пакетов (в отличие, например, от Rust с Cargo или JavaScript с npm), поэтому существует несколько конкурирующих решений:

| Инструмент | Особенности |
|---|---|
| **vcpkg** (Microsoft) | Кроссплатформенный, интеграция с CMake и MSBuild, большой каталог портов |
| **Conan** (JFrog) | Кроссплатформенный, мощное управление версиями и бинарными пакетами, поддержка разных систем сборки |
| **Hunter** | Построен на CMake, ориентирован на воспроизводимость |
| **C++20 Modules / CMake FetchContent** | Не полноценные менеджеры, но часто используются для подтягивания зависимостей |
| **Системные менеджеры** | `apt` (Debian/Ubuntu), `yum`/`dnf` (RHEL/Fedora), `brew` (macOS), `chocolatey` (Windows) — ставят библиотеки на уровне ОС, но плохо управляют версиями на уровне проекта |

## Пример: vcpkg

```bash
# Установка библиотеки
vcpkg install fmt

# Установка с указанием триплета (архитектуры)
vcpkg install fmt:x64-windows

# Просмотр установленных пакетов
vcpkg list
```

В `CMakeLists.txt` подключение выглядит так:

```cmake
find_package(fmt CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE fmt::fmt)
```

## Пример: Conan

Файл `conanfile.txt`:

```ini
[requires]
fmt/10.2.1
nlohmann_json/3.11.3

[generators]
CMakeDeps
CMakeToolchain
```

Установка зависимостей:

```bash
conan install . --build=missing
```

## Зачем это нужно

Без менеджера пакетов разработчик вынужден вручную скачивать библиотеки, собирать их под нужную платформу/компилятор и прописывать пути в системе сборки — это трудоёмко и плохо воспроизводимо. Менеджер пакетов превращает этот процесс в декларативное описание зависимостей и одну команду установки, что упрощает командную работу, CI/CD и перенос проекта между машинами.

## Краткий итог

Менеджер пакетов — это инструмент, который берёт на себя загрузку, установку, обновление и разрешение зависимостей программных пакетов, обеспечивая воспроизводимость сборки. В C++ наиболее распространены **vcpkg** и **Conan**, поскольку единого стандартного менеджера пакетов в языке пока нет.
