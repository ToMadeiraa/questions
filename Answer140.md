# 140. Какие операции можно делать с сокетом?

В C++ (и в лежащем в его основе сокетном API POSIX/Winsock) с сокетом можно выполнять набор стандартных операций, которые делятся на несколько логических групп: создание, установка соединения, передача данных, управление параметрами и закрытие.

Вот подробный разбор операций с сокетами, которые доступны в C++.

### 1. Создание и закрытие
Любая работа с сокетом начинается с его создания и заканчивается закрытием.

*   **Создание (`socket`)**: Системный вызов, который создает новый сокет и возвращает файловый дескриптор (или хэндл в Windows). Вы указываете домен (например, `AF_INET` для IPv4), тип (например, `SOCK_STREAM` для TCP) и протокол .
*   **Закрытие (`close` / `closesocket`)**: Освобождает ресурсы, связанные с сокетом. В POSIX-системах используется `close()`, в Windows (Winsock) — `closesocket()`.

### 2. Установка соединения (для TCP / SOCK_STREAM)
Эти операции характерны для надежных потоковых сокетов.

*   **Привязка (`bind`)**: Связывает сокет с локальным адресом (IP-адресом и портом). Обычно используется на стороне сервера, чтобы указать, на каком порту он будет принимать подключения .
*   **Прослушивание (`listen`)**: Переводит сокет в режим ожидания входящих подключений. Сервер сообщает операционной системе, что готов принимать клиентов .
*   **Принятие (`accept`)**: Извлекает первое подключение из очереди готовых к обработке. Возвращает **новый** сокет, предназначенный для общения с конкретным клиентом, в то время как исходный сокет продолжает слушать дальше .
*   **Подключение (`connect`)**: Используется на стороне клиента для установки соединения с удаленным сервером по указанному адресу .

### 3. Передача и прием данных
Это основные операции для обмена информацией.

*   **Отправка (`send` / `write`)**: Передает данные через установленное соединение. Для TCP-сокетов гарантирует доставку (в рамках соединения), но не гарантирует, что все данные будут отправлены за один вызов .
*   **Прием (`recv` / `read`)**: Читает данные из буфера сокета. Возвращает количество прочитанных байт. Если соединение закрыто другой стороной, возвращает `0` .
*   **Отправка/Прием датаграмм (`sendto` / `recvfrom`)**: Используются для UDP-сокетов (`SOCK_DGRAM`), где каждое сообщение адресуется независимо, и вы должны указывать адрес получателя при каждой отправке .

### 4. Управление сокетом и параметрами
Эти функции позволяют настраивать поведение сокета и получать информацию о нем.

*   **Настройка опций (`setsockopt`)**: Позволяет изменять параметры сокета (например, включить повторное использование адреса `SO_REUSEADDR`, установить таймауты, размер буфера или режим неблокирующего ввода-вывода) .
*   **Получение опций (`getsockopt`)**: Читает текущие настройки сокета.
*   **Управление вводом-выводом (`ioctl` / `ioctlsocket`)**: В Windows `ioctlsocket` используется для управления режимом ввода-вывода, например, для переключения сокета в неблокирующий режим (`FIONBIO`) . В POSIX-системах для этого обычно используют `fcntl`.
*   **Получение адресов (`getsockname` / `getpeername`)**: `getsockname` возвращает локальный адрес, связанный с сокетом. `getpeername` возвращает адрес удаленной стороны (peer), с которой установлено соединение .
*   **Завершение соединения (`shutdown`)**: Позволяет частично или полностью закрыть соединение (например, запретить дальнейшую отправку данных, но оставить возможность чтения) .

### 5. Ожидание событий (Мультиплексирование)
Вместо того чтобы блокироваться в `recv` или `accept`, можно ждать готовности нескольких сокетов сразу.

*   **`select` / `poll` / `epoll` (Linux) / `kqueue` (BSD)**: Эти механизмы позволяют программе ожидать, когда один или несколько сокетов станут готовы к чтению, записи или когда произойдет ошибка .

### Важное замечание для C++
В стандартной библиотеке C++ (STL) **нет** встроенных классов для работы с сокетами. Все перечисленные выше операции являются частью системного API (POSIX на Linux/macOS и Winsock на Windows). В C++ вы либо вызываете эти функции напрямую (например, через `<sys/socket.h>` или `<winsock2.h>`), либо используете сторонние библиотеки-обертки (например, Boost.Asio, которая предоставляет объектно-ориентированный и асинхронный интерфейс для этих же операций ).
