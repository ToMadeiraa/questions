# Вопрос 49. Что такое struct?

> **Кратко:** `struct` — пользовательский тип, который объединяет несколько именованных полей (обычно разных типов) в один объект, так что с ними можно работать как с единым целым. В C структура содержит только данные; в C++ это полноценный класс, у которого доступ по умолчанию — `public`, поэтому она может иметь конструкторы, методы, операторы, наследование и виртуальные функции.

---

## Что это в C

В C `struct` — это только агрегат данных, без методов и наследования. Имя структуры живёт в отдельном пространстве имён тегов, поэтому нужно писать `struct Point`:

```c
struct Point {
    int x;
    int y;
};

struct Point p = {1, 2};   /* без typedef слово struct обязательно */
```

В C++ тег становится обычным именем типа, и `struct` в объявлении переменной не нужен:

```cpp
struct Point { int x; int y; };
Point p{1, 2};             // работает
struct Point q{3, 4};      // тоже работает, но избыточно
```

---

## Что это в C++: struct и class — одно и то же

Единственные различия между `struct` и `class` — доступ по умолчанию и вид наследования по умолчанию.

| Свойство | `struct` | `class` |
|---|---|---|
| Доступ к членам по умолчанию | `public` | `private` |
| Наследование по умолчанию | `public` | `private` |
| Может иметь конструкторы, методы, `virtual` | да | да |
| Может быть агрегатом | да, если нет пользовательских конструкторов и закрытых полей | да, при тех же условиях |
| Может наследоваться и быть базой | да | да |
| Может быть шаблоном | да (`template<class T> struct S`) | да |
| Соглашение об использовании | данные, простые типы, межъязыковой интерфейс | инкапсуляция, инварианты, поведение |

То есть `struct` — это не «урезанный класс», а класс с другой политикой доступа по умолчанию. Компилятор порождает для такой структуры те же специальные функции-члены.

## Структура как полноценный тип

```cpp
#include <cmath>

struct Vector2 {
    double x = 0.0;
    double y = 0.0;

    double norm() const noexcept { return std::sqrt(x * x + y * y); }

    Vector2& operator+=(const Vector2& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;
    }
};

Vector2 a{3.0, 4.0};
a += Vector2{1.0, 1.0};        // a == {4, 5}: у структуры есть оператор
double len = a.norm();          // и метод
```

Здесь `Vector2` — маленький значимый тип: копируется по значению, не владеет ресурсами, инвариант тривиален.

## Агрегаты и агрегатная инициализация

**Агрегат** (C++20) — это массив либо класс, у которого нет пользовательских или унаследованных конструкторов, нет закрытых и защищённых нестатических полей, нет виртуальных функций и нет виртуальных, закрытых или защищённых базовых классов.

Для агрегата разрешена агрегатная инициализация — самый удобный способ создать структуру:

```cpp
struct Config {
    int  width  = 1280;   // значение по умолчанию
    int  height = 720;
    bool vsync  = true;
};

Config a{1920, 1080, false};                    // позиционно, по порядку полей
Config b{.width = 800, .height = 600};          // C++20: designated initializers
Config c{};                                     // все поля — из инициализаторов по умолчанию
// Config d{1920, 1080, false, 60};             // ошибка: лишний инициализатор
```

Правила designated initialization в C++20: инициализаторы идут в порядке объявления полей, пропускать поля можно, повторять — нельзя, сужающие преобразования запрещены. В C то же самое (`{.width = 800}`) появилось в C99 и тоже с ограничениями.

## Разметка памяти: зачем структура нужна как контракт

Структура задаёт **порядок и смещение** полей, то есть двоичный формат. Это используют для сетевых пакетов, файлов, memory-mapped I/O и вызовов C-библиотек:

```cpp
#include <cstdint>
#include <cstring>
#include <type_traits>

struct Header {
    std::uint8_t  version;
    std::uint8_t  flags;
    std::uint16_t length;
};

static_assert(std::is_trivially_copyable_v<Header>);
static_assert(std::is_standard_layout_v<Header>);

Header h{1, 0, 42};
std::uint8_t buffer[sizeof(Header)];
std::memcpy(buffer, &h, sizeof h);      // допустимо: тип trivially copyable
```

Чтобы тип годился для `memcpy` и чтения из буфера, он должен быть **trivially copyable**; чтобы у полей были предсказуемые смещения для C-интерфейса — **standard-layout**.

| Категория | Требование (упрощённо) | Зачем |
|---|---|---|
| `trivially copyable` | тривиальные копирование, перемещение и деструктор | `memcpy`, `std::bit_cast`, передача через границу ABI |
| `standard-layout` | одинаковый доступ у всех нестатических полей, нет виртуальных, ограничения на базы | `offsetof`, совместимость с C |
| `aggregate` | нет пользовательских конструкторов, все поля открыты | инициализация `{...}`, structured bindings |
| `POD` (до C++20) | trivially copyable + standard-layout | «как в C» |

## Структура в C++ и структура в C: совместимость

```cpp
extern "C" {
    struct Timespec {          // layout-совместима с C-версией
        std::int64_t tv_sec;
        std::int32_t tv_nsec;
    };
}
```

Чтобы структура оставалась совместимой с C, в ней не должно быть виртуальных функций, закрытых полей, базовых классов и нетривиальных конструкторов: всё это меняет представление в памяти.

## Полезные детали

- **Пустая структура занимает 1 байт** — объекты должны иметь различимые адреса.
- **Structured bindings** (C++17) разбирают агрегат по полям: `auto [w, h, v] = config;`.
- **Вложенные структуры** допустимы: `struct A { struct B { int x; } b; };`.
- **Битовые поля**: `struct Flags { unsigned ready : 1; unsigned mode : 3; };` — упаковка внутри единицы хранения.
- **Виртуальные функции** добавляют в объект скрытый указатель на таблицу виртуальных функций и увеличивают `sizeof`.
- **Сравнение по умолчанию** (C++20): `bool operator==(const Config&) const = default;` даёт поэлементное сравнение.
- **Неполный тип**: после `struct Node;` можно объявить `Node*` и `Node&`, но не поле `Node` и не `sizeof(Node)`.
- **Статические поля** не входят в размер объекта и существуют в единственном экземпляре.

## Типичные ошибки

1. **Считать, что `struct` в C++ не имеет методов.** Основное различие с `class` — только доступ по умолчанию, а не набор возможностей.
2. **Забыть про `public:` при переходе на `class`** и получить закрытые поля там, где ожидался агрегат.
3. **Ожидать, что `sizeof` структуры равен сумме `sizeof` полей.** Padding добавляет байты — об этом отдельный вопрос.
4. **Передавать структуру с указателями через `memcpy` или в файл** — скопируются адреса, а не данные.
5. **Сравнивать структуры через `memcmp`** при наличии padding: байты заполнения не инициализированы, результат непредсказуем.
6. **Пытаться сделать агрегат из типа с пользовательским конструктором** и удивляться, что `{...}` больше не компилируется.
7. **Использовать `struct` без имени тега** (`struct { ... } s;`) и потом не иметь возможности объявить переменную того же типа.

## Что добавить на собеседовании

- Формулировка «struct — это class с public по умолчанию» точна, но полезно добавить следствие: структуры принято использовать для пассивных данных и для типов, чья разметка важна, а классы — там, где есть инварианты.
- Стоит упомянуть, что структура — единица композиции: предпочтительнее собрать объект из полей-значений, чем строить иерархию наследования.
- Хорошо звучит знание `trivially copyable` / `standard-layout` и того, что `std::bit_cast` (C++20) требует trivially copyable типа.
- Для C++20 уместно назвать designated initializers и `operator==` по умолчанию — эти две возможности сильнее всего меняют работу со структурами-данными.
